# B1-IMP 固定参数命名调用前置

工程期：20O-B1-IMP。此独立前置处理 F12 已冻结的命名调用，不新增语法、intrinsic、ABI、
默认值或可变参数能力，不把七库草稿视为验收完成。

旧动态降低要求每个实参都是 positional/name=None，导致 `abs(value = ...)` 在原生拒绝。
静态降低也拒绝所有 keyword 实参。修复共享一份固定参数绑定计划：

1. 先校验数量、名称及重复绑定，固定普通形参必须全部提供；展开与未知名称仍拒绝。
2. 按源码实参顺序求值并保存各值/拥有槽，保持副作用、失败位置与清理顺序。
3. 仅在发出函数调用时按形参顺序排列已求值的 SSA 值或槽，不重排表达式求值。

最初命名调用修复使用生成器版本 17 隔离新降低指纹，Runtime ABI 保持 1.18。已有全位置调用保留原行为。
类型错误和缺失/重复/未知参数仍由前端按 `X04-TYPE-002` 拒绝；原始无效 IR 在后端也明确拒绝。

`20c_first_modules.rs` 的共享样例验证逆序命名、位置/命名混合、str 拥有结果、按源码顺序
追加的副作用，以及后续实参抛错时的既有清理。样例复用原有原生差分目标，不新增未受守卫的
ignored 精确入口。静态降低保留展开拒绝用例，并将合法固定命名调用改为正向验证。

验证与提交分别登记，不用通过删除七库命名调用来换取绿色；F10 字符串成本另作独立修复。

原生故障路径曾检出先前实参拥有槽未释放，现将所有实参槽预先初始化并在求值失败边统一归还，
保持原 pending 错误的传播目标。带 str 临时值与后续实参抛错的同源 VM/native 用例验证
最终销毁数一致，没有通过减少清理断言掩盖泄漏。

本机原生既有差分目标 `first_modules_match_native_results --exact` 已实际通过
`1 passed; 0 failed; 0 ignored`，耗时 18.44 秒。后续生成器 19 的默认工作区及三平台
维护回归 41372968883 已通过，逐作业与原始日志摘要见
[三模块 CI 证据](assets/20o-b1-imp/maintenance-41372968883/README.md)。这是前置和当前
12/20 产品草稿的功能证据，完整七库及 F10/CLOSE 尚未交付。

完整产品复测另检出未改名的 `statistics.min` 误绑到 `math.min`。版本 19 的独立后续修复
将所有选择导入绑定到真实模块函数，保留同名定义，并让模块内部调用使用自身模块名称。
移除真实函数体后明确拒绝，不借用其它模块同名函数兜底。此项不改变 F12、语法或 ABI。

逐形参负例还检出 `std.` 源码接口只注入了规范路径，公共别名退化成 Dynamic，导致
`abs("bad")` 未在前端拒绝。驱动器现将同一份完整签名同时注入两条路径；类型检查、VM
与原生继续消费既有契约，不新增公开 dynamic 或语言能力。20C 独立回归覆盖别名、限定及
函数内导入的类型、缺参和未知名称错误，B1 产品矩阵保留公共路径负例。
