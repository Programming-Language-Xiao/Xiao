### 2.2 **A2：复用 A1 的契约实现初始化参数**

清单末尾明写「A2 参数构造与 A3 函数值 ABI 后续复用 A1 契约」——**不要另起一套描述符或回调形态**。

**冻结**：

1. 初始化参数走 **A1 已建立的注册式回调**（指针 + 长度 + `i32` 状态，`receiver`/实参调用期借用），
   **不按值返回聚合结构**，也不改 V2 描述符的既有字段含义；
2. 构造与初始化**复用 Runtime 既有的初始化状态机**（`TableInstance::with_initializer` 那条线），
   包含构造失败回滚与错误主因/抑制链；**不另造状态机**；
3. **VM 是语义基准**：构造参数的求值顺序、默认值、缺参/多参/类型不符的错误身份，都以 VM 为准；
   不为了原生好实现而改 VM；
4. 不先删拒绝：`methods.rs:108` 与 `container.rs:216` 两处保留到契约可用，最后一步移除；
5. 若某类参数（例如带默认值、或需要求值顺序保证）暂时接不通，**继续拒绝并登记**，
   不得用「返回空值」之类的占位实现蒙混；
6. 版本规则沿用 10T：只加入口走次版本，改既有布局/所有权才升主版本，并同步断言字面量的测试与兼容矩阵。

### 2.3 **A3：先把能力边界冻住，再决定要不要实现**

10P 的枚举表对 A3 的判定是「**能力边界未冻结**；暂不并入」，而审核看到两处拒绝各有不同性质：

- `expression.rs:47`：`Member` 的结果类型是 `IrType::Function` 时拒绝（**表方法值**）；
- `methods.rs:53`：ABI 没有 Function 标签（**函数值本身**无法进入值 ABI）。

**这可能是「两边都拒绝」而不是原生缺口**——如果 VM 侧同样不支持把方法值/函数值当作一等值，
那 A3 就不该按缺口实现，而应改判为「一致，不是缺口」。

**冻结**：

1. 第一步**只做实验取证**，不改后端：用最小源码在 **VM** 上确定这些形态的实际行为
   （`obj.method` 作为值、把方法值赋给变量、把方法值传参、把方法值作为 callee）；
   注意 VM 里存在 `RuntimeValue::ModuleFunction`，说明函数值并非完全不存在，
   **必须实跑确认，不得只看代码推断**；
2. 结论写进枚举表并**按三种分类之一改判**：原生缺口 / 两边都拒绝 / 原生拒绝且 VM 也不该支持；
3. 只有判定为**原生缺口**时才排实现，且实现前先补一份与 [10S-A1](10s-a1-table-method-abi-preparation.md)
   同规格的开工清单；判定为「两边都拒绝」时，本批只更正文档，不动代码；
4. 无论哪种结论，**都要给最小源码与实跑输出**，不能只写一句结论。

### 2.4 **三平台与释放证据：沿用 10T 的要求，不放宽**

**冻结**：

- 每个阶段性提交在本机 Windows 跑受控原生门控，**并**在至少一个 Unix 目标上验证
  （现在有 Windows + Linux 的 push 门控矩阵作兜底，但裸机证据仍另算）；
- 新增/更新的布局与调用约定测试**同时覆盖 Windows 与 SysV**；
- 释放证据含**事件数、对象数、销毁位置**与**引用持有机制**；成对实验只改一处、采数、恢复；
- 新用例要**能分辨对错**（不是「两边都成功」），并保持过期豁免守卫有效。

### 2.5 **星崽侧：窗口取证用真实 `-debug` 运行**

**冻结**：

- 交接文档（[10T-Linux](10t-linux-bare-metal-handoff.md)）把窗口那一步改成：
  1. `sudo update-alternatives --set x-terminal-emulator /usr/bin/xterm`（与 CI 一致，且规避 Terminator 的配置报错）；
  2. 用 `xiao run -debug <一个能持续数秒的程序>`（不是门控测试），在程序运行期间观察并**截图**；
  3. 记录窗口是否**持续存在**到程序结束、关闭窗口后程序行为是否改变；
  4. 若窗口仍不出现，连同 `pgrep -a xiao-diagnostics`、`pgrep -a xterm` 与日志一起回传；
- 判据不变：**只有测试 ok 不算通过**，必须窗口可见 + 截图；拿不到就照实写「未通过」；
- 这一轮只需要这一件事，不需要重跑整个 `reproduce.sh`（除非实施方另有要求）。
