# 02. 类型与值系统

> 本阶段定义“默认静态、有限动态”的边界，以及数值宽度、转换和溢出行为。

当前 S0 的实现交接记录见 [02A. P2-B/S0 静态标量类型](02a-p2-static-types.md)。本页
保留跨阶段规格；容器静态闭环见第 03 阶段，函数与控制流静态闭环见[第 04 阶段](04-functions-and-control.md)。
真实容器、函数执行和动态变量 Runtime 仍按后续里程碑推进。

## 一级工程目标：实现默认静态类型

### 推断与锁定

- `a = 1` 推断为 `int`，后续赋值必须兼容 `int`。
- 普通变量默认可变；类型兼容时可以重新赋值或使用 `+=` 等复合赋值。
- `int a = 1` 显式建立 `int` 类型槽，初始化值必须满足声明类型。
- 变量首次绑定时建立类型槽；普通赋值不会改变类型槽。
- 函数参数可以省略类型声明，由调用点和函数体约束推断。
- 递归函数、导出函数和跨模块函数必须在编译边界形成稳定签名；无法推断时报告错误，而不是退化成任意类型。

### 重新绑定

原规划中的 `free a` 和 `@f a = value` 保留为候选机制，但它们不能绕过静态检查：

- `free` 若保留，必须明确旧值释放时机和变量是否仍可使用。
- `@f` 只能作用于显式动态变量或动态容器。
- 静态变量不能因为一次 `@f` 操作隐式变成动态变量。

动态变量的声明关键字尚未定稿，暂以 `any` 作为设计讨论中的占位名称。

## 一级工程目标：定义基础类型

### 标量类型

| 类型 | 说明 | 溢出行为 |
| --- | --- | --- |
| `int` | 默认 64 位整数 | 报错 |
| `float` | 默认 64 位浮点 | 超出表示范围时报错 |
| `sint` | 32 位整数 | 报错 |
| `sfloat` | 32 位浮点 | 超出表示范围时报错 |
| `lint` | 不限位宽整数 | 仅受内存限制，超限报错 |
| `lfloat` | 不限位宽浮点 | 仅受内存限制，超限报错 |
| `str` | UTF-8 字符串 | 分配失败报错 |
| `bool` | 布尔值 | 不适用 |

位宽和溢出行为必须跨平台一致。`int` 不能在 32 位平台悄悄变成 32 位；目标平台适配必须使用固定宽度底层类型。

浮点结果超出类型可表示范围属于溢出，必须报错；正常浮点运算中的舍入和精度损失不是溢出。舍入模式、无穷大、非数以及哪些精度损失需要诊断，仍需在本阶段继续定稿。

### 容器类型

容器类型至少包括数组、元组、集合、字典表和字典列。数组允许异构值，也允许通过路径声明局部或整体类型约束；集合默认异构，但也可以显式约束所有元素的类型。详细规则见第 03 阶段。

### 可哈希能力

可哈希是类型能力，不等同于“已经推断出静态类型”。可变数组、字典表、字典列和普通集合即使类型完全静态，也不能作为集合元素。元组仅在所有成员均可哈希时具备可哈希能力；动态值在插入哈希容器时检查其实际类型。

集合的 `+` 是并集，不是数值加法。词法器和解析器只记录同一个二元 `+`，类型检查器根据两个操作数都是集合来选择并集语义。`|` 不作为集合并集运算符。

## 一级工程目标：定义转换和动态值

### 隐式转换

只允许安全的算术加宽，例如 `int + float` 产生 `float`。字符串、布尔值和容器不能被隐式转换成数值。

### 布尔值与整数加减

`bool` 与整数的加减是一个封闭的特殊运算，不代表两种类型可以互相隐式转换。只接受 `bool` 位于左侧，`sint`、`int` 或 `lint` 位于右侧：

```xiao
flag += count
next_flag = flag - offset
```

右侧为偶数时保留左侧布尔值，为奇数时翻转；正负号不改变奇偶性，所以布尔加法和减法遵循同一结果规则。结果类型始终为 `bool`。反向操作、两个布尔值相加减以及任何布尔值与浮点数的加减都在类型检查阶段拒绝。

### 逻辑与身份算子的类型规则（星崽直接裁定，2026-10-14）

- **`and` / `or`**：接受面内的布尔组合，类型层按既有规则判为 `bool`；
  **运行时语义是短路**，求值顺序先左后右，**右侧未求值即不产生释放计划**。
  降低侧需要控制流承载，落点见 [20C-语言边界](20c-language-boundary-and-operators.md) §4.1；
- **`is` / `is not`：不在接受面内**。类型层**以稳定码 `X02-TYPE-005`**
  （`xiao-types/src/diagnostics.rs` 的 `INVALID_OPERANDS_CODE`）拒绝，
  **一律在进入后端之前拒绝**——不许出现「编译通过、后端报内部错误」。

  **实现已同步改三处**（缺一处就会留下绕过路径，逐条见
  [20C-语言边界](20c-language-boundary-and-operators.md) §3.2.1）：

  1. `xiao-types/src/numeric.rs` 已对两者返回 `Err(NumericError::InvalidOperands { .. })`；
  2. `xiao-types/src/checker/constant.rs` 已把两者并入不折叠分支，字面量（`1 is 1`）不能绕过拒绝；
  3. `xiao-types/src/checker/expression.rs` 已把两者从比较算子变量推理分组移出，并在二元检查入口统一上报
     `X02-TYPE-005`。

  `core/rust/crates/xiao-driver/tests/c20_capability_probe.rs` 的穷举算子守卫已覆盖字面量、变量和两条后端入口，
  作为三处修改不能回退的执行点。

  **语法面不动**：两者的 token 与优先级由 [00. 决策基线](00-decisions.md) 的 P1 **原样冻结**，
  **不许**从词法/解析里删掉。**语法认、类型层拒**是裁定的一部分。

### 显式转换

`as` 按“源值 `as` 目标类型”的顺序书写。它根据左侧表达式产生一个目标类型的新值，不会原地修改源变量的类型：

```xiao
small = value as sint
bool flag = raw_text as bool
bool other_flag = bool(raw_text)
str rendered = flag as str
str decimal = value as str
str compact = str(value)
```

第一行表示“读取 `value`，转换成 `sint`，再把结果赋给 `small`”。`sint as value` 的方向是错误的；把转换结果写回原变量时，仍必须遵守该变量已经锁定的类型。

窄化、截断或高精度到低精度的转换必须经过显式 `as`，并在运行时检查是否溢出。

`bool(value)` 是 `value as bool` 的构造式等价写法，两者共享转换矩阵、成功条件和错误类型。两种写法都产生新的 `bool` 值，不会原地修改 `value` 的类型槽。当前已经冻结的 `str -> bool` 输入只有 `"true"`、`"True"`、`"false"` 和 `"False"`；转换结果是对应布尔值，其他字符串报错。不能仅凭 `bool(value)` 的外形推导 Python 的“非空即真”等规则，其他源类型能否转为 `bool` 仍待单独确定。`bool -> str` 始终产生小写 `"true"` 或 `"false"`。

当前显式标量转换矩阵还接受整数族到文本：`int`、`sint`、`lint` 的 `as str` 与
`str(value)` 使用同一语义，结果是十进制文本，并复用 Runtime 的 `display_text()` 表示；
这三个转换不会触发运行时范围检查。动态值的目标为 `str` 时仍走 Runtime 检查路径，实际值若为
整数也必须得到同样的十进制文本。浮点到 `str`、整数字面量到文本的常量折叠尚未开放。

第七批补上整数码点去程：`str` 到 `int`、`sint`、`lint` 的显式转换要求文本恰好包含一个
Unicode 标量值，结果是该码点的整数；空串、多码点文本（包括 `"42"`）和其它非法值由 Runtime
报 `X06-RUNTIME-012`。这条去程不改变整数到 `str` 的十进制语义，也不开常量折叠。
同批新增构造式 `chr(value)`，接受三种整数宽度并返回对应的单码点 `str`；负数、超过
`0x10FFFF` 或落入 `0xD800..0xDFFF` 代理区的码点统一报 `X06-RUNTIME-012`。`chr` 是语言能力
入口，不是标准库专用 intrinsic；浮点、布尔和字符串输入仍在类型层以 `X02-TYPE-006` 拒绝。

第八批收口了 `lint`/`lfloat` 形参的降低边界：普通源码声明这两种对象类形参时，降低器必须按
IR 值的静态类型登记 `ObjHandle`，不能按 ownership 的 `stack` 存储类别退回 `Int`。修复前
形参即使从不使用也会在 VM 生产验证阶段报 `X09-BYTECODE-002`；该路径现在改报已有的
`X07-FATAL-006`（`fatal.internal`），因为它消费的是本进程刚降低的产物。`X07-FATAL-002`
（`fatal.corrupt_artifact`）保留给未来接入的外部产物校验路径。

第八批同时接通整数族与 `lint` 的显式转换：`int`/`sint` 到 `lint` 是精确加宽，`lint` 到
`int`/`sint` 解析十进制文本并做范围检查；窄化越界沿用 `X06-RUNTIME-009`。浮点族与
`lfloat` 的方向仍是登记债项，本批不实现。动态标量转换不再误用错误边界的
`dynamic_conversion` 守卫，普通值直接进入 Runtime 转换；该守卫仍只在错误边界生效。

第九批把已知未实现的降低构造与内部降低缺口分档：前者使用 `X09-BYTECODE-003`，
后者保留 `X09-BYTECODE-001`，两者都在生产入口以 Fatal 级别拒绝。`lint`/`lfloat`
一元负号已按十进制文本翻转符号，`lint`/`lfloat` 的零值归一化为 `0`，非零 `lfloat`
保留原始小数精度；其它高精度算术仍是未实现债项，当前清单见[第九批](20c-ninth-batch-unsupported-diagnostic-split.md)。

因此，读取字符串后转换布尔值应使用新的静态变量接收结果：

```xiao
str raw = input("请输入初始布尔值，true/false")
bool flag = raw as bool
bool same_flag = bool(raw)
str result = flag as str
```

### 动态值表示

动态值需要携带运行时类型标签，至少能够区分所有标量、容器和用户表对象。静态代码调用动态值时必须经过检查；编译器应尽量在可证明时把检查提前到编译期。

## 一级工程目标：实现编译期常量

### `const` 规则

- `const` 表达式必须在编译期求值。
- 常量不能依赖运行时输入、可变变量或运行时对象地址。
- 编译器可以把常量嵌入机器码或只读数据区。
- 常量是否实际占用存储由后端决定，不作为源码语义承诺。

## 二级实现任务

### 类型检查器

1. 建立名称到类型槽的映射。
2. 在完整数值提升矩阵冻结后，实现赋值一致性和算术加宽规则。
3. 实现布尔值位于左侧时的整数奇偶加减规则，不开放一般布尔数值转换。
4. 实现容器元素约束和路径约束接口。
5. 实现可哈希能力判断；不同显式元素类型的集合运算规则冻结后，再实现对应类型检查。
6. 为动态边界插入显式检查节点。

### 数值运行库

1. 为固定宽度数值提供跨平台实现。
2. 为 `lint` 和 `lfloat` 选择统一的高精度库或自研表示。
3. 将高精度加、减、乘、除、整除、取模、幂、比较和转换的结果统一映射为语言错误；
   一元负号的文本实现已在第九批完成。

## 验收标准

### 静态验收

- 静态变量错误赋值在进入任何执行后端前即可报告。
- 相同源码在字节码和原生模式使用相同类型规则。
- 没有隐式字符串转数值或隐式容器转标量。
- 布尔值只在 `bool +/- 整数` 的专用规则中接受整数操作数，结果仍为 `bool`。
- 静态不可哈希值进入集合时在运行前被拒绝。

### 数值验收

- 固定宽度类型在所有目标平台结果一致。
- 每一种溢出都有可测试的错误类别和源位置。
