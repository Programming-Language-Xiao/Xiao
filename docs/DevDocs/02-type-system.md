# 02. 类型与值系统

> 本阶段定义“默认静态、有限动态”的边界，以及数值宽度、转换和溢出行为。

当前 S0 的实现交接记录见 [02A. P2-B/S0 静态标量类型](02a-p2-static-types.md)。本页
保留跨阶段规格；容器静态闭环见第 03 阶段，函数与控制流静态闭环见[第 04 阶段](04-functions-and-control.md)。
真实容器、函数执行和动态变量 Runtime 仍按后续里程碑推进。

## 一级工程目标：实现默认静态类型

### 推断与锁定

- `a = 1` 推断为 `int`，后续赋值必须兼容 `int`。
- 普通变量默认可变；类型兼容时可以重新赋值或使用 `+=` 等复合赋值。
- `int a = 1` 显式建立 `int` 类型槽，初始化值必须满足声明类型。
- 变量首次绑定时建立类型槽；普通赋值不会改变类型槽。
- 函数参数可以省略类型声明，由调用点和函数体约束推断。
- 递归函数、导出函数和跨模块函数必须在编译边界形成稳定签名；无法推断时报告错误，而不是退化成任意类型。

### 重新绑定

原规划中的 `free a` 和 `@f a = value` 保留为候选机制，但它们不能绕过静态检查：

- `free` 若保留，必须明确旧值释放时机和变量是否仍可使用。
- `@f` 只能作用于显式动态变量或动态容器。
- 静态变量不能因为一次 `@f` 操作隐式变成动态变量。

动态变量的声明关键字尚未定稿，暂以 `any` 作为设计讨论中的占位名称。

## 一级工程目标：定义基础类型

### 标量类型

| 类型 | 说明 | 溢出行为 |
| --- | --- | --- |
| `int` | 默认 64 位整数 | 报错 |
| `float` | 默认 64 位浮点 | 超出表示范围时报错 |
| `sint` | 32 位整数 | 报错 |
| `sfloat` | 32 位浮点 | 超出表示范围时报错 |
| `lint` | 不限位宽整数 | 仅受内存限制，超限报错 |
| `lfloat` | 不限位宽浮点 | 仅受内存限制，超限报错 |
| `str` | UTF-8 字符串 | 分配失败报错 |
| `bool` | 布尔值 | 不适用 |

位宽和溢出行为必须跨平台一致。`int` 不能在 32 位平台悄悄变成 32 位；目标平台适配必须使用固定宽度底层类型。

浮点结果超出类型可表示范围属于溢出，必须报错；正常浮点运算中的舍入和精度损失不是溢出。舍入模式、无穷大、非数以及哪些精度损失需要诊断，仍需在本阶段继续定稿。

### 容器类型

容器类型至少包括数组、元组、集合、字典表和字典列。数组允许异构值，也允许通过路径声明局部或整体类型约束；集合默认异构，但也可以显式约束所有元素的类型。详细规则见第 03 阶段。

### 可哈希能力

可哈希是类型能力，不等同于“已经推断出静态类型”。可变数组、字典表、字典列和普通集合即使类型完全静态，也不能作为集合元素。元组仅在所有成员均可哈希时具备可哈希能力；动态值在插入哈希容器时检查其实际类型。

集合的 `+` 是并集，不是数值加法。词法器和解析器只记录同一个二元 `+`，类型检查器根据两个操作数都是集合来选择并集语义。`|` 不作为集合并集运算符。

## 一级工程目标：定义转换和动态值

### 隐式转换

只允许安全的算术加宽，例如 `int + float` 产生 `float`。字符串、布尔值和容器不能被隐式转换成数值。

### 布尔值与整数加减

`bool` 与整数的加减是一个封闭的特殊运算，不代表两种类型可以互相隐式转换。只接受 `bool` 位于左侧，`sint`、`int` 或 `lint` 位于右侧：

```xiao
flag += count
next_flag = flag - offset
```

右侧为偶数时保留左侧布尔值，为奇数时翻转；正负号不改变奇偶性，所以布尔加法和减法遵循同一结果规则。结果类型始终为 `bool`。反向操作、两个布尔值相加减以及任何布尔值与浮点数的加减都在类型检查阶段拒绝。

### 显式转换

`as` 按“源值 `as` 目标类型”的顺序书写。它根据左侧表达式产生一个目标类型的新值，不会原地修改源变量的类型：

```xiao
small = value as sint
bool flag = raw_text as bool
bool other_flag = bool(raw_text)
str rendered = flag as str
```

第一行表示“读取 `value`，转换成 `sint`，再把结果赋给 `small`”。`sint as value` 的方向是错误的；把转换结果写回原变量时，仍必须遵守该变量已经锁定的类型。

窄化、截断或高精度到低精度的转换必须经过显式 `as`，并在运行时检查是否溢出。

`bool(value)` 是 `value as bool` 的构造式等价写法，两者共享转换矩阵、成功条件和错误类型。两种写法都产生新的 `bool` 值，不会原地修改 `value` 的类型槽。当前已经冻结的 `str -> bool` 输入只有 `"true"`、`"True"`、`"false"` 和 `"False"`；转换结果是对应布尔值，其他字符串报错。不能仅凭 `bool(value)` 的外形推导 Python 的“非空即真”等规则，其他源类型能否转为 `bool` 仍待单独确定。`bool -> str` 始终产生小写 `"true"` 或 `"false"`。

因此，读取字符串后转换布尔值应使用新的静态变量接收结果：

```xiao
str raw = input("请输入初始布尔值，true/false")
bool flag = raw as bool
bool same_flag = bool(raw)
str result = flag as str
```

### 动态值表示

动态值需要携带运行时类型标签，至少能够区分所有标量、容器和用户表对象。静态代码调用动态值时必须经过检查；编译器应尽量在可证明时把检查提前到编译期。

## 一级工程目标：实现编译期常量

### `const` 规则

- `const` 表达式必须在编译期求值。
- 常量不能依赖运行时输入、可变变量或运行时对象地址。
- 编译器可以把常量嵌入机器码或只读数据区。
- 常量是否实际占用存储由后端决定，不作为源码语义承诺。

## 二级实现任务

### 类型检查器

1. 建立名称到类型槽的映射。
2. 在完整数值提升矩阵冻结后，实现赋值一致性和算术加宽规则。
3. 实现布尔值位于左侧时的整数奇偶加减规则，不开放一般布尔数值转换。
4. 实现容器元素约束和路径约束接口。
5. 实现可哈希能力判断；不同显式元素类型的集合运算规则冻结后，再实现对应类型检查。
6. 为动态边界插入显式检查节点。

### 数值运行库

1. 为固定宽度数值提供跨平台实现。
2. 为 `lint` 和 `lfloat` 选择统一的高精度库或自研表示。
3. 将加、减、乘、除、幂和转换的溢出统一映射为语言错误。

## 验收标准

### 静态验收

- 静态变量错误赋值在进入任何执行后端前即可报告。
- 相同源码在字节码和原生模式使用相同类型规则。
- 没有隐式字符串转数值或隐式容器转标量。
- 布尔值只在 `bool +/- 整数` 的专用规则中接受整数操作数，结果仍为 `bool`。
- 静态不可哈希值进入集合时在运行前被拒绝。

### 数值验收

- 固定宽度类型在所有目标平台结果一致。
- 每一种溢出都有可测试的错误类别和源位置。
