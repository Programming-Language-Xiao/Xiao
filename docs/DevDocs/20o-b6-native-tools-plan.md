# 20O-B6. 正则、压缩与 fmt 扩展实施规划

> **B6 尚未开始；B2-C与B5完成后进入产品实施。任一前置未完成时，仅可在明确授权下执行B6-0探测/冻结。**
> B6 覆盖成熟线性时间正则引擎、整块 gzip/zlib `compression` 和 `fmt` 扩展；不实现流式/安全/网络。
> 不改 B5 数值语义、B4 `json_value` 或回写 B2 历史快照；新增 intrinsic/值类型/ABI/生成器增量须先在 B6-0 冻结。
> CSPRNG/TLS/HTTP/数据库仍后置；不跑旧721。

## 一、入口与范围

| 项 | 当前状态 |
| --- | --- |
| B5 | 数值库尚未完成；产品实施须等B5收口，B6-0提前进行需要明确授权 |
| B0 | D-11 regex/compression 方向已确认：成熟线性时间引擎；gzip/zlib 整块；输入/编译/输出/解压上限必备，流式后置 |
| 本批目标 | regex、compression、fmt扩展 |
| 未做 | 流式压缩、zip/tar、TLS/加密、HTTP、数据库、CSPRNG |
| 当前状态 | registry/UseDocs尚无regex、compression条目；`stdlib.fmt`及其三项B1函数已verified；新增范围须单独验证后再登记/升级 |

B6 是 **原生工具批**，不是B7安全/网络批。正则和压缩仍须按不可信输入处理：先执行有界接纳，不能把宿主库默认行为直接暴露成语言契约。B6的实现/测试不得声称完成B7安全审阅。

### 1.1 要做

1. 探测候选regex/compression引擎、版本/特性/平台/许可证/依赖闭包，并保留真实源码/工具/原始输出身份；
2. 冻结regex方言/编译/匹配/替换API、线性时间保证、输入/编译/匹配限制、错误；
3. 冻结gzip/zlib整块压缩/解压API、输入/输出/解压上限、畸形/炸弹/截断错误；
4. 冻结fmt扩展的确切新增API、支持的数值类型/格式语法和资源规则，逐项保持B1既有 `pad_left`、`pad_right`、`format_int` 的签名、语义、错误表与verified覆盖；
5. 实现三模块、教程/示例/错误/资源/性能；
6. 接通类型/IR/TAC/VM/LLVM/归档、std/stdlib双路径、导出/移除/隔离；
7. 三平台证据、registry只在验证范围升级；
8. 形成B7安全批交接。

### 1.2 明确不做

- 不实现流式压缩、zip/tar、任意容器格式；
- 不实现TLS/加密/CSPRNG/HTTP/数据库；
- 不改B5数值/B4值模型/B2数值语义，也不回写B2～B5历史快照；
- 不临时或未冻结地新增能力位/错误码/intrinsic/ABI；B6所需增量须由B6-0明确冻结；
- 不提前升级registry/教程，不跑旧721；
- 不把B6扩成B7-B9。

## 三、分批执行

### B6-0：探测、冻结与教程草案

1. 探测regex/compression候选引擎/版本/特性/平台/许可证/传递依赖/二进制体积及Windows/Linux/macOS可构建性；记录Cargo树、锁、许可证原文、构建命令与输出摘要；
2. 冻结regex：
   - 方言/语法子集、精确编译/查找/全匹配/分组/替换签名、捕获编号和替换模板语义；
   - 复杂度按模式规模P与输入规模N写明（例如固定模式下对N线性、最坏O(P×N)），并分别冻结pattern、编译后大小、输入、匹配次数/捕获数和输出限制；不得只写“线性”或只依赖超时；
   - Unicode/ASCII类别、大小写折叠、字节或码点匹配索引、锚点/多行、空匹配推进、未匹配捕获及匹配优先级；拒绝语法与稳定错误；
   - Xiao `str` 已是合法UTF-8；非法UTF-8仅适用于另行冻结的原始字节入口，不把它写成 `str` 输入状态；
3. 冻结compression：
   - 二进制输入/输出的语言表示与所有权，gzip/zlib精确函数签名；仅公开整块接口，允许实现内部有界分块处理；
   - 输入、压缩输出、解压输出绝对上限；若使用膨胀比阈值，须和绝对上限并用并冻结边界，不能以比例替代绝对上限；在扩容/分配前检查预算；
   - gzip多成员、尾随字节、zlib头/校验和、截断/畸形/校验失败、字典需求的处理；原始deflate明确决定是否排除；
   - 压缩级别、gzip时间戳/头字段及跨平台字节确定性；失败不得暴露部分结果，原子性范围和优先错误身份；
4. 冻结fmt扩展：
   - 逐项列出新增函数、格式选项、参数/返回和支持数值类型；明确与B1三项既有语义的边界；
   - 冻结格式语法、对齐/宽度/进制/填充、locale/Unicode行为、非法格式与输入/输出预算；是否接纳B2/B5新增数值类型须明确裁定；
5. 冻结三模块签名/参数/返回/效果/所有权/能力/错误码及优先级/资源和性能工作负载、预算与测量方法；不把库默认超时当作公开契约；
6. 按20P D-15静态内置；固定直接/传递依赖、版本、特性、锁摘要、许可证原文、工具链/目标、`--locked`构建和符号导出策略；禁止运行时任意动态加载，不使用未固定默认特性；
7. 先固定Runtime绑定架构，再核定intrinsic编号、Runtime ABI/生成器/标准库接口版本/`.xiaoc`/`.xar`身份增量；保留既有编号和ID 100墓碑，不重编号或回写B2-B5历史快照；任何新增intrinsic/值类型按20P规则升级ABI并更新产物指纹；
8. 三份完整教程草案、固定示例和registry候选（planned）；完整示例进入VM/受控原生逐字输出与退出码CI；
9. 对regex解析/编译与压缩畸形输入执行有界属性/模糊测试并固定最小重现回归；压缩与独立公开兼容向量交叉验证，记录生成器/版本/摘要；覆盖率不足或无法执行必须作为缺项登记；
10. 记录延期能力（流式/zip/tar等）、明确非目标与B7安全批交接边界。

退出：三模块精确API/方言/格式/限制/错误/资源性能/依赖/版本兼容与教程冻结；未写产品；若必须修改20D能力表或突破B2-C冻结边界，先另行裁定。

### B6-1：`regex`

1. 编译/匹配/替换/分组API；
2. 复杂度按B6-0冻结的P、N及调用次数口径验证；对抗模式不得产生灾难性回溯；
3. 在分配/编译/遍历前检查pattern/编译后大小/输入/捕获/匹配次数/输出预算；超限整次失败；
4. 回归匹配优先级、空匹配进度、捕获/替换展开、Unicode与锚点边界及冻结的错误顺序；
5. 正常、边界、对抗、属性/模糊、性能和教程测试；性能样本绑定被测二进制/工具身份。

退出：regex内部可用；语法、复杂度、预算和错误稳定，超限/畸形输入拒绝。

### B6-2：`compression`

1. gzip/zlib整块压缩/解压；
2. 输入/压缩输出/解压绝对上限及冻结的膨胀比规则；在扩容前限额；
3. gzip多成员/尾随数据和zlib校验语义按冻结表核对；截断/畸形/超限/校验错误有稳定身份；
4. 输入/输出为明确的二进制值，失败不发布部分数组/结果；校验所有权及临时缓冲释放；
5. 标准兼容向量、跨实现往返、边界/畸形模糊测试、最坏性能及教程。

退出：compression内部可用；压缩和解压均有界，无无界分配/部分结果泄漏。

### B6-3：`fmt`扩展

1. 仅实现B6-0冻结的新增函数/选项及明确支持的值类型；
2. B1既有三函数独立保留原签名、错误顺序/资源阈值和verified证据，不通过修改旧实现来容纳新行为；
3. 非法格式/宽度/进制/Unicode/结果预算错误按冻结身份验证；
4. 新增范围与既有三项分别有正负例、逐函数移除/导出和完整教程测试。

退出：fmt扩展内部可用；既有3项未改语义。

### B6-4：语言、双路径与承载

1. 三模块类型/IR/TAC/VM/LLVM/归档；
2. `std.*`/`stdlib.*`双路径、导出/移除/隔离；
3. 能力/错误/取消/资源；
4. 按B6-0选择并验证Runtime依赖链接/符号导出策略，三平台产物不意外暴露内部符号；
5. B1七库20入口/17项资源/双精确/28守卫功能回归；不得运行或引用721条F10；
6. 三平台VM/原生O0/O3。

退出：三模块内部全链路一致；依赖/ABI/能力映射与冻结表一致，无第二套原生语义。

### B6-5：测试、教程与收口

1. 三模块单元/边界/资源/性能/三平台/教程；
2. 三份完整教程示例进入VM和受控原生CI精确入口；逐字核对stdout/退出码；
3. 依赖闭包/许可证原文/锁/特性/构建目标/体积及模糊/互操作向量证据；
4. registry仅在全部必测通过的验证范围升级；fmt既有verified范围保持；
5. 保存产品源码/Runtime/测量工具/负载/实际执行文件、独占任务根、平台、CI run/job/attempt与原始日志；失败和重试不得覆盖；
6. B1七库20入口/17资源/双精确/28守卫功能回归通过；明确不跑721条F10；
7. 完整workspace测试/Clippy/fmt、benchmark/驱动自检、`check:lock`与docs/UseDocs/layout/覆盖率门禁通过；
8. 形成B7交接，标清B6未实现密码学、未执行B7安全审阅的边界。

退出：全部必测功能、错误/资源/性能、依赖、三平台、教程和工程门禁通过，才记B6内部收口。失败/缺项/不可验证只允许受限交接，不得声称B6验收完成或升级未验证范围；B7未开始。
