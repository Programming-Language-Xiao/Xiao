# 13B. 差分套件与边界输入

> **13 阶段的第二批，也是收尾批。** [13A](13a-optimization-boundary-implementation.md)
> 把管线的**边界**立起来了（配置与指纹、Pass 接口与假设、快照回滚、验证阻断、
> 只读事实），并交付了**差分函数**——但**没有把它用起来**。
>
> **一句话概括本批**：把差分从「**一个函数**」变成「**一套会跑的夹具**」，
> 并且**先备好边界输入**——它们与优化无关，所以现在就能建；
> 等 14/15 的 Pass 落地时，**第一时间就能发现破坏**。
>
> **13A 实施记录的原话**：本批「尚未接入……**未优化/优化差分套件**」——
> 引号里那五个字就是本批。

## 二、为什么现在就建边界输入（而不是等 14/15）

**这是本批存在的核心理由，值得写在最前面。**

边界输入（固定随机源、溢出边界、动态值、容器顺序）**与"有没有优化"无关**——
它们描述的是**语言语义的可观察面**。

**先备好的收益**：

- 14/15 的 Pass 落地时，**第一时间**就能发现它破坏了什么，而不是事后回溯；
- **本批没有 Pass，所以差分必然平凡通过**——这恰恰是**给夹具本身做基线**：
  若夹具在"无优化"下都不稳定，那它未来抓到的任何差异都不可信；
- `13.12` 要求「记录**仍不可避免**的目标差异」——**先建才能知道哪些是不可避免的**。

**不这么做的代价**：等 Pass 来了再建，那时**夹具的缺陷和 Pass 的缺陷会混在一起**，
定位成本翻倍。**10E §七「差分要在第 2 步之后就开搭」是同一条教训。**

## 三、必须先冻结的 6 条

### 3.1 **差分沿用 10G 的口径，不另立**

`13.10` 原文：比较「**输出、错误、退出码和 `drop` 记录**」。

**冻结**：

- **这四样就是 10G 那套**（输出、错误、退出码、释放记录）——**同一份口径**；
- 13A 已交付的 `differential.rs` 函数**是本批的起点**，**不重写**；
- **两侧必须消费同一份输入**（10G 冻结过「两侧必须消费同一份 IR」）——本批同样适用。

### 3.2 **边界输入要真的覆盖边界**（`13.11`）

`13.11` 原文：「在**固定随机源、动态值和溢出边界**下执行差分测试」。

**冻结**：

- **三类输入逐类要有用例**，且**真的取在边界上**：
  - **溢出**：`i32::MAX + 1`、`i32::MIN - 1`、窄化转换的边界值——**不是随便加两个数**；
  - **动态值**：类型在运行期才确定、以及**检查失败**的路径（`13` 语义验收点名「动态检查」）；
  - **随机源**：**注入固定种子**，且要覆盖**放回/无放回**两种模式与**抽取顺序**；
- **⚠️ 只有"正常值"的用例不算覆盖边界**——那是本批最容易糊弄过去的地方（§八 第 4 条）；
- **容器顺序**也要有：字典表无序、字典列有序、集合不可索引（`13` 语义验收点名）。

### 3.3 **非确定性必须被清除，而不是被容忍**（`13.12`）

`13.12` 原文：「清除**时间戳、临时路径和未定义排序**造成的非确定差异，
并**记录仍不可避免的目标差异**」。

**冻结**：

- **「未定义排序」在这里最可能指 `HashMap` 迭代顺序**——夹具里**不得**用无序容器承载
  参与比较的集合，或必须**显式排序**后再比；
- **临时路径**：测试自己创建的临时目录名**不得进入被比较的内容**（10G 的差分已有这个意识）；
- **⚠️ 不要靠"多跑几次都过"来掩盖不确定性**——那是把 flaky 当成通过。
  要么**确定性地消除**，要么**明确记录为不可避免**；
- **「仍不可避免的目标差异」要有清单**——不是留白，是**逐条写出并说明理由**。

### 3.4 **逐 Pass 的快照与验证结果**（`13.9`）

`13.9` 原文：「对每个 Pass 保存 IR 前后快照及验证结果」。

**冻结**：

- 13A 已有 `IrSnapshot`/`PassReport` 机制 —— **本批补的是"逐 Pass 的用例"**，
  确认**每个 Pass 都有前后快照**（含**跳过**的 Pass，13A 的 `bf4e446` 已修过这条）；
- **验证结果要跟快照一起留存**——只存快照不存验证结果，审计链是断的；
- **`13.4` 的回滚语义要靠它证明**：失败时保留的是**哪一份**快照，用例要断言到具体那一份。

### 3.5 **本批仍然不做任何语义 Pass**

13A 已冻结「未实现的 Pass 不得伪装为已启用」。

**冻结**：

- **本批不新增任何会改变 IR 的 Pass**——`O1`–`O3` 继续只报跳过；
- **差分的"优化侧"当前就是 O0**——**这一点必须诚实写进报告**，
  不能因为"差分通过"就暗示优化已验证（**那正是 §3.6 待定决策的边界**）；
- 若为了测试需要构造一个"假的变换 Pass"，**只能在测试内、且必须标注**——
  **不得进入生产 Pass 注册表**。

### 3.6 **仍不擅自冻结待定决策**

13A §3.6 的 4 条**继续有效**。特别提醒两条与本批相邻的：

- **Pass 失败时回退上一份产物还是终止命令** —— 本批**不做这个决定**，
  但夹具要**能观察两种行为**（断言"阻断"这件事本身，而不是断言选了哪条路）；
- **优化报告的稳定格式** —— 本批复用 13A 的 `PassReport`，**不新定格式**。

## 八、最可能翻车的地方

1. **拿正常值冒充边界值**（§3.2）——`1 + 2` 不是溢出用例。
   本批头号陷阱：**用例看起来有，边界其实没碰**。
2. **随机源没真固定**（§3.2）——注入是注入了，但种子来自时间或环境。
3. **用 `HashMap` 承载参与比较的集合**（§3.3）——迭代顺序不定，差分**随机通过或随机失败**。
   这类 flaky 最难查，因为它"大部分时候是绿的"。
4. **靠重跑掩盖不确定性**（§3.3）——把 flaky 当通过。
5. **只在一个后端跑差分**（§五）——两条后端共享是 13A 的既定要求，本批要延续。
6. **只存快照不存验证结果**（§3.4）——审计链断在中间。
7. **跳过路径没有快照**（§3.4）——13A 已修过一次（`bf4e446`），**别回退**。
8. **顺手加了个"测试用 Pass"却进了生产注册表**（§3.5）。
9. **把"差分通过"说成"优化已验证"**（§3.5）——当前优化侧就是 O0，**如实说**。
10. **忘了两个 lock 文件**（§六 第 8 条）。

## 九、验收

1. **四样口径**：两侧（字节码 / 原生）在**同一份输入**上比较**输出、错误、退出码、`drop` 记录**，
   沿用 10G 的口径（§3.1）；
2. **边界输入非空且真在边界**（`13.11`）：
   - **溢出**：窄化与上下界，且**语言规定的错误契约**被观察到（不是静默回绕）；
   - **随机源**：**固定种子**下可复现；放回/无放回与抽取顺序都有用例；
   - **动态值**：运行期确定类型、以及**检查失败**路径；
   - **容器顺序**：字典无序、字典列有序、集合不可索引；
3. **逐 Pass 快照**（`13.9`）：每个 Pass（含跳过）都有**前后快照 + 验证结果**；
   失败时保留的是**指定的那一份**快照（断言到具体快照，不是"保留了某一份"）；
4. **非确定性已清除**（`13.12`）：夹具**不依赖**时间戳、临时路径与未定义排序；
   **「仍不可避免的目标差异」有逐条清单与理由**；
5. **稳定**：同一夹具**重复运行结果一致**（不是"多跑几次碰巧都对"）；
6. **诚实**：报告写明**当前优化侧是 O0**，不暗示优化已验证（§3.5）；
7. **不回归**：13A 的全部行为保持绿（尤其 `O0` 走完整管线、占位级别报跳过、
   验证失败阻断）；`cargo test --workspace` 全绿；
8. **门禁全绿**：`bun run check`（含 `check:lock`）、clippy、TS 类型检查、`cli/ts` 测试。

### 当前实施记录（2026-10-02）

- `xiao-optimizer` 已把 13A 的四字段比较函数接成按输入执行的 `run_o0_differential_suite_with`，
  用例按名称排序，报告明确标记当前优化侧为 `O0`；差异字段仍固定为输出、错误、退出码和
  `drop` 顺序。
- 新增共享边界夹具覆盖 `i32` 上下界溢出、窄化边界、固定种子下的放回/无放回抽样、动态检查失败、
  字典表/字典列顺序和集合索引拒绝。夹具只使用固定文本、固定种子和显式排序，不把临时路径或时间写入观察值。
- 现有环境门控的 VM/LLVM 前端差分回环新增动态字符串和数组用例；`catch` 与未匹配错误用例继续逐项
  对照机器错误字段和 Runtime 释放事件。工具链缺失时仍按 10D 的 `#[ignore]` 规则处理。
- 13.9 的逐 Pass 快照、验证结果和失败回滚已由 13A 的测试继续覆盖；13B 新增跳过/差分报告的基线测试。
