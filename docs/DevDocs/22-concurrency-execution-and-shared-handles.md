## 一、阶段目标与边界

### 1.1 目标

在 07-D 的研究和 8 项裁定基础上，交付首版并发能力：

1. **执行机制**：OS 线程/任务池方向；首版显式 OS 线程 `spawn/join` 仍是候选，须由
   22A 冻结确认，任务池作为后续子批；
2. **`Send`/`Sync`**：候选 A 的递归能力推导，普通句柄、可变容器、动态值和资源按规则
   拒绝或要求显式边界；
3. **`CrossThread`**：拆分为任务边界和线程边界两个生命周期事实，IR/诊断分别记录；
4. **值传递**：跨线程默认深拷贝；版本化序列化后置；冻结共享继续研究；
5. **取消清理**：采用 07-D §10.4 顺序，覆盖未开始、执行中、等待中、完成待回收；
6. **原子共享句柄**：只读 + 共享可变；普通 `StrongHandle`/`WeakHandle` 不隐式跨线程；
7. **官方库**：首版只提供显式并发/共享入口；链表、树、观察者、图在模型冻结后评估。

### 1.2 非目标

- 不实现 Actor/Channel 语言表面、`async`/`await`、协程调度器；
- 不修改普通 `StrongHandle`/`WeakHandle` 的单线程布局；
- 不把 07-D 原型结构体、std `Arc`/`Mutex` 或原型尺寸直接写成产品 ABI；
- 不做官方并发容器、JIT、跨 Runtime 堆岛或序列化格式；
- 不跳过 22A 直接写语法、IR 或 Runtime 代码。

## 三、阶段分解

### 22A：冻结与缺口关闭（先做，不写产品代码）

详细冻结清单、裁定表、测量任务和交付格式见
[22A. 并发入口冻结](22a-concurrency-freeze.md)。这是本阶段的**第一道门**，只做决定和
测量，不写语言/IR/Runtime 产品代码：

1. **关闭或接受 07-D 缺口**：Linux/macOS 布局/成本测量、真实取消等待路径；
2. **语言表面**：在候选方案中选定首个并发入口（建议最小 OS 线程 `spawn/join`，任务池
   后置），冻结命名、参数、返回值和错误边界；
3. **`Send`/`Sync`**：候选 A 的递归推导规则；动态值、资源、普通句柄、显式共享句柄的
   接受/拒绝表；
4. **`CrossThread` 拆分**：任务边界/线程边界的 IR 事实、诊断字段和 lowering 入口；
5. **值传递**：深拷贝默认、失败清理、主/suppressed 错误；序列化/冻结暂缓；
6. **原子共享句柄 ABI**：干净对象头布局（强/弱计数、tag、payload offset/对齐）、
   只读/共享可变、锁存放位置、弱升级、对象头回收、ABI 版本；
7. **取消/清理**：07-D §10.4 顺序在 VM/LLVM 的共同验收口径；
8. **诊断身份**：非 Send/Sync、普通句柄跨线程、共享句柄误用、取消等新码；
9. **标准库/发布**：首版 API 清单、ABI/产物兼容矩阵、UseDocs 入口。

**22A 退出条件**：上述九项有冻结记录；跨平台测量/取消等待缺口关闭或明确接受；不写
产品代码，不登记语法之外的实现细节。

### 22B：类型、生命周期与 IR

- `xiao-types`/`xiao-lifetime`：候选 A 能力推导、任务/线程边界事实、普通句柄拒绝；
- IR：新增事实、所有权/释放动作、深拷贝/取消边界、verifier；
- 规格测试：合法/非法边界、动态值、资源、跨线程普通句柄；
- 不接 VM/LLVM 执行；先让前端和 IR 快照稳定。

### 22C：Runtime ABI、VM 与错误

- 原子共享句柄对象头、tag、强/弱计数、锁、弱升级、恰好一次析构；
- VM 线程 `spawn/join`、深拷贝、取消/清理、suppressed 错误；
- Runtime ABI 版本升级；普通句柄布局不变；
- 回归：泄漏、双重析构、弱升级竞态、错误顺序、取消四位置。

### 22D：LLVM、差分与跨平台

- LLVM 生成同步的线程入口、共享句柄、深拷贝、取消；
- VM/LLVM 同一黄金场景的输出、错误、退出码和释放记录一致；
- Windows/Linux/macOS 跨平台回归；ABI 布局/对齐/版本矩阵；
- 竞争/压力/释放顺序测试；不能用单平台结果冻结 ABI。

### 22E：标准库、UseDocs 与发布收口

- 首版并发/共享标准库入口（22A 冻结的名称）；
- UseDocs 教程、错误和兼容说明；
- `.xiaoc`/`.xar`/原生产物的版本拒绝与升级矩阵；
- 官方容器仍后置；最终 ABI/兼容证据与发布报告。

## 四、测试族与验收

### 4.1 测试族

1. **规格/类型**：合法与非法并发边界、动态值、资源、普通句柄；
2. **生命周期/IR**：任务/线程边界、释放计划、IR 快照、verifier；
3. **VM/LLVM 差分**：spawn/join、深拷贝、共享句柄、取消、错误/退出码；
4. **原子句柄**：强弱计数、弱升级、对象头回收、锁、毒化、恰好一次析构；
5. **取消/清理**：四位置、主/suppressed 错误、finally/drop；
6. **跨平台**：Windows/Linux/macOS 同场景；
7. **兼容/发布**：ABI 版本、`.xiaoc`/`.xar`/原生拒绝与升级、归档大小/安全。

### 4.2 阶段退出条件

1. 22A 冻结记录齐全，Linux/macOS 测量和取消等待缺口已关闭或明确接受；
2. 类型/生命周期/IR 对普通句柄和共享句柄边界有正/负例；
3. VM 与 LLVM 对同一并发黄金场景输出、错误、退出码和释放记录一致；
4. 原子共享句柄的 ABI 冻结，跨平台布局/对齐/版本有实测；
5. 取消/清理四位置与主/suppressed 顺序通过；
6. 普通 `StrongHandle`/`WeakHandle` 的单线程边界没有被放宽；
7. 标准库/UseDocs/兼容矩阵登记，旧程序无静默语义变化；
8. 维护回归、workspace gates、平台复现和发布检查全绿。

## 五、风险与约束

1. **ABI 未跨平台实测**：Windows x86_64 的 24B 干净头不能直接冻结为所有平台 ABI；
   22A 必须先补 Linux/macOS 测量。
2. **取消等待未实测**：07-D 只测了标记检查；22A 决定是否首版实现真实等待/唤醒路径。
3. **共享可变成本高**：锁、毒化、取消、对象头/ABI 必须一起设计，不能只加一个
   `Mutex` 包装。
4. **普通句柄边界**：候选 A 拒绝普通句柄跨线程；不得用名称启发式或运行时猜测绕过。
5. **VM/LLVM 分歧**：并发和释放顺序必须在两个后端同一黄金场景；不能只实现 VM。
6. **范围蔓延**：任务池、Actor、序列化、官方容器都后置；首版先做 OS 线程最小闭环。
7. **诊断身份**：新错误码必须在 22A 冻结，不能实现时临时编号。
8. **发布兼容**：ABI 版本、`.xiaoc`/`.xar`/原生产物的拒绝/升级策略必须同时更新。

## 六、第一批 22A 的交接摘要

22A 只做冻结和缺口关闭，建议按以下顺序：

1. 复测 Linux amd64/arm64、macOS arm64 的干净/含探针布局和成本；
2. 决定取消等待是否进入首版，补真实等待或登记为后续子批；
3. 在 `00-decisions.md`/本文冻结语言表面、`Send`/`Sync`、`CrossThread`、值传递、
   原子句柄 ABI、诊断身份、标准库清单；
4. 更新 [12](12-tests-and-milestones.md) 的 P0 里程碑、测试族和发布/兼容矩阵；
5. 不写产品代码；冻结完成后再进入 22B。
