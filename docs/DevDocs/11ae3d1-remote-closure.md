## 二、本批的核心链路（**一句话说清缺什么**）

现在的状态是：**前半段和后半段都在，中间断着**。

```text
配置 → 源声明 → 快照读取 → 联邦合并 → 【求解】 → 锁文件 → 【下载正文】 → 缓存 → 物化
      └──────── E3A/E3B 已交付 ────────┘        └── 本地已通 ──┘  └─ 零 ─┘
                                        └─ 内核已交付，未接线 ─┘
```

**本批补的就是这两个框**：把 `solve_dependencies` 接进 `sync`，再把 `ResolvedPackage`
里的产物引用变成**真实下载并校验的缓存条目**。

## 三、必须先冻结的 6 条

### 3.1 凭据来源与硬约束（**已定**）

**来源**（优先级从高到低）：

1. **环境变量** `XIAO_SOURCE_TOKEN_<ALIAS>`（便于 CI）；
2. **回退** `~/.xiao/credentials`——**必须校验权限为 0600**，
   **权限过宽（如 0644）时拒绝并诊断**，不能"警告后继续"。

**实施格式**：回退文件是以源别名为键的 JSON 字符串映射；Unix 限制普通文件、严格
`0600`，打开时拒绝符号链接并重新核对句柄权限。Windows 不存在 POSIX `0600`，
在未实现等价 ACL 校验前回退文件拒绝使用，CI/Windows 使用环境变量。
仅小写 ASCII 字母、数字与下划线别名映射为大写环境变量名，避免不同大小写别名
共享令牌；其余合法别名只能匿名访问或在 Unix 使用原样键名的回退文件。
Bearer 令牌仅送至 HTTPS 或本机测试端点；Git raw 仅同源或 GitHub 官方 raw 域转发。

**硬约束（`11a:507` 的"权限/凭据边界"）**：

> **凭据绝不进入锁文件、日志、诊断、错误消息、`Debug` 输出。**

**必须有的断言**：构造一个带凭据的源（URL 含 `user:pass@`，或环境变量带 token），
运行完整流程后**断言凭据不出现在锁文件字节、诊断文本、任何 `Debug` 输出里**。

**⚠️ 最容易被忽略的一处**：`{:?}` 格式化。**承载凭据的类型不得 `derive(Debug)`**，
或必须**手写 `Debug` 打码**。这类泄漏常常发生在错误路径的 `expect`/`unwrap` 消息里。

### 3.2 求解器接线的输入构造

`solve_dependencies` 要五样输入（`solver.rs:68`），**每一样从哪来都要定死**：

| 参数 | 来源 |
| --- | --- |
| `sources` | E3A 的 `expand_source_lists()` 展开后的 `ConfiguredSource` |
| `snapshots` | E3B 的 `snapshot_store` 当前快照 |
| `records` | E3A 的 `federate()` 合并结果 |
| `requirements` | **本批要定**：从 `config.xiao` 的 `[dependencies]` 直接声明 + 已解析的传递依赖构造 |
| `target_variant` | 首版传 `None`（§3.6） |

**⚠️ `requirements` 的构造是本批最容易出错的地方**：传递依赖的需求来自**候选包自己的
依赖声明**（索引里的 `IndexDependency`），而直接依赖来自 `config.xiao`。
**两者必须走同一个 `SolveRequirement` 构造路径**，否则"直接依赖约束"与"传递依赖约束"
会各有一套解析逻辑。

**⚠️ 签名不匹配**：`solver.rs` 已经**校验联邦记录与包元数据的身份一致性**（`record.key`
对 `record.package`）。接线时**不要绕过这个校验**。

### 3.3 远程正文下载

`11a:336` 已冻结**完整性依据**：「客户端下载后**始终以锁文件中的摘要为准**」。

**⚠️ 这一句的含义要读准**：索引里也带摘要，但**下载后的校验依据是锁文件里的那个**——
索引是"当时的声明"，锁文件是"我们锁定的"。**两者不一致时以锁文件为准并报诊断**。

**要冻结**：

- 下载的内容**进 E1 的 `objects/source/sha256/…`**（复用其布局与 `.corrupt` 隔离）；
- **摘要校验失败 → 隔离 + 诊断**（复用 E1 已有的机制，不另造）；
- **中断不产生半成品**（复用 E2A 的 `atomic_write_file` 与 E3B 的中断安全规则）；
- **并发下载有界**（复用 E3B 的 `fastpath` 上限与跨进程锁，依据 `11A-CONC`）。

### 3.4 锁文件是否升版

**实施冻结（2026-09-26）**：远程源码正文为无压缩 TAR 字节流；只接受普通文件和目录，
在私有暂存目录逐项检查路径、数量和展开大小后落盘。拒绝链接、设备、稀疏文件、
绝对/父级路径、重复及平台不安全名称；不得调用通用解包捷径或执行内容。
先以**锁定产物字节摘要**校验下载，再导入 E1 目录并验证其**目录摘要**，两种摘要不得混用。
远程依赖的配置形状为 `{ version = "1.*", source = "别名" }`（`source` 可省略，
由联邦来源优先级选择）；本地 `{ path = "..." }` 和显式 `{ git = "..." }` 不变。
已有锁文件的 `sync`/`install` 只能按锁定候选/产物重新取得缺失对象，
索引声明与锁定摘要不同时立即报信任失败，绝不隐式重解升级。

**版本结论：升为 `lock_version: 2`，保留 v1 本地锁文件读取。** v1 的
`content_digest` 是目录摘要，无法同时表达 TAR 字节摘要；v2 远程条目增加锁定
`source_artifact`（路径、长度、摘要），源身份和 `source_snapshots` 构成审计链。
v1 不允许远程条目；v2 的本地条目不需要产物引用。

E3D 已把求解结果写进锁文件（本地操作那一批）。本批新增：

- **远程源身份 + 不可变 commit/快照**（E3C 已在 `LockedPackage.source` 能表达的范围内）；
- **产物引用的摘要**（下载依据）。

**实施结论**：已升到 `lock_version: 2`，并保留读 v1 本地锁文件的能力；
锁定 TAR 原始字节摘要与 E1 目录摘要分别记录，不混作单个字段。

### 3.5 来源审计与信任失败诊断

`11a:507`：「**来源审计**、权限/凭据边界及**明确的信任失败诊断**」。

**要冻结审计链**：锁文件里每个条目要能回答「**它从哪来**」——
源身份 + 解析时的 commit + **下载内容的摘要**，三者齐全且**可追溯**。

**信任失败**要**独立于"包不存在"**（沿用 `12-tests:782` 的口径）：摘要不符、
协议版本不认识、签名缺失（本批无签名）都是**信任失败**，**不能报成"未找到包"**，
且**要有各自的稳定诊断编号**。

已登记：`X05-TRUST-001` 为锁定产物/下载内容不一致，`002` 为来源快照不一致，
`003` 为正文 TAR 不安全，`004` 为凭据权限或结构不安全；未知协议版本保持
`X05-SOURCE-001`，不是"包不存在"。

### 3.6 条件候选：本批**不扩接口**，但**必须登记**

`solver.rs` 现在的行为是：**带目标/ABI/兼容范围的候选不被选择**（注释已说明）。

**冻结**：**本批保持这个保守行为**——扩接口要先冻结一整套兼容性规则
（`11a:217` 的"最低与最高 Xiao/Runtime 兼容范围"），那是独立的一件事。

**⚠️ 但必须显式登记为债项**，并在诊断里**说明为什么某个候选没被选中**
（否则用户看到"没有可用版本"会以为源里真没有）。

**债项 E3D1-COMPAT-001**：目标、ABI、特性与 Xiao/Runtime 区间尚无完整兼容性
上下文，带条件的候选继续保守排除；无解时输出排除原因，规格夹具覆盖该分支。

## 八、最可能翻车的地方

1. **凭据从 `Debug` 泄漏**（§3.1）——错误路径的 `unwrap` 消息是最常见出处。
2. **直接依赖与传递依赖的需求各写一套构造**（§3.2）——本仓头号病史。
3. **下载校验用了索引里的摘要而不是锁文件的**（§3.3）——`11a:336` 明写以锁文件为准。
4. **信任失败被报成"未找到包"**（§3.5）——`12-tests:782` 的口径。
5. **条件候选被静默跳过而无诊断**（§3.6）。
6. **`sync.rs` 超行数上限**（§五）——应拆模块而不是加豁免。
7. **下载的内容被执行**（§六.1）。

## 九、验收

1. **链路通**：从 `config.xiao` 的远程依赖出发，经真实（夹具驱动的）索引求解、
   下载正文、校验摘要、写入缓存、更新锁文件与映射，**端到端可跑**。
2. **摘要依据**：构造"索引摘要与锁文件摘要不一致"的场景，
   断言**以锁文件为准并报诊断**（§3.3 反例）。
3. **凭据**：断言不出现在锁文件、诊断、日志、`Debug` 输出里；
   `~/.xiao/credentials` 权限非 0600 时**拒绝**。
4. **来源审计**：每个锁文件条目可追溯「源身份 + commit + 内容摘要」三者。
5. **信任失败**：与"包不存在"是**不同诊断编号**。
6. **不执行包代码**：副作用探针断言标记不存在（`12-tests:784`）。
7. **不隐式升级**：常规 `sync` 不改已锁定版本。
8. **门禁全绿**。

## 十一、实施记录（2026-09-26）

- `xiao-config` 新增 `{ version, source? }` 远程索引声明提取；直接需求和
  `IndexDependency` 经同一个 `SolveRequirement::new` 入口，再由联邦快照和回溯求解器选包。
- `remote.rs` 在完整包图里拼接直接/传递边；已有锁优先按锁定版本、来源快照和产物引用
  复用 E1 缓存，缓存缺失才查询钉住索引并下载；已锁定 Git 标签是例外：即使正文
  缓存命中，也要在线复核标签提交和清单快照，不可达时失败；`update` 才重解。
- `fetch.rs` 仅接受无压缩 TAR 普通文件/目录，在专属暂存目录展开并限制条目和大小；
  先按锁定产物 SHA-256 校验字节，再按 E1 目录 SHA-256 校验导入结果。
  物化前还校验正文 `config.xiao` 的包名和版本与锁定索引一致，缺失或不符报信任失败。
  `lock_version` 升为 2；v1 本地包锁文件仍能读取。
- `credentials.rs` 的令牌不实现 `Debug` 明文输出；索引与正文 HTTP 均采用同一授权边界。
  E3B 快照、源列表与锁定产物可在缓存命中时复用，无需重取网络内容。
- `tests/spec/11a-remote-closure/` 和本机目录/HTTP 集成测试覆盖传递约束、锁定不升级、
  摘要信任失败、来源审计、凭据脱敏及正文不执行。
- 本机 WSL 原生文件系统运行 `cargo test -p xiao-package --locked --offline` 全部通过
  （原有 DNS 依赖测试按既有设定忽略）；`cargo fmt --all -- --check`、
  `bun tools/repo-check/src/cli.ts all` 与 Windows 的工作区 `clippy -D warnings` 通过。
  Windows 本地未装 SDK 链接库，未在该环境链接执行 Rust 测试。
- **未扩条件兼容规则**；独立 `{ git = "..." }` 单仓库声明仍明确拒绝，
  与通过 `[sources]` 配置的 `git-index` 包不同。签名、安装脚本和预编译变体仍不在本批。
