# 12. 测试与开发里程碑

> 本阶段不是最后才做的测试收尾，而是每个前置阶段的退出门槛。没有双模式一致性测试，就不能宣称语言规划已经落地。

## 一级工程目标：建立测试分层

### 单元测试

覆盖词法 Token、缩进、反引号标识符、路径解析、类型推断、数值运算和引用计数基础操作。单元测试应尽量不依赖操作系统。

### 规格测试

每条已确定语法至少有：

- 一个最小合法例子。
- 一个最小非法例子。
- 一个包含错误位置和错误编号的期望结果。

### 双模式一致性测试

同一源文件分别经过字节码和 LLVM 后端，比较标准输出、退出码、错误类别、容器顺序和 `drop` 记录。允许机器码优化改变性能，不允许改变语义。

### 跨平台测试

在 Windows、Linux、macOS 验证换行、路径、固定宽度数值、环境注入、原生链接和退出码。

## 一级工程目标：定义版本里程碑

### M0：规格与词法闭环

退出条件：

1. 决策基线中没有未标记的冲突。
2. 词法器能处理 UTF-8、缩进、注释、表头和反引号名称。
3. 语法错误有稳定源位置。

### M1：静态核心闭环

退出条件：

1. 变量类型锁定、数值位宽和溢出检查可用。
2. 数组、元组、集合、字典表、字典列能建立值模型。
3. `def`、条件、循环和脚本入口可解析并检查。

### M2：字节码运行闭环

退出条件：

1. `xiao run` 能执行最小脚本和 `[main]` 工程。
2. 默认填充、路径约束和错误传播可测试。
3. 作用域释放和 `drop` 在解释模式确定执行。

### M3：内存与表闭环

退出条件：

1. 逃逸分析、引用计数和 `Weak` 最小实现可用。
2. `[Table]`、`[[Table]]`、`new`、`init`、`drop` 行为明确。
3. 无追踪式 GC 的运行时检查通过。

### M4：原生构建闭环

退出条件：

1. 同一类型化 IR 能生成 LLVM IR 和原生程序。
2. 原生程序不依赖完整虚拟机。
3. 双模式输出、错误和释放记录一致。

### M5：跨平台工具链

退出条件：

1. CLI、配置和测试命令可用。
2. Windows、Linux、macOS 的最小构建矩阵通过。
3. 文档中的所有“已确定”规则都有自动化规格测试。

## 一级工程目标：维护文档与决策

### 变更流程

1. 新规则先写入 `00-decisions.md`。
2. 再更新受影响阶段的语法、IR、运行时和测试章节。
3. 实现与文档冲突时，先标记待定并补充回归测试。
4. 每个里程碑完成后在 README 的状态表更新状态。

### 禁止事项

- 不把实验性语法直接写成稳定语法。
- 不让字节码后端和 LLVM 后端各自发明类型或释放规则。
- 不用“测试没覆盖”替代未解决的语言设计决策。

## 二级实现任务

### 测试基础设施

1. 建立源码快照、AST 快照和 IR 快照测试。
2. 建立正例/负例目录和统一期望文件格式。
3. 建立字节码/原生差分执行器。
4. 建立跨平台 CI 和最小发布样例。

### 质量门槛

1. 每次语法改动必须更新规格测试。
2. 每次 Runtime 改动必须运行生命周期和内存错误测试。
3. 每次 LLVM 改动必须运行双模式差分测试。
4. 每次配置改动必须验证命令行覆盖和原生固化行为。

## 验收标准

### 发布验收

- 文档索引顺序与实际开发依赖一致。
- 每个阶段至少有两个层级的任务和可执行退出条件。
- 所有未决问题在对应阶段开始前有明确结论或被主动延期。
