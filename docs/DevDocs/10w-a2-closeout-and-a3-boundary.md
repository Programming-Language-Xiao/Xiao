### 2.2 **A2 收口：差分要能分辨对错，失败回滚要有证据**

A2 现在只证明了「能降低」。构造参数是**语义敏感**的区域——求值顺序、默认值、缺参/多参、
类型不符、构造失败回滚，任何一条错了都不会被「降低成功」的断言发现。

**冻结**：

1. 在 `d19a_differential.rs` 增加 **构造参数**用例（沿用 `table-*` 命名），至少覆盖：
   - **求值顺序**：多个实参带副作用时按源码顺序求值（VM 是基准）；
   - **关键字与位置参数混用**、重复赋值同一参数；
   - **默认值**：省略参数时用 `init` 的默认值；
   - **缺参 / 多参 / 类型不符**：错误身份与 VM 一致（不是一个笼统的失败）；
   - **构造失败回滚**：`init` 抛错时表实例不被泄漏、释放序列与 VM 一致；
2. 每条用例都**声明基线的输出/错误/drop**（防止"两边都空也算一致"），且**能分辨对错**——
   实现方要证明"把构造参数忽略掉会让该用例变红"（10Q 的 K2 教训）；
3. **完整 VM/原生比对**：值、错误身份、退出码、释放序列四样都要比；只比「都成功」不算；
4. 释放证据沿用 10T/10U：**事件数、对象数、销毁位置**与**引用持有机制**；
   必要时用成对实验（只改一处、采数、恢复）定位差异；
5. 三条调试矩阵与优化级别也要覆盖新用例（`table-*` 命名的用例会被现有 O1–O3 与 debug 矩阵自动带上），
   确认新路径在各级别下都一致；
6. 收口后更新 10P 枚举表与 10U 实施记录，把「仍需差分与回滚证据」这句去掉。

### 2.3 **A2 剩余形状：只分类，不做新功能**

`container.rs` 仍有两处 A2 区域的拒绝：「动态表构造参数缺少 init」与「表构造参数形态」。

**冻结**：

- 对每条给**最小源码 + VM 实跑输出**，按三种分类之一判定：原生缺口 / 两边都拒绝 / 原生拒绝且 VM 也不该支持；
- **判为「两边都拒绝」的不改代码**，只更新枚举表与原因文案（如有必要）；
- 判为原生缺口的，写进 B 系列或单独立项，**不在本批实现**；
- **不得**为了让测试通过而放宽这两处的判定。

### 2.4 **A3：先用 VM 实跑冻结边界，再决定要不要实现**

10P 对 A3 的判定是「能力边界未冻结」，10U 也没动它。两处拒绝性质不同：

- `expression.rs:47`：`Member` 的结果类型是 `IrType::Function`（**表方法值**）；
- `methods.rs:53`：ABI 没有 Function 标签（**函数值本身**进不了值 ABI）。

而 VM 里存在 `RuntimeValue::ModuleFunction`——**函数值并非完全不存在**，所以必须实跑确认。

**冻结**：

1. 用最小源码在 **VM** 上确定：`obj.method` 作为值、赋给变量、作为实参、作为 callee，各自的行为与错误身份；
2. 按三种分类改判并回写 10P 枚举表；**判为「两边都拒绝」时本批不改后端**；
3. 只有判为**原生缺口**时才排实现，且实现前先补一份与 [10S-A1](10s-a1-table-method-abi-preparation.md)
   同规格的开工清单（含语言级能力边界：谁能持有、能否比较、能否跨模块传递）；
4. 结论必须附**最小源码与实跑输出**，不得只写一句结论；也不得只看代码推断。

### 2.5 **三平台与释放证据：沿用，不放宽**

**冻结**：

- 每个阶段性提交在本机 Windows 跑受控原生门控，并在**推送门控矩阵**（Windows + Linux 原生作业）上确认；
  裸机证据仍另算（本批不要求新的裸机轮次，除非星崽安排）；
- 新增/更新的布局与调用约定测试同时覆盖 **Windows 与 SysV**；
- 释放证据口径同 §2.2 第 4 条；
- **本地跑 ignored 套件要用 [10D](10d-environment-gated-test-spec.md) §4.5 的推荐命令**（`--skip` 去掉窗口风暴），
  不要把窗口当成缺陷。

### 2.6 **文档状态与 19 的 O6**

**冻结**：

- 本批完成后更新：10U 实施记录（A2 收口）、10P 枚举表（A2 状态 + A3 改判 + §2.3 的两条）、
  19D 的 O6 对账（条件 2 的措辞随 A2/A3 结论更新）；

## 四、硬约束

1. W 系列、A2 收口、A2 分类、A3 取证各自单独提交，提交说明写明归属 10U/10P，并带正文；
2. 新用例**必须能分辨对错**，并有「让它变红」的验证（§2.2 第 2 条）；
3. 完整比对四样（值/错误身份/退出码/释放序列），不得只比「都成功」（§2.2 第 3 条）；
4. **A2 剩余形状与 A3 只做分类取证，不做新功能**（§2.3、§2.4）；
5. 分类结论必须附最小源码与实跑输出，不得只看代码推断（§2.3、§2.4）；
6. 不新增依赖，`Cargo.lock` 保持同步；
7. 每个提交单独跑 clippy 与 fmt；推送前跑 `cargo test --workspace`、`bun test`、`bun run check`；
8. 本地跑 ignored 用 10D §4.5 的 `--skip` 命令（§2.5）；
9. O6 未满足不宣布收口（§2.6）。

## 五、分步提交

1. **W1**（若选 i18n）与 **§2.3 分类**：两条 A2 剩余形状的最小源码 + VM 实跑 → 改判；
2. **A3 取证**：VM 侧四个形态的实跑 → 三种分类改判 10P；判为缺口则出清单、本批不实现；
3. **A2 差分第一步**：加构造参数用例（求值顺序、关键字/位置混用、默认值），先确认它们在「忽略构造参数」时变红；
4. **A2 差分第二步**：补缺参/多参/类型不符与构造失败回滚，含释放证据；
5. **A2 收口**：更新 10P/10U，去掉「仍需差分与回滚证据」；
6. **W2**：星崽确认默认值与方式后回填 11X0-D；
7. **三平台验证**：本机 Windows + 推送门控矩阵；必要时手动触发平台复现；
8. **全量门禁与实跑**：`cargo test --workspace`、clippy、fmt、`bun test`、`bun run check`；
9. **文档与登记**：本文件实施记录（含数据表）、19D 对账、README。

## 六、最可能翻车的地方

1. **只断言「降低成功」**，把 A2 收口做成又一个「代码存在」；
2. **新用例没有分辨力**（例如只断言两边都成功），重演 10Q 的 K2；
3. **为了让回滚用例变绿而放宽错误身份**，把「VM 报 X，原生报 Y」写成「都失败即可」；
4. **只比释放总数**，不看对象数、销毁位置与持有机制；
5. **A3 直接开工**：边界未冻结就实现，可能在做 VM 本身也不支持的事；
6. **A3/§2.3 只看代码推断**，不实跑 VM；
7. **把「两边都拒绝」写成原生缺口**，虚增缺口清单，进而影响 O6 条件 2 的判定；
8. **本地跑 ignored 又被窗口风暴困住**（用 10D §4.5 的命令）；
9. **O6 条件 2 未达成却写「满足」**；
10. **提交没写正文 / 没单独跑 clippy**。

## 七、验收

1. W1–W3 有结论（W2 以星崽确认为准，未确认则写「待确认」，实现不重做）；
2. A2：构造参数用例覆盖求值顺序、关键字/位置混用、默认值、缺参/多参/类型不符、构造失败回滚；
   每条声明基线且**能分辨对错**（有「忽略构造参数会变红」的验证）；
3. A2：完整比对四样；回滚用例有释放证据（事件数/对象数/销毁位置 + 持有机制）；
4. A2：新用例在 O1–O3 与调试矩阵下同样一致；
5. §2.3 与 A3：各有最小源码与 VM 实跑输出，按三种分类改判并回写 10P；
   判为「两边都拒绝」的未改后端；
6. 10P/10U/19D 已回填，A2 的「仍需差分与回滚证据」已去掉；
7. O6 按五条原文更新，未满足就写「部分/不满足」；
8. `cargo test --workspace`、clippy、fmt、`bun test`、`bun run check` 全绿，且每个提交单独绿；
9. 没有通过放宽断言、删用例或缩小范围换来的绿。

## 八、不负责与不要重复做的事

- **不做** B1/B2（纯降低与诊断、选择计算）；
- **不做** A3 的实现（除非判为缺口且星崽要求本批一并做——那要先补开工清单）；
- **不做**静态路径 `llvm.trap`、性能取数、20C/20D；
- **不改** A1 已冻结的 V2 描述符布局与回调形态；
- **不改**窗口机制（10V 已收敛，本批只碰 W1/W2 的文案与约定）。

## 待定决策

1. **10V 的默认值与保持方式**（W2）：默认 5000 ms 保持、非交互显式设 `0`——确认还是改成
   「非交互默认关闭」？审核已实测实现有效，改的是取值不是可行性。
2. **W1 的取向**：把保持开关的报错文案接进 i18n，还是明确「本文件 argparse 级错误不走 i18n」
   并写进 11X0-D 作为约定？后者与同文件既有做法一致，前者更统一。
3. **A2 收口后是否立即启动 B 系列**（B1 纯降低与诊断 / B2 选择计算），还是先做一次
   引用计数核对或性能受控取数。
4. **裸机轮次**：本批是否需要新的裸机 Linux 轮次（例如为 A2 的构造参数取证），
   还是等 A2/A3 全收口后集中做一次。
