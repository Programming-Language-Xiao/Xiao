# 20O-B4. JSON/TOML 值模型与解析器实施规划

> **B4 尚未开始；B3 完成后才进入产品实施。** B2-C 已完成公共收口；前置未完成时，仅可在明确授权下执行 B4-0 探测/冻结。
> **Windows 产物政策（2026-11-22）**　自 B3 起，所有 Windows 公共/发布产物必须产品级 COFF `Complete`；B2-C 同链接补验是历史例外，不得继承。
> B4 使用一个专用 `json_value` 表示 JSON/TOML 值（20O D-7、20P §五），不另造 `toml_value`，也不并入公开 `dynamic`。
> B4 不实现 B5 decimal/fractions/random、B6 regex/compression、B7安全、B8网络、B9数据库。
> 值模型必须与 B5 数值类型分开评审，不把 JSON 数字直接等同 lfloat/decimal。

| B3 | 简单宿主库尚未完成；B4-0 可在明确授权下探测/冻结，产品实施须等待B3收口或另有明确阶段授权；不把B3能力当默认前置 |

B4 是 **数据格式批**，不是数值批。JSON/TOML 的 number 表示、精度和转换必须在 B4-0 冻结，不能借用 B2 的 lfloat/decimal 语义。值模型须与B5分离；一个共享 `json_value` 是否提供跨格式表示，由冻结表定义。

### 1.1 要做

1. 探测 JSON/TOML 现有语法、平台/依赖和宿主边界；
2. 按 D-7 冻结唯一专用 `json_value` 类型及 JSON/TOML 共用关系；明确构造、类型检查、标量读取、数组/表查询与更新 API，以及所有权、别名、相等/哈希和显示是否提供；
3. 冻结 JSON 严格语法、数字/字符串/Unicode/重复键/深度/大小限制和错误身份；
4. 冻结 TOML 子集/完整版本、日期时间、表/数组表、重复键、数字和限制；
5. 实现值构造/访问 API、解析器、序列化器和错误/资源原子性；
6. 接通类型/IR/TAC/VM/LLVM/归档、std/stdlib双路径、导出/移除/隔离；
7. 为 `json` 与 `toml` 各编写一份可执行教程、固定示例和三平台证据；
8. 只在验证范围升级 registry/教程；B4 值模型与 B5 数值类型分开。

### 1.2 明确不做

- 不把 json/toml 值并入公开 `dynamic` 或扩大 JSON→lfloat 自动转换；
- 不实现 B5 decimal/fractions/statistics/random；
- 不实现网络/数据库/正则/压缩/安全；
- 不改变 B2 数值语义、既有 intrinsic 1～48/ID100；新值类型依既有架构规则升级ABI，不临时占用墓碑或重编号；
- 不新增未冻结能力位/错误码；
- 不提前升级 registry/教程，不跑旧721。

## 三、分批执行

### B4-0：探测、冻结与教程草案

1. 探测 JSON/TOML 语法、候选解析实现（纯Xiao或Rust依赖）、平台差异、错误/资源/性能边界；记录源码、工具、依赖和原始输出身份；
2. 按 D-7 冻结一个专用 `json_value`，由 JSON/TOML 两个模块共同使用；不定义第二个 `toml_value`。冻结共享类型的构造/类型查询/标量读取/数组与表访问及修改面、所有权/别名/生命周期、相等/哈希/显示或明确不提供；
3. 冻结共享模型如何表示 JSON/TOML 的数字差异、TOML 日期时间及 TOML 专属值；逐项规定解析、跨格式序列化和不可表示时的行为，不映射成 B2 `lfloat`/decimal，也不隐式丢失语义；
4. 冻结 JSON：RFC 8259 数字/字符串/Unicode语法、重复键、尾随逗号、注释、NaN/Inf、BOM、错误位置/稳定身份/优先级、深度/节点/字符串/输入字节及输出限制；若入口接收 `str`，非法UTF-8只作为底层字节入口测试，不伪造源级非法 `str`；
5. 冻结 TOML：采用版本/子集、表/数组表/内联表、数字与日期时间语法、时区/偏移语义、重复键/冲突键、错误位置/稳定身份/优先级，以及深度/节点/输入/输出限制；
6. 冻结两个模块的精确函数签名、参数规则、解析/序列化/构造/访问 API、效果/所有权、错误表/优先级、失败原子性、资源和性能预算/测量方法、是否有宿主能力；解析文本不隐式读取文件或网络；
7. 若选择Rust解析依赖，固定直接/传递依赖、版本、特性、锁摘要、许可证、维护工具与 `--locked` 构建策略；若纯Xiao实现，也固定范围、算法/复杂度和来源；
8. `json_value` 是新增运行时值类型，按20P规则必须升级Runtime ABI次版本并更新 `.xiaoc`/`.xar` 指纹；冻结intrinsic编号、ABI/生成器增量、C符号/所有权、VM/LLVM绑定、标准库接口身份、旧产物拒绝与缓存身份，保留ID 100墓碑和既有编号；
9. 冻结 `json_value` 在常量、归档、XCON/并发边界的承载规则；不得因文本JSON/TOML序列化而默认获得跨线程或跨Runtime传递能力，未接入则明确拒绝；
10. 为 `json` 与 `toml` 各写一份完整可执行教程草案和固定示例，按 D-20 放入 `tests/fixtures/docs/<module>/`，并建立VM/受控原生逐字输出与退出码入口；registry候选保持 `planned`；
11. 记录延期能力（流式解析、JSON Pointer、注释保留等），并以可复核裁定记录标明已冻结项、未冻结项和阶段授权。

退出：共享值模型/构造访问API、两种格式映射、语法/限制/错误/资源性能/版本依赖/兼容身份及两份教程草案冻结；未写产品，且本阶段本身不授予产品并行实施授权。

### B4-1：`json_value` 与解析器

1. 实现共享的专用 `json_value` Runtime表示、构造/读取/更新API、所有权与生命周期；
2. 严格 JSON parser：字符串/Unicode/数字/对象/数组，并按冻结策略保留数字语义；
3. 深度/节点/字节/字符串限制；
4. 错误身份/顺序/失败无部分结果；
5. 序列化：确定性键序/转义/数字文本；JSON无法表示的共享模型变体按冻结规则拒绝；
6. 单元/边界/教程测试。

退出：共享 `json_value` 基础API及JSON解析/序列化内部可用，尚未声称TOML适配完成。

### B4-2：TOML解析器与共享值模型

1. TOML解析器和API使用同一个 `json_value`；不得新增独立 `toml_value`；
2. TOML表/数组表/内联表/数组/字符串/数字及日期时间映射按冻结规则；
3. 重复/冲突键、非法数字、日期时间、深度/节点限制；
4. 错误身份/顺序/失败无部分结果；
5. 序列化：确定性输出，并按冻结规则处理JSON与TOML之间不可表示的变体；
6. 单元/边界/教程测试。

退出：TOML到共享 `json_value` 的解析/序列化内部可用；没有第二套值模型。

### B4-3：语言、双路径与承载

1. 共享 `json_value` 的类型/IR/TAC/VM/LLVM/归档；
2. `std.json`/`stdlib.json`、`std.toml`/`stdlib.toml`双路径；
3. 导出/移除/普通包隔离；
4. 常量/归档/XCON承载边界按B4-0接线；需要跨线程传递的场景逐项验证，否则保持拒绝；不暴露Rust布局；
5. 能力/错误/取消/资源；
6. B1七库20入口/17项资源/双精确/28守卫功能回归；不运行或引用721条F10；
7. 三平台VM/原生O0/O3。

退出：两库内部全链路一致，共享同一 `json_value`；无第二套值模型。

### B4-4：测试、教程与收口

1. JSON/TOML正常/边界/错误/资源/Unicode/日期时间，覆盖构造/访问/跨格式限制；
2. 两份完整教程示例进入VM和受控原生精确入口；
3. B1七库20入口/17资源/双精确/28守卫回归，明确不执行721条F10；
4. 记录产品源码、Runtime、工具、依赖锁、夹具、平台、任务根和真实CI run/job/attempt；保存原始日志与失败/重试，不以聚合状态替代实际作业；
5. registry只在全部必测通过的验证范围升级；缺平台、失败或不可验证只允许受限交接，不得标记B4验收完成或升级未验证范围；
6. 与B5数值类型边界复核，运行完整workspace测试/Clippy/fmt、benchmark/驱动自检、`check:lock` 和 docs/UseDocs/layout/覆盖率门禁；
7. 形成B5交接。

退出：全部必测的功能、资源/性能、三平台、教程和工程门禁通过后，方可记B4内部收口；失败、缺项或不可验证只作受限交接。B5未开始。
