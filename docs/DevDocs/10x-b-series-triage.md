### 2.2 **B 系列先分类取证：逐条 VM 实跑，不许只看代码**

剩余 23 处拒绝里混着至少三种东西：**真缺口**、**两边都拒绝的一致行为**、**防御性判定（可能永远走不到）**。
A3 就是活例子——看着像缺口，实跑后是「两边一致拒绝」。**分类不做，实现范围就是猜的。**

当前清单（审核 grep 得到，实施方以代码为准重新枚举一遍）：

```text
动态函数调用（2 处）            动态表构造目标           动态表构造参数缺少 init
表构造参数形态                  表方法参数形态           动态表方法接收者
动态表字段类型                  动态表字段初始化          动态表声明/初始化
动态扩展赋值                    动态非表成员访问          动态非表字段写入
动态混合多项选择器              动态选择器缺少规范选择计划  set 构造器参数
random.seed 缺少参数            print 的关键字或展开实参   input 的关键字或展开实参
错误构造参数（只支持 code/message）  动态错误构造参数（只支持字符串字面量）
FatalError 不能构造为可恢复错误值  动态表方法值（A3）        动态函数值 ABI（A3）
```

**冻结**：

1. 对每一条给：**触发它的最小源码**、**VM 实跑输出**（错误身份 / 输出 / 退出码）、
   以及**按三种分类之一的判定**：原生缺口 / 两边都拒绝 / 原生拒绝且 VM 也不该支持；
2. 判定必须来自**实跑**；允许先读码缩小范围，但结论不能只有读码；
3. 标注**可达性**：这条拒绝在真实源码里能否被触发（有些是防御性分支，永远走不到）；
4. A3 那两条已经判过（两边一致拒绝），**直接引用 10W 的结论，不重复取证**；
5. 结果写回 [10P](10p-differential-exemption-and-coverage.md) 的枚举表（含分类与可达性两列），
   并**提交只含文档的记录**，然后**停下来向星崽汇报**：真缺口有几条、各需要什么、哪些依赖别的阶段；
6. 汇报后才定实现范围（§2.3）。**不得**先动手再补分类。

### 2.3 **B 系列实现：范围由分类结果定，不预设**

**冻结**：

- 只有**判为原生缺口**的才排实现；判为「两边都拒绝」或「防御性不可达」的**只改文档**；
- 实现按 [10P](10p-differential-exemption-and-coverage.md) 的 ABI 顺序（B1 纯降低与诊断 → B2 选择计算），
  每类一个提交，含差分用例与原生比对；
- 涉及新 ABI 的按 10T 的版本规则；纯降低层的**不升版本**，但要在提交说明里说明为什么不升；
- 不先删拒绝；接不通的继续拒绝并登记（沿用 10T/10U 的做法）；
- 若某条判定为缺口但工作量明显超出本批，**单独立项**，不硬塞。

### 2.4 **三平台与释放证据：沿用，不放宽**

**冻结**：

- 每个阶段性提交在本机 Windows 跑受控原生门控，并在推送门控矩阵（Windows + Linux 原生作业）上确认；
- 新增/更新的布局与调用约定测试同时覆盖 **Windows 与 SysV**；
- 释放证据含**事件数、对象数、销毁位置**与**引用持有机制**；成对实验只改一处、采数、恢复；
- 新用例要**能分辨对错**，并有「让它变红」的验证（X1 的教训，本批起一律要求）；
- 本地跑 ignored 用 [10D](10d-environment-gated-test-spec.md) §4.5 的命令（`--skip` 去掉窗口风暴）。

## 六、最可能翻车的地方

1. **跳过分类直接实现**，把「防御性不可达」的分支也当成缺口去做（A3 就是前车之鉴）；

   是要在 10 系列内安排一次受控取数，还是等 B 系列收完再统一做？这直接决定 19 能否收口。
4. **macOS 的长期口径**：无 Mac 宿主、CI 又显式跳过真实终端——是否在 19 的收口标准里
   把 `19.14` 的 macOS 那一格明确标为「不可验证」并写明理由，而不是一直挂「未验证」。
5. **裸机轮次**：B 系列是否需要新的裸机 Linux 轮次，还是等 B 系列收完后集中做一次
   （连同 C 档的窗口截图）。
