## 二、上一批（15C）的未完成项 —— **本批的全部范围**

### 2.1 **链接器产出的符号表顺序** —— 未做（§2.3 的难点）

15B 的"符号排序"排的是 **LLVM 文本里的 `; xiao-symbol=` 注释**，
并且其注释明确写了：「**LLVM 指令和声明顺序仍保持原样**」。
**那不是链接器输出的符号表。**

**冻结**：

- **对象是链接后可执行文件的符号表**（PE 的 COFF 符号表 / ELF 的 `.symtab` /
  Mach-O 的 `LC_SYMTAB`），**不是 LLVM 文本**；
- **⚠️ 10K 的教训直接适用**：Windows 上**默认不保留 COFF 符号表**——
  这正是 10K 判定"Windows 的绿是看不见"的同一个机制。
  **本批要明确：符号表不可读时是"拒绝"还是"记为不可验证"，不能静默当成一致**；
- **顺序要显式规范化并验证**——不能假定"同一个链接器就稳定"（10K 已证明跨平台差别很大）。

### 2.2 **调试信息里的绝对路径** —— 未做（§2.3 的另一项）

`-debug` 产物会把**源码路径**嵌进调试信息（DWARF / PDB / CodeView）。
在不同机器上构建时，这些路径不同。

**冻结**：

- **归一化或记录**，二者必居其一（**不能"比不出差异就跳过"**，15C `§3.1` 已冻结）；
- **与 15C 的 `normalized_fields` 同一机制**——沿用，不新造；
- **⚠️ 路径归一化后的可比性要能说清**：归一化掉的如果是"这台机器的项目路径"，
  要证明**它不影响任何可观察语义**。

### 2.3 **strip / 调试符号 / 可诊断模式的产物级独立验收** —— **完全未做**

`15.7` 原文：「对 **strip、调试符号和可诊断模式**建立**独立验收**」。
15B `§3.5` 冻结了"**三者是三件事**"，但**没有对真实产物做验收**；
**15C 也没有做，且实施记录未提及**。

**冻结**：

- **三者独立验收**，不能用一个用例覆盖：
  - **strip**：剥离后产物仍可运行，且诊断行为**明确**（不静默降级）；
  - **调试符号**：保留时符号/行号信息**可读**；
  - **可诊断模式**：调试激活位存在时**能开独立诊断窗口**；
- **⚠️ "优化之后"是关键词**（15H 验过的是未优化产物）：
  **各 `-O` 级别都要验**，`-debug` 三不（不依赖启动器 / 不受 GUI 抑制 / 失败不静默）仍成立；
- **调试激活位不得被优化掉**——它是**产物标志**，不是可删死代码
  （与 14B/15A 的"不得删除可观察操作"同源）；
- **strip 之后可诊断模式要么仍工作、要么明确失败**——**不许静默降级**（10H 三不之一）；
- **调试信息的发布保留策略仍属待定决策 3**——**建验收，不冻结策略**。

### 2.4 性能基线取数 —— 仍待受控环境

15C 已如实记为待补。**本批若仍拿不到受控环境，继续记待补**。

**冻结**：**不许用开发机数字冒充**（15B `§3.4`、15C `§3.5` 已冻结两次，**第三次重申**）。

### 2.5 三平台门控 —— 仍待平台

按 15A `§3.6` 的 **Windows → Linux → macOS** 顺序推；
**本机可做的三项（§2.1–§2.3）不因平台未齐而搁置**。

## 三、必须先冻结的 6 条

### 3.1 **符号表不可读时，不许当成"一致"**（§2.1）

10K 的核心教训是「**看不见 ≠ 没问题**」。本批面对同一个机制。

**冻结**：

- 符号表**读不到**时（例如 Windows 默认剥离 COFF 符号表），
  **要么显式拒绝并给出稳定诊断，要么把该项标为"不可验证"**——
  **绝不能因为读不到就跳过，然后报告"一致"**；
- **这与 14A 的"剥离符号表不能静默通过"是同一条**：
  14A 在 `.xiaoc` 上做过同样的判断（「ELF/Mach-O 缺少可用符号表时明确拒绝，避免剥离产物静默通过」）；
- **沿用同一措辞与判定方式**，不新造。

### 3.2 **本批的对象是真实产物，不是模型**（§2.1–§2.3）

15B 交付了模型与白名单，15C 开了产物字节的头。**本批要继续落在产物上。**

**冻结**：

- 三项（符号表顺序、调试路径、strip 三态）**都要在真实产物上验**；
- **不做"只加数据结构、不接真实产物"的交付**——
  15C 的内联栈是**合理的预留**（因为没有会内联的优化），
  但**符号表与 strip 不存在这种理由**：产物就在那里。

### 3.3 **沿用同一条确定性规则**（第五次落地）

13A（指纹）→ 14A（`.xiaoc`）→ 15B（构建文本）→ 15C（产物字节）→ **本批**。

**冻结**：**不为本批新造规则**；发现前几处有漏**一并记下**。

### 3.4 **白名单继续沿用 15B 的五类**

**冻结**：

- **不新开一套**。若要新增类别（例如"调试路径差异"），
  **说明它为什么不能归入现有五类**；
- **加入白名单前先证明"确实不可消除"**（15B `§3.2` 已冻结）。

### 3.5 **基线第三次重申：没有受控环境就没有基线**

**冻结**：拿不到就**记待补**——**填数是更坏的选项**（这条已在 15B、15C 各冻过一次）。

### 3.6 **本批不做 16–19 阶段的事**

- **不做** Protobuf 索引与内容寻址缓存（16）——含待定决策 4；
- **不做** `.xar`（17）、TS CLI 参数解析（18）、Java 对照与发布验收（19）；
- **不启用** LTO / PGO / 向量化 / 目标 CPU 特化（待定决策 2）；
- **不冻结**调试信息的发布保留策略（待定决策 3）。

## 九、验收

1. **链接器符号表**（§2.1）：三种对象格式的符号表**顺序显式规范化**；
   **不可读时拒绝或标为不可验证**，**不静默当成一致**；
2. **调试信息绝对路径**（§2.2）：归一化**或**记录，二者必居其一，**并有可比性说明**；
3. **strip / 调试符号 / 可诊断模式**（§2.3）：**三者独立验收**，
   **在真实产物上、各 `-O` 级别下**；`-debug` 三不成立；strip 后不静默降级；
   **调试激活位未被优化掉**；
4. **产物级可复现**（§2.3 合并）：同一输入重复构建，可执行文件**逐字节相同**
   或差异**逐条列在白名单并有理由**；**三项覆盖齐全**（PE 时间戳 + 符号表 + 调试路径）；
5. **归一化字段完整记录**（延续 15C）——**不出现"忽略差异"伪装成可复现**；
6. **性能基线**：受控环境取得，或**如实记待补**（**不以开发机数字顶替**）；
7. **平台**：按 Windows → Linux → macOS 推进；未推的记入运行记录并标待补；
8. **不回归**：15A/15B/15C/14A/14B/13A/13B/10 已交付内容保持绿；`cargo test --workspace` 全绿；
9. **门禁全绿**：`bun run check`（含 `check:lock`）、clippy、TS 类型检查、`cli/ts` 测试。
