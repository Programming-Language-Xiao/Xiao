# 12A. 阶段验收核实记录（01–11）

> **缘起**：主表里 01–11 的阶段级状态长期停在「进行中」，无法判断是**真的没做完**
> 还是**状态没回填**。本文对每个阶段的「验收标准」**逐条**核实，给出可追溯的结论与证据。
>
> **判定方法**：只看**代码与测试的实际存在**，**不采信文档自身的声明**。
> 每条结论都附具体证据（文件:行 或测试名）。无法确证的标「无法判定」，
> **不写成满足**。
>
> **结论一句话**：**01–11 没有任何一个阶段的验收全部满足**，因此主表的「进行中」
> 是**准确的**，不是滞后。但缺口的性质分三类，处置方式不同（见 §三）。

## 二、跨阶段共因（**比单条缺口更值得处理**）

### 2.1 **LLVM 后端不支持选择器与容器动态路径** —— 同时卡住 03 与 08

`IrExpressionKind::Selector` 在**两处**都返回 `CodegenError::Unsupported`：

- `xiao-codegen-llvm/src/dynamic/expression.rs:47-52`（动态路径）
- `xiao-codegen-llvm/src/ir.rs:1051`（静态路径）

**后果**：03 的「字典列字节码与原生同序」「不兼容写入在两种执行模式同类错误」，
以及 08 的「同一选择 IR 在两后端产生相同结果」，**都不满足**。

**这是本仓「双执行路径」立身之本上的缺口**——两条路径在容器/选择器这块尚未汇合。
现有的「多机」测试是 **VM 内的三种载体**对比（`xiao-vm/tests/r2_selector_values.rs`），
**不是 VM 与 LLVM 的双后端对比**。

### 2.2 **`xiao-syntax` / `xiao-ir` 的快照测试不在 CI 覆盖面内** —— 卡住 01、02、08

`tools/platform-reproduction/reproduce.sh` 只跑两条：

```text
:132  cargo test --workspace -- --ignored        # 只有 #[ignore] 门控测试
:144  cargo test -p xiao-driver                  # 只有 driver
```

**后果**：01 的「三平台 Token 序列一致」、08 的「AST/IR 快照跨平台构建稳定」
**都没有 CI 证据**——因为承载它们的那批快照测试**根本不在 CI 执行**。

**注意这与「门控测试」是两回事**：门控测试（需 `XIAO_CLANG` 等）用 `#[ignore]` 是有意为之，
但 `xiao-syntax` 的普通快照测试**既不需要外部工具链、也没被跑**。

### 2.3 **「有实现、缺断言」是出现最多的缺口形态**

02、03、05、06、07 的多数缺口都属于这一类：功能**已经实现**，只是**没有测试锁住它**。
这类缺口的风险不在于「现在错」，而在于**将来被改坏时无人发现**。
处置成本低（补断言），但**最容易被误当成已完成**——正是本轮核实的价值所在。

## 三、逐阶段明细

### 01. 词法 Token 与语法入口

**缺口 1：三平台 Token 序列一致无任何测试**（见 §2.2）。
快照测试本身是平台无关的（对比固定 JSON 的字节偏移），但**没有跨平台比对测试**，CI 也不跑它们。

**缺口 2：缩进/未闭合字符串/未闭合反引号三类错误未断言行列号**。
错误码与字节区间有测试（`lexer.rs:1120` `diagnoses_unterminated_string` 只断言
`tokens[0].kind()` 与 `diagnostics[0].code()`）；**行列断言只出现在普通 Token 上**
（`lexer.rs:904-913`）。

### 02. 类型与值系统

**缺口 1**：「字节码与原生使用相同类型规则」靠**单一前端**的结构保证
（`xiao-driver/src/native.rs:113` 与 `src/run.rs:489` 都调 `FrontendCompiler::compile`），
但**差分用例不含静态类型错误**，只覆盖运行期错误。

**缺口 2**：「固定宽度类型在所有平台结果一致」**无专门断言**，四平台只是间接跑到一个
i64 溢出用例。

**缺口 3**：`lint`/`lfloat` 高精度数值**整体未实现**——
`xiao-runtime/src/value/ops.rs:637` 的测试断言的就是「尚未实现」。
因此「每一种溢出都有错误类别和源位置」只能算部分满足。

### 03. 容器、集合与索引路径

**缺口 1**：凡涉及**原生执行模式**的条目不满足（见 §2.1）。

**缺口 2（边角）**：`[1, 2/1]` → `('b', [2])` 的**确切运行时用例**缺失；
`[<0]` 只有类型层断言、无运行时空容器用例；
C2-C「原地写回 SetMembership」有实现（`xiao-types/src/checker/statement.rs:385`）无断言。

### 05. 表、模块与工程模型

**缺口 1**：`X05-TYPE-001`（`xiao-types/src/table_checker.rs:60`）与
`X05-PARSE-005`（`xiao-syntax/src/diagnostics.rs:136`）**有实现无断言**。

**缺口 2（文档债）**：本文档末尾的「后续验收债项」一节**已过期**——
表运行时分配/释放已由 09R2H 交付（`xiao-vm/tests/r2_table_values.rs`、
`tests/spec/09-bytecode/tables.json`），外部依赖锁定已由 11A 交付
（`xiao-package/tests/e2a_lockfile.rs`、`e3d_solver.rs`）。
**该节需更新，否则会被后人误当作「未完成」的依据。**

### 06. 内存与运行时语义

**缺口 1**：选择结果的**引用计数平衡无断言**——
`xiao-vm/tests/r2_selector_values.rs` 中 `strong_count` 出现 **0 次**。

**缺口 2**：非法步长/随机数量失败的释放路径**只有错误码断言**，无释放或计数断言。

**缺口 3**：**弱引用打破环后整环完全释放的端到端用例不存在**。
强环拒绝有（`xiao-lifetime/src/graph.rs:224` `GraphError::StrongCycle`），
但「弱边破环 → 整环释放」没有测试。

### 07. 错误模型与并发安全边界

**07-A / 07-B 的验收条目本身均满足**。缺口集中在 07-C 由 11X0-D 交付后的三处未闭合：

1. **`breakpoint_hits` 恒为 0**——全仓只有定义（`xiao-diagnostics/src/window.rs:126-138`）
   与显示两处，**没有任何自增点**。
2. **诊断事件的 `error_id` 恒为 `None`**——`xiao-driver/src/diagnostics.rs:843` **硬编码**，
   且 `:930` 的测试还断言 `is_none()`，把当前行为固化了下来。
   **后果：错误实例与窗口事件之间没有身份关联。**
3. **focus/mirror 分流规则无行为测试**——实现齐全（`diagnostics.rs:254-288`），
   测试只验协议解析（`x0_a_protocol.rs:190-191`）。

**07-D 不是缺口**：`07-concurrency-and-errors.md:261-264` 自述 07-D 只是研究归属标签，
**不是并发实现阶段**，也不构成本阶段的退出条件。

### 08. 前端与统一中间表示

**缺口 1**：见 §2.1（LLVM 不支持选择器）。

**缺口 2**：选择器**没有 AST 快照**——`parser_snapshots.rs:185` 的 `assert_expression`
只认 `Literal`/`Name`，选择器只有手写单测。

**缺口 3**：「嵌套形状计划」**无独立 IR 字段**，形状由 `result_type` + `selected_paths`
表达，重建在 `xiao-types/src/selection_shape.rs:81`。

**缺口 4**：见 §2.2。

### 09. 字节码运行模式

**缺口 1**：解释器性能报告**无 Java 参考实现与硬件字段**
（`tests/benchmarks/reports/windows-native-performance.json` 只有 `rust_toolchain`/
`profile`/`opt_level`/`warmup_iterations`/`input_scale`；**全仓无 `.java` 文件**）。
**该条按文档 `:153` 由 19 阶段冻结条件**，属设计上未完成而非缺陷。

**缺口 2**：「动态值集中、不强制装箱标量」**只有结构证据**
（`xiao-runtime/src/value/mod.rs:164` 有独立标量变体、`xiao-bytecode/src/tac.rs:482-485`
有显式 `Box`/`Unbox`），**无「标量路径不产生 Box 指令」的测试**。

**另**：主表曾说「用户可见 CLI 留给 11/X0」——**已由 11/X0 完成**，
见 `cli/ts/src/commands/index.ts:225/263/175/317`，不是占位。

### 10. LLVM 原生后端

**验收 10 条全部满足**。唯一未清账目是 **PE 内部节裁剪证据债 `unverified-coff-exports`**：

- 登记处：`xiao-codegen-llvm/src/artifact.rs:272`（枚举）、`:281`（字符串）、
  `:323-328`（判定 `Coff && !symbol_table_readable`）；
- **判定链仍然生效**：`toolchain.rs:463` 的 `ObjectFormat::Coff => {}` **不**加
  `--gc-sections`；`:516-521` 只用 `-Wl,/export:<symbol>` **主动写导出表**——
  即 PE 上读到的是「自己写、自己读」的导出面；
- 15A 交付的是**链接前**的调用图裁剪报告，15D/15E 明确选择「PE 导入导出不冒充内部符号表」，
  **均未关闭它**。

### 11. CLI、项目配置与平台

**缺口 1**：**X0 第 8 条**（定义在 `12-tests-and-milestones.md:700`）有两项未闭合：

- **macOS 真实终端握手从未验证**——门控测试 `real_terminal_session_is_environment_gated`
  （`xiao-driver/src/diagnostics.rs:961`）需真实 GUI 会话，macOS CI runner 无 GUI，
  故经 `XIAO_SKIP_REAL_TERMINAL_TEST=1` **显式跳过而非放行**；
- **POSIX 开窗只有源码文本断言**——`toolchain.rs:1321`/`:1339` 断言源码含
  `CREATE_NEW_CONSOLE`/`posix_spawn`，`11x0p1:363-364` 自己点名这是文本断言而非功能验证。

**缺口 2**：**`.xar` 子项不满足**——`cli/ts/src` 内 grep `xar` **零匹配**，
`core/rust/crates/xiao-xar/src/lib.rs` 只有 1 行 crate 文档注释。
（`11-cli-config-and-platform.md:53` 自称 `-xar`「不进入本阶段核心 CLI 的退出条件」，
与该文档 `:306` 的验收文字**互相矛盾**，需一并厘清。）

**缺口 3**：`run`/`build`/`test` 的**项目根与配置解析实现不一致**且无一致性测试——
build 从 cwd 向上找（`commands/index.ts:281-282`）、run 交给 Rust
（`xiao-driver/src/protocol/run.rs:59-78`）、test 用 `command.project ?? "."`（`:185`）。

**缺口 4（边角）**：`--global` 实际写入目标无断言；打包产物上的 `--help`/REPL 无测试。

## 四、建议处置

| 类别 | 处置 | 理由 |
| --- | --- | --- |
| **§2.1 LLVM 不支持选择器** | **登记为独立债项，明确归属** | 它同时卡住 03 与 08 两个阶段，横跨「前端」与「原生后端」；不归属清楚就会两头都以为对方管 |
| **§2.2 快照测试不在 CI** | **可低成本修复** | 在 `reproduce.sh` 加一条 `cargo test -p xiao-syntax -p xiao-ir` 即可解锁 01/02/08 的三条验收 |
| **§2.3 有实现缺断言** | **按阶段分批补**，不设统一批次 | 单条成本低，但分散在 5 个阶段；集中做会让批次过大 |
| **10 的 PE 债** | 保持登记 | 已在主表标 `unverified-coff-exports`，是**已知且有意接受**的边界 |
| **09 的 Java 参考** | **不改** | 按 09 文档 `:153` 归 19 阶段的冻结条件 |
| **05 的文档债项节** | **更新** | 内容是错的（债已还清），会误导后人 |
| **11 的自相矛盾** | **厘清** | `:53` 与 `:306` 对 `-xar` 是否属本阶段退出条件说法冲突 |
