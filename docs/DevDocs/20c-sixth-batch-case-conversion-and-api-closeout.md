# 20C-第六批. 大小写转换的表达力与接口收口

> **背景**：[20C-第五批](20c-fifth-batch-reprobe-and-library.md) 的复探七行**双路径实测通过**
> （审核实跑复核，两平台逐条一致），加了 `text.format_int` 与 `text.is_ascii_upper` 两个接口，
> 并把 [F-1](20c-fourth-batch-int-to-str.md) 那笔 `lint` 转换债登记到位。
>
> **但**：该批复探**漏答了它自己 §4.2 第 3 条的后半问**——
> 「大小写转换**能否用不依赖 `str` → `int` 的写法表达**」；
> 而第五批 §八第 2 条的裁定正是**以这问为前提**才把语言侧决定往后推的。
>
> **一句话概括**：**先把那条漏答补探掉**（它决定下一步是库侧还是语言侧），
> 再把两个接口账收口——`format_int` 的零增量、以及模块状态领先于 CI 证据。
>
> 状态：**规划（2026-10-15）**，未开始实施。

## 一、为什么是这一批

1. **上一批的裁定前提没被满足**：第五批 §八第 2 条「`str` → `int` **先不定，等复探之后再说**」，
   连带写明「**绕不开 ⇒ 单独立项；绕得开 ⇒ 省下这个语言批次**」。**复探没问这一问**，
   所以「之后」还没到；
2. **补探很便宜、后果很大**：它决定下一个批次是**加一个语言转换**还是**用库写法绕过去**，
   两条路的成本差一个数量级；
3. **两个接口账要趁早收**：`format_int` 已经进了 `stdlib/` 与 registry，
   **越晚改越贵**（[20C](20c-official-xiao-library.md) §3.2.1 第 2 条：删接口是破坏性变更）。

## 二、并入的返工项（**先做**）

出处：2026-10-15 审核 `432e87a`（第五批）。**三条都不是红**，都属「判据/接口名不副实」那一类。

### 2.1 **F-1（中）：补探「大小写转换能否绕开 `str` → `int`」**

**事实**：第五批 §4.2 第 3 条问了两件事——

> `str` → `int`（码点）仍缺吗？**能否用不依赖它的写法表达**？

复探表只答了**前半**（「前端 `X02-TYPE-006`」），并给了一句**未经探测的断言**：
「最近前置是 `str` → `int` 码点转换」。

⇒ **裁定要的那个答案没拿到**，下一步仍然定不了。

**候选写法（本批要真跑验证的）**：不做码点运算，用**逐个比较**把字母映射出来，例如

```xiao
def lower_ascii(str text) -> str
    result = ""
    for c in text
        if c == "A"
            result = result + "a"
        if c == "B"
            result = result + "b"
        ...
        else
            result = result + c
    return result
```

**冻结**：**不许**在探针里用变量下标、临时 intrinsic 或把逻辑下沉 Rust；
**必须**真写、真跑、**双路径**、成表（口径见 §三）。

### 2.2 **F-2（中）：`text.format_int` 相对 `str(value)` 零增量**

**事实**：`stdlib/text.xiao` 里的实现是

```xiao
def format_int(int value) -> str
    result = ""
    for c in (value as str)
        result = result + c
    return result
```

——**把 `value as str` 拆成字符再拼回去**，语义上**等同于 `str(value)`**，没有增加任何东西；
而且是 **O(n²)** 的往返（每步 `result + c` 都要重新分配）。
数字格式化该有的填充/对齐/进制**一个都没做**（文档也老实写了「不提供」）。

**代价不在性能，在接口**：它已登记在 `stdlib/text.xiao` 与 registry；
按 [20C](20c-official-xiao-library.md) §3.2.1 第 2 条，**将来删接口是破坏性变更**，
要提升 `STDLIB_INTERFACE_VERSION`。

**这是规划侧的措辞洞**：第五批 §五 第 5 条只写了「**先给最小接口**」——
**「最小」不等于「没有增量」**。这句话本批要改掉（见 §五 第 4 条）。

**处置见 §五**（三选一，**由星崽定**）。

### 2.3 **F-3（中）：模块仍标 `verified`，而两个新接口没有 CI 记录**

**事实**：`docs/UseDocs/library/text.md` 与 registry 的首批条目都是 `status: verified`；
而 `format_int` / `is_ascii_upper` 是**第五批新增**的，**CI 最近一次（`38597139383`）时还不存在**。
页面的证据行把两者**分开写**（首批/第二批 → CI 运行号；第五批 → 本批 §四）——**这点是诚实的** ✓，
但 **`verified` 是模块级状态**，而 [20C-首批](20c-first-modules.md) §4.6 第 2 条写着：

> 双路径证据来自受控环境或 CI 的可复核运行记录；**本机单独运行不构成状态转换依据**

**并且先例就是 CI**：首次 `draft → verified` 正是**等到**维护回归 `38550284761` 才翻转的。

**冻结**：二选一，并在实施记录里写明——

1. **等 CI**：把第五批的这次提交推上去，CI 跑到两个新接口之后再在页面上引用该运行号；
   **在此之前**，页面或 registry 要有一句「**第五批接口的 CI 记录待补**」；
2. **按接口粒度登记**：把两个新接口的 `verified` 依据单独写明（受控环境记录），
   并**说明为什么它不构成「本机单独运行」**——**不许**默认继承模块级状态。

**不许**让模块级 `verified` 覆盖到没有 CI 记录的接口而**无一句说明**。

## 三、补探（**先做，成表**）

### 3.1 口径

**逐字沿用** [20C-第二批](20c-second-batch-probe.md) §3.2 的六条。

### 3.2 要回答的问题（**只有一问**）

> **不做 `str` → `int` 码点转换，能不能写出一个可用的 ASCII 大小写转换？**

「可用的」要落到可判定：**输入若干已知字符串，输出与真值逐字相等**，
且在 **VM 与 LLVM 原生两条路径**上一致。

### 3.3 什么时候算「绕得开」

**判据（写死，免得事后各说各话）**：候选写法**满足全部**三条才算绕得开——

1. **只用已接受的语言构造**：`for c in s` 迭代、`c == "x"` 比较、`and`/`or`、字符串拼接；
   **不许**变量下标、**不许**新 intrinsic、**不许**把逻辑下沉 Rust；
2. **双路径逐字一致**，且**等于真值**（至少覆盖：全大写、全小写、混合、非字母、空串）；
3. **规模可接受**：写出来是**库函数**而不是**上百行**的机械展开——
   这一条**由星崽拍板**（见 §八），因为「可接受」是判断题，不是测量题。

**若三条都过** ⇒ **库侧能做**（§四 甲）；**任一条不过** ⇒ **绕不开**（§四 乙）。

## 四、由补探结果二选一（**先汇报，再定**）

### 4.1 甲：**绕得开** ⇒ 库侧加一个真接口

把大小写转换写进 `stdlib/text.xiao`，**并明确它不做的部分**（例如不做 Unicode、
不做 locale、不做非 ASCII）。**接口要有真语义**（对照 F-2 的教训）。

### 4.2 乙：**绕不开** ⇒ 语言侧单独立项 `str` → `int`

按 [20C](20c-official-xiao-library.md) §3.1 第 4 条的登记口径写清三要素，
并开一个**独立的语言批次**；**本批只登记与立项，不实现**。

### 4.3 **不许**

1. **不许**拿本批的探针结果写成「已解封」而不给表；
2. **不许**在甲里顺手把「顺带做 Unicode」或「顺手做 `str` → `int`」塞进来；
3. **不许**用第五批那句未经探测的断言（「最近前置是 `str` → `int`」）当结论——
   **本批就是要证伪或证实它**。

## 五、接口收口

1. **F-1 的补探**按 §三 执行，结论先汇报；
2. **F-3** 按 §2.3 二选一处置；
3. `format_int` / `is_ascii_upper` 的 **UseDocs 与 registry 同笔**保持同步
   （[20C-首批](20c-first-modules.md) §4.2 第 1 条原样有效）；
4. **把「最小接口」的措辞补严**：在 [20C-首批](20c-first-modules.md) 或
   [20C](20c-official-xiao-library.md) 的规模纪律处加一句——
   **「最小接口」指范围的窄，不指「没有增量」；新接口必须相对现有语言构造提供至少一项真实语义**
   （或明确它是**唯一**的安全入口）。**这是 F-2 的根因，改措辞才防复发**；
5. **`format_int` 的处置**（三选一，**由星崽定**）：
   - **甲：撤掉**——趁接口面尚未冻结，删掉最干净；删的是**本批新增、未发布**的接口，
     不构成「删除已发布接口」；
   - **乙：给它真语义**——例如接受宽度做十进制填充/对齐（**要先冻结该语义**，
     并明确不做进制）；**签名一改，本批内改比发布后改便宜得多**；
   - **丙：保留但现在不改**——**必须**在 UseDocs 里写明「它与 `str(value)` 等价」，
     免得使用者以为它做了格式化。
