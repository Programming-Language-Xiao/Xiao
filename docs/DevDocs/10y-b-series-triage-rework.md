## 二、必须先冻结的 6 条

### 2.1 **Y1：变异验证必须是「原生变异 + 原生门控跑红」，并留下输出**

10X §2.1 的 X1 原文要求「改动一处使构造参数被忽略，确认至少位置参数与默认值两条用例变红，**输出进提交说明**，做完恢复」。这条要求**不变**，但要说清楚怎么做才作数：

**冻结**：

1. **变异必须落在原生降低层**（`dynamic/container.rs` 的表构造参数写入等处），**不得**只改 VM 或前端；
2. **必须由受控原生门控跑出红色**，即 [10D](10d-environment-gated-test-spec.md) §4 的环境 + 第 4.5 节的 `--skip` 命令，
   目标用例 `native_side_matches_the_vm_sides_on_every_case`（或等价的定向执行）；
3. **判红对象是差分用例本身**（`table-constructor-positional` / `-default` 等 CASES），
   不是另写一条 VM 侧测试——VM 侧测试**永远不可能**观察到原生 codegen 的变异（审核已实测：变异下
   `a2_constructor_baselines_are_sensitive_to_ignored_arguments` 仍为 `ok`）；
4. **提交说明里贴出红色输出**（至少含 `table-constructor-positional` 与 `table-constructor-default` 两行
   「VM（源码）」与「原生」不一致的实际文本），并写明变异点（文件与行）；
5. **做完恢复**，并用 `git diff --quiet HEAD -- <该文件>` 证明工作区干净；
6. **参考形态**：审核用 `container.rs:280` 的写入改 `zeroinitializer` 时，红的是
   `输出 "9\n" ≠ ""；错误身份 None ≠ Some("X06-RUNTIME-007")；退出码 0 ≠ 3` 加释放序列不一致。
   **红信号与 `"0\n"` 无关**——这正说明 10X 那两条 `assert_ne!(…, "0\n")` 是照着想象写的。

### 2.2 **Y1 附带：不得用互相蕴含的断言冒充验证**

**冻结**：

1. 同一用例内，新增断言**必须能独立失败**。像
   `assert_eq!(x, "9\n"); assert_ne!(x, "0\n");` 这种，后者由前者逻辑蕴含，**不算证据**；
2. `d19a_differential.rs:805-817` 的 `a2_constructor_baselines_are_sensitive_to_ignored_arguments`
   **删掉**（基线已由 CASES 的 `assert_baseline_matches_case` 覆盖），或用**改对了名字的**普通基线测试替代；
   无论哪种，都要在 10W/10X 的实施记录里写清「本条的变异验证结论以 §2.1 的红色输出为准」；
3. **本批起一律适用**：凡是记录里写「已验证 / 已实测 / 已确认」，就必须在同处给出**可复核的输出或运行号**，
   不能只写一句结论（X3 就是这么变成「声称完成」的）。
