# 17B. 资源与索引接入

> **17 阶段的第二批。** [17A](17a-archive-format-and-codec.md) 已把 `.xar` 的物理格式与
> 索引钉死（确定性容器、唯一索引、先验证再暴露）。本批做
> [规范](17-xar-archive.md) §「资源与诊断对象」的 **`17.5`–`17.8`**，
> 外加 17A 审核转来的一支负例补强。
>
> **一句话概括本批**：**让归档能装「非代码的东西」**——资源、调试符号、源码正文，
> 全部走内容寻址并由唯一索引映射回逻辑路径；**同时把 17A 漏掉的六类拒绝面补齐**。

## 二、必须先冻结的 9 条

### 2.1 **资源声明落在新增的 `[resources]` 顶层表**（已决策）

**已决策**（2026-10-04）：新增 `[resources]` 顶层表，与既有 `project`/`exports`/`language` 并列。

**冻结**：

- **必须**同步扩 `xiao-config` 的保留顶层表白名单——否则 `config.xiao` 里写 `[resources]`
  会按「未知顶层表」**直接报错**（05D 的严格语义）；
- 新表的**字段名**在实施第一步定下并写入本文档与 05D 的登记，**不得**只落在代码里；
- **不得**复用 `[exports]`——它的语义是「项目对外导出什么」，与「打包时携带什么」不是同一件事；
- **沿用** 05D 的诊断编号段与风格（`X05-CONFIG-*` + `message_id` + 结构化参数 + `SourceSpan`），
  **不新起编号段**、**不改既有编号的含义**。

### 2.2 **资源只来自显式声明，绝不自动扫描**

规范 `:47` 是**硬要求**，不是建议：

> 应用资源只收录 `config.xiao`（或将来冻结的打包参数）**显式声明**的路径，
> **不扫描并复制整个项目目录**；**密钥、环境变量当前值和未声明文件不得被自动打包**。

**冻结**：

- **不得**实现任何形式的目录遍历式收集；
- **不得**把 `XIAO_HOME`、`~/.xiao` 下的凭据（11A-E3D1 的 0600 凭据）、环境变量当前值
  写入归档——这与本仓既有的凭据边界（绝不进日志/诊断/`Debug`）**同一条判据**；
- 声明路径**必须**限定在项目根内，**拒绝**绝对路径与 `..` 穿越（用 17A 已有的逻辑路径校验口径）。

### 2.3 **资源以内容摘要为物理名，索引映射回逻辑路径**

规范 `:47`：『资源以**内容摘要为物理名称**，索引负责把它映射回**经过规范化的逻辑路径**』。

**冻结**：

- 物理名用 16A 的 `Digest256` + 既有分片规则（**复用，不新造**）；
- **逻辑路径必须规范化**：拒绝空段、`.`、`..`、绝对路径、平台相关反斜杠穿越
  —— 这正是 17A §2.6 已冻结的口径，本批**沿用同一实现**而非另写一份；
- **重复逻辑路径**是错误而非覆盖（见 §2.6）。

### 2.4 **`debug` 与 `source` 可独立选择**（已决策）

**已决策**（2026-10-04）：两个内容对象**各自独立可选**。

**冻结**：

- 索引**分别**引用二者，允许「只带 `debug` 不带 `source`」的组合
  （符号对库作者有用、源码有泄露风险，这是常见发布形态）；
- **标准发布包**（不带调试开关）**只含 `.xiaoc` 自带的紧凑源码位置映射**，
  **不含**完整局部变量表、扩展调试符号或源码正文（`17.7`）；
- **显式调试包不改变程序语义**（`17.7`）——调试对象是**附加信息**，
  不得影响入口解析、执行结果、错误身份或释放顺序。这条要有**差分测试**兜住。

### 2.5 **`config.xiao` 的解析不得执行任何东西**

规范 `:45`：『输入解析**不得执行配置或源码来猜测依赖**，必须复用统一前端和声明式配置解析器』。

**冻结**：复用 05D 的静态解析器；**不得**为资源收集引入任何求值路径。
这与 11A-E2B 的「激活文件不 `source`」是同一条安全判据。

### 2.6 **四类诊断要稳定，且覆盖打包期与运行期**

`17.8` 要求的四类：**缺失资源、重复逻辑路径、摘要不匹配、未声明资源访问**。

**冻结**：

- 四类各有**稳定错误码 + `message_id` + 结构化参数 + `SourceSpan`**（沿用既有诊断形态）；
- **前两类发生在打包期**（声明与文件系统对不上），**摘要不匹配**在两处都要有
  （打包时算的与索引写的不符 / 读取时重算不符），**未声明资源访问**是**运行期**语义
  （程序访问了没被收集进归档的资源）；
- **不得**把「未声明资源访问」在打包期**静默忽略**——规范 `:47` 的「不得被自动打包」
  与 `17.8` 的诊断要能对上。

### 2.7 **本批是库层，不接 CLI**

规范 `:47` 明写：「准确 CLI 参数在**第 18 阶段**冻结」。

**冻结**：

- **不做** `xiao build --xar` 之类的开关、不做打包命令的入参解析；
- 产出的是**库层 API** + 测试；端到端演示归 17C（入口与运行器）与 18（CLI 接入）；
- **但**API 要能让 18 直接包一层——开关语义（如「带 source」「只带 debug」）
  要能映射到本批的参数。

### 2.8 **承接 17A 的六类负例缺口**

17A 的 §2.6 把安全拒绝面写成**硬验收**（「规范 `:59` 列的**每一条**都要有负例测试」），
但实测只覆盖 7 类，**缺 6 类**：

| 规范 `:59` 要求 | 17A 现状 | 本批要做的 |
| --- | --- | --- |
| **重复索引** | `DuplicateIndex` 有实现**无断言** | 补断言 |
| **索引内逻辑路径**（空段 / `.` / `..`） | 有实现（`xiao-xar/src/lib.rs:585`/`:607`）**无断言** | 补断言 |
| **反斜杠穿越** | **无实现也无断言** | **补实现 + 断言** |
| **缺失索引** | 无断言 | 补断言（关系验收 2「恰好一个索引」） |
| **越界长度** | 无断言 | 补断言 |
| **未知必需版本** | 无断言 | 补断言 |

**冻结**：

- **动工前先逐类确认**是「补断言」还是「补实现」——**不得**把「有实现无断言」当成已完成
  （这正是 [12A](12a-stage-acceptance-audit.md) §2.3 总结的全仓最常见形态）；
- 「**反斜杠穿越**」已知**需要补实现**：§2.6 明文点名「平台相关反斜杠穿越」；
- 补的实现**必须复用** 17A 既有的路径校验函数，**不另写第二份**（单一来源）。

### 2.9 **不重开 17A 与 05D 的既有冻结面**

**冻结**：

- **不改** 17A 的容器格式、成员布局、`ArchiveIndex` 的字段 `1`–`12`；
- **不改** 05D 既有诊断编号的含义，**不改**既有表白名单条目的语义（只**增**）；
- **不重开** 14A 的 `.xiaoc` 格式与可选分区编号 `9`–`10`；
- **不改** 16A/16A-FIX 的内容寻址命名与索引 wire 编码。

## 七、最可能翻车的地方

1. **图省事扫描项目目录**（§2.2）——规范明文禁止，且会把密钥/环境变量扫进归档。
2. **凭据进了归档**（§2.2）——本仓的安全底线，且**归档是可分发的**，泄露面比日志大得多。
3. **逻辑路径不规范化或另写一份校验**（§2.3）——重复实现必然漂移。
4. **调试包改变了语义**（§2.4）——没有差分测试就发现不了。
5. **把 CLI 参数做了**（§2.7）——规范归 18，提前做会与 18 的设计撞车。
6. **新起诊断编号段**（§2.1）——05D 的编号是登记过的，新起会重复。
7. **把「有实现无断言」当已完成**（§2.8）——17A 的六类正是这么漏掉的。
8. **反斜杠穿越只补断言不补实现**（§2.8）——它当前**根本没有实现**。
9. **改了 05D 既有表条目的语义**（§2.9）——只允许**增**。
10. **忘了 `Cargo.lock` 同步**——`check:lock` 会红（16A 栽过一次）。

## 八、验收

1. **`[resources]` 可用**：`config.xiao` 写 `[resources]` 不再报「未知顶层表」，且有规格测试；
2. **只收显式声明**：无任何目录遍历式收集；未声明文件不出现在归档里；
3. **凭据不进归档**：用副作用的探针断言 `XIAO_HOME` 凭据与环境变量值**不在**归档字节中；
4. **逻辑路径规范化**：空段 / `.` / `..` / 绝对路径 / 反斜杠穿越均被拒绝，且有断言；
5. **内容寻址**：资源物理名为摘要、索引映射回逻辑路径；重复逻辑路径是**错误**；
6. **标准包只含紧凑映射**：不带调试开关时，归档**不含**符号、局部变量表与源码正文；
7. **调试对象不改变语义**：显式调试包与标准包的**执行结果、错误身份、释放顺序一致**（差分）；
8. **`debug`/`source` 可独立**：只带其一的组合有测试（§2.4）；
9. **四类诊断稳定**：缺失资源、重复逻辑路径、摘要不匹配、未声明资源访问各有错误码与用例；
10. **六类负例补齐**（§2.8）：重复索引、索引内逻辑路径、**反斜杠穿越（含实现）**、
    缺失索引、越界长度、未知必需版本——每类都有可证伪的用例；
11. **不重开**：17A 与 05D 的既有测试**一条未改**且全绿；
12. **不回归**：`cargo test --workspace` 全绿、`cargo clippy --workspace --all-targets -- -D warnings` 绿；
13. **门禁全绿**：`bun run check` 退出码 0（含 `check:lock`，两个 lock 文件都已提交）。
