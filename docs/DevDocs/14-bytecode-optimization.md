# 14. 字节码优化与 `.xiaoc` 产物

> 本阶段在第 09 阶段字节码虚拟机之上增加可验证的优化字节码和正式文件格式。它不改变字节码运行语义，也不把临时缓存和可分发产物混成同一种文件。

## Agent 交接上下文

### 接手前提

- 先阅读 [09. 字节码运行模式](09-bytecode-runtime.md)、[13. 优化契约与统一管线](13-optimization-contract.md) 和 [12. 测试与开发里程碑](12-tests-and-milestones.md) 的 O0/O1 条目。
- 虚拟机已有未优化字节码执行入口和源码诊断接口；第 13 阶段提供 `-O0` 至 `-O3` 的规范化配置及 IR 验证结果。
- `.xiaoc` 已确定为单模块文件；一个项目或归档通过多个 `.xiaoc` 组合，不得把跨模块依赖偷偷塞进单个模块文件。

### 本阶段交付与不负责事项

- 交付：单模块 `.xiaoc` 格式、编解码器、字节码验证器、字节码级优化 Pass、源码映射和直接加载接口。
- 不负责：跨模块打包、第三方依赖闭包、Protobuf 索引和 `.xar` 归档；分别由第 16、17 阶段接手。
- 任何运行时自适应指令、JIT 或临时 quickening 都必须写入独立缓存，不得修改按内容寻址的公开 `.xiaoc`。

### 交接检查

接手代理必须能从同一模块的未优化字节码生成优化字节码，使用格式验证器拒绝损坏输入，并提供源码位置、模块身份、优化指纹和版本信息；测试夹具不得依赖完整项目或网络依赖。

## 一级工程目标：定义 `.xiaoc` 文件边界

### 产物定位

Xiao 的可序列化字节码文件使用 `.xiaoc` 扩展名。它承接旧版 `.pyo`“优化后字节码”的定位，但不是 Python 文件格式的兼容实现。`.xiaoc` 应当是经过统一前端、优化器和字节码验证器处理后的可加载产物；未经验证的临时字节数组不能冒充 `.xiaoc`。

开发目录中的短生命周期缓存可以使用内部名称或私有目录，不得因为缓存命中就改变 `.xiaoc` 的公开格式。每个 `.xiaoc` 固定表示一个可验证模块；项目依赖图和归档成员关系由外部索引描述。

### 文件头与载荷

`.xiaoc` 首版采用 Xiao 自有的确定性分段二进制格式，不把整个文件编码为 Protobuf，也不直接转储任一宿主语言的结构体或内存镜像。这样既能在加载前进行严格边界检查，也能按分区读取函数、常量和源码映射。文件格式保留“固定文件头 + 分区目录 + 可跳过的可选分区”这一架构：这里的“固定”指一个格式主版本内的字段职责、边界规则和解析顺序是稳定契约，不指整个文件头或目录项必须占用某个固定字节数。文件内部不压缩，压缩只由外层 `.xar` 负责。

文件头必须表达以下语义，但字段宽度、精确顺序和扩展编码要等第 09 阶段指令集与验证器稳定后，在任务 14.1 中冻结；本表不是 48 字节布局承诺：

| 字段 | 编码 | 语义 |
| --- | --- | --- |
| `magic` | 固定字节序列 | 固定为 ASCII `XIAOC`、`CR`、`LF`、`0x1A`，即十六进制 `58 49 41 4F 43 0D 0A 1A` |
| `format_major` / `format_minor` | 版本字段 | 主版本表示不兼容变更，次版本表示兼容扩展；具体编码待冻结 |
| `header_size` | 长度字段 | 当前文件头（含允许的头部扩展）的边界 |
| `flags` | 文件标志 | 未定义位必须为零；必需/可选能力不能靠猜测 |
| `section_count` | 分区数量 | 加载器必须先校验数量上限 |
| `directory_offset` / `directory_size` | 目录边界 | 指向分区目录的起点和总长度，或采用等价的可验证边界表达 |
| `file_size` | 文件边界 | 规范文件总字节数，必须与实际输入一致 |
| `required_features` | 功能位集合 | 加载器必须支持的功能位 |
| `runtime_abi_min` / `runtime_abi_max` | Runtime ABI 区间 | 可运行 Runtime ABI 的闭区间 |

文件头之后，或由头部边界字段指向的位置，是分区目录。目录项不固定为 40 字节；目录头或头部必须声明目录项长度/版本，或者使用等价的长度前缀，使加载器能够跳过未来扩展。每个目录项至少要表达分区种类、必需/可选标志、文件偏移、存储长度、逻辑长度、对齐要求和完整性信息；这些字段可以采用定宽或长度前缀编码，但不能依赖宿主结构体布局。首版不允许 `.xiaoc` 内部压缩，因此 `stored_size` 必须等于 `logical_size`。目录按 `offset` 递增排列，分区不得重叠、越过 `file_size` 或指向文件头/目录内部；具体分区编号、标志位、目录项编码和扩展规则在第 09 阶段指令集稳定后由任务 14.1 冻结。

首版必需分区至少包括模块元数据、UTF-8 字符串表、类型/签名表、常量池、导入表、函数表、指令流和紧凑源码位置映射。模块元数据记录 Xiao 语言/IR/虚拟机版本、模块身份、规范源码摘要、优化配置指纹、依赖锁摘要，以及平台无关标记或明确的目标平台/架构约束。完整局部变量名、额外调试符号和源码正文使用可选分区，默认不生成。

不含 FFI、目标 CPU 指令或平台资源的模块必须生成平台无关 `.xiaoc`；使用任一平台能力时必须改为明确的目标三元组/架构和所需功能集合。加载器不能用当前主机信息默默填补缺失约束。

分区正文必须采用该分区版本明确规定的定宽字段或长度前缀编码；禁止依赖宿主指针宽度、结构体填充、系统字节序或未排序哈希表。重复构建时，字符串、常量、函数和元数据的规范排序规则必须稳定。未知必需分区或未知 `required_features` 位直接拒绝加载；未知可选分区可以按长度安全跳过。

头部和分区不能包含时间戳、绝对路径、临时目录或机器随机值。主版本不兼容时拒绝加载；同一主版本的较新次版本只有在全部必需功能和必需分区均受支持时才能加载。源文件可用时可以按明确规则重建，不可用时必须报告版本错误，不能猜测兼容。

## 一级工程目标：实现字节码级优化

### 安全变换范围

在类型化 IR 降低为字节码之后，可以实现不改变语义的字节码级变换：

- 窥孔指令合并、冗余移动删除和常量池去重。
- 无副作用基本块的跳转简化、不可达块删除和跳转目标压缩。
- 局部栈槽/临时槽布局优化及指令编码压缩。
- 在验证器证明安全时使用更专用的指令，保留动态值检查和错误路径。

优化不得删除随机、输入输出、模块加载、引用计数、`drop`、错误构造或数据竞争检查等可观察操作，也不得把运行时自适应 quickening 直接写回不可变 `.xiaoc`。若未来加入 JIT，JIT 产物必须使用另一个可丢弃的运行缓存命名空间。

### 加载与兼容

虚拟机加载 `.xiaoc` 时必须先验证魔数、版本、长度、指令边界、跳转目标、栈高度、释放计划、依赖/运行时 ABI 和完整性校验，再建立执行实例。版本或目标不兼容时应给出稳定诊断，并按照待定的策略重新从源码生成、寻找兼容产物或拒绝运行。

解释模式默认在首次运行时生成、验证并缓存 `-O0` 的 `.xiaoc`，后续运行在缓存键和完整性验证都通过时复用。普通源码模块进入第 16 阶段定义的全局内容寻址缓存，不写到源码旁；依赖可变会话状态的 REPL 片段进入会话缓存，只有形成完整独立模块后才能提升到全局缓存。直接运行源码与直接运行 `.xiaoc` 必须走相同的类型、生命周期和运行时契约。

每个 `.xiaoc` 默认携带紧凑源码位置映射，以保证发布归档仍能输出模块、行号和列号。它不默认携带源码正文、完整局部变量表或扩展调试符号；后者由显式调试产物选项生成，且必须进入格式标志和内容摘要。

## 二级实现任务

### 格式与编解码

1. [14.1] 在第 09 阶段指令集与验证器稳定后，冻结固定语义文件头、目录边界、分区编号、必需/可选标志、目录项编码、分区正文编码与规范排序规则；不得把文件头或目录项的总字节数预先限定为 48/40。
2. [14.2] 实现编码器、解码器、长度/边界检查和格式模糊测试。
3. [14.3] 为函数、常量池、入口、调试映射和依赖摘要建立稳定表结构。
4. [14.4] 提供格式检查工具；检查失败不能执行任何指令。

### 字节码优化器

1. [14.5] 接入第 13 阶段的共享优化配置和效果摘要。
2. [14.6] 逐个实现窥孔、跳转、常量池和槽布局 Pass，并为每个 Pass 建立前后快照。
3. [14.7] 在优化后重新验证栈高度、跳转、释放计划、源码映射和错误路径。
4. [14.8] 对优化失败保留未优化参考结果，具体回退/报错策略按已冻结 CLI 契约执行。

### 运行时与调试

1. [14.9] 让虚拟机只接受通过验证的 `.xiaoc`。
2. [14.10] 验证源码、未优化字节码和优化字节码的输出、错误、随机序列和 `drop` 记录一致。
3. [14.11] 确认调试构建能从优化指令回溯到源码位置。
4. [14.12] 将运行时 quickening/JIT 与不可变 `.xiaoc` 分离。

## 验收标准

### 文件验收

- 合法 `.xiaoc` 可被目标虚拟机读取并执行，损坏、截断、未知版本、错误目标和错误 ABI 都有稳定诊断。
- 相同规范输入可产生可比较的稳定序列化结果；未规范化元数据不会污染产物。
- `.xiaoc` 的来源模块、优化指纹和依赖摘要可被检查工具读取。
- 加载器拒绝错误魔数、非零保留字段、未知必需功能、越界或重叠分区，以及不满足 Runtime ABI 区间的文件。

### 语义与性能验收

- 优化字节码与未优化字节码在双模式差分测试中保持语义一致。
- 优化只影响执行速度、启动时间、字节码大小或解释器内存，不改变语言可观察结果。
- 未安装 LLVM 时仍可生成和运行 `.xiaoc`；运行时自适应缓存不覆盖原文件。

## 待定决策

4. REPL 会话缓存的回收时机，以及缓存只读、损坏或失配后的详细重编译诊断。
