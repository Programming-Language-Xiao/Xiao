# 14. 字节码优化与 `.xiaoc` 产物

> 本阶段在第 09 阶段字节码虚拟机之上增加可验证的优化字节码和正式文件格式。它不改变字节码运行语义，也不把临时缓存和可分发产物混成同一种文件。

## Agent 交接上下文

### 接手前提

- 先阅读 [09. 字节码运行模式](09-bytecode-runtime.md)、[13. 优化契约与统一管线](13-optimization-contract.md) 和 [12. 测试与开发里程碑](12-tests-and-milestones.md) 的 O0/O1 条目。
- 虚拟机已有未优化字节码执行入口和源码诊断接口；第 13 阶段提供 `-O0` 至 `-O3` 的规范化配置及 IR 验证结果。
- `.xiaoc` 已确定为单模块文件；一个项目或归档通过多个 `.xiaoc` 组合，不得把跨模块依赖偷偷塞进单个模块文件。

### 本阶段交付与不负责事项

- 交付：单模块 `.xiaoc` 格式、编解码器、字节码验证器、字节码级优化 Pass、源码映射和直接加载接口。
- 不负责：跨模块打包、第三方依赖闭包、Protobuf 索引和 `.xar` 归档；分别由第 16、17 阶段接手。
- 任何运行时自适应指令、JIT 或临时 quickening 都必须写入独立缓存，不得修改按内容寻址的公开 `.xiaoc`。

### 交接检查

接手代理必须能从同一模块的未优化字节码生成优化字节码，使用格式验证器拒绝损坏输入，并提供源码位置、模块身份、优化指纹和版本信息；测试夹具不得依赖完整项目或网络依赖。

## 一级工程目标：定义 `.xiaoc` 文件边界

### 产物定位

Xiao 的可序列化字节码文件使用 `.xiaoc` 扩展名。它承接旧版 `.pyo`“优化后字节码”的定位，但不是 Python 文件格式的兼容实现。`.xiaoc` 应当是经过统一前端、优化器和字节码验证器处理后的可加载产物；未经验证的临时字节数组不能冒充 `.xiaoc`。

开发目录中的短生命周期缓存可以使用内部名称或私有目录，不得因为缓存命中就改变 `.xiaoc` 的公开格式。每个 `.xiaoc` 固定表示一个可验证模块；项目依赖图和归档成员关系由外部索引描述。

### 文件头与载荷

下列字段是格式设计的候选最小集合，具体编码、顺序和是否必须存在尚待确认：

- 魔数、格式版本和字节序/编码标识。
- Xiao 语言版本、IR 版本、虚拟机版本和 Runtime ABI 版本。
- 目标平台/架构或“平台无关”标记。
- 优化配置指纹、模块身份、模块图摘要和依赖锁图摘要。
- 常量池、函数表、指令流、入口描述和资源引用。
- 源码位置映射、调试信息级别和可选的符号区。
- 载荷长度、完整性校验以及未来扩展字段。

头部不能包含会让同一内容产生不同摘要的未规范化时间戳、绝对路径或机器随机值。格式升级必须能在读取前通过版本字段拒绝或转入明确的迁移路径。

## 一级工程目标：实现字节码级优化

### 安全变换范围

在类型化 IR 降低为字节码之后，可以实现不改变语义的字节码级变换：

- 窥孔指令合并、冗余移动删除和常量池去重。
- 无副作用基本块的跳转简化、不可达块删除和跳转目标压缩。
- 局部栈槽/临时槽布局优化及指令编码压缩。
- 在验证器证明安全时使用更专用的指令，保留动态值检查和错误路径。

优化不得删除随机、输入输出、模块加载、引用计数、`drop`、错误构造或数据竞争检查等可观察操作，也不得把运行时自适应 quickening 直接写回不可变 `.xiaoc`。若未来加入 JIT，JIT 产物必须使用另一个可丢弃的运行缓存命名空间。

### 加载与兼容

虚拟机加载 `.xiaoc` 时必须先验证魔数、版本、长度、指令边界、跳转目标、栈高度、释放计划、依赖/运行时 ABI 和完整性校验，再建立执行实例。版本或目标不兼容时应给出稳定诊断，并按照待定的策略重新从源码生成、寻找兼容产物或拒绝运行。

解释模式可以在首次运行时生成 `.xiaoc` 并复用，但是否默认落盘、缓存放置位置和用户可见命令由第 18 阶段确定。直接运行源码与直接运行 `.xiaoc` 必须走相同的类型、生命周期和运行时契约。

## 二级实现任务

### 格式与编解码

1. [14.1] 冻结规范序列化规则、魔数、版本和必需字段。
2. [14.2] 实现编码器、解码器、长度/边界检查和格式模糊测试。
3. [14.3] 为函数、常量池、入口、调试映射和依赖摘要建立稳定表结构。
4. [14.4] 提供格式检查工具；检查失败不能执行任何指令。

### 字节码优化器

1. [14.5] 接入第 13 阶段的共享优化配置和效果摘要。
2. [14.6] 逐个实现窥孔、跳转、常量池和槽布局 Pass，并为每个 Pass 建立前后快照。
3. [14.7] 在优化后重新验证栈高度、跳转、释放计划、源码映射和错误路径。
4. [14.8] 对优化失败保留未优化参考结果，具体回退/报错策略按已冻结 CLI 契约执行。

### 运行时与调试

1. [14.9] 让虚拟机只接受通过验证的 `.xiaoc`。
2. [14.10] 验证源码、未优化字节码和优化字节码的输出、错误、随机序列和 `drop` 记录一致。
3. [14.11] 确认调试构建能从优化指令回溯到源码位置。
4. [14.12] 将运行时 quickening/JIT 与不可变 `.xiaoc` 分离。

## 验收标准

### 文件验收

- 合法 `.xiaoc` 可被目标虚拟机读取并执行，损坏、截断、未知版本、错误目标和错误 ABI 都有稳定诊断。
- 相同规范输入可产生可比较的稳定序列化结果；未规范化元数据不会污染产物。
- `.xiaoc` 的来源模块、优化指纹和依赖摘要可被检查工具读取。

### 语义与性能验收

- 优化字节码与未优化字节码在双模式差分测试中保持语义一致。
- 优化只影响执行速度、启动时间、字节码大小或解释器内存，不改变语言可观察结果。
- 未安装 LLVM 时仍可生成和运行 `.xiaoc`；运行时自适应缓存不覆盖原文件。
