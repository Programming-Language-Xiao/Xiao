## 04-A：函数语法与 AST

### 04-A.1 定义头与缩进体

函数关键字固定为 `def`，函数头不需要冒号，函数体只能由四空格缩进（或词法层等价的 Tab 展开）界定：

```xiao
def add(int left, int right = 1) -> int
    return left + right
```

解析器生成 `Statement::Function`，保存名称、参数、可选返回类型、递归语句体、文档注释和源码区间。
空体、头部尾随内容、缺少换行或缺少缩进体必须恢复并产生 `X04-PARSE-*` 诊断。

### 04-A.2 参数和调用参数

参数节点保留以下种类：

- 普通位置/关键字参数；
- `/` 之前的位置专用参数；
- `*args` 可变位置参数；
- 裸 `*` 之后的关键字专用参数；
- `**kwargs` 可变关键字参数；
- 默认值表达式和可选标量/`none` 注解。

`/` 和 `*` 必须作为独立的参数分隔标记，参数之间必须使用逗号；重复名称、默认参数顺序错误、
多个可变参数和 `**kwargs` 后继续声明参数均在解析阶段拒绝。反引号名称保留原始形式，规范化键由类型层统一。

调用参数节点区分位置、关键字、`*` 展开和 `**` 展开。解析器只记录形状，不读取容器、不展开参数，
也不判断参数数量。

### 04-A.3 控制流节点

解析器把缩进块递归转换为 `If`、`For`、`While`、`Return`、`Break`、`Continue` 节点：

- `if` 节点保存主条件、零个或多个 `elif` 分支和可选 `else` 体；
- `for name in expression` 保存绑定名称、可迭代表达式和循环体；
- `while expression` 保存条件和循环体；
- `return` 可以没有表达式；
- `break`/`continue` 不接受尾随表达式。

嵌套块必须消费自己的 `Dedent`，不能吞掉外层 `elif`/`else` 或后续顶层语句。AST 的所有节点继续使用
原始 UTF-8 字节区间，文档注释挂接规则与前序阶段一致。

## 04-B：函数签名、参数匹配与类型推断

### 04-B.1 签名预登记和作用域

类型检查开始时先登记当前程序的顶层函数占位签名，再检查函数体。因此递归和同一文件中的前向调用不依赖
源码顺序。签名包含规范化名称、参数种类、参数类型、默认值标志、返回类型和定义区间。

检查函数体时建立独立参数作用域；函数参数可以遮蔽外层普通名称，但不能破坏外层函数绑定。函数体检查完成后
先退出参数作用域，再回写已统一的函数签名。嵌套函数仍只作为当前阶段的静态记录，不生成闭包对象。

### 04-B.2 参数匹配规则

类型检查器按调用源码顺序执行以下静态约束：

1. 位置参数不能出现在关键字参数之后；
2. 位置专用参数不能通过关键字传入；
3. 普通参数不能重复传入；
4. 未知关键字只有在存在 `**kwargs` 时允许；
5. 普通位置实参统一到 `*args` 的元素类型，而不是数组外壳类型；
6. `*` 只能展开已知可迭代容器，`**` 只能展开字典表/字典列或动态值；
7. 没有默认值且不是可变参数的参数必须被填充。

默认值在定义环境中检查并与参数类型统一。调用结果类型是签名的返回类型；错误调用返回动态占位，继续让检查器
完成后续诊断，而不是中止整份程序。

### 04-B.3 推断与动态边界

无注解参数先使用 HM 类型变量。函数体运算、返回语句、赋值和后续调用共同提供约束；整份程序检查完成后才
报告仍未解析的参数或返回变量（`X04-TYPE-004`）。无法证明的动态表达式不会被静默当成任意静态类型，
而是登记后续 Runtime 要消费的 `RuntimeCheckKind`。

条件只接受 `bool`，不沿用 Python 的整数/字符串真值转换。已知数组、元组、集合、字典表和字典列可以作为
`for in` 的静态可迭代对象；动态边界登记 `Iterable` 检查。`bool` 与整数的特殊加减规则由 02 阶段数值模块
负责，本阶段只消费其结果类型。

## 04-C：条件、循环、返回与循环控制

### 04-C.1 条件和循环

`if`、`elif`、`while` 的条件必须是 `bool`；静态非 `bool` 产生 `X04-TYPE-005`，动态条件留下
`BooleanCondition` 运行时检查。`for` 的右值必须是已知可迭代容器或动态值；其他类型产生
`X04-TYPE-006`。集合与字典表的遍历顺序不在本阶段承诺，字典列的固定顺序由后续 Runtime 执行。

### 04-C.2 返回值和隐式 `none`

`return value` 必须位于函数体内，并与函数声明/推断返回类型统一；同一函数的所有返回路径必须得到同一类型。
函数没有显式返回值时，收尾阶段把返回类型统一为 `none`。函数外的 `return` 或类型冲突产生
`X04-TYPE-003`，但检查器仍继续收集其余诊断。

### 04-C.3 `break` 与 `continue`

检查器维护循环深度，仅在 `for` 或 `while` 体内允许 `break`/`continue`；函数边界会重置循环深度，
避免嵌套函数错误地控制外层循环。循环控制离开边由 `X04-TYPE-007` 标记，供后续生命周期和 IR 阶段消费。

本阶段不插入释放动作，也不决定异常、`finally` 或闭包捕获后的控制流；这些行为必须由第 06/07/08 阶段
在同一控制流模型上实现。

## 04-D：入口、诊断、测试与文档

### 04-D.1 入口元数据

没有 `[main]` 时，程序的顶层语句记录为脚本模式；出现一个独立 `[main]` 表头时记录为工程模式。重复或
结构非法的表头产生 `X04-PARSE-006`。本阶段只登记 `EntryMode`，不生成真正的启动函数，也不改变函数调用语义；
初始化顺序和跨文件入口留给第 05/08/09/10 阶段。

### 04-D.2 诊断与国际化边界

解析和类型诊断必须同时具备：稳定 `code`、稳定 `message_id`、结构化参数、严重级别和 `SourceSpan`。
中文文本只是当前预览译文，不能被测试、UseDocs 或后端当作协议。国际化阶段可以替换译文，但不得改变
编号、参数键或源码位置。动态检查标记只描述后续 Runtime 的责任，不等于运行时错误已经发生。

本阶段的诊断编号：
