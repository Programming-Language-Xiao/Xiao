# 04. 函数与控制流

> 本阶段在值系统之上加入可复用行为、流程控制和程序入口。

## 一级工程目标：实现 `def` 函数

### 函数定义

函数关键字统一为 `def`，函数体使用缩进：

```xiao
def add(a, b)
    return a + b
```

参数默认不写类型，由函数体和调用点推断。递归函数、跨模块函数和导出函数必须在编译结束前得到稳定参数/返回值签名；无法推断时要求补充类型信息。

### 调用与返回

- 位置参数是首版必需能力。
- 返回值通过 `return` 产生。
- 没有显式返回值的函数使用统一的空值类型，空值名称待定。
- 参数传递、返回和闭包捕获都必须交给第 06 阶段的逃逸分析。

## 一级工程目标：实现控制流

### 条件分支

支持 `if`、`elif`、`else`。条件必须是 `bool`，不把整数、字符串或空容器自动当作布尔值。

### 循环

- `for value in collection` 遍历数组、元组、字典表和字典列。
- 字典表的遍历顺序不保证；字典列按照其固定顺序遍历。
- `while` 重复执行条件块。
- `break` 和 `continue` 只作用于最近的循环。

### 赋值与运算

支持以下复合赋值：

```text
+=  -=  *=  /=  //=  %=  **=
```

禁止 `i++` 和 `i--`。除法、整除、模和幂运算的类型与溢出规则由类型系统统一检查。

## 一级工程目标：定义入口规则

### 脚本模式

没有 `[main]` 时，顶层可执行语句自动组成入口，允许直接运行：

```xiao
print("hello")
```

### 工程模式

出现 `[main]` 后，入口由该表显式声明；其他顶层语句降级为模块初始化钩子。初始化顺序和多模块依赖顺序在第 05 阶段确定。

## 二级实现任务

### 函数编译

1. 建立局部作用域和参数作用域。
2. 推断参数、返回值和闭包捕获类型。
3. 生成统一的函数调用 IR。
4. 为递归和前向引用建立符号占位。

### 控制流编译

1. 把缩进块转换为显式基本块。
2. 验证 `break`、`continue` 和 `return` 的合法位置。
3. 为每个可能离开作用域的边插入内存释放计划。
4. 保证字节码和 LLVM 后端的分支语义一致。

## 验收标准

### 函数验收

- 相同函数在 `xiao run` 和 `xiao build` 中参数、返回值和错误行为一致。
- 未声明类型的参数不会被无条件推成动态值。
- 递归推断失败能给出具体的签名诊断。

### 控制流验收

- 缩进层级唯一决定代码块范围。
- 循环和函数退出时资源释放顺序可追踪。
- 字典表与字典列的遍历顺序符合各自定义。
