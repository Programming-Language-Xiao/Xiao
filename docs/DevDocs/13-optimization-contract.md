# 13. 优化契约与统一管线

> 本阶段是字节码优化、原生优化和产物缓存的共同前置。它建立“可以怎样变换程序”的边界，但不改变 Xiao 的语言语义，也不要求最小字节码或 LLVM 闭环等待优化完成。

## Agent 交接上下文

### 接手前提

- 必须先阅读 [00. 决策基线](00-decisions.md)、[08. 前端与统一中间表示](08-frontend-pipeline.md) 和 [12. 测试与开发里程碑](12-tests-and-milestones.md)。
- 第 08 阶段已经能产出带源码位置、类型、控制流和生命周期信息的类型化 IR；第 09、10 阶段的未优化后端接口可以独立运行。
- `.xiaoc`、`.xar`、SHA-256、Protobuf 和 `-O0` 至 `-O3` 的方向已经确认；所有模式的内建默认级别为 `-O0`。具体 Pass 清单、配置覆盖和缓存失配边界仍以本阶段冻结结果为准。

### 本阶段交付与不负责事项

- 交付：规范化优化配置、Pass 管理器接口、效果/所有权摘要、IR 验证器、优化指纹和差分测试基线。
- 不负责：具体 `.xiaoc` 文件编码、LLVM 具体 Pass、Protobuf 索引存储、`.xar` 归档和 TypeScript CLI；这些由第 14 至 18 阶段接手。
- 接手代理不得把某个临时 `-O` 级别、文件头字段或缓存目录直接写成语言规范；所有未确认值必须先回写“待定决策”。

### 交接检查

完成本阶段时，下一位代理应能仅凭本文件、类型化 IR 接口和测试夹具，复现一份未优化 IR、一份优化 IR、两者的配置指纹及验证报告；不得要求读取未提交的本地状态或依赖某个平台的隐式行为。

## 一级工程目标：定义优化边界

### 优化输入与输出

优化器只接收第 08 阶段生成的类型化 Xiao IR，或接收已经通过验证的字节码级中间表示；它不能重新解析源码、重新推断类型或自行决定生命周期语义。推荐的总流水线如下：

```text
源码
  -> 统一前端
  -> 类型化 IR
  -> 共享优化管线（可选优化级别）
      ├─ 字节码降低 -> 字节码级优化 -> .xiaoc
      └─ LLVM 降低   -> LLVM 优化/链接 -> 原生产物
```

“解释模式优化”在本阶段定义为：在交给虚拟机前生成或读取经过验证的字节码，并按显式级别运行相应 Pass；它不自动等同于运行时 JIT、动态重写指令或 Profile-Guided Optimization（PGO）。未显式选择级别时采用 `-O0`，仍执行生成、规范化和验证，但不运行可选语义优化 Pass。是否把这些自适应能力纳入后续版本，列入待定决策。

优化器的输出至少包括变换后的 IR 或字节码、可追溯的源码位置映射、优化配置指纹和验证结果。任何一个优化步骤失败，都不能产出未验证的可执行产物；失败后的回退到上一份有效产物还是直接报错，需在 CLI 阶段冻结。

### 语义保持约束

优化只能改变执行成本、产物体积、启动时间或编译时间，不能改变可观察语义。至少必须保持：

- 固定宽度数值的溢出错误，不得变成目标平台的静默回绕。
- `bool +/- 整数` 的奇偶翻转规则及结果类型。
- 有副作用表达式的求值顺序、输入输出、模块初始化和延迟加载行为。
- 资源所有权、逃逸提升、引用计数、`Weak` 和 `drop` 的确定性释放顺序。
- 随机选择的抽取顺序、放回/无放回模式和注入测试随机源后的结果。
- 动态值检查、数据竞争诊断、错误类别、退出码和必要的源码位置。
- 字典表无序、字典列有序以及集合不可索引等容器约束。

编译器必须为每个变换声明其效果、所有权和控制流假设；不能因为某个目标平台的 LLVM 或虚拟机“通常如此”就省略证明。常量折叠若遇到语言规定的溢出或其他错误，必须遵守统一的错误契约，具体是提前报错还是保留到运行时由语言错误模型决定。

## 一级工程目标：建立可复现的优化管线

### 优化配置与指纹

优化配置需要形成规范化对象，至少能区分：

- 优化级别及各级别启用的 Pass 集合。
- 调试信息、源码映射和诊断保留策略。
- 调试激活位、独立诊断组件版本和诊断事件保留策略。
- 目标平台、架构、运行时 ABI 和工具链版本。
- 当前项目模块图、依赖锁定图和相关 `config.xiao` 静态配置。
- 是否允许目标 CPU 特化、链接时优化或实验性 Pass。

上述字段应参与构建/字节码缓存指纹，避免用一个项目或平台的产物替代另一个条件下的产物。相同输入、相同工具链和相同优化配置应产生可比较的稳定结果；时间戳、临时路径和机器随机标识不能未经规范化写入可寻址产物。

首组优化级别名称已采用 `-O0`、`-O1`、`-O2`、`-O3`。`xiao run`、REPL、普通 `xiao build` 和 `xiao build -xar` 的内建默认值统一为 `-O0`；缓存命中、规范化序列化、格式验证和安全检查不属于可关闭的优化。命令行优先级、配置表名称和 `-Os`/`-Oz` 等扩展级别尚未冻结，不能在实现中擅自增加或改变这些接口。

### 调试与诊断

优化前后的 IR、字节码和原生产物都要能追溯到源码位置。被合并、删除或内联的代码需要保留足以生成栈回溯和错误诊断的映射；发布模式是否允许剥离完整源码和变量信息，交由第 14、15 阶段分别确认。

每个 Pass 应能单独启用、禁用和记录摘要。诊断报告至少说明：输入指纹、Pass 顺序、改变的函数/模块数量、跳过原因、验证结果和产物指纹。报告格式可以是人类可读文本或机器可读记录，但不能把调试日志混入 `.xiaoc` 的规范字节。

## 二级实现任务

### Pass 管理器与验证器

1. [13.1] 定义共享 Pass 接口、输入输出版本和失败边界。
2. [13.2] 为 IR 建立控制流、类型、所有权、效果和源码映射验证器。
3. [13.3] 建立 `O0`（不做语义变换的基线）和 `O1`/`O2`/`O3` 的配置占位，未实现的 Pass 不得伪装为已启用。
4. [13.4] 让每个 Pass 可独立快照、回滚到上一个有效 IR，并输出稳定诊断。

### 语义与成本模型

1. [13.5] 为纯表达式、可能溢出的运算、动态值、容器访问、随机源、输入输出和资源释放标记可重排边界。
2. [13.6] 建立别名、逃逸和生命周期信息的只读接口，禁止优化器伪造所有权。
3. [13.7] 定义代码尺寸、执行成本、编译时间和调试可见性的可比较指标。
4. [13.8] 为优化收益不足、目标不支持或证明失败的情况定义跳过策略。

### 回归与可复现性

1. [13.9] 对每个 Pass 保存 IR 前后快照及验证结果。
2. [13.10] 使用同一源码分别执行未优化和优化字节码、LLVM 原生结果，比较输出、错误、退出码和 `drop` 记录。
3. [13.11] 在固定随机源、动态值和溢出边界下执行差分测试。
4. [13.12] 清除时间戳、临时路径和未定义排序造成的非确定差异，并记录仍不可避免的目标差异。

## 验收标准

### 管线验收

- 字节码和 LLVM 后端可共享同一套已验证的 IR 优化接口。
- 优化关闭时可以得到稳定的未优化参考产物；优化开启不会成为 B0/N0 最小闭环的前置条件。
- 任一 Pass 验证失败都不会把未验证结果交给虚拟机或链接器。
- 同一输入和配置的优化指纹稳定，改变源码、依赖图、目标或工具链会导致明确的缓存失配。

### 语义验收

- 优化前后所有已冻结语言规则保持一致，尤其是溢出、布尔加减、随机选择、容器顺序、动态检查和释放顺序。
- 错误类别和必要的源码位置仍可追溯；优化不会通过删除诊断来伪造成功。
- 优化报告可以说明启用的 Pass、跳过原因和验证状态。

## 待定决策

1. 命令行与 `config.xiao` 的优先级、配置表名称，以及 `-Os`/`-Oz` 等扩展级别是否加入；无配置时统一 `-O0` 已经确定。
2. 是否在后续版本支持 JIT、PGO、跨模块优化、LTO、向量化和目标 CPU 特化。
3. 常量错误的发生时机、优化后栈位置和变量可见性的精确规则。
4. Pass 失败时回退上一份产物还是终止命令，以及优化报告的稳定格式。
