## 二、必须先冻结的 5 条

### 2.1 Git 探测方式（**已定：调 `git` 命令**）

```text
git status --porcelain=v2 --branch
  # branch.oid <sha>
  # branch.head main
  # branch.ab +2 -1
```

一条命令同时拿到分支与领先/落后。

**⚠️ 要一并冻结"是仓库但没装 git"的行为**——这是本批最容易被含糊过去的一处：

- **不在 Git 仓库** → 不显示摘要（`11b:103` 已冻结）；
- **在 Git 仓库但 `git` 不可用** → **同样不显示摘要**，且**不得报错、不得阻断提示符**。
  **但要在诊断/日志里留一条可查的记录**，否则"没显示"和"探测失败"无法区分。

**⚠️ 与 E3C 的关系（不要误读成冲突）**：E3C 为**包管理**选了零 git 依赖
（用 HTTP 取 `info/refs`，因为不能要求用户装 git 才能装包）。
本批是**提示符显示**，语义是"有则显示、无则隐藏"——**两者语境不同，不矛盾**。
**但不要因为本批调了 git 命令，就去改 E3C 的选择。**

**⚠️ 不得阻塞提示符**（`12-tests:800`）——探测要有超时，
且**超时/失败一律降级为"不显示摘要"**，不能挂住整个提示符。

### 2.2 没有跟踪上游时的显示（**`00-decisions:636` 的待定项，本批冻结**）

`00-decisions:636`：「Git 分支没有跟踪上游时，摘要中的领先/落后区域如何显示。」

**冻结为：只显示分支名，省略领先/落后段**（不显示 `?`、不显示 `+0 -0`）。

理由：

- `# branch.ab` 在无上游时**根本不出现**——所以"省略"是**对现实的自然表达**，
  而 `+0 -0` 会**说谎**（"与上游同步"和"没有上游"是两回事）；
- `?` 之类占位符需要用户学习含义，而摘要的价值是"一眼看懂"。

**⚠️ 要有反例测试**：构造无上游的仓库，断言**显示分支名且不含任何计数**。

### 2.3 颜色与真彩色降级（**`11b:101` 已给颜色表，本批定降级**）

`ui/color.ts` 已有 `COLORTERM` 判定。**要冻结降级链**（沿用 E0 的四条件）：

```
非 TTY → 纯文本（无 ANSI）
NO_COLOR 已设 → 纯文本
TERM=dumb → 纯文本
--color=never → 纯文本
否则 → 真彩色（COLORTERM 含 truecolor/24bit）或 256/16 色回退
```

**⚠️ 本批最容易踩的既有坑**：`ui/color.ts` 的 `createColorizer` 会**回退读
`process.env.COLORTERM`**。E1 审核时这导致过一条测试在真彩色终端下**必失败**、
在 CI 上通过（本地红、CI 绿）。**I0 大量使用颜色，新增的颜色测试必须显式传参**，
不得依赖宿主终端环境。

### 2.4 三平台的提示符一致性（`12-tests:800`）

`12-tests:800` 要求「在**三个目标平台**稳定显示，不支持真彩色的终端具有**可读降级**」。

**要冻结**：路径分隔符（Windows `\` 与 Unix `/` 按平台原样显示，**不强制统一**——
那是用户的工作目录）、`[X>` 三平台一致、环境段与工作目录之间**恰好一个空格**。

### 2.5 提示符渲染**不得执行包代码**（为 I4 预留边界）

`12-tests:844`（I4）要求「启动、提示符渲染、名称枚举和只读接口查询**都不执行包模块**」。

**I0 虽然不加载包，但要在这一批把边界立住**：提示符渲染只读**环境元数据**
（`XIAO_ACTIVE_ENV` 与环境名），**不触碰包内容**。I4 会在这条边界上加东西。
