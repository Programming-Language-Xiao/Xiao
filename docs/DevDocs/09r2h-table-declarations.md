## 设计定稿（2026-09-20）

**选择新增程序级 `table_definitions` 区段，研究编码 `FORMAT_VERSION` 从 2 升为 3，
本批必须先于 09R3 完成。** 表的身份、字段类型与可见性不能从运行时字段值反推，
方法和初始化函数也需要稳定索引；把这些信息塞进常量或约定函数名会失去引用校验。
新段携带前端表签名的 IR 镜像、字段初始化函数和方法索引。旧编码明确拒绝，
既有 opcode 不改号。IR 的可选表签名字段使用空值兼容旧快照，不改变既有字段含义。

1. **指令**：追加 `LoadTable`、`MemberGet`、`MemberSet`。`LoadTable` 区分构造与
   读取已声明单例，携带定义索引和构造实参；字段操作对单例和实例共用。
   静态方法直调复用 `Call`，第一个实参显式传入接收者。方法值的动态调用仍属于
   既有 `CallDynamic` 未实现边界，必须明确拒绝，不能伪装成字段读取。
2. **编号**：入口为 0，原顶层函数编号保持不变；随后按表的源码顺序追加字段初始化
   函数和按源码顺序排列的方法。先登记全部索引，再降低函数体，允许方法互调。
3. **时机**：`[[T]]` 声明登记构造定义，不创建实例；`[T]` 在声明语句处构造唯一对象。
   每次构造先按源码顺序求值字段默认值（包括 `const` 字段），再执行 `init`，
   容器默认值每次独立创建。没有初始化器的字段保留未初始化状态，读取报告错误。
   `const` 沿用 05C 的静态语义，本批不另行发明成员可写性规则。
4. **Runtime 适配**：保留 06B 状态机和原有函数指针钩子，只补充可捕获上下文的
   析构钩子、构造闭包和已通过静态检查的字段访问入口。初始化中的方法可以读取
   已写入字段；表外普通读取仍受状态约束。析构接收者使用只在 `Dropping` 有效的
   弱只读视图，不增加原对象强计数，不能复活对象。
5. **执行与释放**：构造、普通方法和析构均执行同一份 TAC 语义核。析构回调使用同种
   载体的执行帧，并共享调用深度、随机源、单例弱引用与事件上下文；动态回调只存在
   生命周期边界，不进入逐指令派发。表值消费既有释放计划；容器内及隐式覆盖释放
   同样触发 Runtime 的最后强引用钩子。析构错误汇回当前执行边界，初始化失败保留
   原因链及清理错误；致命故障先封闭用户钩子，再销毁宿主载荷。
6. **验收取材**：真实源码覆盖单例、实例隔离、字段读写、私有字段、方法互调、
   初始化失败、析构读取、别名与容器持有、异常展开及致命故障。三种载体共用结果和
   冻结释放序列；编码用两种操作数宽度往返，并实际撤回关键执行接线验证用例会失败。

## 一、那个**可能阻塞 09R3** 的问题（**动手前必须先回答**）

09R3 结束后要冻结七项，其中一项是**指令编码与版本字段**，其载体是 `TacProgram` 的
程序级布局。于是：

| 如果本批… | 那么 |
| --- | --- |
| **只追加指令与函数条目**（在 `TacProgram.functions` 里加表方法，追加 `LoadTable`/`MemberGet`/`MemberSet` 三条 opcode） | ✅ **纯追加，可以在 R3 之后做**——追加不破坏已冻结的格式 |
| **需要新增程序级区段**（例如 `table_definitions`） | ❌ **必须赶在 R3 之前**：那会改动 `TacProgram` 的编码布局，等于换 `FORMAT_VERSION` 重新冻结，本轮全部基准数字作废 |

**这是本批的第一个交付物，而且是一个判断，不是一段代码**：先确定走哪条路，
把结论写进本批交接文档，再动实现。

### 已知的相关事实

- `IrStatementKind::Table { name: IrName, table_kind: String, body: Vec<IrStatement> }`
  （`xiao-ir/src/model.rs:211-218`）——`table_kind` 是 `"singleton"`/`"instance"` 字符串。
- 表体的静态白名单是**闭合的**：`Assignment`/`Declaration`/`ConstDeclaration`/`Function`，
  其余由 `TABLE_MEMBER_CODE`（`X05-TYPE-002`）拒绝。**表体内不能再出现 `for` 或嵌套
  `table`**——这条影响测试取材。
- 表方法体是 `body` 里的**嵌套 `IrStatementKind::Function`**，而该变体在
  `lower/stmt.rs` 的程序级遍历里是**被忽略**的（函数只在程序级被收集成 `FuncId`）。
  **表方法需要一条不同的收集路径**——这是本批最可能低估工作量的一处。
- `xiao-runtime/src/tables/` 已有完整的 `TableDefinition`/`TableState`/`TableObject`/
  `TableInstance` 与状态机（`Allocated -> FieldsInitializing -> InitCompleted -> Usable
  -> Dropping -> Released`）。

## 二、需要设计并写进交接文档的

1. **指令形状**：`LoadTable`/`MemberGet`/`MemberSet` 三条是否够？字段访问要不要区分
   singleton 与 instance？方法调用走现有 `Call` 还是新指令？
2. **函数表扩展**：表方法如何进入 `TacProgram.functions` 并获得稳定 `FuncId`，
   以及它与程序级函数的编号关系（**编号一旦分配就要稳定**——参见 opcode 表的同款理由）。
3. **降低形状**：表声明是语句、不产生值。注意它与第 9 条变量的交互，以及
   表体内 `const` 字段与 `init` 的求值时机。
4. **释放**：表实例是堆对象，必须参与既有的确定性释放。**09R2G 刚修的释放边界问题
   就在这里附近**——标量/栈值逃逸不得被伪装成堆句柄，表实例则**确实**是堆句柄，
   两者的门控不能写反。
5. **共享向量与区分度**：至少覆盖 singleton 与 instance 的构造、字段读写、
   `init` 失败回滚、`drop` 只执行一次。

## 硬性约束

门禁、区分度验证、工具规定、单一来源原则、解耦约束**全部沿用 09R2D 文档第二章**。

### ★ 提交正文必须写「为什么」

这条单列出来，因为它在本仓**反复复发**，而最近一笔的代价可以量化。

**事实**：`c239948`（09R2G）**正文 0 行**，而它同时做了两件最需要解释的事——
把既有共享向量的期望值改成空（`control` 2→0、`errors` 7→6、`sets` 6→5），
以及把 `FORMAT_VERSION` 从 1 升到 2。

**代价**：审核者只能读 diff 反推。**审核者先误判成「改期望去迁就实现」**——
那是最典型的假绿形态——直到翻到 `xiao-lifetime/src/escape.rs` 里那五行
（`if value.storage.is_heap() && ...`）才纠正过来：旧向量断言的**正是那个 bug**，
改动是修复的正确后果。

**规则**：正文说明「为什么」。当改动属于下面三类之一时，正文**必须**写清：

1. **改了既有共享向量的期望值**——要说明旧期望断言的是什么错，或者为什么旧期望过时；
2. **升了 `FORMAT_VERSION`**——要说明是哪个指令/字段的布局变了；
3. **删除了断言**（把非空断言改成空、去掉字段）——要说明删掉它之后**还剩什么**能抓住回归。

**反过来说**：如果一笔提交同时做了上面两件，而正文是空的，审核者**没有义务**
替你还原意图——他会先按最坏假设看。

## 实现与验收记录（2026-09-20）

### 已交付的接线

| 层次 | 实际变更 |
| --- | --- |
| 类型与生命周期 | 成员赋值复用可见性/类型规则；静态方法调用复用普通函数参数匹配；按源码区间读取各方法的参数类型，确保 `self` 使用表堆值的释放计划 |
| IR | `table_signatures` 保存唯一前端签名的可序列化镜像；空列表省略，旧快照不变；验证重复成员、非法类型与区间；方法函数保留完整接收者参数 |
| TAC 降低 | `lower/tables.rs` 预登记字段函数与方法；入口 0 和已有顶层函数编号保持；单例在声明处构造，实例声明只登记定义；两者共享字段指令 |
| 编码与分析 | 布局版本 3，追加 opcode 38/39/40；标签、编码、解码、引用验证、活跃分析、CFG 与执行八处接线齐全；两种操作数宽度均往返 |
| Runtime | 原状态机新增初始化闭包、可捕获上下文的析构回调和编译后字段入口；析构弱只读视图不可哈希，保存到回调外也不能复活对象 |
| VM | 字段函数、`init` 和静态方法执行同一语义核；析构帧共用载体、随机源、单例弱引用、调用深度及事件上下文，错误在当前边界汇合 |

表定义段位于随机种子计划之后、`unsupported` 之前，签名序列化复用 IR；字段和方法
`FuncId` 按所选宽度编码。版本 1/2 均在读取函数体前拒绝，0–37 的操作码不变。
这次升级针对新增的程序级区段，09R3 必须以布局 3 重新取得编码体积基线。

真实源码验证暴露了前置阶段的三处遗漏：成员赋值仍落入只接受名称的旧分支；方法调用
没有消费完整的关键字/缺省参数签名；表体内已检查成员直到表结束才发布，生命周期也没有
定位表方法的参数签名。本批在相应唯一来源层修复，并以静态正反用例与 IR 镜像用例锁定，
没有在降低器猜测字段类型或改写释放计划。

### 验证范围与释放审阅

`r2_table_values.rs` 包含 12 条三载体执行回归和 1 条编码/编号回归，覆盖实例隔离、
私有字段、普通/复合赋值、方法互调与缺省参数、独立容器默认值、顶层常量、单例声明顺序、
未初始化字段、返回转移、覆盖和别名/容器持有、析构只执行一次、可捕获的析构错误、
初始化原因链与清理错误、只读接收者、Fatal 隔离及析构递归深度。编码回归另锁定旧版本
拒绝、重复表、方法映射缺失、坏函数/表索引和既有顶层函数编号稳定性。

`tables.json` 新增 6 条共享向量，目录总计 **79 条**，旧 73 条的期望完全不变。
向量的完整释放序列逐项对照 `IrOwnership` 和冻结计划：

- 实例用例先释放两次 `init` 接收者，再依调用顺序释放 `read/add/read` 接收者，最后
  按逆声明顺序释放 `second`、`first`。
- 别名用例的计划依次释放 `items`、`alias`、`first`，对象最后强引用只触发一次析构，
  全局单例在脚本退出时释放；方法中标记转移的值继续服从原计划。
- 回滚用例保留 `init` 和 `drop` 的接收者清理，之后释放外层字符串；构造从未成功的
  `item` 和未物化的构造定义不虚报释放。未捕获错误沿现有路由消费 `unmatched_error`，
  有匹配处理器时消费 `catch` 计划；构造指令标记原始 `construct_failure` 退出原因。
- 容器异常展开先记录容器释放，再记录其中两个实例的析构帧清理；Fatal 不执行释放计划
  或用户钩子，调用深度上限覆盖析构重入。

Runtime 公开接口回归另外验证初始化中可读取已写入字段、普通私有访问仍被拒绝、字段类型
检查、弱句柄标签检查、析构视图不可哈希以及回调后访问失效。IR 镜像在序列化和还原时
保留静态字段类型、成员可见性和方法接口。
