# 18. 优化与产物 CLI 接入

> 本阶段把第 13 至 17 阶段的稳定接口接入 TypeScript CLI。CLI 只负责参数、配置、文件和进程边界，不复制编译器、虚拟机或归档格式的语义。

## Agent 交接上下文

### 接手前提

- 先阅读 [11. CLI、项目配置与平台](11-cli-config-and-platform.md)、[11C. 国际化、系统提示与语言包插件](11c-localization.md)、[14. 字节码优化与 `.xiaoc` 产物](14-bytecode-optimization.md)、[16. SHA-256 内容寻址与二进制索引](16-content-addressed-artifacts.md) 和 [17. `.xar` 字节码归档与启动](17-xar-archive.md)。
- 后端已经提供优化、编解码、校验、内容寻址和归档库接口；本阶段不重新实现这些语义。
- 已确认的用户入口是 `xiao build -xar "<源路径>" [-O0|-O1|-O2|-O3]` 和 `xiao -xar "<归档路径>"`。`<源路径>` 可以是 `config.xiao`、包含 `[main]` 的 `.xiao` 文件或任意可打包 `.xiao`；方括号只表示参数可省略。

### 本阶段交付与不负责事项

- 交付：命令路由、参数诊断、配置覆盖、有效语言上下文传递、输入扩展名分派、文件关联安装接口和脚本化输出。
- 不负责：决定新的语言语义、Pass 算法、Protobuf Schema 字段、归档成员格式或缓存淘汰策略。
- `-O<级别>` 中的 `<级别>` 取已确认的 `0`、`1`、`2`、`3`；未提供命令行或配置级别时统一使用已经确认的 `-O0`。

### 交接检查

下一位代理应能在没有网络和 Node.js 的用户环境中，使用同一 CLI 解析结果调用后端，生成/验证 `.xar`，并证明配置、命令行、缓存指纹和归档清单使用的是同一份规范化输入。

## 一级工程目标：提供用户入口

### 命令草案

以下命令用于讨论和验收拆分，尚未冻结为最终 CLI 语法：

```text
xiao run <file.xiao|file.xiaoc> [优化/运行选项] [-debug]
xiao build <file.xiao> [优化/目标选项] [-debug]
xiao build -xar "<config.xiao|main.xiao|任意.xiao>" [-O0|-O1|-O2|-O3] [-debug]
xiao -xar "<file.xar>" [-debug]
xiao optimize <file.xiao|file.xiaoc> [输出选项]
xiao pack <输入或项目> -o <file.xar>
xiao inspect <file.xiaoc|file.xar>
xiao verify <file.xiaoc|file.xar>
xiao cache <list|verify|rebuild|clean>
```

`xiao build -xar "<源路径>" [-O0|-O1|-O2|-O3]` 和 `xiao -xar "<归档路径>"` 已是确定入口；省略 `-O` 后按配置或内建 `-O0` 执行。`optimize`、`pack`、`inspect`、`verify`、`cache` 是否另保留为独立命令，仍需在本阶段冻结。已有 `xiao run`、`xiao build`、`xiao config` 的旧项目默认行为不能因新增命令而改变。

所有支持优化级别的入口在没有显式命令行参数和配置字段时都采用 `-O0`，包括 `xiao run`、脚本快捷入口、REPL、普通 `xiao build` 和 `xiao build -xar`。`-O0` 仍执行必要的编译、规范化、生命周期与安全验证。字节码执行路径默认生成并缓存已验证的 `.xiaoc`；普通原生 `xiao build` 直接消费类型化 IR，不为 LLVM 不使用的模块额外物化 `.xiaoc`。

例如：

```text
xiao build -xar "main.xiao" -O0
xiao build -xar "config.xiao" -O2
xiao build -xar "hello.xiao"
xiao -xar "dist/app.xar"
```

第三个构建示例省略优化参数，因此在配置也未指定时使用 `-O0`。需要显式选择时直接写 `-O0`、`-O1`、`-O2` 或 `-O3`，不存在字面参数 `-Ox` 或 `-O<级别>`。

`-debug` 是强制诊断开关，不属于优化级别。它在 `run`、脚本快捷入口和 `.xar` 启动时必须在用户代码前打开独立诊断进程与终端窗口；在 `build`/`build -xar` 时还要把调试激活位、源码映射、诊断元数据和运行时钩子能力写入产物，保证产物直接启动时自动打开窗口。调试版原生程序不得依赖 `xiao` 启动器，普通 GUI 子系统设置也不能抑制窗口。诊断窗口、日志分级、模块/文件聚焦、`mirror` 分流和固定指标栏遵守第 07 阶段契约，CLI 只负责归一化并传递配置。

### 配置与优先级

优化配置可以在 `config.xiao` 中声明，也可以由命令行临时覆盖。候选表名包括 `[Optimization]`、`[Build]` 和 `[Artifacts]`；字段白名单、项目/全局范围、命令行优先级和未知字段行为尚待确认。任何影响字节码、原生二进制、缓存或归档的字段都必须进入第 13 阶段定义的指纹。

CLI 读取 `config.xiao` 时继续使用声明式子集，不能执行项目代码。命令行覆盖只作用于当前调用，除专门的配置命令外不能偷偷修改项目配置或锁文件。

## 一级工程目标：建立可诊断工作流

### 产物生命周期

CLI 应能清楚区分源码、临时字节码、公开 `.xiaoc`、内容寻址对象和 `.xar` 归档，并在每一步显示输入、输出、命中/失配原因和验证状态。优化失败、格式失配、索引损坏和平台不兼容必须落到稳定错误类别，不得自动运行未验证文件。

普通源码模块的 `.xiaoc` 默认写入全局内容寻址缓存，不落在源码旁边。REPL 产生且依赖当前会话状态的片段只写入会话缓存；完整独立模块才可提升到全局缓存。`xiao build -xar` 从经过验证的缓存对象或新生成对象组装 ZIP/ZIP64，不允许因缓存命中跳过完整文件 SHA-256 校验。

### 平台发布

文件关联安装、卸载和无关联退化路径由 TypeScript CLI 的平台适配层负责。Windows、Linux 和 macOS 的参数传递、工作目录、标准流、退出码和颜色/无颜色诊断需分别测试。CLI 本身仍打包为无需用户另装 Node.js 的独立可执行程序。

## 二级实现任务

### 参数与配置

1. [18.1] 实现 `-O0` 至 `-O3` 参数，并验证所有相关入口在无配置时统一回落到 `-O0`。
2. [18.2] 将项目配置、全局配置、`[language].locale` 和命令行覆盖归一化为后端接口对象；语言上下文交给第 11C 阶段的消息渲染器。
3. [18.3] 对 `config.xiao`、`[main]` 文件、任意 `.xiao`、`.xiaoc` 和 `.xar` 的输入路由提供互斥/缺失诊断。
4. [18.4] 生成按有效语言呈现的帮助文本和机器可读错误模式；机器模式保留稳定 `code`、`message_id` 和参数。

### 后端调用

1. [18.5] 调用第 13 至 17 阶段的库/进程接口，不在 TypeScript 中重写 Pass、哈希或 Protobuf 解码器。
2. [18.6] 展示缓存命中、重编译、校验和回退原因。
3. [18.7] 在输出前确认产物已通过格式和完整性验证。
4. [18.8] 保持 `xiao run`、REPL、`.xiaoc` 和 `.xar` 使用同一运行契约。

### 文件关联与脚本化

1. [18.9] 实现三平台 `.xar` 文件关联的安装、检查和移除接口，并指向已安装的 `xiao`。
2. [18.10] 提供非交互模式、详细日志和机器可读结果，便于 CI 使用。
3. [18.11] 验证中断、重复执行、只读目录和并发命令不会破坏缓存或索引。
4. [18.12] 记录实际使用的优化指纹、对象摘要和归档版本。
5. [18.13] 解析 `-debug` 并与 `[debug]` 配置合并，验证运行、构建和 `.xar` 启动使用同一诊断配置；调试构建必须写入强制诊断激活位，并验证直接启动、调试版原生产物无 `xiao` 启动器和 GUI 子系统场景都会打开独立窗口；`.xar` 仍由 `xiao -xar` 按 Runtime 前提启动。
6. [18.14] 验证项目/全局 `[language].locale` 的优先级、别名规范化、内置目录回退和语言插件缺失诊断；CLI 不在自身复制翻译逻辑。

## 验收标准

- 用户可通过稳定 CLI 生成、验证、检查和运行 `.xiaoc`/`.xar`；命令语法与旧核心命令无冲突。
- CLI 与后端的错误边界、退出码和输入输出路径清晰，失败不执行未验证产物。
- 配置、命令行和缓存命中使用同一规范化优化指纹。
- `-debug` 能正确传递终端/文件等级、堆栈、聚焦和 `mirror` 规则；所有直接运行和调试产物启动都会打开独立诊断窗口，诊断输出不会污染程序标准输出或改变错误退出语义。
- CLI 在中文和英语下显示对应系统文案，但机器可读错误、退出码、错误位置和产物语义一致；`[language].locale` 的项目/全局优先级符合第 11C 阶段规定。
- 三平台独立 CLI 不依赖 Node.js，并能完成文件关联或可读退化。
- `xiao run`、REPL 和 `.xar` 构建默认生成并缓存可验证 `.xiaoc`，而且不会污染源码目录。
