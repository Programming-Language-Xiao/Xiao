## 一级工程目标：建立容器分类

### 数组与元组

- 数组使用 `[]`，支持异构元素。
- 元组与 Python 类似，长度固定但元素可以异构。
- 数组可以嵌套数组、元组、集合、字典表和字典列。
- 显式类型可以约束整个数组或某个路径：

```xiao
int list2 = [1, 2, 3]
int list3[2/0]
```

`int list2` 表示数组元素必须满足 `int`；如果元素不满足，编译期或运行时立即报错，不能静默转换。`int a = 1` 与 `int list2 = [...]` 先统一解析为“带类型前缀的绑定”，再由类型检查阶段结合初始化值判定前者是标量类型、后者是容器元素约束。非字面量容器初始化、无初始化声明和其他容器如何消除这一上下文歧义，必须在本阶段实现前继续定稿。

#### C0 已实现的消歧与读取边界

- 无初始化、无路径的 `int name` 仍建立标量绑定。
- `int name = [...]` 检查所有直接数组元素并形成同构数组形状；`[]` 只形成未知长度数组。
- `int name[3/2]` 将路径保存为零基精确约束；未知边界生成物化计划，不在类型阶段填默认值。
- `name[0]` 这类读取在 C0 只允许一个精确项；多选、范围、步长和随机项明确拒绝。
- 字典重复键在类型阶段报错，字典表键路径只能使用键名，字典列还允许数字位置。

### 集合

集合采用 Python `set` 的基础语义：

- 使用花括号直接包裹元素，例如 `{1, "x", true}`。
- 元素唯一且不保持顺序。
- 不支持数字索引或键名索引。
- 默认允许异构元素，并可在变量根使用 `set<T>` 或 `set<T | U>` 显式声明成员类型。
  旧式 `int name = {...}` 仍是同构容器约束，不能借默认异构规则放宽。
- 每个元素都必须可哈希。
- `set()` 表示空集合；`{}` 固定表示空字典表。

集合不暴露可赋值的元素位置，因此已有元素不能被原地重新绑定或改成另一种类型。修改集合内容通过增加和删除元素完成；显式同构集合的新增元素还必须满足其元素类型约束。

```xiao
values = {1, "x", true}
empty_values = set()
int ids = {1, 2, 3}
set<int | str> typed_values = {1, "x"}
```

`set<T | U>` 的并集只描述允许出现的成员类型，不是位置声明，也不会给无序集合增加
顺序。未显式声明的非空集合会推导静态成员类型并集；当前 C2-B 的类型项只开放标量和
`none`。即使初始化器只出现一个成员类型，显式声明仍保留完整并集，例如
`set<int | str> values = {1}` 的绑定类型仍为 `set<int | str>`。

动态表达式作为成员时，类型层保留已知并集并登记 `SetHashability`；后续把动态集合赋给
受限集合或执行动态成员判断时登记 `SetMembership`。这些标记由 Runtime 阶段消费，当前
不会创建真实集合对象。

### 可哈希规则

Xiao 沿用 Python 对集合元素的可哈希要求：元素的哈希值在其位于集合期间必须稳定，并且相等元素必须具有相同哈希值。

- 整数、浮点、字符串、布尔值等不可变标量可以作为集合元素；`bool` 与整数/浮点是不同
  静态类型，`true` 与 `1` 不会被视为同一元素。不同整数宽度也保持不同哈希身份。
- 总体语义规定元组只有在每个成员都可哈希时才可哈希；C2-B 尚未实现元组递归证明，
  因而当前类型层仍拒绝元组成员。
- 数组、字典表、字典列和普通集合等可变容器不可哈希，不能作为集合元素。
- 动态值在插入时执行运行时可哈希检查；已知为不可哈希类型的静态值直接产生编译错误。
- 集合不会追踪某个可变对象的内部变化，也不会为维持哈希而执行动态重排。

因此，先前“集合可以包含数组并继续修改数组内容”的设想被本条新决策取代，不再属于 Xiao 规范。

### 集合运算

集合运算的含义沿用 Python，但并集运算符改为 `+`：

| 运算 | Xiao 写法 | 结果 |
| --- | --- | --- |
| 并集 | `left + right` | 返回包含两侧全部元素的新集合 |
| 原地并集 | `left += right` | 将右侧元素并入左侧集合 |
| 交集 | `left & right` | 返回两侧共有元素 |
| 差集 | `left - right` | 返回只在左侧的元素 |
| 对称差 | `left ^ right` | 返回只在其中一侧的元素 |
| 子集 | `left <= right` | 判断左侧是否为右侧子集 |
| 真子集 | `left < right` | 判断左侧是否为右侧真子集 |
| 超集 | `left >= right` | 判断左侧是否为右侧超集 |
| 真超集 | `left > right` | 判断左侧是否为右侧真超集 |
| 成员 | `value in values` | 判断元素是否存在 |
| 非成员 | `value not in values` | 判断元素是否不存在 |

`|` 和 `|=` 不承担集合并集语义。集合方法式 API 是否完整复刻 Python、不同显式元素类型参与运算时如何合并类型，都必须在对应实现开始前另行冻结，不能由实现临时选择。

### 不可变集合候选

Python 中 `set` 是可变集合，`frozenset` 是不可变集合。Xiao 是否提供 `frozenset` 尚未确定，早期 Token、解析器和基础容器里程碑都不能依赖它。

`frozenset` 锁定的是外层集合结构：创建后不能增加或删除元素。不可变本身不要求动态追踪，反而有利于共享、缓存哈希和作为其他哈希容器的成员；主要开销仍来自元素哈希、唯一性检查和集合存储。如果未来加入，它的所有元素同样必须可哈希。

### 字典表

字典表相当于 Python 字典：

- 使用花括号包裹定义。
- 由键值对组成，不承诺键的迭代顺序。
- 使用 `dict[key_name]` 按键访问。
- 键值可以是异构值，并且可以继续嵌套数组或其他容器。

示例：

```xiao
profile = {
    "name" = "星崽",
    "level" = 1
}
profile["name"]
```

非空花括号通过条目形式区分：只有值的是集合，包含 `键 = 值` 的是字典表。一个花括号字面量中不能混用这两种条目。

### 字典列

字典列与字典表一样由键值对组成，但保持固定顺序：

- 使用尖括号包裹定义。
- 支持异构值，也支持显式指定类型。
- 支持数字索引、键名索引和数字加键名的组合索引。
- `/` 可以继续进入嵌套值，例如 `column[1/keyname]` 先选择位置 `1` 再进入其内部键；
  数字位置和键名位置可以在同一条路径中混用。C1 的高级选择仍沿用这套路径表示。

## 一级工程目标：统一容器读取与高级选择

### 可索引能力边界

数组、元组、`str` 和字典列是有序可索引容器，支持精确路径、多项选择、范围、步长和随机选择。能力边界固定如下：

| 容器 | 精确索引/路径 | 多选、范围、步长、随机 |
| --- | --- | --- |
| 数组 | 数字索引及嵌套路径 | 支持 |
| 元组 | 数字索引及嵌套路径 | 支持 |
| `str` | 数字索引 | 支持 |
| 字典列 | 数字、键名及其嵌套路径 | 支持；重复直接键时返回元组 |
| 字典表 | 键名及嵌套路径 | 不支持 |
| 集合 | 不支持 | 不支持 |

字典表是无序容器，只能精确按键读取，例如 `profile["name"]`，或作为嵌套路径中的键段被精确读取。集合完全不可索引。对字典表或集合使用范围、多选、步长或随机选择必须报错，不能依赖某次运行时的存储顺序产生结果。

### 统一选择器语法

选择项统一放在同一对 `[]` 中，数字坐标从 `0` 开始：

```xiao
exam_tuple = ('python', 'c', 'c++', 'c#', 'rust', 'go', 'ts', 'js')

exam_tuple[0]              # 'python'
exam_tuple[0, 1]           # ('python', 'c')
exam_tuple[0~2]            # ('python', 'c', 'c++')
exam_tuple[0~2, 5~6]       # ('python', 'c', 'c++', 'go', 'ts')
exam_tuple[<2]             # ('python', 'c')
exam_tuple[<=2]            # ('python', 'c', 'c++')
exam_tuple[>0]             # ('c', 'c++', 'c#', 'rust', 'go', 'ts', 'js')
exam_tuple[>=0]            # 全部元素
exam_tuple[=]              # 全部元素
```

`~` 表示双端都包含的闭区间。`<`、`<=`、`>`、`>=` 分别决定是否包含边界；当选择不到任何元素时，返回与来源根容器同类型的空结果。单项精确索引越界仍然报错，不因这条空结果规则而改成返回空容器。

### 嵌套路径与结果形状

高级选择先产生有序路径选择，再按来源结构重建结果：

- 单项精确索引直接返回元素，不包裹来源容器类型。
- 多选、范围和随机选择原则上返回与来源根容器相同的类型；字典列如果同一直接键被
  重复选中，结果改为按选择顺序排列的元组，避免伪造重复键的字典列。
- 选择进入嵌套容器时，保留抵达所选元素所必需的中间容器形状及其容器类型。
- 范围端点按来源容器的深度优先顺序解释，端点本身可以是嵌套路径；跨入一个嵌套
  分支时只保留落在闭区间内的部分，未被边界切入的中间分支以完整容器保留。
- 范围路径只能沿有序容器建立顺序；一旦路径需要穿过无序字典表，必须拒绝范围选择。字典表仍可出现在精确路径中。

```xiao
exam2_tuple = ('a', 'b', [1, 2])

exam2_tuple[1, 2/1]        # ('b', [2])
exam2_tuple[1~2/1]         # ('b', [1, 2])
```

第一个表达式精确选择路径 `1` 和 `2/1`，所以嵌套数组只保留被选中的 `2`。第二个表达式从路径 `1` 选择到路径 `2/1`，且 `~` 双端包含，因此索引 `2` 的数组是被边界切入的分支，保留其中的 `1` 和 `2`；同一父容器下的路径会在结果投影时重新合并。

### 步长

步长使用来源表达式后的 `{step}` 指定，并可以应用于全选、单边范围、闭区间和多范围结果：

```xiao
exam_tuple{2}[=]
exam_tuple{2}[>=0]
exam_tuple{2}[0~6]
exam_tuple{2}[0~2, 5~7]
```

`step` 可以是能得到整数语义的表达式（最常见的是整数字面量或整形变量）。正数从范围结果的起始方向每隔 `step` 个位置取值；负数先反转遍历方向，再按其绝对值取值。`0` 没有合法遍历含义：字面量直接产生编译错误，变量在运行时得到 `0` 时产生运行错误。无法静态确定的步长登记 `SelectorStep` 运行时检查。

### 随机选择

```xiao
exam_tuple[?count]          # 无放回，结果中不会重复抽中同一位置
exam_tuple[!?count]         # 放回，每次抽取后放回候选位置
```

候选项是来源根容器的直接有序元素；抽中嵌套容器时，该元素作为完整候选项保留。结果元素按实际抽取顺序排列，并原则上保持来源根容器类型。放回抽取允许 `count` 大于候选项数量；无放回抽取在数量超过候选项数量时报错。字典列放回抽取可能重复同一键，此时结果使用元组而不是重复键的字典列。

两种模式都要求 `count` 是整数语义值。`count == 0` 返回同来源根容器类型的空结果；`count < 0` 报错。空来源在 `count > 0` 时无法抽取：无论是否放回都报错。动态数量登记 `RandomCount` 运行时检查。测试和后端通过统一随机源接口注入可复现序列，不能各自维护抽样算法。

数组、元组和 `str` 能直接保留放回抽取产生的重复位置。字典列的键在容器本身仍然唯一；若抽样结果重复同一键，C1 将该次结果表示为保序元组，元组项仍按抽样顺序保存值。

### 随机种子与静态边界

`random.seed(value)` 为当前执行上下文登记随机种子。种子必须是非负整数语义值（可由
`int`、`sint` 或 `lint` 提供，最终按 `lint` 的非负表示交给 Runtime）；动态值会登记
`RandomSeed` 运行时检查，负数、浮点数和超出种子表示范围的常量产生 `X03-TYPE-013`。
类型阶段只记录计划，不推进全局随机状态。

静态随机数量为零时直接得到来源同类型空结果。非零随机项的具体位置由 Runtime 决定，
类型阶段使用来源类型作为保守上界；因此静态检查不会把无放回随机误判为空数组。

### 选择器左值广播

选择器可以作为确定性赋值目标，但只支持标量广播：

```xiao
items = [1, 2, 3]
items[0, 2] = 0
```

标量会复制到所有静态或运行时解析出的目标路径。右侧数组、元组、字典或其他容器不做
逐项配对，直接报告 `X03-TYPE-012`；随机选择不能作为赋值目标。当前计划只允许直接
名称作为根容器，写入要求绑定已初始化且可变。Runtime 必须先验证全部目标，再一次性
提交，任一目标失败都回滚整次写入。

## 一级工程目标：实现路径约束

### 数字路径

斜杠只表示“继续进入嵌套容器”的路径分隔符，不表示除法，也不参与浮点数解析：

```xiao
int list[3/2]
```

容器数字索引统一从 `0` 开始。其结构含义是：`list` 中索引为 `3` 的元素（第 4 个位置）必须是一个内嵌数组，该内嵌数组中索引为 `2` 的元素（第 3 个位置）必须是 `int`。这条声明约束的是元素类型，不是一次读取操作。

### 混合路径

路径可以进入字典表的键：

```xiao
str list[1/keyname]
```

这里的 `keyname` 是键名，不是数组索引。字典列还需要支持数字和键名组合路径。解析器只保留路径段的原始语法与源码位置，由名称解析和类型检查根据实际容器类型判定数字段、键名段及其合法性；词法器或解析器不能提前猜测运行时容器类型。

### 逐条声明与覆盖

- 路径声明可以先声明较宽的父路径，再声明更窄的子路径。
- 如果类型声明停在一个数组节点上，它约束该节点下的全部直接元素。例如 `str list3[2]` 表示 `list3` 中索引为 `2` 的元素是数组，且该内嵌数组的所有元素都必须是 `str`。
- 如果路径继续向下，则只约束路径指向的那个元素。例如 `int list3[2/0]` 只覆盖该内嵌数组中索引为 `0` 的元素类型。
- 后出现的、更具体的声明覆盖先出现的父路径声明。
- 不兼容的容器形状或类型约束应产生诊断。

`const` 的已定基础语义是第 02 阶段定义的编译期常量。早期提出的 `const list[3]` “锁定运行时容器位置”会引入另一种只读语义，目前不属于已冻结规则；是否保留及如何与编译期求值相容，必须另行确认，不能在路径实现中直接加入。

## 一级工程目标：实现空数组和默认填充

### 自动扩容

对空数组声明局部路径时，编译器根据路径创建所需的嵌套形状。路径目标使用其声明类型的默认值；为了抵达更深目标而创建的中间节点使用数组；其余没有类型声明的空洞使用 `""`。已确认的类型默认值为：

| 类型 | 默认值 |
| --- | --- |
| `str` | `""` |
| `int`/`sint`/`lint` | `0` |
| `float`/`sfloat`/`lfloat` | `0.0` |
| `bool` | `false` |
| 数组 | `[]` |

例如，数字索引从 `0` 开始时：

```xiao
int list4[3/2]
list4 = []

# 自动扩容后的值
list4 = ["", "", "", ["", "", 0]]
```

外层索引 `3` 必须创建数组才能继续进入路径，最终索引 `2` 使用 `int` 默认值 `0`。空洞和用户主动写入的默认值目前都表现为相同值；是否引入独立的“未初始化”状态属于待定设计。

### 同构与异构边界

数组默认允许异构，但显式声明的路径优先级更高。若一个位置被声明为 `int`，写入字符串、布尔值或不兼容容器都必须失败。

## 二级实现任务

### 容器数据模型

1. 先实现数组与元组的基础数据模型。
2. 再实现数组元素约束、形状信息和路径规则。
3. 随后实现字典表的键查找结构与字典列的顺序结构。
4. 上述容器稳定后，再为集合实现唯一性、哈希和元素类型约束。
5. 集合不实现索引接口；C2-A/C2-B 只实现静态成员判断和类型约束，真实增删与集合
   运算接口留给后续阶段。

### 集合实现拆分

1. **C2-A（已完成静态阶段）**：完成集合 AST、单一元素类型推断、显式元素类型约束、

## 验收标准

### 结构验收

- 异构数组能保存全部已确认的标量和容器值。
- 集合自动维持元素唯一性，不能用数字或键名索引，且迭代顺序不构成程序语义。
- 数组、字典表、字典列和普通集合作为元素时会因不可哈希而被拒绝。
- `+` 产生并集，`|` 不产生并集；其余集合运算与 Python 的对应运算结果一致。
- `set()` 和 `{}` 分别稳定产生空集合与空字典表。
- 字典表不承诺顺序，字典列在字节码和原生模式保持相同顺序。
- `list[0]` 访问首个元素；`list[3/2]` 只命中外层索引 `3`、内层索引 `2` 指向的位置。
- `list[1/keyname]` 不会被误解析成除法或浮点数。
- 数组、元组、`str` 和字典列支持范围、多选、步长与随机选择；字典表只支持精确键路径，集合拒绝全部索引操作。字典列放回抽取或重复直接键选择时，结果按选择顺序表示为元组。
- `tuple[0, 1]` 和 `tuple[0~2, 5~6]` 分别按项目顺序返回同类型元组，且 `~` 的两个端点都包含在结果中。
- 对 `('a', 'b', [1, 2])` 执行 `[1, 2/1]` 得到 `('b', [2])`，执行 `[1~2/1]` 得到 `('b', [1, 2])`。
- `[<0]` 等零元素范围返回同类型空容器；单项精确索引越界仍然报错。
- 步长 `0` 报错，负步长反向遍历；相同规则同时覆盖 `[=]`、单边范围、闭区间和多范围。
- `[?x]` 无放回且超量时报错；`[!?x]` 可以放回并超过候选数量。两者在 `x == 0` 时返回同类型空结果，在 `x < 0` 或空源且 `x > 0` 时报错。

### 类型验收

- 父路径和子路径声明按出现顺序合并，后者能覆盖前者允许覆盖的类型。
- 不兼容写入在两种执行模式都产生同类错误。

### C2-A 静态验收

- 非空花括号中的纯值条目形成无序集合；含 `键 = 值` 的花括号仍形成字典表；
  `{}` 始终是空字典表，`set()` 始终是空集合构造式。
- 集合的显式元素类型约束成员类型而不是位置；C2-A 的历史边界要求未声明集合为单一
  元素类型，`bool` 不与任何数值类型统一。
- `none` 可作为可哈希元素；数组、字典表、字典列、普通集合和未能静态证明可哈希
  的容器元素被拒绝或登记后续动态检查。
- 静态重复标量产生稳定诊断；集合完全拒绝数字、键名、多选、范围、步长和随机索引。
- `value in values` 与 `value not in values` 返回 `bool`，右侧必须是集合且左侧类型
  必须满足元素约束。
- 本批次不生成集合代数计划，不创建 Runtime 集合，不实现 `frozenset`。

### C2-B 异构集合静态验收

- 未显式声明的非空集合推导静态成员类型并集；`set<T>` 与 `set<T | U>` 只允许变量根，
  显式声明保留完整并集，`set()` 在声明上下文具体化。
- 旧式 `int name = {...}` 继续执行同构成员约束；`bool`、数值类型和不同整数宽度不
  因隐式转换而合并集合身份。
- 静态成员并集按稳定类型文本规范化、去重；动态成员保留已知并集并登记
  `SetHashability`，动态集合赋值/成员判断登记 `SetMembership`。
- 显式成员冲突、非集合初始化器、集合路径和 `const set<...>` 都有稳定语法或类型诊断；
  集合仍完全不可索引。
- 本批次不生成集合代数计划，不创建 Runtime 集合，不实现增删、集合比较、元组递归
  哈希或 `frozenset`。
