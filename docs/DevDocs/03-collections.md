# 03. 容器、集合与索引路径

> 本阶段落实数组、元组、集合、字典表、字典列和局部类型声明。数组路径是 Xiao 的独有语法，必须先把结构语义写清楚再实现。

## 一级工程目标：建立容器分类

### 数组与元组

- 数组使用 `[]`，支持异构元素。
- 元组与 Python 类似，长度固定但元素可以异构。
- 数组可以嵌套数组、元组、集合、字典表和字典列。
- 显式类型可以约束整个数组或某个路径：

```xiao
int list2 = [1, 2, 3]
int list3[2/0]
```

`int list2` 表示数组元素必须满足 `int`；如果元素不满足，编译期或运行时立即报错，不能静默转换。

### 集合

集合采用 Python `set` 的基础语义：

- 使用花括号直接包裹元素，例如 `{1, "x", true}`。
- 元素唯一且不保持顺序。
- 不支持数字索引或键名索引。
- 默认允许异构元素，也可以显式声明统一的元素类型。
- `set()` 表示空集合；`{}` 固定表示空字典表。

集合中已经存在的元素不能被原地重新绑定成另一种类型。若某个元素本身是数组、字典表或其他可变容器，修改其内部数据不会改变这个外层元素的容器类型，因此允许修改内部数据。集合增加、删除、成员判断和集合运算所使用的最终 API 语法尚待确定。

```xiao
values = {1, "x", true}
empty_values = set()
int ids = {1, 2, 3}
```

Python 会禁止数组、字典和可变集合成为 `set` 元素；Xiao 此前已经提出允许集合内包含可变容器。两条规则无法同时完整成立，因此可变容器元素按对象身份还是内容判断唯一、是否参与哈希，必须在实现前单独定稿。

### 不可变集合候选

Python 中 `set` 是可变集合，`frozenset` 是不可变集合。Xiao 是否提供 `frozenset` 尚未确定，因此首版实现不能依赖它。

`frozenset` 锁定的是外层集合结构：创建后不能增加或删除元素。不可变本身不要求动态追踪，反而有利于共享和缓存；主要开销仍来自元素哈希、唯一性检查和集合存储。如果未来仍允许它包含内部可变的容器，它就不能直接按深层内容获得稳定哈希，这与普通集合的可变容器元素规则需要一起决定。

### 字典表

字典表相当于 Python 字典：

- 使用花括号包裹定义。
- 由键值对组成，不承诺键的迭代顺序。
- 使用 `dict[key_name]` 按键访问。
- 键值可以是异构值，并且可以继续嵌套数组或其他容器。

示例：

```xiao
profile = {
    "name" = "星崽",
    "level" = 1
}
profile["name"]
```

非空花括号通过条目形式区分：只有值的是集合，包含 `键 = 值` 的是字典表。一个花括号字面量中不能混用这两种条目。

### 字典列

字典列与字典表一样由键值对组成，但保持固定顺序：

- 使用尖括号包裹定义。
- 支持异构值，也支持显式指定类型。
- 支持数字索引、键名索引和数字加键名的组合索引。
- 具体组合索引的标点形式需要在语法阶段补充完整。

## 一级工程目标：实现路径约束

### 数字路径

斜杠只表示“继续进入嵌套容器”的路径分隔符，不表示除法，也不参与浮点数解析：

```xiao
int list[3/2]
```

其结构含义是：`list` 的第 3 个元素必须是一个内嵌数组，该内嵌数组的第 2 个元素必须是 `int`。这条声明约束的是元素类型，不是一次读取操作。

数字索引的基准（从 0 开始或从 1 开始）尚未定稿；在基准确定前，编译器测试只能验证路径层级关系，不能把数字解释成某一个绝对位置。

### 混合路径

路径可以进入字典表的键：

```xiao
str list[1/keyname]
```

这里的 `keyname` 是键名，不是数组索引。字典列还需要支持数字和键名组合路径；路径解析器必须根据容器类型区分数字段和键名段。

### 逐条声明与覆盖

- 路径声明可以先声明较宽的父路径，再声明更窄的子路径。
- 如果类型声明停在一个数组节点上，它约束该节点下的全部直接元素。例如 `str list3[2]` 表示 `list3` 的第 2 个元素是数组，且该内嵌数组的所有元素都必须是 `str`。
- 如果路径继续向下，则只约束路径指向的那个元素。例如 `int list3[2/0]` 只覆盖该内嵌数组的第 0 个元素类型。
- `const` 可以附着在路径或数组节点上，锁定对应位置或节点的值/结构；后续写入不能通过普通赋值或路径覆盖解除锁定。
- 后出现的、更具体的声明覆盖先出现的父路径声明。
- 不兼容的常量、容器形状或类型约束应产生诊断；“覆盖”不能成为绕过 `const` 的方式。

## 一级工程目标：实现空数组和默认填充

### 自动扩容

对空数组声明局部路径时，编译器根据路径创建所需的嵌套形状。未声明位置使用对应的默认值：

| 类型 | 默认值 |
| --- | --- |
| `string` | `""` |
| `int`/`sint`/`lint` | `0` |
| `float`/`sfloat`/`lfloat` | `0.0` |
| `bool` | `false` |
| 数组 | `[]` |

例如，`int list4[3/2]` 后写入空数组时，必须生成至少能容纳该路径的嵌套结构。空洞和用户主动写入的默认值目前都表现为相同值；是否引入独立的“未初始化”状态属于待定设计。

### 同构与异构边界

数组默认允许异构，但显式声明的路径优先级更高。若一个位置被声明为 `int`，写入字符串、布尔值或不兼容容器都必须失败。

## 二级实现任务

### 容器数据模型

1. 为五类容器定义统一的值接口；集合不实现索引接口，只实现成员和集合运算接口。
2. 为数组保存元素约束、形状信息和常量标记。
3. 为集合保存唯一性结构和元素类型约束，不暴露内部槽位顺序。
4. 为字典表保存键查找结构，为字典列保存顺序结构。
5. 为元组固定长度并保留每个位置的独立类型。

### 路径编译与运行

1. 把斜杠路径解析为路径段 AST。
2. 在类型检查阶段合并父路径和子路径约束。
3. 在运行时执行自动扩容和默认填充。
4. 为越界、键不存在、类型冲突和只读位置提供不同错误类别。

## 验收标准

### 结构验收

- 异构数组能保存全部已确认的标量和容器值。
- 集合自动维持元素唯一性，不能用数字或键名索引，且迭代顺序不构成程序语义。
- `set()` 和 `{}` 分别稳定产生空集合与空字典表。
- 字典表不承诺顺序，字典列在字节码和原生模式保持相同顺序。
- `list[1/keyname]` 不会被误解析成除法或浮点数。

### 类型验收

- 父路径和子路径声明按出现顺序合并，后者能覆盖前者允许覆盖的类型。
- 不兼容写入在两种执行模式都产生同类错误。
