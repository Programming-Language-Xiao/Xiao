# 05. 表、模块与工程模型

> 本阶段定义 TOML 风格表在 Xiao 语言中的实际身份，并把单文件脚本提升为可构建工程。

## 一级工程目标：区分表的两种语言身份

### 单例表 `[TableName]`

`[TableName]` 表示一个单例命名空间，可承载静态字段、函数和模块级状态。它适合配置、工具模块和只需要一份实例的服务。

表头和字段声明顶格书写；缩进只用于函数或控制流代码块：

```xiao
[App]
name = "Xiao"
version = 1

def start()
    print(name)
```

单例表的字段是否默认可变、是否允许私有字段，需要在模块阶段补充可见性规则。

### 可实例化表 `[[TableName]]`

`[[TableName]]` 表示可通过 `new` 创建多个实例的类型表：

```xiao
[[User]]
name = ""

def init(self, name)
    self.name = name

def drop(self)
    close(self.name)
```

实例表支持字段、方法和生命周期钩子。`new` 的参数如何映射到 `init`，由类型检查器验证。

### 与字典表的边界

花括号集合和字典表都是运行时值，不自动生成类型或方法；方括号表是源码级命名空间/类型声明。它们不能仅凭相似的外观互换。

## 一级工程目标：实现生命周期

### 初始化

`def init(self)` 在实例构造成功后执行。初始化失败时，实例不能进入可用状态，也不能执行未完成对象的普通 `drop`。

### 释放

`def drop(self)` 在对象离开作用域或最后一个强引用释放时执行。它必须遵守第 06 阶段的确定性释放规则，不能依赖追踪式垃圾回收。

具体的字段释放顺序、异常中的释放行为和强引用环诊断仍待定。

## 一级工程目标：定义跨表访问和入口

### 跨域访问

跨表字段访问沿用显式插值形式：

```xiao
${App.name}
```

花括号用于标记跨表引用，不能省略。普通局部变量和同一表内部成员是否允许简写点号访问，需在语法阶段统一。

### `[main]` 工程入口

工程可以声明 `[main]` 表作为显式入口：

- 没有 `[main]`：顶层可执行语句组成脚本入口。
- 存在 `[main]`：入口由表声明决定，其他顶层语句作为模块初始化钩子。
- 多个入口、入口参数和退出码规则需要在 CLI 阶段定稿。

## 一级工程目标：建立模块边界

### 文件即模块

每个 `.xiao` 文件形成一个独立模块作用域。源码是模块的规范来源，不需要配套头文件或由用户维护的二进制接口描述。编译器可以在构建目录生成模块缓存，但缓存不能成为导入语义的一部分。

模块之间必须有显式导入关系，不能依赖文件扫描顺序隐式共享名称。一个模块的实际依赖写在使用它的源码中，而不是集中抄写到 `config.xiao`。

### 目录即命名空间

配置的源码根目录下，子目录按路径自动形成层级命名空间，不需要 `__init__.py` 或其他标记文件：

```text
src/main.xiao             -> main
src/app/user.xiao         -> app.user
src/app/http/client.xiao  -> app.http.client
```

目录命名空间不包含可执行初始化代码。导入命名空间只能用于解析其中的模块或限定名称；模块初始化只来自具体 `.xiao` 文件。

同一路径同时存在 `app.xiao` 与 `app/` 时是否允许模块和命名空间同名，仍需单独决定。

### 源码导入

导入语法采用 Python 风格，规划支持完整模块导入、别名和选择性符号导入：

```xiao
import net.http
import net.http as http
from app.models import User
```

上述三种形式已经确定为语法方向；相对导入、通配导入、同名冲突以及导入语句允许出现的位置仍待定。编译器根据所有源码导入边生成项目内部模块图。

### 默认私有与集中导出

模块和符号默认不向其他包公开。包作者在根目录 `config.xiao` 的导出配置中显式列出公共模块或公共符号，未列出的实现细节不能被外部依赖导入。

同一个包内部是否可以导入所有符号，还是也必须经过内部可见性声明，目前尚未确定。包外导出规则不应提前替这个问题作答。

## 一级工程目标：管理外部依赖

### 直接依赖写入配置

项目根目录统一使用全小写 `config.xiao`。它集中声明项目身份、直接外部依赖、包外导出和约束，但不逐条记录源码文件之间的实际导入，也不要求用户手写传递依赖树。

外部依赖以 Xiao 包为单位。每个包拥有自己的 `config.xiao` 和 `.xiao` 源码；具体支持注册表、路径、版本库中的哪些来源，留到依赖解析阶段冻结。

### 完整依赖树写入锁文件

依赖解析器读取所有包的直接依赖，计算完整依赖图，并生成工具维护的依赖锁文件。锁文件至少需要记录最终版本、来源、完整性信息和依赖边，使 `xiao run` 与 `xiao build` 使用同一组依赖。

锁文件不由用户日常手写。它的最终文件名、格式、应用项目与库项目是否采用不同提交策略，仍待定。

### 初始化与循环

编译器从内部模块图和外部包图计算确定的初始化顺序，每个具体模块至多初始化一次。目录命名空间永远不初始化。

循环导入是否一律拒绝，还是允许只涉及类型声明的循环，尚未决定。在规则冻结前不能依赖循环模块初始化。

### 尚待确定的模块规则

- 源码根目录默认值及模块路径与文件名的完整映射。
- 相对导入、通配导入和动态字符串导入。
- 包内可见性、符号级导出别名和重复名称处理。
- 模块与同名目录共存规则。
- 循环依赖和模块初始化失败的传播方式。
- `config.xiao` 是复用完整语法前端还是只允许不可执行的声明式语法子集。
- 版本约束、包来源、完整性校验及锁文件格式。

## 二级实现任务

### 模块实现子阶段

1. 先让词法器和解析器识别绝对模块导入，不进行文件加载。
2. 再实现单项目内的文件模块发现、纯目录命名空间和名称绑定。
3. 随后读取 `config.xiao` 的包身份与包外导出，建立最小包边界。
4. 本地模块闭环稳定后，才实现外部包来源、版本求解和锁文件。
5. 相对导入、循环依赖、动态导入和远程注册表都不能阻塞最小本地模块闭环。

### 表解析与符号表

1. 解析 `[Table]` 与 `[[Table]]` 的顶层边界。
2. 区分源码表、配置表和运行时字典表。
3. 为单例表和实例表建立不同的符号/布局信息。
4. 检查顶层字段是否重复或与方法冲突。

### 生命周期与入口

1. 将 `init`、`drop` 注册为特殊方法。
2. 生成脚本入口和工程入口两种初始化计划。
3. 为表实例生成构造、释放和成员访问 IR。
4. 在字节码与 LLVM 后端中保持相同调用顺序。

### 模块发现与名称解析

1. 从 `config.xiao` 指定的源码根构建文件模块和目录命名空间。
2. 解析完整模块导入、别名导入和选择性符号导入。
3. 由源码导入生成内部模块图，并诊断不存在或重复的模块路径。
4. 对照 `config.xiao` 的导出清单检查包外访问。

### 依赖解析与锁定

1. 只从 `config.xiao` 读取直接外部依赖。
2. 解析每个依赖包自己的配置并构建完整依赖图。
3. 生成稳定的依赖锁文件，后续运行和构建优先复用锁定结果。
4. 对版本冲突、来源冲突、完整性失败和缺失包给出不同诊断。

## 验收标准

### 表语义验收

- `[Table]` 和 `[[Table]]` 的实例数量、字段作用域和访问方式不会混淆。
- 集合和字典表仍然只是运行时值，不会被错误地当作类。
- 表字段顶格、代码体缩进的源码在所有平台生成相同 AST。

### 工程验收

- 脚本模式和 `[main]` 模式都有可执行的最小样例。
- 初始化失败、构造失败和释放钩子都有可追踪诊断。

### 模块验收

- 不创建 `__init__.py` 也能从目录路径解析模块命名空间。
- 目录不会生成隐藏的初始化函数，具体模块至多初始化一次。
- 源码导入边、`config.xiao` 直接依赖和锁文件完整依赖图职责互不混淆。
- 未经 `config.xiao` 导出的模块或符号不能被其他包导入。
- 字节码和原生构建消费同一份已经解析并锁定的依赖图。
