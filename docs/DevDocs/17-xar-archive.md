# 17. `.xar` 字节码归档与启动

> 本阶段定义类似 JAR 的 Xiao 字节码归档。`.xar` 面向可分发的字节码应用，由已安装的 `xiao` 启动器校验、定位入口并运行；归档携带外部/第三方依赖，但不携带由 Xiao Runtime 提供的官方依赖。

## Agent 交接上下文

### 接手前提

- 先阅读 [14. 字节码优化与 `.xiaoc` 产物](14-bytecode-optimization.md)、[16. SHA-256 内容寻址与二进制索引](16-content-addressed-artifacts.md) 和 [12. 测试与开发里程碑](12-tests-and-milestones.md) 的 O4 条目。
- 每个 `.xiaoc` 是一个模块；`.xar` 可以包含入口模块及其外部/第三方依赖模块的多个 `.xiaoc`。
- `.xar` 采用 ZIP/ZIP64 兼容容器，每个归档固定只有一个 `META-INF/xiao/index.pb`。归档运行依赖已安装的 Xiao Runtime；官方依赖不重复打包，第三方依赖必须按锁定结果随归档携带。

### 本阶段交付与不负责事项

- 交付：确定性 ZIP/ZIP64 配置、唯一 Protobuf 索引、内容寻址成员布局、归档校验、打包/列目录/验证/运行读取器和文件关联接口。
- 不负责：优化 Pass、`.xiaoc` 内部编码、全局缓存淘汰和 CLI 参数解析；这些分别由第 13、14、16、18 阶段提供稳定接口。
- 不生成自包含 Xiao Runtime；没有安装 `xiao` 时归档不能被声称为可运行。

### 交接检查

接手代理应能用一个只有 `print("hello world!")` 的 `.xiao` 文件生成测试归档，也能用包含第三方依赖的项目生成多模块归档；两种归档都必须在执行前完成唯一索引、依赖和摘要校验。

## 一级工程目标：定义归档模型

### 运行前提与自解释边界

`.xar` 不要求自解释，也不承诺脱离 `xiao` 和 Xiao Runtime 独立运行。它采用标准 ZIP/ZIP64 作为物理容器，通用 ZIP 工具可以列出、解压和检查成员；但 `META-INF/xiao/index.pb` 的 Protobuf Schema、入口解析、依赖约束、模块语义和字节码执行都由已安装的 `xiao`/Xiao Runtime 提供。归档不携带 Protobuf descriptor，不重复打包官方 Runtime，也不为没有 Xiao 的系统提供独立启动路径。

### 归档内容

`.xar` 使用一个固定位置的 `META-INF/xiao/index.pb` 同时承担归档清单、入口描述和对象索引，不再并列维护第二份 manifest 或入口文件。这个唯一的 Protobuf 消息至少记录：归档格式/Schema 版本、入口模块与函数或脚本顶层入口、依赖锁摘要、最低/最高 Runtime ABI、平台约束，以及每个模块、资源和可选调试对象的逻辑身份与 SHA-256。

ZIP 内部成员采用固定 ASCII 物理路径；用户可见的 UTF-8 模块名和资源路径只保存在索引中：

```text
META-INF/xiao/index.pb
objects/xiaoc/sha256/ab/<64-character-digest>.xiaoc
objects/resource/sha256/ab/<64-character-digest>
objects/debug/sha256/ab/<64-character-digest>
objects/source/sha256/ab/<64-character-digest>
```

其中 `ab` 是完整摘要的前两位。第一方模块和外部/第三方模块共享字节码对象目录，由索引字段区分来源、包身份和逻辑模块名，因此相同内容只保存一次。由 Xiao Runtime 提供的官方依赖只记录模块/ABI 要求，不把对象复制进归档。

打包输入允许三种形态：指定项目 `config.xiao`，指定包含 `[main]` 的 `.xiao` 文件，或指定任意 `.xiao` 文件。前两种根据项目入口和依赖锁生成归档；最后一种把该文件的脚本顶层入口作为归档入口，即使只有一条 `print("hello world!")` 也可以打包。输入解析不得执行配置或源码来猜测依赖，必须复用统一前端和声明式配置解析器。

归档必须在不读取项目源码、也不依赖构建机缓存的情况下携带并验证所需外部/第三方依赖；标准 `.xar` 不采用只引用外部缓存的瘦包语义。应用资源只收录 `config.xiao` 或将来冻结的单文件打包参数显式声明的路径，不扫描并复制整个项目目录。资源以内容摘要为物理名称，索引负责把它映射回经过规范化的逻辑路径；密钥、环境变量当前值和未声明文件不得被自动打包。

每个 `.xiaoc` 默认已经包含生成错误回溯所需的紧凑源码位置映射，所以标准发布归档保留行列定位，但默认不包含源码正文、完整局部变量表或扩展调试符号。显式调试打包可以把后两类信息写入独立的 `debug`/`source` 内容对象并由索引引用；准确 CLI 参数在第 18 阶段冻结。全部模块都标记为平台无关时，`.xar` 可在具有兼容 Runtime 的目标系统间移动；任何模块具有目标约束时，唯一索引必须把约束提升为归档运行条件。是否允许平台相关原生组件仍是后续决策。

### ZIP 兼容配置

`.xar` 必须可被标准 ZIP/ZIP64 读取器识别，但 Xiao Runtime 只接受以下受限配置：单卷归档、标准中央目录、UTF-8 标志、无加密、无自解压前缀、无符号链接；达到 ZIP32 上限时自动使用 ZIP64。`META-INF/xiao/index.pb` 使用 `STORE` 方式不压缩，以便启动器首先做有界读取。其余对象由打包器使用固定实现和固定级别 `DEFLATE-6` 试压缩，只有压缩结果更小时才使用 `DEFLATE`，否则使用 `STORE`。

ZIP 层的压缩不会改变对象身份：索引中的 SHA-256 始终针对解压后的规范对象字节。ZIP CRC 只能用于快速发现传输损坏，不能代替 SHA-256。为支持可复现构建，成员按物理路径字节序排列，时间戳固定为 ZIP 可表示的纪元 `1980-01-01 00:00:00`，归档注释为空，权限与额外字段规范化；除 ZIP64 必需字段外不写入实现私有 extra field。压缩器及版本必须进入工具链指纹。

### 确定性与安全

同一输入、依赖锁、优化配置和工具链应产生可比较的归档。归档读取必须拒绝路径穿越、绝对路径、重复或缺失的 `META-INF/xiao/index.pb`、重复物理成员、越界长度、未知必需版本、危险压缩比和哈希不匹配对象。索引内的逻辑资源路径同样必须拒绝空段、`.`、`..`、绝对路径和平台相关反斜杠穿越。

SHA-256 只能证明内容完整性，不能证明发布者身份。签名、信任来源、撤销和权限策略属于待定安全决策；在未完成前，启动器至少要在校验失败时拒绝执行并指出具体成员。

## 一级工程目标：实现运行与双击入口

### 启动流程

推荐的运行顺序为：打开 ZIP/ZIP64 中央目录 -> 有界读取唯一的 `META-INF/xiao/index.pb` -> 验证索引版本和结构 -> 校验所有将要加载的 `.xiaoc` 和资源 -> 检查虚拟机、Runtime、平台和依赖条件 -> 解析入口 -> 调用统一字节码运行接口。校验失败时不得部分执行已加载模块。

用户要求 `.xar` 可以双击直接用 `xiao` 运行，因而发布安装器或平台集成必须注册文件关联，把双击交给 `xiao` 启动器，而不是把文本编辑器当作默认程序。已确定的命令行入口为 `xiao -xar "<file.xar>"`；没有安装 `xiao` 或没有文件关联时，双击不能运行，命令行也应给出安装提示。是否保留其他别名由 CLI 阶段决定。

### 生命周期与更新

归档内对象按摘要视为不可变；更新应生成新归档或新对象，不原地改写运行中的归档。启动器要限制资源解压大小、递归深度和临时目录权限，并清理失败留下的临时内容。归档中的模块初始化仍遵守第 05/09 阶段“每个具体模块至多初始化一次”的契约。

## 二级实现任务

### 归档编解码

1. [17.1] 冻结受限 ZIP/ZIP64 配置、唯一索引消息、版本和内容寻址成员布局。
2. [17.2] 实现创建、列目录、验证、提取和读取流，执行固定元数据、成员排序及 `STORE`/`DEFLATE-6` 选择规则。
3. [17.3] 接入第 16 阶段的内容寻址对象和 Protobuf 索引，避免重复存储。
4. [17.4] 对截断、重复索引/成员、越界、ZIP bomb、路径穿越、加密、多卷和未知版本建立负例测试。

### 资源与诊断对象

1. [17.5] 收集显式声明资源并规范化逻辑路径，不自动打包项目目录、密钥或环境变量值。
2. [17.6] 将资源、可选完整调试符号和可选源码正文写为独立内容寻址对象，并在唯一索引中建立映射。
3. [17.7] 验证标准发布包只含紧凑源码位置映射，显式调试包不会改变程序语义。
4. [17.8] 对缺失资源、重复逻辑路径、摘要不匹配和未声明资源访问建立稳定诊断。

### 入口与运行器

1. [17.9] 定义唯一索引中的入口字段及其与 `[main]`、脚本顶层入口的映射。
2. [17.10] 在执行前完成归档、对象、第三方依赖、平台和 Runtime 验证。
3. [17.11] 调用第 09 阶段统一虚拟机接口，保留源码映射、错误回溯和 `drop` 记录。
4. [17.12] 实现缺少对象、版本不兼容、依赖未满足和校验失败的稳定错误码。

### 平台关联

1. [17.13] 为 Windows、Linux 和 macOS 设计可安装/可移除的 `.xar` 文件关联，并指向已安装的 `xiao`。
2. [17.14] 明确 `xiao -xar "<file.xar>"` 与双击时的工作目录、参数传递、标准输入输出和退出码行为。
3. [17.15] 在无图形界面或未安装关联时提供同一命令行入口和清晰安装提示，不提供无 Runtime 自包含承诺。
4. [17.16] 限制启动器权限和临时文件，记录可审计的验证结果。

## 验收标准

- `.xar` 能在目标平台被 `xiao` 验证并运行，且入口唯一明确。
- 归档内恰有一个固定路径的 Protobuf 索引；所有 `.xiaoc`、资源和可选调试对象均在执行前通过完整性、版本和路径安全检查。
- 双击入口与命令行入口使用同一字节码运行接口，输出、错误和退出码一致。
- 缺少依赖、Runtime、入口或对象时不会部分执行，诊断指出可修复原因。
- 相同输入和工具链生成的 ZIP 成员、压缩选择和规范化元数据稳定；跨平台差异有明确目标标记。
- 标准发布包保留紧凑行列回溯但不泄露源码正文或完整调试符号，只包含显式声明的资源。

## 待定决策

1. 唯一 Protobuf 索引的具体字段号、归档格式初始版本和入口消息细节。
2. 完整调试符号与源码正文的显式 CLI 参数，以及未来是否另行定义瘦包格式。
3. 平台相关原生组件的目标目录与选择规则；首个纯字节码闭环不自行引入原生成员。
4. 平台/架构兼容矩阵和旧归档迁移策略。
5. 文件关联安装器、权限、升级和未安装 `xiao` 时的提示方式。
6. 签名、信任、撤销、权限和沙箱策略。
