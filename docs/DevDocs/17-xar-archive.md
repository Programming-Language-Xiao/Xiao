# 17. `.xar` 字节码归档与启动

> 本阶段定义类似 JAR 的 Xiao 字节码归档。`.xar` 面向可分发的字节码应用，由已安装的 `xiao` 启动器校验、定位入口并运行；归档携带外部/第三方依赖，但不携带由 Xiao Runtime 提供的官方依赖。

## Agent 交接上下文

### 接手前提

- 先阅读 [14. 字节码优化与 `.xiaoc` 产物](14-bytecode-optimization.md)、[16. SHA-256 内容寻址与二进制索引](16-content-addressed-artifacts.md) 和 [12. 测试与开发里程碑](12-tests-and-milestones.md) 的 O4 条目。
- 每个 `.xiaoc` 是一个模块；`.xar` 可以包含入口模块及其外部/第三方依赖模块的多个 `.xiaoc`。
- Protobuf 是索引格式，归档运行依赖已安装的 Xiao Runtime。官方依赖不重复打包，第三方依赖必须按锁定结果随归档携带。

### 本阶段交付与不负责事项

- 交付：`.xar` 清单/成员布局、入口描述、Protobuf 索引嵌入、归档校验、打包/列目录/验证/运行读取器和文件关联接口。
- 不负责：优化 Pass、`.xiaoc` 内部编码、全局缓存淘汰和 CLI 参数解析；这些分别由第 13、14、16、18 阶段提供稳定接口。
- 不生成自包含 Xiao Runtime；没有安装 `xiao` 时归档不能被声称为可运行。

### 交接检查

接手代理应能用一个只有 `print("hello world!")` 的 `.xiao` 文件生成测试归档，也能用包含第三方依赖的项目生成多模块归档；两种归档都必须在执行前完成清单、索引、依赖和摘要校验。

## 一级工程目标：定义归档模型

### 归档内容

`.xar` 至少需要一个清单（manifest）、一个 Protobuf 二进制索引和一个入口描述，并能够携带一个或多个单模块 `.xiaoc` 对象。候选内容包括：

- 内容寻址的 `.xiaoc` 字节码对象及模块身份。
- 入口模块/函数、脚本顶层入口或 `[main]` 入口信息。
- 依赖锁定摘要、最小 Xiao 虚拟机/Runtime 版本和目标平台约束。
- 应用资源、配置默认值、源码映射和可选调试信息。
- 外部/第三方依赖的锁定 `.xiaoc` 对象；由 Xiao Runtime 提供的官方依赖不放入归档。

打包输入允许三种形态：指定项目 `config.xiao`，指定包含 `[main]` 的 `.xiao` 文件，或指定任意 `.xiao` 文件。前两种根据项目入口和依赖锁生成归档；最后一种把该文件的脚本顶层入口作为归档入口，即使只有一条 `print("hello world!")` 也可以打包。输入解析不得执行配置或源码来猜测依赖，必须复用统一前端和声明式配置解析器。

归档必须在不读取项目源码、也不依赖构建机缓存的情况下携带并验证所需外部/第三方依赖；标准 `.xar` 不采用只引用外部缓存的瘦包语义。是否压缩、是否携带源码/调试信息、是否允许原生组件，仍需在本阶段细化。不能因为文件扩展名相同就假设所有 `.xar` 在任何平台都可运行。

### 确定性与安全

同一输入、依赖锁、优化配置和工具链应产生可比较的归档：成员顺序、清单字段顺序、压缩参数和时间元数据需要规范化。归档读取必须拒绝路径穿越、绝对路径、重复关键清单、越界长度、未知必需版本和哈希不匹配对象。

SHA-256 只能证明内容完整性，不能证明发布者身份。签名、信任来源、撤销和权限策略属于待定安全决策；在未完成前，启动器至少要在校验失败时拒绝执行并指出具体成员。

## 一级工程目标：实现运行与双击入口

### 启动流程

推荐的运行顺序为：打开 `.xar` -> 读取并验证归档头/清单/索引 -> 校验所有将要加载的 `.xiaoc` 和资源 -> 检查虚拟机、Runtime、平台和依赖条件 -> 解析入口 -> 调用统一字节码运行接口。校验失败时不得部分执行已加载模块。

用户要求 `.xar` 可以双击直接用 `xiao` 运行，因而发布安装器或平台集成必须注册文件关联，把双击交给 `xiao` 启动器，而不是把文本编辑器当作默认程序。已确定的命令行入口为 `xiao -xar "<file.xar>"`；没有安装 `xiao` 或没有文件关联时，双击不能运行，命令行也应给出安装提示。是否保留其他别名由 CLI 阶段决定。

### 生命周期与更新

归档内对象按摘要视为不可变；更新应生成新归档或新对象，不原地改写运行中的归档。启动器要限制资源解压大小、递归深度和临时目录权限，并清理失败留下的临时内容。归档中的模块初始化仍遵守第 05/09 阶段“每个具体模块至多初始化一次”的契约。

## 二级实现任务

### 归档编解码

1. [17.1] 冻结 `.xar` 魔数、版本、清单、Protobuf 索引位置和成员布局。
2. [17.2] 实现创建、列目录、验证、提取和读取流，支持确定性成员排序。
3. [17.3] 接入第 16 阶段的内容寻址对象和 Protobuf 索引，避免重复存储。
4. [17.4] 对截断、重复、越界、路径穿越和未知版本建立负例测试。

### 入口与运行器

1. [17.5] 定义入口字段与 `[main]`、脚本顶层入口的映射。
2. [17.6] 在执行前完成归档、对象、第三方依赖、平台和 Runtime 验证。
3. [17.7] 调用第 09 阶段统一虚拟机接口，保留源码映射、错误回溯和 `drop` 记录。
4. [17.8] 实现缺少对象、版本不兼容、依赖未满足和校验失败的稳定错误码。

### 平台关联

1. [17.9] 为 Windows、Linux 和 macOS 设计可安装/可移除的 `.xar` 文件关联，并指向已安装的 `xiao`。
2. [17.10] 明确 `xiao -xar "<file.xar>"` 与双击时的工作目录、参数传递、标准输入输出和退出码行为。
3. [17.11] 在无图形界面或未安装关联时提供同一命令行入口和清晰安装提示，不提供无 Runtime 自包含承诺。
4. [17.12] 限制启动器权限和临时文件，记录可审计的验证结果。

## 验收标准

- `.xar` 能在目标平台被 `xiao` 验证并运行，且入口唯一明确。
- 归档内所有 `.xiaoc`、索引和资源均在执行前通过完整性、版本和路径安全检查。
- 双击入口与命令行入口使用同一字节码运行接口，输出、错误和退出码一致。
- 缺少依赖、Runtime、入口或对象时不会部分执行，诊断指出可修复原因。
- 相同输入生成的归档成员顺序和规范化元数据稳定；跨平台差异有明确目标标记。

## 待定决策

1. `.xar` 采用 ZIP 兼容容器还是自定义容器，是否压缩及压缩算法。
2. 归档内第三方依赖、资源、源码和调试信息的精确布局，以及未来是否另行定义瘦包格式。
3. 入口字段、平台/架构矩阵、版本兼容和旧归档迁移策略。
4. 文件关联安装器、权限、升级和未安装 `xiao` 时的提示方式。
5. 签名、信任、撤销、权限和沙箱策略。
