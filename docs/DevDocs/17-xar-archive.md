# 17. `.xar` 字节码归档与启动

> 本阶段定义类似 JAR 的 Xiao 字节码归档。`.xar` 面向可分发的字节码应用，由 `xiao` 启动器校验、定位入口并运行；它是否自带完整 Runtime 和全部依赖，尚未冻结。

## 一级工程目标：定义归档模型

### 归档内容

`.xar` 至少需要一个清单（manifest）、一个二进制索引和一个入口描述，并能够引用或携带一个或多个 `.xiaoc` 对象。候选内容包括：

- 内容寻址的 `.xiaoc` 字节码对象及模块身份。
- 入口模块/函数、脚本顶层入口或 `[main]` 入口信息。
- 依赖锁定摘要、最小 Xiao 虚拟机/Runtime 版本和目标平台约束。
- 应用资源、配置默认值、源码映射和可选调试信息。
- 可选的外部依赖引用、内嵌依赖或平台相关 Runtime。

归档是否是“瘦包”（只带索引和外部对象）还是“胖包”（把传递依赖全部带入），是否压缩、是否携带源码/调试信息、是否允许原生组件，必须在本阶段冻结。不能因为文件扩展名相同就假设所有 `.xar` 在任何平台都可运行。

### 确定性与安全

同一输入、依赖锁、优化配置和工具链应产生可比较的归档：成员顺序、清单字段顺序、压缩参数和时间元数据需要规范化。归档读取必须拒绝路径穿越、绝对路径、重复关键清单、越界长度、未知必需版本和哈希不匹配对象。

SHA-256 只能证明内容完整性，不能证明发布者身份。签名、信任来源、撤销和权限策略属于待定安全决策；在未完成前，启动器至少要在校验失败时拒绝执行并指出具体成员。

## 一级工程目标：实现运行与双击入口

### 启动流程

推荐的运行顺序为：打开 `.xar` -> 读取并验证归档头/清单/索引 -> 校验所有将要加载的 `.xiaoc` 和资源 -> 检查虚拟机、Runtime、平台和依赖条件 -> 解析入口 -> 调用统一字节码运行接口。校验失败时不得部分执行已加载模块。

用户要求 `.xar` 可以双击直接用 `xiao` 运行，因而发布安装器或平台集成必须注册文件关联，把双击交给 `xiao` 启动器，而不是把文本编辑器当作默认程序。是否同时提供 `xiao run <file.xar>`、直接写 `xiao <file.xar>` 和无 Xiao 安装的自包含启动器，列入 CLI 阶段确认。

### 生命周期与更新

归档内对象按摘要视为不可变；更新应生成新归档或新对象，不原地改写运行中的归档。启动器要限制资源解压大小、递归深度和临时目录权限，并清理失败留下的临时内容。归档中的模块初始化仍遵守第 05/09 阶段“每个具体模块至多初始化一次”的契约。

## 二级实现任务

### 归档编解码

1. 冻结 `.xar` 魔数、版本、清单、索引位置和成员布局。
2. 实现创建、列目录、验证、提取和读取流，支持确定性成员排序。
3. 接入第 16 阶段的内容寻址对象和二进制索引，避免重复存储。
4. 对截断、重复、越界、路径穿越和未知版本建立负例测试。

### 入口与运行器

1. 定义入口字段与 `[main]`、脚本顶层入口的映射。
2. 在执行前完成归档、对象、依赖、平台和 Runtime 验证。
3. 调用第 09 阶段统一虚拟机接口，保留源码映射、错误回溯和 `drop` 记录。
4. 实现缺少对象、版本不兼容、依赖未满足和校验失败的稳定错误码。

### 平台关联

1. 为 Windows、Linux 和 macOS 设计可安装/可移除的 `.xar` 文件关联。
2. 明确双击时工作目录、参数传递、标准输入输出和退出码行为。
3. 在无图形界面或未安装关联时提供 `xiao run` 等命令行退化路径。
4. 限制启动器权限和临时文件，记录可审计的验证结果。

## 验收标准

- `.xar` 能在目标平台被 `xiao` 验证并运行，且入口唯一明确。
- 归档内所有 `.xiaoc`、索引和资源均在执行前通过完整性、版本和路径安全检查。
- 双击入口与命令行入口使用同一字节码运行接口，输出、错误和退出码一致。
- 缺少依赖、Runtime、入口或对象时不会部分执行，诊断指出可修复原因。
- 相同输入生成的归档成员顺序和规范化元数据稳定；跨平台差异有明确目标标记。

## 待定决策

1. `.xar` 采用 ZIP 兼容容器还是自定义容器，是否压缩及压缩算法。
2. 瘦包/胖包选择，是否携带传递依赖、Runtime、资源、源码和调试信息。
3. 入口字段、平台/架构矩阵、版本兼容和旧归档迁移策略。
4. 双击是否要求预先安装 `xiao`，还是提供带启动器/Runtime 的自包含发布形式。
5. 签名、信任、撤销、权限和沙箱策略。
