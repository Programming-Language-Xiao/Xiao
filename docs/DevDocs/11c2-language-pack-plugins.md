# 11C-2. 语言包插件与安全

> **11C 的 L3。** 11C-0 建了模型与上下文，11C-1 把内置的 317 个目录键搬完并贯通了渲染器。
> 本批做**最后一件事**：让**第三方**能提供语言包——**纯资源、可校验、不执行代码**。
>
> **本批的性质与前面两批不同**：它引入**外部输入**。
> 内置目录是本仓自己写的，插件是**别人给的**，且**要经网络分发**。
> 所以本批的重心不是"翻译能不能显示"，而是**「不可信资源进来之后，边界守不守得住」**。
>
> **做完本批，11C 只剩 L4**（跨平台与发布），而 L4 的 `:126` 依赖 `.xar` 与原生后端，
> 要等工程期——**所以本批是 11C 当前阶段能收口的最后一块**。

## 三、必须先冻结的 6 条

### 3.1 **不执行插件代码**（本批的红线，与 11A 同源）

`11c:88` 明确：插件目录**只能包含声明式清单和消息资源**
（目录文件、复数/格式规则数据），**首个实现不得加载插件代码、执行初始化钩子、
或访问用户项目**。

**冻结**：

- **清单是纯数据**——解析它**不得**涉及任何求值、`eval`、动态导入或脚本引擎；
- **资源文件只读**——不执行、不解码为可执行形式；
- **⚠️ 这条与 11A 的「首个远程闭环拒绝任意安装前/后/卸载脚本」是同一条原则的两次落地**。
  **本批不重开它的讨论**，直接沿用；
- **要有负例测试**：构造一个"清单里藏可执行内容"的插件，断言**它被拒绝或至少从不执行**
  （做法参照既有「不执行包代码」的**副作用探针**）。

### 3.2 安装走 **11A 的既有链路**，不另建

`11c:88`：「插件安装和更新**沿用 11A 的锁文件、源优先级、不可变缓存和来源审计规则**」。

**冻结**：

- **不新建一套"插件安装器"**——复用 11A 的包源适配、锁文件、内容寻址缓存、摘要校验；
- **⚠️ 但插件有自己的清单**（`11c:84` 列了六类声明）——
  **清单是插件的元数据，不是"又一种包格式"**。
  两者的关系要**说清楚**（§3.3），否则会变成"包管理里长出一个平行的东西"；
- **安装来源、版本、摘要要能审计**——沿用 11A 的来源审计，
  **诊断里要有来源与摘要**（`11c:150` 第 2 条）。

实现上，11A 负责从已配置的源选择版本、写入锁文件并完成来源与正文摘要审计；
`xiao-package` 只在这条链路完成后接收语言包目录，调用语言包校验并导入独立的
`language/sha256` 不可变对象空间。这个导入接口不是绕过 11A 的安装入口：直接给它一个
本地目录只适用于已经由 11A 验证过的包正文，首版不提供平行的语言包安装器或独立来源协议。

### 3.3 插件与包的关系（**要显式定义，不能含糊**）

这是本批最容易含混的一点：插件要"走包的安装链路"，但它**不是普通包**。

**冻结**：

- **插件是"一类资源型包"**——它有清单、有摘要、可安装、可锁版本，
  **但不含可执行内容**，所以 11A 里"安装后要能运行"的那部分语义**不适用于它**；
- 11A 的**源选择、锁定、来源审计、正文摘要和不可变缓存**适用；语言包资源对象导入
  复用这些结果，但不重复建立来源或锁文件；
- 11A 的**普通包依赖图不适用于语言包之间的关系**：首版语言包是依赖图中的叶资源，
  不声明插件间依赖，也不参与插件依赖求解。若项目把一个语言包作为包来源中的条目，
  仍由 11A 解析其包身份和锁定版本，语言包清单不会偷偷扩展普通包依赖图；
- `package_version` 必须是严格三段 SemVer，只用于 11A 锁定、审计和诊断身份，**不进入
  运行时兼容判断，也不进入语言资源缓存键**；
- 清单中的 `xiao_version` 与 `runtime_abi` 只用于当前宿主的受限 SemVer 合取兼容检查，
  不用于选择依赖、不触发升级，也不允许表达插件间关系。首版支持 `*`、严格三段版本、
  `^`/`~`、比较运算和逗号连接的合取；项之间不得含空白；
- 普通包的入口、初始化、安装后运行、卸载钩子和用户项目访问语义均**不适用于语言包**。
  加载只解析声明式 JSON 清单和目录资源；
- 运行时同一 `plugin_id` 只保留一个由 11A 选中的版本。重新激活同一标识时，新目录会
  原子替换该插件旧目录；若与内置目录或其他插件冲突，候选注册表整体回滚，不靠安装顺序
  决定优先级。

### 3.4 命名空间冲突：**拒绝，且不依赖安装顺序**

`11c:91-93`：

- 内置目录拥有 `xiao.*`、`runtime.*`、`cli.*`、`repl.*`、`package.*` 等**核心命名空间**；
- 插件**可以新增自己的命名空间**，或**完整提供新的语言标签**；
- **但不能无提示覆盖内置条目**；
- **重复 `message_id`、参数签名不一致、目录版本不兼容 → 拒绝，并报告来源和摘要**；
- **⚠️「未来若要允许用户明确覆盖文案，必须另行定义信任和优先级，不得依赖安装顺序」**
  ——**本批不实现覆盖**，但**要在文档里留这句话**，否则将来有人会拿安装顺序凑一个优先级。

**⚠️ 冲突检测要对着"权威清单"做**（§2.2）：**内置的 317 个键 + 台账**，
**不要另扫源码**——那是两处各判一次。

### 3.5 缓存键与不可变性

`11c:95-97`：

- **目录版本、Xiao 版本、Runtime ABI 都要进语言资源缓存键**；
- **缓存对象按内容摘要保存并设为只读**；
- **语言配置变化只切换目录**，**不修改错误对象或源码**；
- **同一目录内容在多项目中可复用且保持只读**（`11c:150` 第 3 条）。

首版语言资源对象位于：

```text
<XIAO_HOME>/cache/objects/language/sha256/
  catalog-v<目录版本>/xiao-v<Xiao 版本>/abi-<Runtime ABI>/<内容摘要>/
```

内容摘要只覆盖清单中声明的目录资源，不包含清单自身；资源路径按字节序排序，摘要输入
为领域标签 `xiao-language-pack-v1`、路径长度和路径字节、资源长度和资源字节的长度前缀
序列，长度使用大端 `u64`，结果为小写 64 位十六进制 SHA-256。资源对象提交后设为只读，
校验失败的对象移动到 `.corrupt` 隔离名；语言对象与源码、元数据缓存使用不同命名空间。

**⚠️ 现有缓存键不含这三要素**——本批要补，且**补的时候不要影响既有缓存的其他用途**
（11A 的内容寻址缓存是共用的）。

### 3.6 加载失败的降级：**当前进程保留、新进程拒绝**

`11c:97`：

> 目录加载失败时**保留上一次已验证目录供当前进程使用**，同时记录诊断；
> **新进程不能继续使用已知摘要不匹配的资源**。

**冻结**：

- **这是"进程内降级、进程间严格"的不对称设计**——要显式写清，否则会被当成 bug；
- **理由**：正在跑的进程突然换回内置目录会让用户看到语言中途变化；
  **而新进程没有这个包袱，应当从严**；
- **⚠️ "保留上一次"只对"已验证"的目录有效**——**从未验证成功的，不能保留**；
- **诊断要能区分**："用着旧目录"和"完全不可用"是两件事。

## 九、验收

**以 [11C 规范](11c-localization.md) `:145-150` 的插件验收为准**，本批补充：

1. **不执行**：加载插件**不执行任何插件代码**、安装钩子或用户项目代码——**有探针**（§3.1）。
2. **冲突拒绝**：重复核心 `message_id`、参数签名不一致、版本不兼容、**摘要错误**
   都会拒绝，**并指出来源与原因**（`:146`、§3.4）。
3. **缓存隔离**：语言配置变化**不污染**源码/字节码/依赖缓存；
   **同一目录内容在多项目中可复用且保持只读**（`:150`、§3.5）。
4. **缓存键**：目录版本、Xiao 版本、Runtime ABI **都在键里**（§3.5）。
5. **降级不对称**：当前进程保留**已验证**的旧目录并记诊断；**新进程拒绝**摘要不匹配的资源（§3.6）。
6. **回退链**：插件缺条目时走 `11c:74-77` 的四级回退，**不显示空白、不抛新异常**。
7. **机器输出不变**：`code`/`message_id`/参数/位置/退出码跨语言一致（`11c:112`）。
8. **§3.3 的问题有明确答案**（依赖图、版本约束是否适用），且写进文档（§七 第 1 步）。
9. **不回归**：11B、I4 系列、11C-0/11C-1 的用例保持绿；**`cargo test --workspace`** 全绿。
10. **门禁全绿**。

当前实现的定向回归覆盖：有效目录和四级回退、清单/资源拒绝、摘要与兼容性失败、核心键和
参数签名冲突、同插件原子更新、进程内降级/新进程不可用，以及语言对象跨项目复用、只读和
损坏隔离。完整仓库门禁仍按本节命令执行，不以定向测试代替全量验收。
