# 15. LLVM 原生优化与链接

> 本阶段把第 13 阶段的优化契约接入 LLVM 原生后端。它只改变原生程序的性能、体积、启动时间或编译成本，不改变 Xiao 的数值、错误、生命周期和容器语义。

## Agent 交接上下文

### 接手前提

- 先阅读 [10. LLVM 原生后端](10-native-backend.md)、[13. 优化契约与统一管线](13-optimization-contract.md) 和 [12. 测试与开发里程碑](12-tests-and-milestones.md) 的 O0/O2 条目。
- 第 10 阶段已有未优化原生构建接口、目标描述和 Runtime ABI；第 13 阶段提供统一优化配置、效果边界和差分测试。
- 对外首组级别固定为 `-O0`、`-O1`、`-O2`、`-O3`。LTO、PGO、目标 CPU 特化等扩展不因本阶段存在就自动进入默认级别。

### 本阶段交付与不负责事项

- 交付：LLVM Pass 映射、级别开关、Runtime 裁剪、调试/可复现构建支持和性能基线。
- 不负责：`.xiaoc` 文件编码、Protobuf 索引、`.xar` 归档和 TypeScript 参数解析；这些接口只通过稳定后端契约接收。
- 不得用 LLVM 的未定义行为假设替代 Xiao 的溢出、错误、所有权或 Runtime 检查。

### 交接检查

下一位代理应能使用同一类型化 IR 在 `-O0` 和已实现级别之间复现 LLVM IR、目标参数、Pass 报告和差分结果；构建不能依赖本机绝对路径或未记录的 CPU 特性。

## 一级工程目标：建立 LLVM 优化管线

### 级别映射

LLVM Pass 管线必须由规范化优化配置驱动，并与字节码路径共享语义边界。首组对外级别为 `-O0`、`-O1`、`-O2`、`-O3`，普通 `xiao build` 未收到显式配置时采用 `-O0`；调试、发布、体积优先和可诊断方向可以作为内部构建属性，`-Os`、`-Oz` 等额外级别另行确认。

`O0` 是默认未优化路径和差分基线，但仍执行合法 IR 降低、必要的 ABI 规范化、验证和链接；它不能被解释为跳过安全检查。普通原生构建直接从类型化 IR 进入 LLVM 管线，不为 LLVM 不消费的模块强制额外生成 `.xiaoc`。任何级别都不能启用 LLVM 的快速数学近似、未定义溢出回绕或会跳过 Xiao Runtime 检查的选项。目标 CPU、链接时优化（LTO）、PGO、向量化和跨模块内联在首版是否启用，必须有单独配置和缓存指纹。

### Runtime 裁剪与调试

后端可以根据优化后的 IR 和链接图裁剪未使用的 Runtime 组件，但不能借“不可达”判断删除可能产生错误、释放、随机或外部 I/O 的路径。调试构建应保留足够源码映射、栈回溯和变量信息，并保留调试激活位及独立诊断组件的启动能力；发布构建是否剥离源码、符号或诊断区，交由发布阶段冻结。

## 一级工程目标：保持跨平台一致

### 目标与 ABI

优化配置必须记录目标三元组、架构、Runtime ABI、LLVM/链接器版本及所有目标特化参数。平台验收顺序固定为 **Windows → Linux → macOS**：后一个平台只有在前一个平台的语义、ABI 和产物回归可复现后才进入正式门槛，同一 Xiao 语义测试集最终必须在三个目标上通过。固定宽度类型、高精度数值和溢出错误沿用第 10 阶段规则，不能由 LLVM 优化级别改变。

第 19 阶段的 Java 性能对照只使用 `xiao build` 的 LLVM 原生发布路径；本阶段负责提供各 `-O` 级别的可重复原生产物和测量数据，不以字节码解释速度替代原生基线。

### 产物比较

原生优化结果要与同一类型化 IR 的未优化原生结果、未优化/优化字节码进行差分。允许指令布局、文件体积和时间不同，不允许标准输出、退出码、错误类别、随机序列、容器顺序或 `drop` 记录不同。

## 二级实现任务

### Pass 与链接接入

1. [15.1] 把第 13 阶段的规范化配置转换为 LLVM Pass 管线。
2. [15.2] 分别实现函数内、跨模块、链接时和目标特化 Pass 的开关及验证。
3. [15.3] 让 Runtime 裁剪依据可证明的调用图和效果摘要，不依赖链接器偶然删除。
4. [15.4] 输出 Pass 报告、LLVM 版本和目标参数，纳入构建指纹。

### 调试与可复现构建

1. [15.5] 维护优化指令到源码位置的映射和内联栈信息。
2. [15.6] 规范化构建时间、路径和符号排序，支持重复构建结果比较。
3. [15.7] 对 strip、调试符号和可诊断模式建立独立验收。
4. [15.8] 对三平台的链接器差异、Runtime ABI 和失败原因提供稳定诊断。

### 性能基线

1. [15.9] 测量每个级别的编译时间、启动时间、运行时间、内存和文件体积。
2. [15.10] 使用固定硬件/容器条件记录可比较基线，区分噪声和真实回归。
3. [15.11] 优化收益不足或 Pass 不适用时保留可运行结果，不得为追求指标破坏语义。

## 验收标准

- 同一 IR 在未优化和各已冻结级别下的原生结果通过双模式差分。
- 未使用的 Runtime 组件可以裁剪，并能通过报告解释保留/删除原因。
- 三个平台的固定宽度数值、溢出、错误和释放行为一致。
- 可复现构建不受机器绝对路径、时间戳或未定义排序影响，或差异具有明确白名单。
