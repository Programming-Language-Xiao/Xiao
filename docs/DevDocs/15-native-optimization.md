# 15. LLVM 原生优化与链接

> 本阶段把第 13 阶段的优化契约接入 LLVM 原生后端。它只改变原生程序的性能、体积、启动时间或编译成本，不改变 Xiao 的数值、错误、生命周期和容器语义。

## 一级工程目标：建立 LLVM 优化管线

### 级别映射

LLVM Pass 管线必须由规范化优化配置驱动，并与字节码路径共享语义边界。调试、发布、体积优先和可诊断方向可以作为抽象构建配置；是否对外暴露 C 风格 `-O0`、`-O1`、`-O2`、`-O3`、`-Os` 或 `-Oz` 尚待确认。

`O0` 或等价的未优化路径应作为差分基线。任何级别都不能启用 LLVM 的快速数学近似、未定义溢出回绕或会跳过 Xiao Runtime 检查的选项。目标 CPU、链接时优化（LTO）、PGO、向量化和跨模块内联在首版是否启用，必须有单独配置和缓存指纹。

### Runtime 裁剪与调试

后端可以根据优化后的 IR 和链接图裁剪未使用的 Runtime 组件，但不能借“不可达”判断删除可能产生错误、释放、随机或外部 I/O 的路径。调试构建应保留足够源码映射、栈回溯和变量信息；发布构建是否剥离源码、符号或诊断区，交由发布阶段冻结。

## 一级工程目标：保持跨平台一致

### 目标与 ABI

优化配置必须记录目标三元组、架构、Runtime ABI、LLVM/链接器版本及所有目标特化参数。Windows、Linux 和 macOS 可逐个平台验收，但同一 Xiao 语义测试集必须在三个目标上通过。固定宽度类型、高精度数值和溢出错误沿用第 10 阶段规则，不能由 LLVM 优化级别改变。

### 产物比较

原生优化结果要与同一类型化 IR 的未优化原生结果、未优化/优化字节码进行差分。允许指令布局、文件体积和时间不同，不允许标准输出、退出码、错误类别、随机序列、容器顺序或 `drop` 记录不同。

## 二级实现任务

### Pass 与链接接入

1. 把第 13 阶段的规范化配置转换为 LLVM Pass 管线。
2. 分别实现函数内、跨模块、链接时和目标特化 Pass 的开关及验证。
3. 让 Runtime 裁剪依据可证明的调用图和效果摘要，不依赖链接器偶然删除。
4. 输出 Pass 报告、LLVM 版本和目标参数，纳入构建指纹。

### 调试与可复现构建

1. 维护优化指令到源码位置的映射和内联栈信息。
2. 规范化构建时间、路径和符号排序，支持重复构建结果比较。
3. 对 strip、调试符号和可诊断模式建立独立验收。
4. 对三平台的链接器差异、Runtime ABI 和失败原因提供稳定诊断。

### 性能基线

1. 测量每个级别的编译时间、启动时间、运行时间、内存和文件体积。
2. 使用固定硬件/容器条件记录可比较基线，区分噪声和真实回归。
3. 优化收益不足或 Pass 不适用时保留可运行结果，不得为追求指标破坏语义。

## 验收标准

- 同一 IR 在未优化和各已冻结级别下的原生结果通过双模式差分。
- 未使用的 Runtime 组件可以裁剪，并能通过报告解释保留/删除原因。
- 三个平台的固定宽度数值、溢出、错误和释放行为一致。
- 可复现构建不受机器绝对路径、时间戳或未定义排序影响，或差异具有明确白名单。

## 待定决策

3. 调试信息/源码映射的发布保留策略。
4. 原生二进制是否加入与 `.xiaoc` 相同的内容寻址缓存和索引。
