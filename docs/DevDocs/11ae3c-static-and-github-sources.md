## 三、必须先冻结的 6 条

### 3.1 HTTP 客户端：`ureq`（**已冻结，理由是硬的**）

**`11A-CONC` §1.2 已冻结**：「不引入 `rayon`、`crossbeam`、**`tokio`**、`async-std`
或任何任务池 crate」，且「不在工具链内部引入 `async`/`await`」。

**`reqwest` 因此不可用**——它默认依赖 tokio，其 blocking 模式的内部实现也是 tokio runtime，
**依赖树里仍然有 tokio**。

**冻结**：用 **`ureq`**（纯同步 API、无线程池、无 async）。
TLS 由 `ureq` 的 rustls/native-tls 特性提供——**TLS 是 HTTPS 的必需项，不算违反 §1.2**。

**⚠️ 与并行的关系**：`ureq` 是同步阻塞的，所以**并行读源仍用
`11A-CONC` §1.2 的 `std::thread::scope`**——E3B 的 `fastpath.rs` 已有此结构，
**本批不改它**，只是把适配器的实现从"本地目录"换成"HTTP"。

### 3.2 分支 → 不可变 commit：HTTP 取 `info/refs`（**已冻结**）

`11a:338` 要求「不强依赖 GitHub 私有 API」且「避免为查询一个包而克隆完整历史」。

**冻结做法**：

```text
GET <repo>/info/refs?service=git-upload-pack
  → pkt-line：<sha> refs/heads/main
GET <raw-base>/<sha>/snapshot.json
GET <raw-base>/<sha>/index/<package>.json
```

- **零 git 依赖**——不引 `git2`/`gix`，也不要求用户装 `git`；
- **不拉取任何 git 对象**——只解析 refs 再按不可变 commit 取文件，
  天然满足「不为查一个包克隆完整历史」；
- **不依赖 GitHub 专有 API**——`info/refs` 是任何 git 服务端都支持的标准端点。

**⚠️ 要写 pkt-line 解析**：格式是 `<4 位十六进制长度><内容>`，`0000` 为 flush-pkt。
**必须处理好畸形输入**（长度不合法、超长行、非 UTF-8）——这是**对端可控的输入**，
不能 `unwrap`。

**⚠️ 拒绝姿态沿用 `:297`**：不认识的协议版本、无法解析的 refs **必须明确拒绝并诊断**，
**不得尽力而为地解析或静默降级**。

### 3.3 静态源的 URL 形态

E3A 已冻结**文件名与分片形状**（`snapshot.json`、`index/<package>.json`、JCS SHA-256）。
本批补**它们如何被取到**：

- `location` 是**基址**，快照与分片是**相对于它的路径**；
- **必须固定基址拼接规则**（尾斜杠归一、不允许路径穿越 `..`）；
- **⚠️ 重定向策略**：跟随与否、跟随几次、跨 host 跟随是否允许——**要定死**，
  且跨 host 跟随要在诊断里记下最终来源（否则"源身份"与"实际来源"会脱节）。

### 3.4 单仓库直接依赖的 `config.xiao` 语法（**`11a:340` 明说是本批要冻结的**）

`11a:340`：「两者最终都要归一化为相同的包身份、依赖元数据和内容摘要，
但命令/config 表达及**首版是否同时实现仍需分别冻结**。」——**本批两者都做，所以要冻结语法。**

D1 冻结的依赖字段白名单是 `path`/`version`/`source`
（`xiao-config/src/validation.rs:231` 处校验后两者）。**本批要扩**：

```xiao
[Dependencies]
lib = { git = "https://github.com/acme/lib.git", rev = "v1.2.0" }
```

**要一并冻结的约束**：

- **`path` 与 `git` 互斥**——同时给必须报错，不能"后者胜"；
- **`rev` / `tag` / `branch` 三者至多一个**——多个必须报错；
- **`git` 缺省引用**：只给 `git` 不给 `rev`/`tag`/`branch` 时用什么？
  建议**报错要求显式**（否则"默认分支"是可变名称，与 `:338` 的
  「不得把可变名称当成完整性证明」冲突）；
- **`git` + `version`**：`version` 是约束文本，D1 起就"只保存不求解"（E3D 才求解）。
  **本批不改这个口径**。
- **锁文件要记录解析出的不可变 commit**（`11a:338` 要求）——E2A 的
  `LockedPackage.source` 已能承载源身份，**确认它能表达 commit 引用**。

### 3.5 可变名称的拒绝规则（`:338` 已给方向，本批落成判据）

`:338`：「分支可以用于发现新的仓库索引状态，但**锁文件必须固定实际解析时的不可变提交**、
标签解析结果或仓库快照摘要；**同一标签或路径内容变化且摘要不符时必须拒绝**，
**不得把可变名称当成完整性证明**。」

**要冻结的判据**：

| 场景 | 行为 |
| --- | --- |
| 锁文件记录的 commit 与本次解析一致 | 复用（走 E3B 的快速路径） |
| 锁文件记录的 **tag** 现指向**另一个 commit** | **拒绝**并诊断——tag 被改写 |
| 同 commit、`snapshot.json` 内容变化 | **拒绝**并诊断——摘要不符 |
| 分支前进 | **正常**，但要更新锁文件（`sync` 的既有规则） |

**⚠️ 这条要有反例测试**：构造"同名 tag 指向新 commit"与"同 commit 下文件被改"两种，
断言**拒绝**而不是静默采用。

### 3.6 适配器差异不得改变语义（`12-tests:777` 明文）

`:777`：「源适配器对注册表、静态目录、本地目录和符合规范的 GitHub 仓库提供
**一致的解析结果**」。所以：

- **适配器只能产出规范化记录**，不得让传输方式影响源顺序、候选语义或诊断码；
- **同一条 `snapshot.json` 通过 HTTP 取和通过本地目录取，结果必须逐字节相同**
  （这是可测的，且是本批最该有的跨适配器一致性测试）。

### 5.3 测试驱动（**远程适配器怎么测**）

**⚠️ 这是本批最难的一点**：CI 不能依赖真实网络。

- **pkt-line 解析**：纯函数，用**夹具字节**测（含畸形输入）；
- **HTTP 静态源**：起一个**本机 HTTP 服务**（`std::net::TcpListener` 手写极简响应即可，

- **GitHub 适配器**：**不测真实 GitHub**——测的是"给定 refs 响应与 raw 文件，产出正确的
  不可变引用与记录"；**真实 GitHub 的联调不进 CI**（可作为显式门控的手动项，按 `10D` 的
  `#[ignore]` 惯例）。
- **跨适配器一致性**（§三.6）：同一份夹具，本地目录与 HTTP 两条路径产出必须相同。

## 九、验收

1. **条件 4/10**：静态 HTTP 源与 GitHub 源各自能产出**可验证的完整索引快照**；
   **同一夹具经本地/HTTP/（模拟）GitHub 三条路径产出逐字节相同**（§三.6）。
2. **不可变提交**：分支→commit 解析正确；**tag 被改写 → 拒绝**；
   **同 commit 内容变化 → 拒绝**（§3.5 两条反例）。
3. **协议版本**：不认识的版本**拒绝并诊断**（`:297`）。
4. **pkt-line**：畸形长度、超长行、非 UTF-8 各有夹具，**不 panic**。
5. **断点恢复**：真实 Range 续传可用；中断后不产生半成品条目（§十.1）。
6. **不执行包代码**：`12-tests:784` 在远程路径上重新验证（副作用探针，同 E2B 手法）。
7. **零 tokio、零 git 客户端**（`Cargo.toml` 可查）；门禁全绿。
