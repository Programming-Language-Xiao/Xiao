# 20C-第五批. 库侧复探与推进

> **背景**：[20C-第四批](20c-fourth-batch-int-to-str.md) 已接通 `int`/`sint`/`lint` → `str`，
> 两平台 CI 逐字一致（维护回归 `38597139383`）。该批 §7.2 预告的下一步是
> **回到库批次**，并规定「**按第二/三批的口径再复探一次，不拿预期当结果**」。
>
> **一句话概括**：先按 [20C-第二批](20c-second-batch-probe.md) §3.2 的纪律**真跑双路径复探**，
> 由结果决定这一批往库里加哪些接口、以及**哪些仍被语言边界挡住**；
> 同时把第四批欠的两笔证据/登记并进来。
>
> 状态：**规划（2026-10-15）**，未开始实施。

## 一、为什么是这一批

1. **裁定链**：第四批 §7.2 已把「回到库批次」写成下一步，并冻结了「**再复探一次**」；
2. **`int` → `str` 改变了可写面**：数字格式化此前登记为「**不能列入已验证候选**」
   （[20C](20c-official-xiao-library.md) §3.1 的探测结论），现在它的前置已被解除——
   **但解除到什么程度必须真跑**，不拿第四批的预期当结论；
3. **顺手清账**：第四批有**两笔**该回填的东西（CI 运行号、F-1 的登记落点）挂在那里，
   本批先清掉再开新工作。

## 二、并入的返工项（**先做**）

### 2.1 **R-a（低）：第四批的 CI 运行号回填，并去掉一处**过时前提

**事实**：`docs/DevDocs/README.md` 的 `20C-第四批` 行仍写着
「LLVM 原生复跑**需 10D §4 工具链**」——那是**该批当时的实话**，但现在**前提已经不成立**：
维护回归 `38597139383` 的两个原生作业（Linux `115966670682`、Windows `115966670696`）
**都跑到了**该批的新夹具，日志里 `20C-PROBE` 行数由 **14 → 15**，
且 `second-int-to-str` 在两平台输出**逐字一致**（`42:42:42:42:42:42:42`）。

**冻结**：

1. 把该行改成 CI 事实，并回填**运行号与两个作业号**；
2. **第四批文档 §7.1** 也回填同一组运行号（`main` 已绿，不再是"待外部"）；
3. **不许**只改 README 不改文档——两处不一致就是本仓库反复吃的那个形状。

### 2.2 **R-b（中）：F-1 的登记落点还没落**

**事实**：第四批 §8.1 已把 F-1（`lint as int` / `as float` 的**双路径不一致**：
类型层接受、**原生构建成功**、**VM 以 `X09-BYTECODE-002` Fatal 拒绝**）写清，
但它的**登记落点**（§8.1 第 2 条冻结）**尚未执行**——
`02-type-system.md:118` 只写了「整数族到文本」，全仓仍**没有** `lint` → 数值转换的债项登记。

**冻结**：

1. 按第四批 §8.1 的登记口径（**需要什么 / 当前以什么码被拒 / 阻塞哪条接口**）
   落到 [02. 类型系统](02-type-system.md) 的显式转换节，**并与 `lint`/`lfloat` 的算术债并列**；
2. **同时**修第四批 §8.2 的注释（`convert_to` 的「算术」改回「算术与数值转换」）——
   **注释与登记一起改**，否则注释会继续盖住它；
3. 诊断身份那条（「降低器缺陷没有档位、只能报成产物损坏」，与语言边界批 §5.4 同族）
   **只登记、不改**；要不要补身份**由星崽另定**。

## 三、现状盘点（规划侧实测，2026-10-15）

**口径先声明**：本节是**规划侧本机、VM 单路径**的探测，**只用来确定本批的候选面**；
**本批 §四 仍须真跑双路径成表**（[20C-第二批](20c-second-batch-probe.md) §3.2 第 1 条）——
**本机单路径结论不构成验收依据**。

| 探测（本机 VM，单路径） | 结果 | 含义 |
| --- | --- | --- |
| `def describe(int value) -> str / return "n=" + str(value)` | **成功**，输出 `n=42` | **数字格式化可写**：整数转文本 + 拼接在库函数里可用 |
| `def is_upper(str v) -> bool / return v >= "A" and v <= "Z"` | **成功**，输出 `true` | **字符分类可写**（`and`/`or` 接通的直接收益） |
| `int("A")` | 前端拒绝 **`X02-TYPE-006`** | **`str` → `int` 仍缺** ⇒ **大小写转换仍被挡**（与第四批 §7.2 的预期一致） |

⇒ **三条候选的现状**：数字格式化与字符分类**看起来解封**，大小写转换**仍挡**。
**但这是单路径、本机的**——本批必须以双路径实测为准。

## 四、复探（**先做，成表**）

### 4.1 口径

**逐字沿用** [20C-第二批](20c-second-batch-probe.md) §3.2 的六条（真写真跑、双路径、成表、
不许绕开、一夹具一拒绝、结论先汇报）。

### 4.2 候选与要回答的问题

| # | 候选 | 要回答 |
| --- | --- | --- |
| 1 | **数字格式化** | 纯 Xiao 能否把一个整数渲染成文本（含拼接与循环）？双路径一致吗？ |
| 2 | **字符分类**（大小写/数字判断） | 区间比较 + `and`/`or` 的写法在两条路径上都成立吗？ |
| 3 | **大小写转换** | `str` → `int`（码点）仍缺吗？**能否用不依赖它的写法表达**（若不能，按缺口登记） |
| 4 | **字符串比较（字面量）** | 常量折叠路径仍未开放吗？（[20C-语言边界](20c-language-boundary-and-operators.md) §2.1） |
| 5 | **子串查找 / 切分** | 非字面量下标与容器参数类型仍是前置吗？（第二/三批已登记，复查是否变化） |
| 6 | **集合最小操作** | 通用容器参数类型未冻结前，是否仍只保留探测结论？（[20C-第二批](20c-second-batch-probe.md) §3.3 第 7 行） |

### 4.3 产出

**一张双路径表**（六行，逐行给「成功 / 在哪一层以什么码停下」+ 依据）+ **缺口登记的合并**：
仍被挡的候选，登记统一收口到**一处**，并写清各自**最近的一个前置**。

## 五、由复探结果决定本批的库清单

1. **只有解封的候选才进清单**；每条接口逐条含
   **模块名 / 函数与完整签名 / 返回与错误身份 / 依赖哪些已探测操作 / 明确不做的部分**；
2. **不许为了把某个候选塞进清单而放宽任何既定边界**（第二批 §四 第 2 条原样有效）；
3. **不许新增 intrinsic、不许为写库扩语言**（[20C-首批](20c-first-modules.md) §4.4 原样有效）；
4. **大小写转换若仍被挡**：按缺口登记（需要什么 = `str` → `int` 码点；当前以 `X02-TYPE-006` 被拒；
   阻塞哪条接口），**不修**——它的修复是**下一个语言批次**的事，本批只登记；
5. **数字格式化若解封**：**先给最小接口**（不要一次把填充、对齐、进制都做进去），
   并明确「**不做的部分**」。

## 七、验收

1. **R-a**：README 与第四批文档都回填了 `38597139383` 与两个作业号；
   README 里「LLVM 原生复跑需 10D §4 工具链」**已换成 CI 事实**；
2. **R-b**：`02-type-system.md` 有 `lint` → 数值转换的债项登记（与算术债并列，含三要素）；
   `ops.rs` 的注释已改回「算术与数值转换」；
   诊断身份那条**只登记**、**没有**擅自补身份；
3. **复探**：六行**双路径**表；每行给「成功 / 在哪一层以什么码停下」；
   **没有**变量下标、临时 intrinsic 绕开；**结论先汇报**；
   仍被挡的缺口**登记已合并到一处**并写清各自最近的前置；
4. **库清单**：每条都能在复探表里找到依据；**没有**为了塞候选而放宽边界；
   **没有**新增 intrinsic；范围外的东西写进「明确不做」；
5. **诚实**：第四批 §8.1 的 F-1 **仍是既有缺口**，本批**不许**把它写成已修
   （本批只做**登记**与**注释**两件）；
6. **通用**：`cargo test --workspace`、clippy、fmt、`bun test`、`bun run check`、`bunx tsc --noEmit` 全绿；
   提交标题带类型前缀、正文非空。
