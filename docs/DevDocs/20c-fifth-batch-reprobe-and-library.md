# 20C-第五批. 库侧复探与推进

> **背景**：[20C-第四批](20c-fourth-batch-int-to-str.md) 已接通 `int`/`sint`/`lint` → `str`，
> 两平台 CI 逐字一致（维护回归 `38597139383`）。该批 §7.2 预告的下一步是
> **回到库批次**，并规定「**按第二/三批的口径再复探一次，不拿预期当结果**」。
>
> **一句话概括**：先按 [20C-第二批](20c-second-batch-probe.md) §3.2 的纪律**真跑双路径复探**，
> 由结果决定这一批往库里加哪些接口、以及**哪些仍被语言边界挡住**；
> 同时把第四批欠的两笔证据/登记并进来。
>
> 状态：**复探完成、库接口已实施（2026-10-15）**。六行双路径结果见 §4.3；
> 只有数字格式化与 ASCII 大写分类进入最小 `text` 接口，大小写转换、字面量常量折叠、子串/切分和集合公共接口继续登记；
> F-1 只完成登记与注释修正，未修复。

## 一、为什么是这一批

1. **裁定链**：第四批 §7.2 已把「回到库批次」写成下一步，并冻结了「**再复探一次**」；
2. **`int` → `str` 改变了可写面**：数字格式化此前登记为「**不能列入已验证候选**」
   （[20C](20c-official-xiao-library.md) §3.1 的探测结论），现在它的前置已被解除——
   **但解除到什么程度必须真跑**，不拿第四批的预期当结论；
3. **顺手清账**：第四批有**两笔**该回填的东西（CI 运行号、F-1 的登记落点）挂在那里，
   本批先清掉再开新工作。

## 五、由复探结果决定本批的库清单

1. **只有解封的候选才进清单**；每条接口逐条含
   **模块名 / 函数与完整签名 / 返回与错误身份 / 依赖哪些已探测操作 / 明确不做的部分**；
2. **不许为了把某个候选塞进清单而放宽任何既定边界**（第二批 §四 第 2 条原样有效）；
3. **不许新增 intrinsic、不许为写库扩语言**（[20C-首批](20c-first-modules.md) §4.4 原样有效）；
4. **大小写转换若仍被挡**：按缺口登记（需要什么 = `str` → `int` 码点；当前以 `X02-TYPE-006` 被拒；
   阻塞哪条接口），**不修**——它的修复是**下一个语言批次**的事，本批只登记；
5. **数字格式化若解封**：**先给最小接口**（不要一次把填充、对齐、进制都做进去），
   本批只提供十进制 `text.format_int(int value) -> str`，并明确不做填充、对齐、进制。
6. **字符分类若解封**：只提供复探覆盖的 ASCII 大写判断 `text.is_ascii_upper(str value) -> bool`，
   不扩到完整大小写转换、Unicode 分类或 `str` → `int`。

## 八、裁定结果（星崽直接裁定，2026-10-15）

| # | 问题 | 裁定 | 落在哪 |
| --- | --- | --- | --- |
| 1 | **§五 库清单怎么定** | **复探结果决定**（六行双路径表说了算），**但选出后先汇报一次**再动手 | §五（与第三批 §八第 1 条同形） |
| 2 | **下一批若走语言侧**：`str` → `int` 是不是最小前置 | **先不定，等复探之后再说** | 见下方连带 |
| 3 | **F-1 的诊断身份**是否补一个 | **先只登记**，**与 F-1 的修复同批定** | §2.2 第 3 条（只登记、不改） |

**来源**：星崽直接裁定；三条与审核倾向**一致**——但按
[20C](20c-official-xiao-library.md) §2.4 **G-2** 的口径，一致**不等于**推定，本文以**直接裁定**记。

**第 2 条的连带（写下来免得反复问）**：**不预先立项** `str` → `int` 的原因——
本批 §4.2 第 3 条已经把「**大小写转换能否用不依赖它的写法表达**」列为复探要回答的问题；
- **绕不开** ⇒ 它是最近的前置，届时**单独立项**（语言批次）；
- **绕得开** ⇒ 这个语言批次就是多余的，**省下来**。

⇒ **先问再定**——这正是 [20C-语言边界](20c-language-boundary-and-operators.md) §六
「复探结果决定下一批」那条纪律的第三次应用。

**第 3 条的连带**：只登记的原因是目前**只有一个样本**，且它本身还是个未修的缺口；
为一个样本设计新分类，容易先定出一个后来发现不合适的形状。
**参照 [20C-语言边界](20c-language-boundary-and-operators.md) §5.4**：那次也是先把
001/002 的边界弄清、再动身份，而不是先加档位。
