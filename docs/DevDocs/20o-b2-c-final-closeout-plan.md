# 20O-B2-C. B2 最终公共收口与发布规划

> **2026-11-16：B4-5已完成Windows内部收口；B5已实施ABI1.19/21版本矩阵，但默认并发workspace仍因URL Unicode用例看门狗失败而未封存。** 串行全量测试通过，不能替代该失败；B6/B7/B2-C尚未开始。B1历史原件缺失、获批重建来源和独立LLVM比较问题均保留，不表示三平台/性能或公共发布通过。
> B7 有效内部收口后才有 B2-C 开工入口；受限交接中的未验证项须在本批补齐，不能直接认领最终通过。
> 入口为 B7 固定的最终 1.19/21 源码/证据与 B6 资源/性能结论；B2-B 内部可用不等于公共发布。
> B2-C 只做最终 721、三平台公共产物、最终教程/registry、发布证据和 B2 收口。
> 不新增数学/ABI/intrinsic，不关闭 22C/22D、19/11/22 或 B1 历史债务。

B2-C 是 **B2 最终公共发布批**，不是 B2-B 内部收口的重复。只有最终 1.19/21 快照、完整 721 和三平台公共产物全部成立，才能把 `stdlib.cmath` 和新增数值能力范围升级为最终状态。

C0～C3可以采集并记录失败或不可验证结果；只有全部必测功能、版本、资源/性能与平台结果通过，才允许 C4 升级对应状态并由 C5 签收最终通过。证据审计通过不代替产品验收，缺平台、缺样本或预算失败不能以“已登记”完成公共收口。

- 保持 intrinsic 1～48/ID100墓碑、C符号与布局、ABI1.19/生成器21/标准库接口1，不新增49+，不改容器格式/索引schema；

发现产品、工具或语料缺口时保留失败，回所属实现批次修复并固定新基线，补验受影响证据；不得在收口中变更语义、预算或门禁来取得通过。
