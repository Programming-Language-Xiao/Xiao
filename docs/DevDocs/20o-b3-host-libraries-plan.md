# 20O-B3. 简单宿主库实施规划

> **B3-0B/C 的六模块已冻结，B3-0D 已完成版本、能力、协议、C ABI 与 COFF 政策冻结，B3-0E 入口已就绪。** 固定基线为 `e79fab3c`，当前产品 ABI 1.19、生成器 22、标准库接口 1；B3-0D 的实现输入为 ABI 1.20、生成器 23、标准库接口 1。[B2-C 交接](assets/20o-b2-c/entry-20261122-b2-c/README.md) · [B3-0B 收口证据](assets/20o-b3/entry-20261123-b3-0b/README.md) · [B3-0C 收口证据](assets/20o-b3/entry-20261123-b3-0c/README.md) · [B3-0D 收口证据](assets/20o-b3/entry-20261124-b3-0d/README.md)
> **Windows 产物政策（2026-11-22）**　自 B3 起，所有 Windows 公共/发布产物必须产品级 COFF `Complete`，且声明组件与观察组件一致；B2-C 的同链接 10 份候选只是历史例外，不得继承。`UnverifiedCoffExports`、同链接映射或仅导出表检查不能替代。
> B3 涉及六个模块、五个实施工作流：`time`（UTC + sleep）、`args`、`cli`、`fs`、`env`、`log`。
> B0 只确认了部分方向；精确签名、模块归属、能力/错误、资源/性能及版本要求必须在 B3-0 冻结。
> B3 不实现网络/安全/JSON/TOML/数据库，不改 B2 数值语义；冻结和实现分批，不得先写产品后补契约。
> 历史债务、B1 旧721、B2-C 721 均不在 B3 核销。

B3 从简单宿主库的探测、契约冻结和教程草案开始。产品实现沿本规划分批进入。

### 1.1 要做

1. 探测 time/fs/argv/env/log 的现有宿主能力、平台差异、错误和取消边界；
2. 冻结 `time`、`args`、`cli`、`fs` 扩展、`env`、`log` 六个模块的精确 API/错误/能力；
3. 为六个模块分别编写可执行教程和固定示例；
4. 实现 `time` UTC/单调钟/格式化/sleep；
5. 实现 `args`/`cli` 的 argv/程序名/空参数/非法Unicode规则；
6. 实现 `fs` 扩展的路径解析、覆盖、原子写和错误；
7. 实现 `env` 读取/写入边界与非法Unicode；
8. 实现 `log` 时间戳/级别/输出边界；
9. 按 B3-0 冻结接通类型/IR/TAC/VM/LLVM/归档、std/stdlib双路径、能力/取消/移除/隔离；
10. 三平台证据、教程/registry 只在验证后升级。

### 1.2 明确不做

- 不实现 B4 JSON/TOML、B5 decimal/fractions、B6 regex/compression、B7安全、B8网络、B9数据库；
- 不修改既有 intrinsic 1～48或ID 100墓碑，不新增与B3无关的运行时能力；B3所需新 intrinsic/值类型的编号、ABI/生成器增量及 `.xiaoc`/`.xar`兼容身份必须在B3-0冻结，不得假设 ABI/生成器保持不变；
- 不改 B2 数值语义；
- 不把 sleep 实现成无取消/无上限的宿主阻塞；
- 不把 fs 做成无权限/无路径解析/无原子保证的任意文件访问；
- 不给 env/log 添加未冻结的隐式缓存/全局配置、无上限路径或能力映射；env对宿主进程环境的显式可见性须按B3-0契约执行；
- 不提前升级 registry/教程，不跑 B1 旧721。

## 二、开工闸门

1. 核对 B2-C 已封存的最终公共基线及本页 B3-0 开工范围；
2. B0 已确认方向、20P Day-1 标准、D-8/D-9/D-10 与能力/错误/取消原则可读；现有20D能力位及拒绝未知位的边界不得被本规划默认为可扩展；
3. 当前标准库加载器/能力位/错误表/取消通道可复现；明确 `clock` 已有固定能力位，而 `stderr` 没有独立位；
4. B1 七库 20 入口、18 项资源、VM 与原生双精确入口及 28 项守卫（4 项实测输出、24 项派生负例）可复现；
5. 三平台目标/工具链/CI可用；
6. 唯一任务根、独立target/Runtime/缓存已建立；
7. env/log 未冻结项已列入 B3-0，不得先写产品再补冻结；
8. B3-0 的逐项裁定与产品实现授权分别记录，冻结通过本身不代表获准并行实施。
9. Windows 产物政策已固定：自 B3 起产品级 COFF `Complete` 是 Windows 公共/发布产物的硬条件；B2-C 同链接补验不得继承。

## 三、分批执行

### B3-0：探测、冻结与教程草案

详细实施边界、冻结表、证据和 B3-1 入口见 [B3-0 探测/冻结实施规划](20o-b3-0-probe-freeze-plan.md)。

1. 探测六个模块的现有宿主API、平台差异、能力位、错误/取消和实际资源行为；保留原始日志与工具/源码身份，探测本身不等于冻结；
2. 冻结 `time`：墙钟/单调钟表示、UTC格式/精度、sleep单位/舍入/零/负/最大时长/超时/取消、安全点、时钟回退和能力；明确阻塞期收到取消时的清理与错误传播；
3. 冻结 `args`/`cli`：argv/程序名的分工、快照时点、空参数、Windows不二次拆引号、非法Unicode、选项解析范围、重复项及`--`规则；
4. 冻结文件API的公开归属：已有 `stdlib.os` 文件/目录句柄接口与拟议 `stdlib.fs` 扩展如何分工，禁止产生含义重叠的入口；同时冻结宿主权限失败、相对路径基准、绝对路径/`..`/符号链接、覆盖、同目录原子替换和失败清理。是否提供受限/沙箱模式须明确裁定；
5. 冻结 `env`：读取/写入/删除范围、快照或实时语义、名称比较（含Windows大小写）、名称/值编码、非法Unicode、子进程继承关系、并发可见性、能力与错误；
6. 冻结 `log`：级别、时间戳来源/格式/时区、输出目标、并发下记录边界、刷新/写入失败、能力与资源限制；
7. 六模块逐一确定函数签名、参数/返回类型、效果与所有权、所需能力、稳定错误码/优先级、资源限额、性能工作负载/预算与测量方法、三平台目标及教程完整示例；能力映射先限于20D已冻结位且不得改变已有含义，新能力位须另行修订冻结并取得裁定；错误码不得在实现批临时分配；
8. 依据新增宿主操作/值类型冻结 intrinsic 编号、ABI/生成器版本增量、C符号与所有权、VM/LLVM绑定、`.xiaoc`/`.xar`拒绝与缓存身份；保留1～48现有编号及ID 100墓碑，遵守20P新增intrinsic/值类型需升级ABI并更新产物指纹的规则；
9. 为六个模块各写一份可执行教程草案和固定示例，按 D-20 放入 `tests/fixtures/docs/<module>/`，示例须进入VM及受控原生逐字输出/退出码测试；保持模块、UseDocs、DevDocs、registry及兼容身份的候选范围一致；尚未验证的registry/教程保持 `planned`；
10. 为宿主状态测试冻结隔离方式：fs只操作任务专属临时目录，env变更在隔离子进程中执行，log输出捕获到独立流；不依赖或改写用户环境和工作区外文件，时间测试使用受控时钟或仅验证冻结的容差/单调关系；
11. 记录被明确延期的 API、平台行为和能力；用可复核签字/裁定记录标明冻结项与仍未冻结项。

退出：六模块精确契约、版本/兼容身份、能力/错误/取消、资源/性能预算及六份教程草案均已冻结；未写产品，也不由本出口本身授予并行实施授权，后续仍按§二闸门核验。
