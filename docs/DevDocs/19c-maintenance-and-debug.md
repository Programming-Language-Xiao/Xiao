### 2.2 **`19.10`、`19.11`：只定义规则并用测试锁住，不发明格式、不发明信任规则**

- **格式废弃周期**：以 19B 的兼容矩阵为唯一数据源，每条轴补一列「状态」（现行、已废弃、已移除）。
  现状是 16 阶段冻结的「版本不匹配直接重新生成」，所以**现在没有任何一格处于已废弃**。
  本批写下的周期只能是对这个事实的描述和一条升级流程，不得凭空规定迁移窗口；
- **迁移工具**：19B 的矩阵测试断言了「没有 `Migrate` 格」。本批仍不做迁移工具，只写明何时才需要、需要满足什么条件；
- **安全修复回溯范围**：本批按当前发布版本记录，理由是项目处于早期、不做向前兼容；
- **缓存清理与重建**：16B 已有两阶段清理与重建。本批只做规则化：对象保留依据是什么、
  引用集合怎么算、清理前后哪些命令只读。**不改 16B 的冻结面**；
- **归档撤销**：撤销需要「谁有权撤、撤什么、客户端怎么知道」，这正是 17 待定决策 6 里
  尚未决定的信任模型。**没有信任模型就做撤销，等于本批自己定了信任规则**，违反 19
  规范「接手前提」。建议本批只写明「当前没有撤销机制」，并让 CLI 和发布报告明确这一点
  （与 19B 已有的「未签名」提示同一口径），撤销留给 17 的信任模型决定之后。

### 2.3 **`19.12`：先查清构建会不会在更早处拒绝，再决定补什么**

已知事实：`TargetDescription::host()` 在不认识的平台上返回 `unknown-unknown-unknown`，
产物校验对未知架构**跳过**机器类型比较。**不知道的是**：`xiao build` 走到这里之前有没有拒绝。

**冻结**：

1. 第一步是**实测**：构造一个不在支持表里的目标，走完 `xiao build`，记录它在哪一步、以什么错误码停下，
   或者是否产出了文件。结论写进实施记录，不凭读代码判断；
2. 若已有稳定拒绝，本批只补「支持表」文档和回归测试；
3. 若会产出文件，这是缺陷，归 15，**在那里修**；本批只留回归样本和「已知不支持」清单；
4. 「已知不支持」清单由代码生成（与兼容矩阵同一做法），不手写散文；
5. 清单必须区分「不支持」和「未验证」：Linux 与 macOS 的真实构建在没有 CI 证据前属于后者。

### 2.4 **`19.13`：拆成「现在能接」和「等 19D」两半**

规范要把性能、体积和安全回归接入持续集成，并保留可复现构建样本。现状是只有一个每周定时的工作流，
不随 push 触发；性能阈值和基准硬件要等 19D 冻结。

**冻结**：

- **现在做**：体积回归（`.xiaoc`、`.xar` 大小相对已提交基线的上限）和安全回归（19.2 的四组模糊测试、
  19B 的路径穿越与压缩炸弹单测）。这两类都是确定性的，不依赖硬件；
- **等 19D**：性能回归。阈值、基准硬件、取样规则都是 19 规范的待定决策 2，本批不替它们定数字；
- **触发方式**已按星崽裁定采用 push/PR 相关路径过滤的轻量工作流；
- 可复现构建样本的保留位置和期限沿用现有 `upload-artifact` 的 30 天，不另立规则；
- 任何新工作流的 action 版本**一次查全**，不只查几个（见 R7）。

### 2.5 **`19.14` 与 `18.13`：证据分三档，分别标注来源**

诊断窗口是新开的终端，不是 GUI 窗口，这一点 11X0-D 已确认，本批不重开。

| 档位 | 内容 | 来源 |
| --- | --- | --- |
| A. 可自动化 | `-debug` 日志脱敏、聚焦分流、固定指标；日志目标不可写、无法创建窗口时的**明确失败**且不改变程序语义 | 本机与 CI 都能跑，进 `cargo test` |
| B. 需要宿主 | Windows GUI 子系统启动时开窗；调试产物脱离 `xiao` 启动器直接启动 | 本机 Windows 可做行为验证，CI 没有 GUI 会话，**不得写成 CI 已验证** |
| C. 需要别的宿主 | macOS LaunchServices 注册；Linux 桌面环境下的开窗 | 本机没有，只能等对应宿主的证据；没有证据就保持「未验证」 |

**冻结**：

1. 18C 已记录「GUI 子系统仍只有文本断言」是它自己点出的风险；B 档必须给**行为证据**（进程确实起来、
   窗口进程确实存在、关闭窗口后主程序结果不变），不能只断言字符串；
2. 「无法创建窗口」的失败路径要能在无显示环境下构造，否则 A 档没法在 CI 上跑；
3. 任何一档拿不到证据，验收里写「未验证」，不写「通过」。

### 2.6 **CI 实跑需要授权，它是多项验收的共同前提**

R8、`19.13`、`19.14` 的 CI 侧证据都要先把本地提交推到远端并触发工作流。这会在共享仓库留下新提交
和运行记录，**不是本机可逆的操作**。

**冻结**：

- 实现 Agent 不得自行推送或触发工作流；仍由星崽明确授权后进行；
- 授权之前，所有涉及 Linux、macOS 的结论一律写「未验证」，附上缺的是哪个运行号；
- 授权之后，先推送、手动触发、读**四个平台各自的日志**，再写结论。只读两个平台就写「同因失败」，
  已经出过一次这样的错（19B 现状盘点里就标过）。
