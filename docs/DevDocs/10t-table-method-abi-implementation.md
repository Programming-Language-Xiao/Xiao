### 2.2 **A1 按清单实现，不放宽这几条**

清单已经把契约、顺序和验收写清了，本批只强调**容易被做偏**的几条：

**冻结**：

1. **不先删拒绝**：`dynamic/container.rs:262` 的方法拒绝要保留到契约真正可用，最后一步才移除；
   期间 `table-user-drop` 的既有测试继续**钉住**拒绝，不能提前放松；
2. **不改旧描述符的原地布局**：新入口配新描述符；只加入口按次版本走，一旦改到既有布局或所有权契约，
   按主版本升，并同步 ABI 版本常量、那个**断言字面量的测试**、工具链指纹与兼容矩阵；
3. **回调不用按值返回聚合结构**（避免 MSVC/SysV 返回约定差异）——用清单建议的「receiver 指针 + 连续
   `XiaoValue` 实参 + 长度 + 结果输出指针 + `i32` 状态」形态；
4. **所有权按清单**：普通 receiver/实参调用期间借用，被调方需要持有就显式复制；结果是调用方唯一拥有；
   失败输出保持 `none`；元数据由 Runtime 复制，函数指针生命周期由产物保证；
5. **`drop` 只用既有 `TableDropView` 借用契约**：不得用强引用复活正在析构的实例，不得逃逸、写 receiver 或跨线程；
6. **不另造生命周期状态机**：复用 Runtime 已有的初始化状态机、错误主因/抑制链、Fatal 绕过与构造失败回滚；
7. **VM 是语义基准**，本批不改 VM 行为。

### 2.3 **这次必须三平台验，不能只看 Windows**

上一批的教训是直接的证据：一个 ELF/Mach-O 才可见的 `weak` 可达性问题，**Windows push 门控全程是绿的**，
最后靠裸机 Linux 和平台矩阵才发现。A1 引入的是**新的 ABI 入口与回调调用约定**——正是最容易出现
「Windows 通过、Unix 失败」的那类改动。

**冻结**：

1. 每个阶段性提交都要在**本机 Windows** 跑受控原生门控；**并**在至少一个 Unix 目标上验证
   （Linux 矩阵任务，或星崽的裸机 Linux 机器）；
2. 新增/更新的调用约定与结构布局测试要**同时覆盖 Windows 与 SysV**（沿用现有两条布局测试的做法），
   不能只测当前宿主；
3. 平台复现工作流（`platform-reproduction.yml`）在关键节点手动触发，四平台结论逐条回填；
   汇总作业不能代替四个作业的结论；
4. **不得**因为「Windows 绿了」就宣布跨平台完成——本批的验收明确要求 Unix 侧证据；
5. 若本批拿到 Linux push 门控的授权（待定决策 2），把它作为这条要求的自动化兜底，但**裸机证据仍然另算**。

### 2.4 **释放证据：不能只看总数相等**

A1 改变了表的构造、字段初始化与 `drop` 路径，正是 10Q/10S 反复出问题的区域。

**冻结**：

- 验收必须同时给出**事件数、对象数、销毁位置**，以及**引用持有机制**的说明（谁持有、何时归还）；
- 沿用 10S 的成对实验方法：怀疑某处多/少一次释放时，**只改一处**、采数、恢复，把对照数据写进记录；
- 新增路径的差分用例要**能分辨对错**（10Q 的 K2 教训）：例如 `drop` 的输出与顺序、方法返回值参与聚合，
  而不是只断言「两边都成功」；
- `table-user-drop` 从拒绝转为真执行后，必须**摘掉**钉住拒绝的那段断言，并补上 VM/原生的完整比对；
- 若新路径仍有追踪口径差异，按 10S 的做法写机制、留 `Drops` 豁免，**不得**放宽值/错误/退出码的比较。

### 2.5 **分阶段检查点：中途状态必须仍然是绿的**

A1 跨 ABI crate、Runtime 与 codegen 三处，不可能一步到位。

**冻结**：

- 在「ABI 描述符与 Runtime 侧就绪、LLVM 侧仍拒绝」的中间态，**既有门禁应保持全绿**，差分与探测不变；
  这个中间态是自然的提交边界，不要为了「一次做完」把大改动压在一个提交里；
- 每个提交单独跑 `cargo test --workspace`、clippy、fmt；推送前跑 `bun test` 与 `bun run check`；
- 版本常量与断言字面量的测试若需要改，**在提交说明里写明**（属于既有测试改动，必须披露）。

### 2.6 **星崽侧动作：Linux 裸机复跑与窗口证据**

**冻结**：

- 复跑用**本批的稳定提交**（不要用中途会变的 head），按 [10S-Linux 裸机交接](10s-linux-bare-metal-handoff.md) 执行：
  不设 `XIAO_USE_XVFB`、不改源码、失败也照实回传；
- 窗口那一步要**肉眼可见 + 截图**；看不到窗口就照实写「未通过」，**不得**用「测试断言 ok」替代；
  上一批在这个判断上做对了，本批沿用；
- 回传后由实现方把结果并入 10T 实施记录与 19 的 O6 对账。

## 四、硬约束

1. N 系列与 A1 的各步骤各自单独提交，提交说明写明归属 10S/10P，并带正文；
2. **不先删拒绝**（§2.2）；不放松 `table-user-drop` 钉住拒绝的断言，直到它真的能跑；
3. 版本与兼容：只加入口走次版本，改布局/所有权走主版本，并同步断言字面量的测试、指纹与兼容矩阵（§2.2）；
4. 回调一律用清单约定的注册式形态，**不按值返回聚合结构**（§2.2）；
5. `drop` 只用 `TableDropView` 借用契约；不改变 VM 行为（§2.2、§2.7）；
6. **必须有三平台证据**，不得以「Windows 绿」代替（§2.3）；
7. 释放证据要含事件数/对象数/销毁位置与持有机制，不能只比总数（§2.4）；
8. 每个提交单独跑 clippy 与 fmt；推送前跑全量门禁含 `bun run check`；
9. 不新增依赖，`Cargo.lock` 保持同步；
10. 判定原生行为必须实跑受控环境（含 `XIAO_DIAGNOSTICS_PATH`）。

## 六、最可能翻车的地方

1. **先删拒绝再用空实现顶替**——清单明令禁止，本批再强调一次；
2. **按值返回聚合结构**，在 MSVC/SysV 上出现返回约定差异；
3. **只测 Windows**：上一批的 `weak` 问题就是这么漏掉的（§2.3）；
4. **改动既有布局或所有权却不升主版本**，也没同步断言字面量的测试与兼容矩阵；
5. **`drop` 用强引用复活正在析构的实例**，或让它逃逸/跨线程；
6. **另造一套生命周期状态机**，与 Runtime 既有的初始化与回滚分叉；
7. **只比释放总数**就宣布一致，不看对象数、销毁位置与持有机制；
8. **`table-user-drop` 的钉住断言被顺手删掉却没补真比对**，缺口悄悄消失；
9. **大改动压成一个提交**，中间态无法验证，出问题无法二分；
10. **把「测试断言 ok」当窗口证据**（N4 已明确）；
11. **提交没写正文 / 没单独跑 clippy**。

## 七、验收

1. N1–N4 逐项有结论；N4 以星崽的回传为准，未回传则写「待补」；
2. A1：新描述符与调用入口上线，`table-user-drop` 从明确拒绝变为**真实原生执行**，与 VM 的 `drop` 输出、
   错误与释放顺序完全比对；`container-dense` 可构建、可运行、可差分，探测基线同步更新
   （**可构建不等于性能达标**，性能仍按 19D 的「数据不足」口径）；
3. 方法相关边界有测试：普通/私有方法、同名不同表、方法互调、非法参数、返回堆值、返回覆盖；
4. 生命周期有测试：字段初始化顺序、`init` 失败、`drop` 恰好一次、共享引用、弱观察失效、`drop` 抛错与嵌套错误抑制；
5. Fatal 不运行普通 `drop`，构造失败无泄漏；三平台 `O0`–`O3`、调试产物与非调试产物分别验证；
6. **释放证据**含事件数/对象数/销毁位置与持有机制；成对实验数据在记录里；
7. **三平台证据齐全**：Windows 本机、Linux（矩阵或裸机）、macOS（CI；并照实记录其跳过项）；
8. 版本与兼容：描述符版本、ABI 版本常量、断言字面量的测试、工具链指纹、归档元数据与兼容矩阵同步更新，
   且既有测试改动在提交说明里逐条披露；
9. `cargo test --workspace`、clippy、fmt、`bun test`、`bun run check` 全绿，且每个提交单独绿；
10. 没有通过放宽断言、删用例、缩小范围或新增豁免字段换来的绿。

## 待定决策

### ABI 检查点

独立 XiaoTableDescriptorV2 采用 size/version + 旧字段描述 + 方法数组 + 字段/init/drop 回调；旧描述符不变。方法记录规范名、由既有值标签生成的确定性签名 ID、参数标签数组、返回标签、可见性及非空回调。动态类型使用单独的元数据通配标识，不新增运行时值标签；类型事实只由已检查 IR 提供。

Runtime ABI 次版本 7 → 8（主版本仍 1），同步修改既有 version_encoding_is_stable 的两个字面量断言。现有产物指纹和归档/报告的版本要求均读取 ABI_ENCODED_VERSION，旧 Runtime 将拒绝要求 1.8 的产物。当前仅加入边界声明，LLVM 方法拒绝仍保留；Runtime 实现在下一检查点接入。

前置提交 e99c81e 的维护运行 [37653713650](https://github.com/Programming-Language-Xiao/Xiao/actions/runs/37653713650) 全绿，新增 Linux 原生门控与 Windows 原生门控分别通过。ABI 检查点本机 Rust workspace、fmt、Clippy、Bun 全量与仓库检查通过；Windows 六项受控原生测试通过，clang 对 Windows x64、Linux x64、macOS arm64 的 C 布局探针通过。该交叉布局探针不冒充 Unix 原生运行，后者继续由提交后的门控确认。

### Runtime 中间态（LLVM 仍拒绝）

新增 abi_tables 模块复制方法元数据，校验结构版本/长度、重复字段/方法、签名与生命周期回调一致性，复用 TableInstance::with_initializer 和 with_drop_executor。定义以 Rc 持有后端不可变元数据，不建立全局实例注册表。普通参数仅借用；返回类型或错误状态不符时回收输出，保持调用方 none。

析构使用独立不透明弱视图盒子，内部仅保存 TableDropView，不保存或升级对象强句柄；原有弱句柄布局对外不变。复制/释放分派可识别此盒子，写入与复活被拒绝，回调外字段与方法借用均失败。回调隔离外层错误槽，初始化包装/清理抑制链仍由原状态机组装；隐式 StrongHandle::drop 的回调错误转交 ABI 传播边界，Fatal 绕过普通 drop。VM 代码未改。

七项新增 ABI 回归覆盖方法返回参与计算（7→init 9→add 11）、元数据离开构造作用域后的调用、借用前后真实强计数、共享引用/弱观察失效、析构视图失效、初始化错误链、嵌套析构错误、Fatal 与坏元数据。Windows 六项受控原生测试及全量门禁通过；container-dense 和 table-user-drop 仍按原断言拒绝。push 矩阵增加 Runtime/ABI 单元测试及三目标 C 布局探针，保障中间态在 Unix 也执行新边界测试。

ABI 提交 49b0c32 的维护运行 [37655760509](https://github.com/Programming-Language-Xiao/Xiao/actions/runs/37655760509) 全绿，Windows/Linux 原生作业分别成功。最初 Git 代理出现 TLS 握手失败，使用单次命令直连完成推送，未改全局配置。

Runtime 提交 08c5983 的维护运行 [37656742203](https://github.com/Programming-Language-Xiao/Xiao/actions/runs/37656742203) 与完整平台复现 [37656744315](https://github.com/Programming-Language-Xiao/Xiao/actions/runs/37656744315) 均全绿；Windows、Linux amd64/arm64、macOS 分别成功。后者为 workflow_dispatch，验证与定时共用的作业路径，不改写成 schedule 事件；macOS 真实终端仍跳过，Linux CI 仍为 Xvfb。

### LLVM 回调生成检查点（构造拒绝仍保留）

方法按表名和成员键预登记，生成四个指针/长度参数、返回 i32 的独立回调；字段初始化合成为独立局部帧。方法共用原有函数返回、finally 和错误清理，参数按源码顺序求值后绑定固定参数/默认值。字段值入口支持弱只读 receiver，普通函数被表回调调用时也按实际值标签归还临时槽。已清空的弱槽不再次调用 weak_release，避免显式 return 与统一出口重复经过时出错。

CODEGEN_VERSION 2 → 3，隔离旧生成文本与缓存。三目标文本布局断言及实际 clang 编译探针覆盖回调参数、CFG 和支配关系。构造处 emit_table_descriptor 的方法拒绝及 table-user-drop 既有断言仍保留；尚不宣称表方法可执行。

container-dense 的方法拒绝前还有 values[0, 2] 的多项精确选择缺口。本检查点复用前端 selected_paths 接通该必要路径，并新增 3/7/11/19 的差分用例，要求结果为 11；不扩展混合/动态选择语义。原生构建探针继续在表方法处拒绝，未放松拒绝原因断言。

本机 Rust workspace、fmt、Clippy、Bun 287 通过/5 跳过及仓库检查通过；受控原生现为七项（新增三目标回调 IR 编译探针），全部通过。多项精确选择用例的 VM/原生完整轨迹相同：9 事件、2 对象，销毁位置 6:对象2、8:对象1，无新增 Drops 豁免。

## 十、A1 实际接通与释放核对

独立 V2 描述符已接入 new/singleton：先经 Runtime 既有状态机执行字段辅助函数，再执行零参数 init，最后强引用执行 drop。方法支持按表身份隔离、私有访问的静态检查、方法互调、位置/关键字/缺省实参、堆值返回与 finally 覆盖；A2 构造参数和 A3 方法值仍明确拒绝。方法拒绝断言在接通后替换为真实回调登记断言，并将原 table-user-drop 原样加入完整多路差分。

生成器组件清单现在从 main 可达块、直接调用和描述符中的回调地址共同计算；与产物验证共用符号归属表，补全通用复制/归还及新表入口的 weak 传递依赖。删除按整份 AST 泛化保留容器/表的旧谓词，未调用且未注册的方法不再造成“声明有、产物无”。验证器仍双向拒绝缺失/意外组件，没有强行保留无用符号。

CODEGEN_VERSION 从检查点的 3 升到 4，避免已经生成成功的旧表构造文本命中缓存；ABI 仍为本批新增的 1.8。为完整执行 container-dense，补齐多项精确索引、规范字典键读取及缺失声明、真正推进状态的 random.seed/随机源；种子和抽样直接复用 VM 使用的 SeededRandom/sample_indices。没有删除基准操作，也没有把“只定义 benchmark 函数”当作运行成功。当前 Windows 原生与 VM 均执行 80 轮，输出 28760，五项构建探针均成功；性能仍记数据不足。

### 单点对照与判定

- 字段辅助函数重复复制 receiver：初次接通 table-user-drop 为 VM 9 / 原生 10 事件，普通实例为 6 / 7。只把帧已拥有的字段/接收者槽借给 ABI 后，分别变为 9 / 9、6 / 6，完整轨迹相同。Runtime 构造视图、ABI receiver、字段函数参数帧和 setter 临时引用各自归还；不制造 retain 补数。held-table-instance 的过期豁免守卫报出后已摘除该登记。
- 堆字段返回：旧借用转换重复克隆已拥有的返回值，加上重复 receiver 复制，原生 17 事件、VM 15。改为借用名称槽并转移已经拥有的字段结果后总数均为 15，但释放顺序仍不同，未据此宣布一致。
- 返回覆盖：旧实现立即释放被 finally 覆盖的返回值；table-return-finally 两边同为 14 事件，却分别在原生 5、VM 6 销毁旧字符串。按 VM 帧临时寄存器持有关系保留各返回站点，先执行函数作用域计划，再复制/移交最终结果并归还帧临时值后，两边完整轨迹相同。所有临时槽在入口分配，避免被 finally 的 stackrestore 撤销。
- 临时接收者：原生曾把 print((new Item()).read()) 输出成“drop、7”，VM 为“7、drop”；字段读取临时接收者甚至事件数/销毁位置都相同，仍有输出顺序错误。现在表达式原值持有到语句末尾，调用另持绑定引用；字段访问借用原值。三条新增临时接收者用例的输出和完整轨迹均对齐。条件临时值、终止边、堆缺省参数以及临时 drop 错误进入 catch 均另有回归。
- 函数实参和循环来源：补齐表达式实参的语句期持有后，暴露原生 for 额外持有名称来源的 SSA 引用。名称来源改为借用并每轮重读绑定，保持 VM 在循环体重绑来源后的行为；visit([1, 2]) 中把来源改为 [9, 8]，必须输出 1、8。未知 iterable 的 Runtime 检查仍执行。
