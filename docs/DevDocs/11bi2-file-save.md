## 三、必须先冻结的 5 条

### 3.1 三条待定项（**已定，本批开局清账**）

`12-tests:844` 要求它们在 I2 开始前冻结：

| 待定项 | 出处 | **冻结为** |
| --- | --- | --- |
| 首次保存的目标已存在时是否覆盖确认 | `00-decisions:674` | **不额外确认，直接覆盖** |
| `--inLF <不存在文件>` | `00-decisions:676` | **创建空缓冲区并绑定该路径** |
| 保存目标是否必须 `.xiao` 扩展名 | `00-decisions:677` | **当前必须 `.xiao`**（见 §3.5） |

**理由**：

- **直接覆盖**：用户已经**显式输入完整路径并按了 Enter**，意图明确；
  与 VSCode 等编辑器一致；且写入走**原子替换**（§3.3），中途失败不留下半文件。
  `11b:178` 描述保存流程时也只说「输入包含文件名和扩展名的目标路径并按 Enter 后保存」，**没提确认**；
- **不存在则创建**：像 `vim` / VSCode 打开新路径。`11b:186` 要求的是不能绕过
  「**编码、路径和读取错误**」诊断——而「文件不存在」**不是读取错误**，是新建场景，两者不矛盾。

**⚠️ 处理方式照 I1b 的先例**：把结论写进 `00-decisions` 的「终端交互式解释器」**已冻结段**，
并**把这三条从待定段删除**。**不要留着待定项又在新段落里写结论**——那是漂移的开端。

### 3.2 保存态：路径输入**不得进入编辑器缓冲区**

`12-tests:852` 明确：「**光标不属于实际路径文本**」。
`11b:178` 也说取消时「**丢弃尚未提交的路径输入**」，且「不得写入文件或改变文件绑定」。

**冻结**：

- **保存态的路径输入是一个独立的临时字符串**，**不放进 `EditorState`**——
  这样「不改变源码缓冲区」是**结构上必然成立**的，而不是靠记得去还原；
- **保存态的按键处理与确认态同构**：**不调用 `applyKey`**（编辑器的 `applyKey` 操作的是源码缓冲区）。
  路径输入需要自己的最小编辑（插入、退格、左右），**写在保存态自己的处理器里**；
- **`q` + Enter 取消**（`11b:178`）：由于 §3.1 冻结了**必须 `.xiao`**，
  **`q` 不可能是合法的保存目标**，所以这个取消键**没有歧义**——这一点要写进注释，
  否则将来放开扩展名时会踩到；
- **Esc 取消**：与 `q` 等价，两条路都**丢弃路径输入**、**不写文件**、**不改变绑定**。

**⚠️ 保存态是 `multiline.ts` 状态机的第四个状态**，与 `"edit" | "confirm" | "output"` 并列。
**新增状态时必须同时检查**：确认态的既有守卫（`confirmationReady` 那道防同块回车绕过的闸）
**在保存态要有对应物**，否则同一个输入块里的 Enter 会绕过保存界面。

### 3.3 原子写：**抽出来共用，不要写第二份**

TS 侧**已经有**原子写（`cli/ts/src/config/editor.ts:189` 的 `atomicWrite`），
它已经处理了跨平台最难的部分：

- 同目录临时文件 + `rename`；
- **Windows 上 `rename` 覆盖已存在目标失败时的备份/替换/回滚**（先 `rename` 原文件到备份，
  再 `rename` 临时文件到位，失败则回滚）；
- **保留原文件的权限 mode**。

**冻结**：**把它抽成参数化的共享函数，`config` 与 `repl` 共用**。**⚠️ 不要为保存再写一份**——
这是本仓头号病史，而且原子替换的跨平台细节错一次就是**数据损坏**。

**抽的时候要参数化两点**：

1. **临时文件前缀**：现有实现写死了 config 专用名（`CANONICAL_FILE`），
   保存别的文件时要传目标文件的 basename；
2. **文件系统注入**：现有实现通过 `ConfigFileSystem` 接口注入（可测试），
   **这个注入点要保留**——不能因为抽出共用就把可测试性丢掉。

**落点**：`cli/ts/src/platform/`（该目录已存在，职责正是跨平台差异）。
抽完后 `config/editor.ts` **改为调用共享实现**，两份之间**不允许有行为差异**。

**⚠️ 还要一并冻结的**：写入的**编码固定 UTF-8 无 BOM**、**换行固定 LF**（§3.4）。

### 3.4 编码与换行的诊断边界

`12-tests:851` 要求「路径、权限、**编码和换行**错误具有独立诊断」。
但**"换行错误"是什么**规范里没说。本批冻结为：

- **读入**：`CRLF`、`CR`、`LF` **一律正常接受**并归一化为 `LF` 存入逻辑行——
  这是 `11b:131`「保留输入中的真实换行」在编辑器内部表示上的落地
  （**逻辑行是换行无关的，真实换行只在 `editorSource` 拼接时还原为 `LF`**）；
- **写出**：**统一写 `LF`**。**⚠️ 这意味着 CRLF 文件保存后会变成 LF**——
  **本批接受这个行为**，但它是一个**用户可感知的变更**，要写进 UseDocs；
- **"换行错误"解释为**：文件中存在**既不是 `LF`/`CRLF`/`CR` 的、会破坏行结构的字节**
  （如 `NUL`），**与编码错误分开诊断**；
- **"编码错误"**：不是合法 UTF-8 的文件 → **读取时拒绝并给出独立诊断**，
  **不得**用替换字符静默吞掉（那会悄悄损坏用户源码）。

**⚠️ 这一条是本批的解释，不是规范原文。** 若实现中发现与 `11b` 的意图不符，
**要在文档里更正而不是自行改行为**。

### 3.5 `.xiao` 限定：当前强制，扩展点显式登记

**冻结为「当前必须 `.xiao`」**，与 `11b:19` 的入口形态 `xiao --inLF "<file.xiao>"`、
以及 `parser.ts:95` 既有的 `.xiao` 快捷运行识别保持一致。

**⚠️ 但要显式登记将来的扩展点**——星崽的原话是「其他文件后续再扩展」。
所以：

- 不符合扩展名时给**明确诊断**（不是静默接受，也不是装作路径不存在）；
- **在文档与代码注释里写明「当前限定，扩展点已登记」**，
  免得将来放开时被当成「偷偷改冻结」；
- **`q` 取消键的无歧义性依赖这条**（§3.2），放开扩展名时**必须重新检查 `q`**。

### 3.6 绑定后的行为

- **首次保存成功** → 缓冲区**绑定该实体文件**、**保留缓冲区内容**、返回编辑态（`12-tests:842`）；
- **已绑定** → 通过**任一**保存入口（`!save!` 或 Ctrl+Shift+S）**直接写回**，
  **不再显示路径输入**（`:843`）；
- **`xiao --inLF <file.xiao>` 载入成功** → **立即建立绑定**，所以第一次保存就**直接写回**（`:843`、`11b:180`）；
- **保存失败** → **不建立新绑定、不破坏已有绑定、不清空缓冲区**（`:851`），
  并报告**目标路径 + 可操作的原因**（`11b:178`）。

**⚠️ 绑定信息放在哪里要一致**：它是**缓冲区状态**（跟着缓冲区走），
不是终端状态、也不是「最近一次执行」的状态。**执行（I1b）不得清除绑定**。

## 八、最可能翻车的地方

1. **为保存另写一份原子写**（§3.3）——跨平台覆盖细节错一次就是数据损坏。
2. **路径输入放进了 `EditorState`**（§3.2）——取消时得记得还原，漏一处就改了用户源码。
3. **保存态没有防输入块绕过的闸**（§3.2）——确认态踩过同一个坑（`42fcf01`）。
4. **用替换字符吞掉非法 UTF-8**（§3.4）——用户源码被静默损坏，且保存后不可逆。
5. **保存失败时破坏了已有绑定**（§3.6）——用户以为还在编辑原文件，其实已经断了。
6. **执行（I1b）清了绑定**（§3.6）——绑定是缓冲区状态，不是运行状态。
7. **把保存标题复制成第二个分隔线函数**（§五）——`11b:182` 明确要求两个界面不能混淆。
8. **抽取原子写时丢掉了文件系统注入点**（§3.3）——可测试性会退化。
9. **CRLF 文件保存后变成 LF 却不说**（§3.4）——用户可感知的变更，必须写进 UseDocs。
10. **放开扩展名时忘了 `q` 取消键会歧义**（§3.5）——这是登记扩展点的意义。

## 九、验收

1. **载入**：`xiao --inLF "<file.xiao>"` 装入现有 UTF-8 文件，保留换行与缩进；**载入即绑定**（`:842`、`:843`）。
2. **不存在文件**：创建空缓冲区并**绑定该路径**，首次保存即创建文件（§3.1）。
3. **未绑定保存**：`!save!` 与 Ctrl+Shift+S 都进入路径输入；成功后绑定并返回编辑（`:842`）。
4. **已绑定**：两个入口都**直接写回**，**不显示**路径输入（`:843`）。
5. **取消**：`q`+Enter 与 Esc 都**无损返回**——路径输入被丢弃、**不写文件、不改变绑定**（`:844`）。
6. **`!save!` 剔除**：不进缓冲区、不进源码行号映射、不进保存内容（`:845`）。
7. **原子性**：写入不留半文件；**在写入中途失败时原文件完好**（`:851`）。
8. **四类诊断**：路径、权限、编码、换行**各有独立诊断码**；非法 UTF-8 **被拒绝而非替换**（`:851`）。
9. **失败不破坏绑定**：保存失败后缓冲区仍绑定原文件（`:851`）。
10. **界面**：保存态上方分隔线显示 `Enter the save location`，`>` 用 `#DCDCAD`；
