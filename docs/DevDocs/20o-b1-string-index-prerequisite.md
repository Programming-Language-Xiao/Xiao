# B1-IMP 字符串读取成本前置

F10 初测发现既有 `StringHandle::len` 逐次执行 `chars().count()`，VM 下标和原生迭代
逐次执行 `chars().nth(index)`；完整遍历重复扫描前缀，实际为二次成本。

此独立修复在不可变字符串构造时建立 Unicode 码点起点索引。ASCII 直接以字节位置读取，
不分配索引数组；非 ASCII 使用共享载荷中的起点数组。长度与单码点读取为常量时间，
构造成本为 O(n)，额外空间 O(n)。VM 下标、原生下标和原生迭代共用同一读取路径。
字符串本身保持 UTF-8，负下标归一化和错误身份沿用原规则。

索引缓冲的实际容量计入 Runtime 对象拥有字节数，分配失败沿用 ResourceError /
X06-RUNTIME-011。克隆共享载荷，最后一个强引用释放时统一销毁文本与索引。
不改变 C ABI 1.18、intrinsic、语法或公开函数集合。

同源原生回归另检出精确路径的负数字面量被重复反转：IR 的 `text` 已含负号，
降低又按 `negative` 取负。现与字节码路径统一为先读绝对值，再仅应用一次符号，
包含最小 int 下标的安全解析；该降低修正将生成器版本升至 18。

回归包括 Runtime 独立码点表（NUL/BOM/组合字符与 UTF-8 边界）、ASCII 零索引分配、
共享生命周期及内存计数；20C 默认测试核对正负下标与逐字符迭代，完整样例含越界，
复用 B1 原生语义精确目标。性能测试保留默认执行与原 10 秒/翻倍比预算，另补最大填充输出，
不能用未触发填充的输入扫描代表全部 F10。

首次修复后 debug 最大 ASCII 输入五次中位数为 3.5998628 秒；这是本机初测，最终完整
样本与日志另在 IMP 证据中登记，不据此宣称七库或三平台性能达标。

扩展 20C 诊断时另外暴露了原生释放缺口：成功的字符串循环末次字符未销毁；含越界的
完整样例还留存输入文本（native 14 / VM 16）。这些行为未由本次私有字符索引修复覆盖。
按本批不改 22 释放债务的范围，保留原始失败日志和语义样例，不修改原有 20C 释放断言；
不把语义或速度通过表述为完整失败清理验收通过，B1-CLOSE 仍需处理该阻塞。
