## 三、必须先冻结的 5 条

### 3.1 单行模式的 `Ctrl+Shift+P`：**传统终端下不可用，这不是缺陷**

**⚠️ 本批最容易被误解的一条。**

规范（`12-tests:855`）要求「单行和多行模式都能通过 Ctrl+Shift+P 或 `!panel!` 打开」。
但**单行模式用的是 `node:readline`**（I1a §3.4 冻结：本批不动它），而：

- **传统终端下 `Ctrl+Shift+P` 与 `Ctrl+P` 发送相同字节 `\x10`**，**无法区分**；
- 即使能区分（Kitty 键盘协议），**readline 会先接管按键**，我们未必拿得到。

**冻结**：

- **单行模式在传统终端上不支持 `Ctrl+Shift+P`**——按 `00-decisions` 已冻结的
  **「不能把无法上报的组合键猜成别的动作」**，此时**静默无反应**，**不报错**；
- **`!panel!` 是单行模式的完整入口**，与 `!outLF!`/`!save!` 的降级逻辑**同源**
  （`11b:217` 的 R0 第 5 条）；
- **Kitty 协议确认后**，若 readline 仍拿不到该按键，**同样静默降级**——
  **不得为了满足字面上的"两个入口"而去改单行模式的输入模型**（§3.2）。

**⚠️ 这一条要在 UseDocs 里写明**，否则用户会以为单行模式的快捷键坏了。

### 3.2 单行模式的面板：**临时接管终端，不改 readline 架构**

`!panel!` 在单行模式触发了面板，而面板界面（分隔线 + `>` 栏 + Esc 关闭）
**需要 raw mode**，readline 画不出来。

**冻结：照搬 `!inLF!` 的交接方式，不另创新的机制。**

`session.ts:59` 已有先例：读到独占一行的 `!inLF!` → **退出 readline**
（`setRawMode(false)`、收尾光标与换行）→ 进入 raw mode 会话 → 结束后**重新进入 readline**。

**面板复用同一条交接路径**：

- 单行模式读到独占一行的 `!panel!` → **不作为源码执行**（`12-tests:856`）→
  退出 readline → 临时 raw 会话显示面板 → Esc 或再次 `Ctrl+Shift+P` 关闭 →
  **回到单行模式**（`runSingleLineRepl` 带 `showBanner: false`，先例已存在）；
- **⚠️ 终端状态必须成对恢复**，与 I1a §3.4 的约束一致；
- **⚠️ 单行模式的面板会话与多行模式的面板会话要用同一个模态实现**（§3.3），
  **不要为单行单独写一份面板**。

### 3.3 面板是一个**独立模态**，单行与多行共用

I3 的界面与开关在多行模式里有 `multiline.ts` 的状态机可挂，
但**单行模式没有那个状态机**（它只有 readline 加一个 `!inLF!` 判断）。

**冻结**：**面板做成独立的模态**，与 `confirm.ts` / `save.ts` 平级：

```text
repl/panel.ts     面板状态与渲染（标题、`>` 栏、两条分隔线、开关判定）
```

**两边都调用它**：

- **多行模式**：`multiline.ts` 的状态机加第五态 `"panel"`；
- **单行模式**：临时 raw 会话里直接驱动同一个面板模态。

**⚠️ 不要写两份**。这是本仓头号病史，而且面板的宽度自适应与配色一旦分叉，
两个模式下会长得不一样——用户一眼就能看出来。

### 3.4 标题：**硬编码英文，11C 替换；本批不引入消息目录**

`12-tests:858` 写的是 `Command Panel`（英文），
`11b:31` 说「示例中的英文标题只表示默认示例文本；**实际显示由第 11C 阶段的消息目录决定**」。

**冻结**：**照 `confirm.ts:9` 的 `CONFIRM_TITLE` 模式办**——
**导出一个常量 + 注释说明 11C 会替换可见文案**。
**本批不读 `[language].locale`、不建消息目录、不做中英切换。**

**⚠️ 理由**：`12-tests:859` 那一条（「中英语言切换只改变系统文字」）是
**约束**（切换语言不得影响源码、错误码、退出码），**不是要求 I3 实现语言切换**。
语言切换的实现在 11C。**本批只要不违反它**——即**标题之外的一切都不因语言而变**。

**⚠️ 但要把这个判断写进文档**，否则接手者会以为 I3 漏做了本地化。

### 3.5 开关与"不虚构命令"

- **打开**：多行模式用 `!panel!` 或 `Ctrl+Shift+P`；单行模式用 `!panel!`
  （`Ctrl+Shift+P` 见 §3.1）；
- **关闭**：**Esc** 或**再次按 `Ctrl+Shift+P`**（`12-tests:861`、`11b:207`）；
- **关闭后恢复打开前的交互界面**——且在**单行模式**下要回到**单行**，
  在**多行模式**下要回到**多行编辑**（含缓冲区与光标）；
- **打开与关闭都不得修改源码缓冲区或文件绑定**（`12-tests:861`）——
  与 I2 的保存态同理，**面板状态是终端状态，不是缓冲区状态**；
- **⚠️ 首版不为未来功能虚构命令**（`11b:207` 末句）：
  **面板里不出现任何占位命令、示例命令、灰色菜单项**。
  空就是空——`>` 栏接受输入但没有命令可执行，**输入的回车不产生任何动作**。

**⚠️ 输入行的行为要显式冻结**：面板的 `>` 栏**可以接受键入**（否则不像输入栏），
但**回车不执行任何东西**；输入的文本**随面板关闭一起丢弃**，
**不得进入源码缓冲区**（与 §3.3 的"面板是终端状态"一致）。

1. **入口**：多行模式下 `!panel!` 与 `Ctrl+Shift+P`（Kitty 确认后）都能打开；
   **单行模式下 `!panel!` 能打开**，`Ctrl+Shift+P` 在传统终端**静默无反应**且不报错（`:855`、§3.1）。

   线条 `#7F7F7F`、`>` 用 `#DCDCAD`；**两条分隔线随终端宽度变化**（`:858`）。
