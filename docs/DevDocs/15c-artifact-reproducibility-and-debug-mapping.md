# 15C. 产物层可复现与调试映射

> **15 阶段的第三批，收尾批。** [15B](15b-reproducible-builds-and-performance-baseline.md)
> 把可复现比较建在 **LLVM 文本层**，并交付了性能基线模型；
> 本批把它**下到产物层**，并补齐**调试映射与独立验收**。
>
> **一句话概括本批**：`15` 的验收原话是「**可复现构建**不受机器绝对路径、时间戳或
> 未定义排序影响」——**"构建"指产物**。文本层一致是必要的第一步，但不是那一条的全部。
>
> **⚠️ 本批的未做项全部有出处**（§二）——**都是上一批自己在实施记录里标出来的**，
> 不是本档新提的要求。

## 二、上一批（15B）的未做项 —— **本批的全部范围**

**四项，全部有出处**；前两项是 15B 自述的，后两项是本档核范围时确认的。

### 2.1 `15.5` 调试映射与内联栈 —— **未做**（15B 自述）

**冻结**：

- 优化后的指令要能回溯到**源码位置**；**被内联的帧要能还原**（内联栈）；
- **与 14B 的三方差分衔接**：源码 / 未优化字节码 / 优化字节码三方可比的前提，
  是**每一方都能给出源码位置**——优化方丢了映射，差分就只剩"输出一样"；
- **不是"重新生成一份映射"**：要在**优化过程中维护**，否则内联后无从还原。

### 2.2 `15.7` strip / 调试符号 / 可诊断模式的**独立产物验收** —— **未做**（15B 自述）

**冻结**：

- **三者独立验收**（15B `§3.5` 已冻结），本批把它**落到产物层**——
  15B 建的是模型与白名单，**没有对真实产物做独立验收**；
- **"优化之后"是关键词**：10H 验过未优化产物的 `-debug` 三不，
  本批要验**各 `-O` 级别优化之后**这条边界仍然成立；
- **调试信息的发布保留策略仍属待定决策 3**——**建验收，不冻结策略**。

### 2.3 链接后产物的**逐字节可复现** —— **本批核出的范围缺口**

15B 的比较对象是**规范化后的 LLVM 文本**（`llvm_text_identical`）。
而 `15` 验收的原话是「**可复现构建**不受机器绝对路径、时间戳或未定义排序影响」——
**"构建"指产物**。

**冻结**：

- **比较对象要下到产物**（可执行文件字节）；
- **至少要覆盖**：
  - **PE 的 `TimeDateStamp`**（链接器写入的时间戳，是这类差异的经典来源）；
  - **链接器产出的符号表顺序**（15B 只规范了 LLVM 文本里的 `; xiao-symbol=` 注释，
    **不是链接器的符号表**）；
  - **调试信息里的绝对路径**；
- **⚠️ 不能只靠"两次跑看起来一样"**——那是 10K 那条教训的同款
  （「什么都没找到可能只是探测方法失效」）：**要给出比较的是哪些字节、哪些字段被归一化**；
- **白名单继续沿用 15B 的五类**，不为本批新开一套。

### 2.4 性能基线的**实际取数** —— 模型在，数据未取

15B 交付了 `baseline.rs` 的模型（固定条件、中位数、离散度、非有限样本拒绝），
但**正式基线数据尚未在受控环境取得**。

**冻结**：

- **本机测量只作方向参考**（15B `§3.4` 已冻结），正式基线需**受控环境**；
- **没有数据就说没有数据**——**不许用开发机的数字冒充基线**；
- **若本批拿不到受控环境**，**明确记为待办**，而不是填一个看起来合理的数。

### 2.5 三平台门控运行 —— **环境依赖，不作为本批的阻塞**

15B 自述「实际三平台门控运行……仍需对应平台工具链」。

**冻结**：

- **按 15A `§3.6` 的 Windows → Linux → macOS 顺序推**，**不在本批强行三平台齐跑**；
- **本机能做的先做**（§2.1–§2.4 大部分可在本机完成），
  平台相关部分**记入运行记录并标为待补**；
- **不因为三平台未齐就搁置 §2.1–§2.4**——那四项**不依赖具体平台**。

## 三、必须先冻结的 6 条

### 3.1 **比较的对象是产物，不是文本**（§2.3）

15B 做的是文本层。本批要**下到产物字节**。

**冻结**：

- **产物级可复现的判据是"逐字节相同"**（或差异在白名单内）；
- **比较范围要写清楚**：哪些字节参与、哪些字段被归一化（§2.3 的三项至少覆盖）；
- **⚠️ 归一化 ≠ 忽略**：归一化掉的时间戳字段要**显式记录**，
  不能"反正比不出差异就跳过"。

### 3.2 **确定性的第三次落地 —— 三处共用一条规则**（15B `§3.1` 继续）

13A（指纹）、14A（`.xiaoc`）、15B（构建）是同一原则的三次；**本批是第四次，
且第一次要求到产物字节**。

**冻结**：

- **不为本批新造规则**——沿用同一条：「时间戳、临时路径、机器标识不进可寻址产物；
  未定义排序必须消除」；
- **若发现前三处有漏**，一并记下，**别各自打补丁**（15B `§3.1` 已这么要求）。

### 3.3 **调试映射要在优化过程中维护，不是事后重建**（§2.1）

**冻结**：

- **内联栈的还原**要求映射**在内联发生时就记录**——事后从优化后的指令反推，
  在跨函数内联下**信息已经丢了**；
- **与三方差分的衔接**：优化方丢了源码位置，差分就退化成"只看输出"；
- **不重开** 14B/15A 的 Pass 与差分设计——本批是**补映射**，不是改 Pass。

### 3.4 **`-debug` 三不在优化之后仍成立**（§2.2）

10H 验的是**未优化**产物。本批验**各 `-O` 级别优化之后**。

**冻结**：

- **调试版产物（含 `-O1`–`-O3`）仍能开独立诊断窗口**；普通产物仍**不自动开窗**；
- **优化不得把调试激活位"优化掉"**——那是产物标志，不是可删的死代码
  （**与 14B/15A 的"不得删除可观察操作"同源**）；
- **strip 之后**：可诊断模式**要么仍工作、要么给出明确失败**——
  **不许静默降级**（10H 三不之一）。

### 3.5 **没有受控环境就没有基线**（§2.4）

**冻结**：

- **开发机数字不作正式基线**；
- **拿不到就记为待办**——**填一个"看起来合理"的数是更坏的选项**；
- **噪声阈值必须来自实际测量**，不是拍的。

### 3.6 **本批不做 16–19 阶段的事**

- **不做** Protobuf 索引与内容寻址缓存（16）——含待定决策 4；
- **不做** `.xar`（17）、TS CLI 参数解析（18）、Java 对照与发布验收（19）；
- **不启用** LTO / PGO / 向量化 / 目标 CPU 特化（待定决策 2）；
- **不冻结**调试信息的发布保留策略（待定决策 3）。

## 六、硬约束

1. **比较对象下到产物**（§3.1）——文本层一致是必要不充分。
2. **归一化要显式记录**，不能"比不出差异就跳过"（§3.1）。

8. **门禁**：`cargo test --workspace`、**`bun run check`（含 `check:lock`，两个 lock 都要提交）**、
   `cargo clippy --workspace --all-targets -- -D warnings`、TS 类型检查、`cli/ts` 全目录测试。

## 九、验收

1. **产物级可复现**（§2.3）：同一输入重复构建，**可执行文件逐字节相同**，
   或差异**逐条列在白名单里并有理由**；**比较范围与归一化字段写清楚**；
   **PE `TimeDateStamp`、链接器符号表顺序、调试路径**三项至少覆盖；
2. **调试映射与内联栈**（`15.5`）：优化后指令可回溯源码位置；**内联帧可还原**；
   映射**在优化过程中维护**；
3. **strip / 调试符号 / 可诊断模式**（`15.7`）：**三者独立验收**，
   **在各 `-O` 级别下**；`-debug` 三不成立；strip 后不静默降级；
4. **性能基线**（`15.9`/`15.10`）：**受控环境**取得的数据，含噪声阈值；
   **若未取得，如实记为待办**（**不以开发机数字顶替**）；
5. **文本层不回归**：15B 的 `llvm_text_identical`、符号顺序、五类白名单保持绿；
6. **平台**：按 Windows → Linux → macOS 推进；未推的**记入运行记录并标待补**，
   **不阻塞 §2.1–§2.4**；
7. **不回归**：15A/15B/14A/14B/13A/13B/10 已交付内容保持绿；`cargo test --workspace` 全绿；
8. **门禁全绿**：`bun run check`（含 `check:lock`）、clippy、TS 类型检查、`cli/ts` 测试。
