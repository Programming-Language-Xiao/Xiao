# 10V. 诊断窗口会话结束后的保持（N0-N）

> **背景**：本地跑原生 ignored 套件时，Windows 上诊断窗口会连续弹出并立即关闭
> （`native_table_methods_debug_execution_o0_o3` = 18 个表用例 × `O0`–`O3` = **72 次调试执行**，每次一个窗口）；
> 而 19.14 的 C 档又需要一个**能截图留证**的可见窗口。两者是同一个根因：
> **渲染器收到 `Close` 后立刻返回，进程退出 → 终端窗口随即关闭**。
>
> **一句话概括本批**：**让会话结束时窗口留下来**（显示最终状态，等用户看完再关），
> 同时保证它**不改变程序语义**、**在测试与 CI 里可显式关掉**。
>
> 状态：**规划稿（2026-10-08）**。行为取值集中在末尾「待定决策」。

## 二、必须先冻结的 6 条

### 2.1 **保持的语义边界：只影响窗口，不影响程序**

11X0-D 已经冻结了两条硬约束，本批**不得**因为「让窗口留下来」而破坏它们：

**冻结**：

1. **不得改变程序语义**。现状之所以安全，是因为 `finish()` 用 `child.try_wait()` 而非 `wait()`；
   **保持逻辑不得引入任何形式的阻塞等待**（不 `wait()`、不 join 渲染进程）。程序该多快结束就多快结束；
2. **窗口关闭、通信中断、日志目标不可写都不能改变程序结果**（11X0-D 原话）。保持只是渲染器自己的事；
3. **不得静默降级**：找不到可用终端时仍然是**明确失败**（既有 §5.2 路径），
   **不能**因为「反正窗口会关」就把启动失败吞掉；
4. 保持期间**不得**让程序退出码、事件流、指标或日志受影响；这些在 `finish()` 时已经定稿；
5. 保持**不改变**「调试产物直接启动必定开窗」的强制语义（18.13），也不影响普通发布产物不激活窗口的行为。

### 2.2 **保持的形态与开关**

**冻结**：

1. 形态：会话结束后**保留最后一屏内容**（含「诊断会话结束：{reason}」与状态栏指标），
   并明确提示如何关闭（例如「按任意键关闭窗口」），**不是**静默地卡住；
2. 交互式场景（用户手工 `xiao run -debug`）与测试/CI 场景**必须能区分**——后者要显式关掉，
   否则 72 次执行会堆 72 个窗口、CI runner 上还可能永久挂住；
3. 开关**优先用环境变量**（沿用 `XIAO_DIAGNOSTICS_*` 的命名习惯，与既有的 `XIAO_DIAGNOSTICS_PATH` 并列），
   因为它要下传给**渲染进程**；若实施方判断必须走协议/产物字段，则按 10T 的版本规则处理（见 §2.5）；
4. 两个入口都要处理：**管道模式**（`Close` 分支）与 **`run_standalone`**（原生 shim 无连接窗口）；
5. 保持应当是**有界的**或**可被用户立即关掉**——不允许出现「窗口关不掉、只能杀进程」的形态；
   具体是「等按键」还是「固定超时后自动关」，见待定决策 2；
6. 关闭窗口后**渲染进程退出码不影响程序退出码**（二者本就是两个进程，但要写进测试断言）。

### 2.3 **测试与 CI：必须显式设置，且把风暴写进文档**

**冻结**：

1. **默认值必须让测试与 CI 不堆积窗口**（见待定决策 1 对默认值的取舍）；无论选哪种默认，
   维护门控的 Windows 与 Linux 原生作业都要**显式**设置成不开窗保持，
   macOS 作业本来就不执行调试运行（`execute = false`），只需在文档里说明；
2. 本地跑 ignored 套件会开大量窗口这件事要**写进相关文档**（10D 门控规范或 10U/10T 的实施记录），
   并给出跳过或关闭的用法，避免下一个接手的人被弹窗风暴困住；
3. 调试矩阵测试本身**不得为了少开窗而删用例或降低覆盖**；要少开窗就改开关，不改覆盖；
4. CI 设置方式写进实施记录：哪个作业、哪个变量、什么值，以及**该作业是否仍然真的执行了调试产物**
   （不能因为关窗口而把执行也关掉——那会让 `native_table_methods_debug_execution_o0_o3` 变成空跑）。

### 2.4 **失败路径不变**

**冻结**：

- 「找不到可用终端」「shim 无法启动」「通信中断」的既有失败诊断与稳定 `code` **一条都不改**；
- 保持逻辑只作用于**已经开始渲染并收到 `Close`** 之后；
- 新增的保持如果自身失败（例如环境变量取值非法），应当是**明确失败**并带稳定诊断，
  不得静默回退到「关掉就完事」——与 11X0-D 的失败口径一致。

### 2.5 **版本与接口**

**冻结**：

- 若开关走**环境变量**：不涉及 ABI、不涉及产物字段，**不升版本**；
- 若实施方判断必须走**协议字段或产物字段**：按 10T 的规则——只加入口走**次版本**、
  改既有布局/所有权才升**主版本**，并同步版本断言、工具链指纹与兼容矩阵；
- 渲染器命令行参数如有变化，要保证**旧调用方仍可用**（新增可选参数，不改既有参数语义）。

### 2.6 **取证收益与仍然要做的事**

**冻结**：

- 本批之后，[10T-Linux 交接](10t-linux-bare-metal-handoff.md) §五 的窗口取证可以简化：
  用**短程序**也行（窗口会保持），但**仍应在裸机上执行并截图**——
  本批只让取证**可行**，**不代替**取证本身；
- 因此 **19.14 的 C 档在本批之后仍记为未通过**，直到收到裸机截图；
- 文档不得把「窗口现在会保持」写成「C 档已验证」。

## 四、硬约束

1. **不得引入阻塞等待**（§2.1）——程序退出时机与现状一致，用 `try_wait` 的现状不能改成 `wait`；
2. 不改变既有失败诊断与稳定 `code`（§2.4）；
3. 开关必须能让**测试与 CI** 关掉保持；两个渲染入口都处理（§2.2）；
4. **不得靠删用例或少执行来减少窗口**（§2.3）；
5. 保持必须可被用户立即关闭，不允许关不掉（§2.2）；
6. 文案走既有 i18n 目录，中英双语，不硬编码（§三 落点）；
7. 不新增依赖，`Cargo.lock` 保持同步；
8. 每个提交单独跑 `cargo test --workspace`、clippy、fmt；推送前跑 `bun test` 与 `bun run check`；
9. 提交说明带正文；涉及既有测试改动时逐条披露。

## 六、最可能翻车的地方

1. **顺手把 `try_wait()` 改成 `wait()`**——那就真的改变了程序语义；
2. **保持实现了，但测试与 CI 没关**——本地 72 个窗口堆积、CI runner 上可能挂住；
3. **用「少跑几个用例」来减少窗口**，把覆盖偷偷降下来；
4. **把保持做成关不掉的窗口**，用户只能杀进程；
5. **只处理了管道模式**，漏掉 `run_standalone`（原生 shim 的无连接窗口）；
6. **文案硬编码中文**，绕过 i18n 目录；
7. **把「窗口现在会保持」写成「C 档已验证」**（§2.6）；
8. **非法开关值静默回退**，与 11X0-D 的失败口径相悖；
9. **只看 `cargo test` 就宣布门禁全绿**（`bun run check` 不在其中）；
10. **提交没写正文**。

## 七、验收

1. 会话结束后窗口**保持显示**最后状态并给出关闭提示，用户可立即关闭；
2. **程序语义不变**：退出码、事件、指标、日志与改动前一致；`finish()` 仍不阻塞（有测试或代码证据）；
3. 开关生效：测试与 CI 关闭后**无窗口堆积**，且调试矩阵**仍然真的执行**（不是空跑）；
4. `run_standalone` 同样保持；
5. 失败路径一字未改，非法开关值是明确失败；
6. 窗口风暴与用法写进文档；11X0-D 与 10T-Linux 交接已回填；
7. **C 档仍记未通过**，直到收到裸机截图（§2.6）；
8. `cargo test --workspace`、clippy、fmt、`bun test`、`bun run check` 全绿，且每个提交单独绿；
9. 没有通过删用例、降覆盖或放宽断言换来的绿。

## 八、不负责与不要重复做的事

- **不改**窗口机制本身（新开终端的候选顺序、失败诊断、启动 shim）；
- **不做** A2/A3 剩余部分、B1/B2、静态溢出、性能取数；
- **不做** GUI 窗口（11X0-D 已明确：这是新开的**终端**窗口，不是 GUI）；
- **不代替**裸机取证——本批只让取证可行。

## 实施记录（2026-10-08）

- 连接模式收到 `Close` 和 standalone 父进程结束后，都会显示保持提示并短暂保留最后一屏；Runtime 侧仍使用 `try_wait()`，渲染器保持不会阻塞用户程序。
- 开关为环境变量 `XIAO_DIAGNOSTICS_HOLD_MS`：未设置默认 5000 ms，设置为 `0` 明确关闭；非法值或超过 3600000 ms 会以诊断通道错误退出，不静默回退。
- 平台复现脚本和维护回归的 Windows/Linux 原生作业均显式设置 `XIAO_DIAGNOSTICS_HOLD_MS=0`，调试矩阵仍执行，不删用例。交互取证可不设置变量，窗口会保留 5 秒。
- 提示文案已加入中英双语 i18n。C 档仍需裸机截图，本改动不替代取证。
- **审核补正（2026-10-08）**：规划 §2.3 第 2 条要求「本地跑 ignored 会开大量窗口」写进文档，
  实现漏了。已补进 [10D](10d-environment-gated-test-spec.md) §4.5：窗口规模（72 次调试执行）、
  `XIAO_DIAGNOSTICS_HOLD_MS` 的语义与默认值、推荐用 `--skip` 消窗，并说明走 `reproduce.sh`/CI
  时窗口闪退是**预期**的（那些路径显式设了 `0`）。
- **审核实测（2026-10-08）**：保持本身已验证有效——`--standalone` 预览在默认下耗时 **6170 ms**
  并打印保持提示，`XIAO_DIAGNOSTICS_HOLD_MS=0` 时耗时 **1154 ms** 且不打印。用法说明见 10D §4.5。

## 决策结论

1. **默认值**：采用一律默认保持 5000 ms；测试、CI 和平台复现脚本显式设置 `0`。
2. **保持方式**：采用有界固定超时；终端窗口仍可由用户关闭，关闭不影响原程序结果。
3. **开关载体**：采用环境变量 `XIAO_DIAGNOSTICS_HOLD_MS`，不改变协议和 ABI 版本。
4. **机制回填**：已在 11X0-D 增加窗口生命周期补充，继续沿用其失败路径和非阻塞约束。
