## 二、20L 审核返工项（先做）

### F-1 **20L 字典静态链接污染 set-only 程序（阻断）**

**CI 证据**：维护回归 `39442513478` 三平台原生作业全红：

```text
first_modules_match_native_results ... FAILED
set-alias 原生退出状态不符：
X06-RUNTIME-002 type_mismatch actual=set expected=字典
```

**本地复现**：`from stdlib.set import size as count` 的原生构建成功，运行报同一错误；
`--emit-llvm` 产物含 `xiao_runtime_value_dict_keys`/`dict_values` 的真实调用，
说明 set-only 程序被 `stdlib.dict` 静态链接/符号解析污染，`count` 最终执行了
`dict.size`。

**要求**：

1. 模块限定或隔离 set/dict 的同名自由函数（`size`/`is_empty`/`contains`），
   不允许后链接的字典实现覆盖 set；
2. 字典方法链接只在类型确认的字典方法接收者上触发；set-only 程序不得携带字典函数体；
3. 补 `set-alias`/`text-alias` 的原生回归，作为 20L 的门禁用例；
4. 三平台原生作业恢复绿后，才能把 20L 写成验收通过。

### F-2 **`run.sh` 的已知抖动分类模式与真实失败名不匹配**

脚本允许 `"(fail) Ctrl+D"*`，真实失败行是
`(fail) !inLF! 后空缓冲 Ctrl+D 结束整个会话，不重新进入单行`；前缀不匹配，
已知抖动会被判成非已知失败。自测用的是合成 `(fail) Ctrl+D`，覆盖不到真实名字。
要求按实际测试名（或子串）匹配，并让 `XIAO_GATE_SELF_TEST` 使用真实失败行；
对带 ANSI 的 Bun 输出先去色再分类。

### F-3 **私有字典动作仍在契约外**

## 三、21A 已确认、本批不得改写的边界

1. **默认单线程非原子 RC**；跨 Runtime 能力必须显式表示，不能悄悄扩散原子语义；
2. **强拥有图是 DAG，不是森林**；共享/菱形合法，强环静态拒绝；
3. **`CrossThread` 是值级生命周期事实**，不是可发送能力；模型冻结前不得名称启发式产生；
4. **当前 `RefCountStrategy` 不是原子实现接口**；共享句柄需要独立对象头/句柄；
5. **`Arena` 不豁免强环**；区域分配是新的存储类别；
6. **并发实现后置**：07-D 只研究；实现必须是 B0/N0 之后的新独立阶段；
7. **复制/冻结/共享可变对象尚未冻结**；普通 `Clone` 是浅层句柄克隆，不是跨线程深拷贝；
8. **不新增 `Weak`/`spawn`/`send`/`async`/`await`/Actor/Channel 语法**；
   不预留不存在的阶段代号或 `std.concurrent` API。

## 四、研究问题与交付物

### 4.1 模型候选与成本矩阵

至少比较：

| 候选 | 语义 | 需要回答 |
| --- | --- | --- |
| OS 线程 | 多线程共享进程内存 | 调度/栈、竞争面、句柄边界、错误/取消传播 |
| 单线程任务/协程 | 可暂停恢复、同一线程 | 挂起语义、RC/Weak 可见性、I/O 等待、取消 |
| 任务池 | 复用工作线程 | 任务迁移、Send 边界、阻塞/饥饿、清理 |
| Actor/Channel | 消息隔离 | 消息复制/冻结、邮箱生命周期、错误传播、背压 |
| 多 Runtime/堆岛 | 每岛独立 RC | 跨岛值集合、隔离边界、启动/关闭、ABI |
| 组合模型 | 上述组合 | 哪些组合必须显式禁止，避免隐式跨线程 |

**矩阵列**：语义清晰度、RC/Weak 影响、错误/取消/清理、实现成本、ABI/IR 影响、
标准库依赖、可测试性、与 21A 边界的冲突点。

### 4.2 Send/Sync 与任务边界

- 「移动到另一个执行单元」与「多执行单元同时只读」分开讨论；
- `CrossThread` 是否拆成「任务边界」与「线程边界」两个事实；
- `Send`/`Sync` 或等价能力的名称、推导规则、动态值/容器的策略；
- 普通句柄、共享句柄、消息值三者的类型/ABI 边界；
- 不得把协程挂起/恢复自动等同于跨线程。

### 4.3 值传递：拷贝、序列化、冻结、共享可变

- 递归深拷贝的集合、动态值、资源句柄和错误对象处理；
- 序列化的稳定格式、版本、失败传播；
- 冻结共享的发布/可见性/失败清理，以及如何阻止别名修改；
- 共享可变对象是否需要锁、原子操作或不同的所有权模型；
- 普通 `Clone` 的浅层句柄克隆不得被当作跨线程复制。

### 4.4 竞争、错误与取消

- 可静态证明的竞争拒绝规则；只能运行时检测的稳定错误边界；
- 主错误/suppressed/释放顺序在 VM 与 LLVM 的一致验收；
- 取消、超时、线程退出、资源关闭的清理顺序；
- 与 07-B 错误展开、06B 表生命周期、20D 资源句柄的交互。

### 4.5 原子共享句柄的候选形状

只做研究/差分原型，不落地：

1. 原子强/弱计数存储与内存顺序；
2. 弱升级的非零检查并递增竞态；
3. 最后强引用的唯一销毁与对象头回收；
4. 载荷不可变/锁/访问同步；
5. 与字节码、LLVM、错误/清理 ABI 的一致性；
6. 与普通句柄的 ABI 分离点。

### 4.6 标准库与 20 系列边界

- 双向链表、树、观察者、图等结构是否值得官方库，Weak 语义先由内存/并发阶段冻结；
- 图结构不默认 Weak，必须先定义节点存活/边失效/ID 注册表；
- 20D 资源句柄、20L 字典方法等不得被包装层掩盖所有权/竞争规则；
- 不新增用户可见 API，直到模型冻结。

### 4.7 交付物

1. **模型比较记录**（矩阵 + 每个候选的最小差分原型或伪代码 + 成本/风险）；
2. **Send/Sync/任务边界候选定义**（至少两套可选，注明冲突点）；
3. **值传递/冻结/共享可变候选**；
4. **竞争与取消/清理验收方案**；
5. **原子共享句柄 ABI 前置清单**；
6. **对 B0/N0、IR、Runtime ABI、标准库的依赖清单**；
7. **推荐方案 + 仍需星崽裁定的事项**；
8. **新独立阶段的入口条件与阶段编号建议**（只建议，不登记）。

研究记录必须逐条引用 21A §3.1 的六项；不得把候选方案写成已冻结的语言 API。

但 06A/21A 明确在并发表面冻结前没有 AST/IR 生产者；本批没有新增生产者，也没有把代码
检索结果包装成运行通过。未来若有显式 lowering，必须另立测试和运行号。

## 十、模型研究记录

### 10.1 候选模型与成本矩阵

“差分实验”只比较边界和清理记录。伪代码中的 `worker`、`mailbox`、`copy_value` 等是
研究记号，不能直接翻译成 Xiao 源码。

| 候选 | 语义与最小差分实验 | RC/Weak 影响 | 错误、取消、清理与调度 | 实现成本 / ABI、IR 与标准库依赖 | 可测试性与 21A 冲突 |
| --- | --- | --- | --- | --- | --- |
| OS 线程 | `thread := start(worker, value); join(thread)`；实验只传一个标量和一个含句柄的容器 | 普通非原子句柄不能跨线程；需要共享句柄或值集合；Weak 升级必须并发安全 | 线程失败要回收到 join 点；取消依赖停止协议；栈和调度由宿主承担 | 成本高；需要任务边界事实、线程入口 ABI、跨线程值表示和标准库线程封装 | 可用确定性夹具测，但时序探索面大；直接碰撞当前单线程 RC 边界 |
| 单线程任务/协程 | `task := suspendable(worker); run_until_idle(task)`；实验在等待点暂停后恢复同一 Runtime | 同一线程可继续使用普通句柄；挂起/恢复不能自动产生 `CrossThread` | 取消点、等待点和 finally 顺序可确定；需要公平性和阻塞 I/O 规则 | 中等；主要改调度器、栈/帧或状态机 IR，不必立刻改对象头 | 最容易做确定性回归；与 21A 冲突最少，但不能宣称解决跨线程 |
| 任务池 | `pool.submit(worker, value); pool.join()`；实验让两个任务竞争同一只读值并迁移一次 | 任务可能迁移线程；必须先决定 Send-like 边界，普通句柄不能隐式进入池 | 需处理饥饿、阻塞任务、池关闭和未开始任务；取消需要队列状态 | 高；任务描述、工作线程、迁移事实和 ABI 都新增；标准库依赖多 | 可用受控调度器重放，但真实竞争仍有非确定性；不能把任务迁移等同 `CrossThread` |
| Actor/Channel | `actor := start_actor(worker); actor.mailbox.put(message)`；实验消息含嵌套容器 | 默认复制或冻结消息，Actor 内部保留普通句柄；共享可变必须另行设计 | 邮箱背压、关闭、失败回复和取消传播是核心；清理顺序可按邮箱 drain 固定 | 中高；需要消息值编码、邮箱生命周期和错误 ABI；官方库不能掩盖所有权 | 消息日志天然可重放；通道容量和关闭竞态仍需模型检验；符合 21A 的隔离方向 |
| 多 Runtime/堆岛 | `island_a.run(worker); island_b.accept(value_set)`；实验只允许显式边界值 | 每岛保持非原子 RC；跨岛不能携带普通句柄，只能复制/序列化/冻结或新共享句柄 | 岛启动/关闭、边界错误和孤儿资源要有宿主级顺序；取消需跨岛握手 | 很高；Runtime ID、边界传输 ABI、资源归属和标准库启动契约都要冻结 | 岛级日志好隔离；跨岛故障难重放；与 21A 的“显式跨 Runtime”一致但工程量最大 |
| 组合模型 | 推荐研究组合为“单线程任务 + 消息隔离”，将任务池/多 Runtime 作为可选后端 | 任务内使用普通句柄；跨任务默认值传递；共享句柄独立开启 | 先定义任务取消和邮箱清理，再接线程池；后端不得改变错误身份/释放顺序 | 分阶段成本可控，但组合交互最多；IR 必须表达边界而不是靠名称推断 | 可先用单线程调度器做确定性黄金测试；组合项必须逐项禁用隐式升级 |

矩阵结论是成本排序，不是语言选择：单线程任务和消息隔离最适合作为第一组原型；任务池、
OS 线程和多 Runtime 只有在值边界、取消和 ABI 先冻结后才有实施条件。

### 10.2 `Send`/`Sync` 与任务边界的两套候选

以下两套候选都保留 21A 的三层区分：普通句柄、共享句柄、消息值。二者都不把
`CrossThread` 直接当作类型能力，也不把同线程挂起自动当作跨线程。

**候选 A：能力递归推导。**

- “移动到另一个执行单元”是 Send-like 能力；“多个执行单元同时只读”是 Sync-like 能力，
  两者独立推导。
- 标量、不可变文本和递归只读容器可推导；普通 `StrongHandle`/`WeakHandle`、可变表、
  含资源的动态值默认拒绝。
- 数组、集合、字典和动态值必须递归检查元素；无法证明的动态值在边界处拒绝，而不是
  运行时猜测。
- `CrossThread` 由显式任务迁移或消息 lowering 写入 IR；它仍是值级事实。

优点是错误较早、与静态类型系统相容；代价是泛型/动态值规则复杂，未来冻结共享对象还要
增加不可变发布证明。主要冲突是 21A 当前只定义事实，没有定义能力推导，不能直接实现。

**候选 B：边界值优先。**

- 任务和线程入口只接受一个“边界值”集合；集合由深拷贝、序列化或冻结产生，普通值和
  共享句柄都不能隐式穿过入口。
- 第一版不提供 Sync-like 能力；只允许在同一执行单元内使用值。需要共享可变时必须另立
  共享句柄候选，并在对象头/锁/错误契约同时冻结后再开放。
- `CrossThread` 只说明边界值已跨越，Send-like 名称可以留给后续类型层，避免把能力名
  先写进语法和标准库。

优点是 ABI 和错误边界小、容易在 VM/LLVM 做等价验收；代价是复制成本高、无法表达高性能
只读共享，序列化版本也要先固定。主要冲突是它暂时不能满足需要共享只读大对象的场景。

两套候选的共同拒绝规则是：不能以变量名/函数名推断能力；不能用浅层 `Clone` 作为跨边界
复制；不能把 `Weak` 升级成功当作载荷同步；不能让动态值在 VM 与 LLVM 走不同策略。

### 10.3 值传递、冻结与共享可变的差分比较

| 方式 | 边界动作（伪代码） | 可变性与别名 | 失败与清理 | 主要成本/未决点 |
| --- | --- | --- | --- | --- |
| 递归深拷贝 | `message := deep_copy(value)` | 新集合、新句柄和新资源策略；源与目标不共享可变载荷 | 任一子值失败必须释放已复制前缀，并保留主错误 | 复制时间/内存高；资源句柄不能盲拷，需按类型列策略 |
| 序列化 | `bytes := encode(value, version); value2 := decode(bytes, version)` | 彻底断开别名；格式是显式版本数据 | 编码、传输、解码各阶段都可能失败；半成品缓冲需回收 | 稳定格式、版本兼容、错误定位和性能；资源通常只能传 ID/描述 |
| 冻结共享 | `frozen := publish_read_only(value)` | 发布后禁止写入，读取者共享同一载荷；冻结失败不得留下半冻结状态 | 发布前完成可达图检查；取消时撤销未发布句柄，已发布对象按共享计数回收 | 需要不可变类型/运行时保护、可见性顺序和冻结 ABI；当前没有公开操作 |
| 共享可变 | `shared := publish_locked(value); lock(shared)` | 允许别名写入，必须有锁或原子访问协议；普通句柄不能冒充 | 锁等待取消、死锁检测、异常释放和最后引用析构必须定义 | 成本最高；需要对象头、锁、错误/取消与调度整体设计 |

普通 `Clone` 当前只是浅层句柄克隆，不能放入上述“深拷贝”栏。研究原型的共同断言是：
改变发送方集合后，接收方的观察结果必须按候选定义保持独立或明确共享；不能因为 VM 复制了
句柄而误报为消息复制成功。

### 10.4 竞争、错误与取消验收

静态层先拒绝三类可证明错误：同一可变载荷同时被两个执行单元持有且没有共享协议；普通
句柄进入可能迁移的任务边界；消息值含未定义复制策略的资源/动态值。无法静态证明的情况
只能进入一个明确的运行时边界，不能静默继续。具体错误编号留待实现阶段按现有诊断注册规则
登记，本批不预留编号。

VM 与 LLVM 共用同一组黄金场景：

1. 两个只读任务并行观察同一不可变值，结果和释放记录一致；
2. 一个写入任务与一个只读任务竞争同一可变值，静态可拒绝的样例必须在两条路径拒绝；
3. 消息复制中途失败，已分配的前缀按逆序清理，主错误不被清理错误覆盖；
4. 任务取消发生在未开始、执行中、等待中、完成待回收四个位置，所有 finally/drop 都只执行一次；
5. Actor/Channel 关闭时先停止接收新消息，再 drain/关闭邮箱，最后释放载荷；
6. 线程/Runtime 退出时，主错误、suppressed 错误、对象销毁和资源关闭顺序逐项相同。

建议的取消清理序列是“标记取消 → 停止接纳 → 关闭或 drain 边界队列 → 等待已运行任务
到达安全点 → 执行 finally/drop → 释放边界值 → 汇总主错误与 suppressed 错误”。这是验收
顺序候选，不是当前 Runtime 行为或公开 API；实现阶段必须用 06B/07B 的既有释放展开重新确认。

### 10.5 原子共享句柄 ABI 前置清单

实现前必须单独冻结以下项目，且普通句柄与共享句柄使用不同的 ABI 身份：

1. 对象头的原子强计数、弱计数、溢出/下溢处理和目标平台宽度；
2. 增强/释放的内存顺序，弱升级的非零检查与递增竞态；
3. 最后一个强引用的唯一析构、弱引用清零、对象头回收和异常路径；
4. 载荷是不可变、锁保护还是原子字段，容器元素访问如何证明同步；
5. 普通 `StrongHandle`/`WeakHandle` 与共享句柄的 tag、布局、复制/释放入口；
6. 字节码指令、IR 所有权动作、LLVM 声明和 Runtime C ABI 的一一对应；
7. 错误对象、finally/drop、取消和 suppressed 错误在共享句柄释放时的顺序；
8. 版本/目标兼容性、调试观测字段、泄漏/双重析构/弱升级竞态测试；
9. 迁移失败时的回滚和能力检查，确保不会把普通句柄悄悄升级为原子句柄。

本清单不实现原子计数、不修改对象头，也不登记新的 ABI 版本；它是未来阶段的冻结门槛。

### 10.6 B0/N0、IR、Runtime ABI 与标准库依赖

| 依赖面 | 进入实现阶段前必须稳定的内容 | 本批处理 |
| --- | --- | --- |
| B0 字节码 | 运行入口、验证、取消检查点、PC/span 映射和确定性事件 | 只引用现有闭环；不增加并发 opcode |
| N0 LLVM | 动态值 ABI、错误入口、静态库链接和跨平台构建/运行 | 只修标准库同名函数解析；不扩 Runtime ABI |
| IR | 执行单元/边界事实、值传递动作、所有权与释放计划、取消安全点的形状 | 只提出候选字段，未写入生产 IR |
| Runtime ABI | 普通/共享句柄区分、复制/冻结/锁访问、错误与清理入口 | 只列原子句柄前置清单，未添加符号 |
| 标准库 | 消息/任务封装不能隐藏复制、锁和资源归属；Weak/图结构先等内存阶段 | 不新增 `std.concurrent` 或用户可见并发 API |

依赖清单的通过条件是 B0/N0 各有 VM/LLVM 等价黄金测试，IR/ABI 版本与标准库身份先写入
决策基线，再建立新阶段；任何一项未满足都只能继续研究或做隔离原型。

## 十一、推荐方案、未决裁定与未来入口

### 11.1 当前推荐（非冻结）

推荐先采用“单线程任务 + 消息边界值”的组合做下一轮隔离原型：任务挂起/恢复留在同一
Runtime，跨任务默认使用候选 B 的深拷贝或版本化序列化；暂不允许共享可变，也不实现原子
共享句柄。这样可以先验证取消、错误和清理顺序，再用同一套边界黄金测试替换任务后端。

如果后续工作负载证明复制不可接受，再比较候选 A 的递归只读能力与冻结共享；只有在载荷
同步和对象头 ABI 均冻结后，才评估任务池、OS 线程或多 Runtime。此推荐不改变当前语言边界，
也不等于选择了最终执行器。

### 11.2 需要星崽裁定的事项

1. 选择候选 A、候选 B，或允许先做两者的隔离原型；
2. `CrossThread` 是否拆成任务边界与线程边界两个生命周期事实；
3. 动态值和含资源容器的复制/序列化失败策略；
4. 冻结共享是否进入首个实现阶段，共享可变是否暂缓；
5. 取消清理序列中队列关闭、任务等待和 suppressed 错误的精确顺序；
6. 原子共享句柄是否值得承担对象头、锁和跨平台 ABI 成本；
7. 双向链表、树、观察者、图等结构是否在模型冻结后进入官方库。

### 11.3 新独立阶段的入口条件

建立实现阶段前必须同时满足：

- 20L F-1 的三平台维护回归 `39517248193` 已绿；f119ed0 已包含新增夹具和空日志门禁并有运行号，当前 HEAD a53bc97 仍需新的四平台平台复现且 Windows 绿；
- 21A 验收 1–3 的 DAG/菱形、强环拒绝、普通句柄边界有测试证据；`CrossThread` 在没有生产者期间只能保留契约级“无生产者”记录，不能伪造运行事实；
- 星崽在 `00-decisions.md` 裁定模型、值传递、取消和共享可变边界；
- B0/N0 的 VM 与 LLVM 消费方都能执行同一组错误、竞争、取消和释放黄金场景；
- 普通句柄/共享句柄 ABI、IR 事实、诊断字段、标准库依赖和 UseDocs 入口已登记；
- 新阶段自行登记代号、主文档、12 的里程碑、测试族和发布/兼容矩阵。

在这些条件满足前，`07-D` 继续作为研究记录，不登记阶段编号，不预留语法或标准库名称。

当前成本矩阵仍是桌面定性研究和伪代码比较，不是可测量的性能/内存成本报告；若要据此
冻结执行模型、对象头或 ABI，必须先补可执行差分原型、测量方法和结果记录。
