### 2.2 **I1 的修法：按选择计划的冻结语义实现，不许「先返回源值再说」**

VM 侧的选择器语义在 [09R2b](09r2b-selector-execution.md) 已冻结。原生要做的不是发明一套，而是消费同一份语义。

**冻结**：

1. **先写用例、确认会红，再改代码**（I5 的教训）。用例至少覆盖：范围、随机（放回/不放回若语义不同则各一）、全选 `[=]`、
   开区间；每个用例的基线必须声明 VM 侧的具体结果，不能只断言「两边相等」；
2. 结果值本身的**可观察性**：`print` 当前对数组输出的是 `Array(ArrayHandle { length: N })` 这类内部表示（VM 与原生一致）。
   用它只能看出长度。要断言**选中的元素**，用例应把结果喂给一个能暴露元素或错误的下游操作
   （例如继续索引、参与算术），并声明期望的错误码或输出；**不允许**因为「打印不出内容」就把断言停在「长度相同」；
3. 修好后摘掉对应的 `native_gap` 与临时登记，`native_benchmark_probe` 的可构建基线按 §2.5 更新；
4. 若某类选择器一时接不通，就**继续拒绝**（15A §3.2 的口径），**不得**留着返回源值的分支；
5. I6 的释放差异在同一批里处理：先按 09R2C 判定哪一侧正确，再修，判据写进提交说明。

I1 的教训是「没有被测到的路径等于没做」。选择器是 VM 侧语义最复杂的一块，必须有差分覆盖。

**冻结**：

## 九、实施记录（2026-10-07）

提交 `de3d29b` 先加入范围、随机、全选和开区间四个长期差分用例。VM 基线分别为 `2\n`、`3\n`、`4\n`、`1\n`；修复前 Windows 受控原生差分复现范围/随机/开区间错值，原生输出为 `1\n`。提交 `6fda1fa` 让 LLVM 动态降低器消费类型阶段的 `selected_paths`，并新增 Runtime 随机选择 ABI，复用 `SeededRandom::new(0)` 与 `sample_indices`。修复后 Windows `x86_64-pc-windows-msvc` 受控差分通过，四类选择器下游元素值与 VM 一致。

VM 侧 `r2_stack.rs` 的 `nested_finally_return_releases_each_scope_once` 是 I6 判据，因此 VM 的两层作用域各释放一次为正确语义；原生缺一条嵌套 `finally` 释放仍保留 `native_gap`。范围、随机、开区间构造数组的原生释放序列也有额外差异，已登记为对应 `native_gap`；全选释放序列已对齐。

本批没有新增 CI 作业、没有推送、没有触发工作流。I7 动态表方法 ABI 不并入本批。I8 来源补充为“星崽 2026-10-06 会话确认扩大范围”。剩余拒绝面枚举如下：

| 原生拒绝点 | VM 对照 | 结论 |
| --- | --- | --- |
| 动态表方法 | VM 支持，原生缺函数表 ABI | 缺口，单独立项 |
| 表构造参数、字段复合赋值、动态扩展赋值 | VM 有对应约束或路径 | 缺口，后续 ABI/赋值批次 |
| 动态函数调用、动态非表成员访问 | VM 与原生能力边界不同 | 暂登记，后续定范围 |
| 动态错误构造非字符串参数 | 两边均拒绝非文本参数 | 保持一致 |
| 多项/动态字典键选择器 | VM 支持部分语义 | 原生拒绝，后续选择器扩展 |

Linux/macOS 原生运行、CI 原生门控、受控 Java 性能基线和动态表方法 ABI 均未完成；静态 `ir.rs` 的 7 处 `llvm.trap` 继续单独跟踪。
