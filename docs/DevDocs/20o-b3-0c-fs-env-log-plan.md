### 1.1 要做

1. 回答并登记 B3-0C-FS、B3-0C-ENV、B3-0C-LOG 首轮问题；
2. 冻结 `fs`：`stdlib.os`/`stdlib.fs` 归属、路径基准/`..`/绝对路径/符号链接、宿主权限、覆盖、同目录原子替换、失败清理、受限模式、能力、错误和资源/性能；
3. 冻结 `env`：读取/写入/删除范围、快照/实时、名称比较（含 Windows 大小写）、编码/非法 Unicode、子进程继承、并发可见性、能力、错误和限额；
4. 冻结 `log`：级别、时间戳来源/格式/时区、输出目标、并发记录、刷新/写入失败、能力、错误和资源/性能；
5. 冻结三模块的公开路径、签名、所有权、错误码/优先级、取消/超时、资源/性能、平台范围和新增 intrinsic/ABI/生成器候选；
6. 确认 B3-0B 的 ABI 1.20/生成器 23 候选如何与本批合并；未批准不落产品；
7. 产出三份教程草案、固定示例和精确测试入口候选，保持 `planned`；
8. 形成 B3-0C 证据、冻结表和 B3-0D 入口。

### 1.2 明确不做

- 不在 B3-0C 写 `fs`/`env`/`log` 产品代码、测试实现或真实 registry/教程升级；
- 不修改 ABI 1.19、生成器 22、接口 1、intrinsic 1～48/ID 100；新增编号只进入候选表；
- 不启动 B3-0D/B3-1/B4，不跑旧 721，不关闭 22C/22D 或历史债务；
- 不使用隐式全局环境缓存、隐式日志配置或无权限/无上限文件访问；
- 不用 B2-C 同链接补验、`UnverifiedCoffExports` 或导出表抽查替代 B3 Windows 产品级 COFF 验收；
- 不在冻结前写产品再补契约。

## 四、分批执行

### B3-0C0：裁定登记与冻结表骨架

1. 建立 B3-0C 决定台账，逐条记录答复、来源、时点和适用范围；
2. 建立 `fs`/`env`/`log` 冻结表骨架：公开路径/签名/所有权/能力/错误/优先级/取消/资源/性能/平台/教程状态；
3. 固定 B3-0B 已冻结的 `time`/`args`/`cli` 和版本候选 ABI 1.20/生成器 23；
4. 建立 `entry-20261123-b3-0c/` 证据目录和唯一任务根；
5. 未答问题保持“待裁定”，不得标为冻结。

退出：三首轮问题有明确答复或仍为待答；冻结表骨架可复核。

### B3-0C1：`fs` 契约

1. 探测既有 `stdlib.os` 文件/目录句柄、路径解析、权限、覆盖和失败行为；
2. 冻结 `stdlib.os` 与拟议 `stdlib.fs` 的归属，禁止重叠入口；
3. 冻结相对路径基准、`..`、绝对路径、符号链接、目录/文件覆盖、同目录原子替换、失败清理和权限失败；
4. 冻结受限/沙箱模式的裁定结果；不默认扩大宿主能力；
5. 冻结能力、错误码/优先级、取消/超时、资源/性能预算和平台差异；
6. 编写教程草案和固定示例候选，保持 `planned`。

退出：`fs` 契约、能力、错误、资源/性能、平台和教程候选冻结。

### B3-0C2：`env` 契约

1. 探测合成环境名称/值的读取、缺失、空串、删除、大小写和非法 Unicode 行为；
2. 冻结读取/写入/删除范围、快照或实时语义、名称比较（含 Windows 大小写）、编码和值边界；
3. 冻结子进程继承、并发可见性和能力；禁止隐式全局缓存；
4. 冻结错误码/优先级、资源/性能预算和平台差异；
5. 编写教程草案和固定示例候选，保持 `planned`；
6. 任何新增能力位进入决定台账，未批准不落产品。

退出：`env` 契约、能力、错误、资源和教程候选冻结。

### B3-0C3：`log` 契约

1. 探测级别、时间戳/时区、stdout/stderr/独立流、并发记录、刷新和关闭流写入行为；
2. 冻结级别、时间戳来源/格式/时区、输出目标、并发记录边界、刷新/写入失败和返回/错误策略；
3. 冻结能力、资源/性能预算和平台差异；禁止隐式全局配置；
4. 明确时间戳是否复用 `clock` 授权；新增能力单独裁定；
5. 编写教程草案和固定示例候选，保持 `planned`；
6. 教程/registry 不升级。

退出：`log` 契约、能力、错误、资源和教程候选冻结。

### B3-0C4：版本、错误、资源和平台表

1. 汇总三模块签名，合并 B3-0B 的 ABI 1.20/生成器 23 候选；
2. 冻结新增 intrinsic 编号、C 符号、上下文传递、归档/缓存身份和旧产物拒绝；未批准不落产品；
3. 冻结稳定错误码、优先级、span/catch/finally/release、取消和安全点；
4. 冻结输入/输出/条目/字节/时间/内存预算和性能测量协议；
5. 冻结三平台目标、工具链、CI 入口和 Windows 产品级 COFF `Complete` 证据路径；
6. 没有版本增量时明确写“不新增”。

退出：版本/错误/资源/性能/平台冻结表成立，B3-0D 可据此定案。

### B3-0C5：教程草案、固定示例与测试入口

1. 三模块各一份可执行教程草案：导入、quickstart、边界/错误、能力、资源上限和平台差异；
2. 固定示例按 `tests/fixtures/docs/<module>/` 组织，包含源码和独立黄金；
3. 设计 VM 和受控原生 O0/O3 精确入口；产品未实现前只登记候选；
4. 教程/registry 保持 `planned`；

退出：三份教程草案、固定示例和精确测试入口候选冻结；保持 planned。

### B3-0C6：证据、自反例与 B3-0D 入口

1. 生成 B3-0C 证据清单：裁定台账、冻结表、探测日志、教程草案、示例、平台/工具身份；

6. 定稿后单次 docs 门禁；最终 Markdown 由回执覆盖。

退出：B3-0C 证据完整；B3-0D 入口明确；没有产品/registry/教程 verified 变化。
