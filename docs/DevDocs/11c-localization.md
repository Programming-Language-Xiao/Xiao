# 11C. 国际化、系统提示与语言包插件

> 本阶段把 Xiao 工具链、编译器、Runtime、包管理器和交互式解释器中的人类可读系统文案统一到可扩展的本地化层。它只改变文案呈现语言，不改变 Xiao 源码语义、错误控制流、稳定错误码或用户程序输出。

## Agent 交接上下文

### 接手前提

- 先阅读 [07. 错误模型与并发安全边界](07-concurrency-and-errors.md)、[11. CLI、项目配置与平台](11-cli-config-and-platform.md)、[11A. 虚拟环境与包管理](11a-environments-and-packages.md) 和 [11B. 终端交互式解释器](11b-interactive-repl.md)。
- `XiaoError`、结构化诊断事件、源码位置和机器可读错误码已经由前置阶段定义；本阶段不能以翻译文本替代这些稳定接口。
- `config.xiao` 只能使用不可执行的声明式子集。项目级和全局配置都可以提供 `[language]` 表；语言包插件必须经过包管理器的完整性校验。

### 本阶段边界

- 首版内置简体中文和英语两套完整消息目录。首版不翻译 Xiao 关键字、变量名、包名、路径、用户写入的字符串或用户程序的 `print` 输出。
- 本阶段面向 CLI、编译器、Runtime 错误报告、日志/调试窗口、包管理器和 REPL 的系统提示；业务应用如何自行翻译界面属于库或应用层能力。
- 语言包是资源型插件，不得在加载、查找或格式化消息时执行任意插件代码。插件分发、来源和摘要沿用 11A 的包安全边界。

## 一级工程目标：定义有效语言配置

### `[language]` 表与规范值

项目根目录的 `config.xiao` 可以声明：

```xiao
[language]
locale = "zh-CN" # 首版也支持 "en-US"
```

全局 `config.xiao` 可以使用相同的表和字段，为没有项目级设置的 CLI、REPL 和其他工具调用提供默认语言。首版规范字段为 `locale`，值采用大小写规范化的 BCP 47 语言标签；`zh`、`en` 作为 `zh-CN`、`en-US` 的输入别名，内部统一保存规范标签。表名和字段名必须按小写形式识别。

语言设置的作用范围是“系统文案的呈现语言”，不是把 Xiao 变成另一套关键字语法。它不能改变 Token、类型、错误码、退出码、日志事件类型、包名解析或用户程序的标准输出。

### 项目、全局与默认值

语言字段采用以下确定性优先级：

1. 当前项目 `config.xiao` 的 `[language].locale`。
2. Xiao 全局 `config.xiao` 的 `[language].locale`。
3. 内置默认 `zh-CN`。

项目表存在但值非法时必须报告配置错误，不能静默回退到全局值；全局配置损坏时应指出全局文件和键，并使用内置目录呈现该诊断。全局配置文件的跨平台物理位置仍由 CLI 阶段决定，但不影响上述逻辑优先级。

同一进程只解析一次有效语言配置，并把不可变的语言上下文传给 CLI、编译器、Runtime、包管理器、REPL 和诊断窗口。构建期间使用的有效语言应写入产物的运行时默认元数据，使脱离项目目录启动的调试产物仍有确定的初始文案语言；运行时是否允许另一个显式启动配置覆盖该默认值，属于后续 CLI/发布阶段的独立决策。

### 配置诊断

`locale` 只接受首版支持的规范标签或别名。未知标签、非字符串值、重复键和不允许的动态表达式在执行项目代码前报错，并提供稳定错误码、文件/表/键位置以及可用语言列表。配置错误本身也必须经过语言层渲染；如果选定目录不可用，使用完整的内置回退目录，不调用插件。

## 一级工程目标：建立稳定消息目录

### 消息身份与参数

所有由 Xiao 工具链产生的可翻译文案都必须先表示为稳定消息记录，再在展示边界渲染：

| 字段 | 作用 |
| --- | --- |
| `message_id` | 稳定的目录键，例如 `xiao.type.mismatch`；程序和测试依赖它，不依赖译文 |
| `params` | 经过类型约束的插值参数，例如类型名、路径和行号；不得先拼接成不可解析的大字符串 |
| `code` / `kind` | 错误或事件的机器身份，与语言无关 |
| `locale` | 本次渲染实际使用的规范语言标签 |
| `text` | 按目录和参数得到的人类可读文本，可按需生成 |

`XiaoError` 保留 `code`、`kind`、`location`、`cause`、`context` 和 `stack` 等原始结构；`message_id` 与 `params` 用于生成 `message`，不能把译文写回并覆盖错误身份。模块名、函数名、变量名、文件路径和源码片段默认保持用户原文，不进行机器翻译。

### 输出边界

- 人类可读的标准错误流、CLI 帮助/警告、包管理器提示、REPL 状态标签和 `-debug` 窗口标题按有效语言呈现。
- 结构化日志和机器可读错误输出始终包含稳定 `code`/`message_id`/`params`；是否附带本地化 `text` 不得影响机器解析。
- 日志文件可以保存本地化文本，但必须同时保存稳定身份和规范 `locale`，以便跨语言检索和重放。
- 用户程序显式写入的字符串、第三方程序原始输出和包自身未声明目录键的文本保持原样；Runtime 不擅自翻译它们。
- 同一个运行实例的所有组件使用同一有效语言，不能因字节码/LLVM 后端、线程或诊断窗口不同而混用语言。

### 回退与格式化

目录查找采用“精确标签 → 基础语言 → 内置英语参考目录 → 原始 `message_id` 与参数”的顺序。内置 `zh-CN` 和 `en-US` 目录在首版必须覆盖所有核心消息；插件缺少某个条目时只能触发上述回退，不能显示空白或抛出新的格式化异常。插值参数必须经过目录声明的格式检查，格式化失败时保留错误码并使用安全的占位文本。

## 一级工程目标：扩展语言包插件

### 插件契约

语言包插件是可安装、可校验的资源包，至少声明：

- 插件标识、提供的规范语言标签和语言目录版本。
- 覆盖的 `message_id` 命名空间及每个条目的参数签名。
- Xiao/Runtime 兼容范围、包版本、内容长度和 SHA-256 摘要。
- 可选的版权、贡献者和显示名称元数据。

插件目录只能包含声明式清单和消息资源（例如目录文件、复数/格式规则数据）；首个实现不得加载插件代码、执行初始化钩子或访问用户项目。插件安装和更新沿用 11A 的锁文件、源优先级、不可变缓存和来源审计规则。

### 命名空间与冲突

内置目录拥有 `xiao.*`、`runtime.*`、`cli.*`、`repl.*` 和 `package.*` 等核心命名空间。插件可以新增自己的命名空间或完整提供新的语言标签，但不能无提示覆盖内置条目；重复 `message_id`、参数签名不一致或目录版本不兼容时，插件被拒绝并报告来源和摘要。未来若要允许用户明确覆盖文案，必须另行定义信任和优先级，不得依赖安装顺序。

### 版本与缓存

目录版本、Xiao 版本和 Runtime ABI 进入语言资源缓存键。缓存对象按内容摘要保存并设为只读；语言配置变化只切换目录，不修改错误对象或源码。目录加载失败时保留上一次已验证目录供当前进程使用，同时记录诊断；新进程不能继续使用已知摘要不匹配的资源。

## 二级实现任务

### L0：消息模型与内置目录

1. 为编译器、Runtime、CLI、包管理器、REPL 和诊断窗口建立统一 `message_id`、参数签名和目录版本。
2. 将现有错误、日志等级、状态栏和交互标签从硬编码文本改为结构化消息记录。
3. 提供完整的 `zh-CN` 与 `en-US` 内置目录，建立缺失条目、参数类型和格式化失败的测试。

### L1：配置解析与语言上下文

1. 在项目和全局 `config.xiao` 中解析 `[language].locale`，实现别名规范化、项目优先级和 `zh-CN` 默认值。
2. 在 CLI 启动、编译/运行入口、REPL 和 `.xar` 启动入口只创建一个不可变有效语言上下文。
3. 为非法值、全局配置损坏、目录不可用和配置读写中断提供语言无关的稳定错误码及本地化呈现。

### L2：错误、日志与交互接入

1. 让 `XiaoError`、堆栈报告、标准错误流、结构化日志和 `-debug` 窗口使用同一消息渲染器。
2. 保证机器输出的 `code`、`message_id`、参数、位置和退出码跨语言一致，且源码标识符不被翻译。
3. 将 REPL 的版权/帮助、运行确认、保存、命令面板、包安装和同步提示接入有效语言；控制指令如 `!save!`、`!panel!` 保持固定拼写。

### L3：语言包插件与安全

1. 定义资源型语言包清单、命名空间、参数签名、目录版本和摘要校验接口。
2. 通过 11A 的包源、锁文件和不可变缓存安装语言包，不执行插件代码或安装脚本。
3. 实现缺失翻译、重复键、版本不兼容、摘要不匹配和源不可达的确定性回退与诊断。

### L4：跨平台与发布

1. 在 Windows、Linux、macOS 验证 UTF-8 文案、终端宽度、路径/数字插值和诊断窗口显示。
2. 为原生调试产物和 `.xar` 保存构建时有效语言的默认元数据，验证脱离项目目录启动时仍能呈现可读错误。
3. 建立翻译目录的快照、伪本地化、双语差分和机器输出兼容性测试，不把译文快照当作语义测试的唯一依据。

## 验收标准

### 配置与解析验收

- 项目 `[language].locale` 覆盖全局同名设置；没有项目设置时使用全局设置，再没有时使用 `zh-CN`。
- `zh`/`en` 别名规范化为 `zh-CN`/`en-US`；非法值、非字符串和重复键在执行前产生稳定诊断。
- 配置语言只影响系统文案，不改变 Token、源码标识符、错误码、退出码和用户程序输出。

### 消息与错误验收

- 同一错误在中文和英语下拥有相同 `code`、`kind`、位置、原因链、堆栈和退出码，仅人类可读文本改变。
- 编译器、Runtime、CLI、包管理器、REPL 和 `-debug` 窗口不会混用语言；结构化日志始终保留机器字段和实际 `locale`。
- 缺失目录条目按规定回退到基础语言、内置英语或 `message_id`，不会因翻译失败掩盖原始错误。

### 插件验收

- 可安装资源型语言包以摘要和目录版本校验；加载过程中不执行插件代码、安装钩子或用户项目代码。
- 重复核心 `message_id`、参数签名不一致、版本不兼容和摘要错误会拒绝插件，并指出来源与原因。
- 语言配置变化不会污染源码/字节码/依赖缓存；同一目录内容在多项目中可复用且保持只读。

### 跨平台验收

- Windows、Linux、macOS 的 CLI、REPL、错误流、日志和调试窗口均能显示中英双语 UTF-8 文案；终端不支持完整颜色或宽字符时仍可读。
- 调试原生程序和 `.xar` 在没有项目目录或外部语言插件时，仍能使用内置目录输出可读诊断。

## 待定决策

- 构建产物中嵌入的语言默认值能否被启动时项目/全局配置覆盖，覆盖的安全边界和优先级。
- 语言目录的物理序列化格式、复数/性别/文本方向规则和插件发布签名方案。
- 是否允许受信任插件明确覆盖内置文案，以及覆盖后的审计和回滚方式。
