# 06. 内存与运行时语义

> 本阶段落实“绝对不使用追踪式 GC”的要求，并确保解释执行和原生执行拥有相同的释放语义。

当前进度：06-A（静态生命周期闭环）和 06-B/R0-B（Runtime 对象与表生命周期）已完成；
数组、元组、集合、字典和选择器的真实 Runtime 仍未开始。实现与交接细节见
[06A](06a-lifetime-static-closure.md) 和 [06B](06b-runtime-objects-and-tables.md)；本文继续
作为整个 06 阶段的总规格，不得把后置容器执行能力提前写成当前可用功能。

## 一级工程目标：建立确定性生命周期

### 作用域与释放

变量离开缩进作用域时，资源释放计划必须立即生效；表实例的 `def drop(self)` 也属于这条规则。释放不能推迟到某个未知的全堆扫描时刻。

编译器应为每个离开边生成释放计划，包括：正常到达块尾、`return`、`break`、`continue`、错误退出和构造失败。

### 释放顺序

释放顺序必须是可复现的，并在字节码和 LLVM 后端保持一致。已冻结的规则是：所有权边
`A -> B` 表示 A 先于 B 释放；先做强边拓扑排序，同一拓扑层内按声明序号逆序，序号
相同再按稳定值身份逆序。强环在静态阶段拒绝，弱边不参加拓扑。06-A 已输出每个作用域
和八类退出边的独立计划；真实调用 `drop` 留给后续 Runtime。

## 一级工程目标：实现无 GC 的堆管理

### 栈与堆

- 不逃逸且大小可知的值优先放在栈上。
- 被闭包捕获、从函数返回或存入更长生命周期容器的值，经逃逸分析后自动提升到堆。
- 用户不需要写生命周期标注，也不需要手动选择栈或堆。

### 引用计数

逃逸堆对象使用确定性的引用计数。最后一个强引用消失时立即释放对象及其资源；引用计数增减可由编译器插入，动态值路径由运行时处理。

### 弱引用与循环

强引用环不能靠引用计数自行消失，因此标准库提供 `Weak`。形成父子、缓存或图结构环时，必须把至少一条不拥有对象的边声明为弱引用。06-A 已能拒绝静态强环；Weak 只作为不参加强图的静态边模型，真实句柄和 `upgrade` 留给 Runtime。

## 一级工程目标：06-A 静态闭环（已完成）

### 输入与输出

独立 crate `xiao-lifetime` 消费 `SourceFile`、`Program` 和 `TypeCheckResult`，输出
`LifetimeResult`。结果包含作用域/值/基本块身份、强弱所有权边、动态检查、诊断以及
`(ScopeId, ExitKind)` 到 `ReleasePlan` 的映射。它不修改 AST 或类型结果，也不执行用户代码。

### 静态退出模型

当前为每个作用域预建 `Normal`、`Return`、`Break`、`Continue`、`Error`、
`ConstructFailure`、`DynamicCheckFailure` 和 `Fatal` 八种计划。实际 AST 尚未产生
`Error`/`Fatal`/异常语句，但后续阶段可以直接复用这些键。每份计划去除已经转移到
外层或调用方的值，并保证动作值不重复。

### 交接边界

06-A 只负责静态事实和排序；06-B 已实现不透明堆对象、引用计数、Weak 句柄、字符串、
表状态机和释放计划测试驱动器。08 必须保留本阶段的身份、边方向和源码区间，09/10 用
同一释放计划降低到字节码与 LLVM。Runtime 不重新解析 AST 或复制类型/生命周期规则。

## 一级工程目标：统一运行时值

### 静态值

固定宽度整数、浮点、布尔值和小型元组可以直接嵌入栈、寄存器或原生结构体。后端不得因为存在动态能力就把所有静态值装箱。

### 动态值与容器

动态值、异构数组、集合、字典表、字典列和字符串需要带有运行时类型信息及生命周期信息。运行时接口至少提供：

- 类型标签检查。
- 引用计数增减。
- 索引、键查找和边界检查。
- 有序容器的多选、范围、步长及放回/无放回随机选择。
- 集合成员判断、唯一性维护和集合运算。
- 默认填充和容器扩容。
- 资源释放和错误传播。

显式同构集合可以为固定元素类型使用专用存储，不必给每个元素重复附加动态类型标签。默认异构集合需要逐元素记录运行时类型，但这项成本来自异构能力，而不是来自是否提供不可变集合 `frozenset`。

集合元素必须可哈希，因此运行时不追踪数组、字典或其他可变容器的内部变化。静态类型检查器提前拒绝已知不可哈希类型；只有动态值插入时需要一次运行时类型与可哈希能力检查。

### 选择结果的运行时表示

数组、元组、`str` 和字典列共享有序选择运行时接口。接口接收已经由前端规范化的精确路径或高级选择描述，不重新解释源代码标点。

- 单项精确索引返回命中的值。
- 多选、范围和随机选择新建与来源根容器同类型的结果容器；字典列重复条目是否构成例外，等待其键唯一性规则确认。
- 跨嵌套选择为命中路径重建必要的中间容器节点；未命中的兄弟元素不进入结果。
- 随机选择按抽取顺序写入结果；数组、元组和 `str` 的放回抽取必须保留重复抽中的项，字典列的重复结果表示仍待其键唯一性规则确认。
- 字典表只进入精确键查找路径，集合不进入任何索引分派。

重建结果时，每个新容器节点获得独立生命周期；其中引用到的堆值必须执行正确的引用计数增量，重复放回抽取也必须逐项持有并逐项释放。该规则保证选择结果释放时不会提前销毁来源仍在使用的值，也不会因同一值重复出现而漏减引用。

步长和随机数量在动态路径上由运行时验证。步长为 `0`、数量为负数、无放回数量超过候选量，以及空来源上请求正数次抽取，都产生明确错误；不能用截断、取绝对值或静默返回空结果掩盖错误。

## 一级工程目标：定义运行时边界

### 无虚拟机原生程序

原生构建不依赖完整字节码虚拟机，但可以链接按需裁剪的 Xiao Runtime。链接器应移除未使用的动态容器、诊断和并发组件。

### 运行时诊断

原规划中的 `gc_verbose` 不能表示垃圾回收，因为 Xiao 没有追踪式 GC。实现时应改为引用计数、分配或释放日志项，具体名称在配置阶段确定。显式 `-debug` 时，Runtime 还要把分配、释放、引用计数、`drop` 和内存峰值作为结构化诊断事件提供给第 07 阶段的窗口和日志；这些观测不能改变释放顺序或错误语义。

## 验收标准

### 生命周期验收

- 作用域退出、提前返回和错误退出都能确定执行释放。
- 同一程序在字节码和原生模式的 `drop` 次序一致。
- 强引用环不会被错误地宣称“自动回收”；弱引用用例能释放完整环。

### 资源验收

- 没有追踪式 GC 线程、暂停或隐式全堆扫描。
- 动态值和静态值使用的内存策略可从编译产物中解释。
- 多选、范围和随机结果释放后引用计数恢复平衡；跨嵌套结果和放回重复项不会提前释放或泄漏。
- 非法步长或随机数量在构造到一半时失败，也会释放已经建立的结果节点。
