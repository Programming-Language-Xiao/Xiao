## 三、必须先冻结的 6 条

### 3.1 追加式输出的边界（**本批最大的重构**）

现状是**全屏重绘**：每帧 `[H[2J` 清屏后重画。
执行输出可能远超一屏，**全屏重绘会把输出冲掉**。

**冻结为「三段式」**，边界必须精确：

```text
① 编辑段   全屏重绘（维持 I1a/I1c 现状）
              ↓ 用户确认执行
② 输出段   **退出全屏重绘**：清屏一次，画上方分隔线，
           然后像普通程序一样**顺序写 stdout / stderr**（可滚动、可进终端滚动缓冲）
              ↓ 执行结束
③ 收尾段   画下方分隔线 + `time:x.xxxx memory:xxMB`，
           **重新进入编辑段**（回到 ①，重画整个编辑区）
```

**⚠️ 三条必须一并冻结**：

1. **输出段不得清屏**——`[2J` 只能出现在 ① 的开头。输出段里再清屏就等于
   **把用户刚要看的输出擦掉**，这是本批最容易被忽略的翻车点；
2. **输出段的每一行必须以 `\r\n` 结尾**。进入 raw mode 后终端**不再做 `\n` 到 `\r\n` 的转换**，
   只写 `\n` 会让输出呈阶梯状；
3. **输出段结束后必须完整重画编辑区**，不能假设屏幕上还有残留的编辑内容。

### 3.2 执行期间的终端状态

**冻结：执行段临时退出 raw mode，把 stdin 交还给程序。**

理由与代价：

- `11b:243`（R3 第 5 条）要求覆盖**「运行时交互输入」**——程序读 stdin 时必须能读到；
- 退出 raw mode 后，**`Ctrl+C` 恢复产生 SIGINT**，正好用于中断执行（§3.5），
  不需要我们自己在 raw mode 里转发；
- **代价**：输出段的键盘输入不再被我们逐字节接管，**Esc 在输出段没有意义**
  （要取消得等回到编辑段）——**这是可接受的**，因为取消执行的是 `Ctrl+C` 而不是 Esc。

**⚠️ 与 I1a §3.4 的约束一致**：进出必须成对。进入输出段前 `setRawMode(false)`，
回到编辑段前 `setRawMode(true)`，**两者都要在 `finally` 里兜底**。

### 3.3 内存计量：**峰值存活字节**（已定）

`11b:155` 只写了 `memory:xxMB`，没有定义语义。**冻结为**：

- **语义**：本次执行期间**同时存活的运行时对象字节数的最大值**（峰值）。
  它回答「这段代码最多吃了多少内存」；结束时残留量会随释放时机波动，累计分配量会被循环放大到失真；
- **单位**：字节，展示时换算为 MB（`xxMB`，保留两位以内）；
- **⚠️ 统计范围必须包含容器内容**，不能只算对象头——
  否则「装了一百万元素的数组」和「空数组」一样重，这个数字就没有意义。
  容器类型要上报自己的元素字节数；
- **⚠️ 但要给一个明确的边界**：只统计 **Xiao Runtime 管理的对象**，
  **不统计** VM 自身的栈/帧、编译期结构、字符串驻留表等。
  **这条边界要写进协议 UseDoc**，否则读者会把它当成进程 RSS。

**实现位置**（已勘察）：

```text
core/rust/crates/xiao-runtime/src/memory/mod.rs:403   ObjectHeader 的唯一构造点
                                                      ——分配是集中的，加计数器是小改动
core/rust/crates/xiao-runtime/src/memory/mod.rs:281   try_release ——释放点，在这里减
```

用**原子计数器**（当前存活 + 峰值），即使将来 `07-D` 定了语言级并发也不需要重做。

### 3.4 执行后光标：**回到执行前的位置**（已定，清 `00-decisions:670`）

`00-decisions:670` 的完整待定项是「执行完成后**是否保留缓冲区及光标位置**；
保存成功已确定返回多行编辑并保留缓冲区及文件绑定，但**光标回到何处仍待确认**」。

**冻结**：

- **缓冲区保留**（规范已定）；
- **光标回到执行前的位置**——用户接着改刚才那一处，与「运行后回到原处」的直觉一致；
- **同时冻结**：执行**不清除**覆盖模式与编辑器剪贴板（它们是编辑器状态，不是这次运行的状态）。

**⚠️ 要把 `00-decisions:670` 整条删掉**，并把结论写进「终端交互式解释器」已冻结段。
**不要留着待定项又在新段落里写结论**——那正是漂移的开端。

### 3.5 中断与尺寸变化

- **执行中 `Ctrl+C`**：中断执行，**回到编辑段**，缓冲区与光标保持（§3.4）。
  退出码按既有约定（130）；**不得**让会话整体退出；
- **编辑段 `Ctrl+C`**：维持 I1a 的「清空当前输入并回到新提示符」（`00-decisions` 已冻结）；
- **确认态 `Ctrl+C`**：按「取消本次运行」处理，等价于 Esc（§3.6）；
- **⚠️ 尺寸变化（`12-tests:813`）**：编辑段 I1a 已有 `onResize` → 重绘。
  本批要补：**确认态的尺寸变化**（分隔线与标题按新宽度重画）与
  **输出段的尺寸变化**（**不重画历史输出**——已经写出去的行不受影响，
  只保证收尾段用新宽度画分隔线）。**输出段重新布局已输出的内容是做不到的，不要尝试。**

### 3.6 确认态与它的 Esc

**确认态是一个独立状态**，与编辑态、输出段并列：

- **进入**：`Shift+Enter`（Kitty 协议确认后）或 `!outLF!` 独占行（`00-decisions` 已冻结的降级路径）；
- **界面**（`11b:149-153`）：

```text
─ Press Enter to confirm and run ↩︎ ──────────────────────────────────────────
>
──────────────────────────────────────────────────────────────────────────────
```

- **标题嵌在上方分隔线里**，**下一行只有独立的 `>`**（不是 `[X>`、不是行号栏）；
- **分隔线长度随终端宽度**（`terminal.width`），**不能写死示例里的字符数**；
- **`Enter` 确认** → 进入输出段执行**完整缓冲区**（`editorSource(state)`）；
- **`Esc` 取消** → **无损返回编辑态**：不调用执行入口、不改变缓冲区、不改变源码行号映射、不改变文件绑定；
- **⚠️ 编辑态的 Esc 仍是「无操作」**（`00-decisions` 冻结）。
  两个状态下的 Esc 语义不同但**不冲突**——是**按状态分派**，不是改冻结。
  **实现上要在状态机里区分，不要动 `applyKey` 里 `escape` 的既有分支**；
- **⚠️ 确认态不接受源码输入**：`11b:141` 明确「编辑器停止接收源码」。
  在确认态敲字符**不得**修改缓冲区。

## 八、最可能翻车的地方

1. **输出段里又清了一次屏**（§3.1）——用户刚要看的输出被擦掉，且**只在长输出时才发现**。
2. **输出只写 `\n` 不写 `\r\n`**（§3.1）——raw mode 下输出呈阶梯状。
3. **忘了在输出段前退出 raw mode**（§3.2）——程序读不到 stdin，`Ctrl+C` 也传不进去。
4. **内存只算对象头**（§3.3）——数组内容不计，数字完全失真。
5. **把内存说成进程占用**（§3.3）——UseDoc 里含糊其辞，读者当成 RSS。
6. **确认态还能改缓冲区**（§3.6）——`11b:141` 明确禁止，但状态机容易漏。
