# 19. 优化、兼容性与发布验收

> 本阶段是优化和产物链的发布门槛。它把性能收益、可复现性、跨平台兼容、损坏恢复和安全验证纳入同一份验收，不以“文件能运行一次”作为完成标准。

## Agent 交接上下文

### 接手前提

- 先阅读 [13. 优化契约与统一管线](13-optimization-contract.md) 至 [18. 优化与产物 CLI 接入](18-optimization-cli.md)，以及 [12. 测试与开发里程碑](12-tests-and-milestones.md) 的 O0–O6 条目。
- `-O0` 至 `-O3`、单模块 `.xiaoc`、第三方依赖归档、Protobuf 索引、SHA-256 内容寻址和 `xiao -xar` 入口已经是本轮规划输入。
- 本阶段只验收已实现功能，不在发布测试中偷偷补充新的优化级别、归档字段或安全信任规则。

### 本阶段交付与不负责事项

- 交付：性能/体积基线、兼容矩阵、跨平台差分、模糊测试、损坏恢复和发布报告。
- 不负责：改变优化算法或格式；发现缺陷时回到对应的 13–18 阶段修复，并在本阶段保留回归样本。

### 交接检查

最终接手代理必须能从源码、依赖锁、优化指纹和工具链版本重建同一 `.xiaoc`/`.xar`，解释每个字节码对象的 SHA-256 和 Protobuf 索引记录，并在 Windows、Linux、macOS 重复运行差分套件。

## 一级工程目标：建立性能与体积基线

### 基准维度

对每个 `-O0` 至 `-O3` 级别和目标平台记录：源码编译时间、字节码生成时间、`.xiaoc` 大小、`.xar` 大小、启动时间、峰值内存、运行时间和原生二进制大小。基准必须注明硬件、操作系统、工具链、Runtime、输入规模和依赖锁摘要，避免把环境差异误当成优化收益。

### 回归门槛

未优化基线始终保留。性能回归、文件膨胀、编译时间超限或调试信息丢失时，允许暂缓某个 Pass/级别，但不能降低语义测试门槛。随机选择、输入输出、错误和资源释放等不可重排路径应有专门的压力用例。

## 一级工程目标：兼容与安全发布

### 版本矩阵

建立语言版本、IR 版本、字节码格式、虚拟机/Runtime ABI、优化配置、索引 Schema、`.xar` 版本和目标平台的兼容矩阵。旧产物的行为必须明确为直接运行、重新生成、迁移或拒绝；不能因“看起来能解码”而跳过版本检查。

### 完整性与信任

发布测试覆盖 SHA-256 重算、对象/索引不一致、截断、碰撞模拟、路径穿越、恶意压缩比、资源上限和权限错误。若签名尚未实现，文档和 CLI 必须明确 SHA-256 只提供完整性，不等于发布者信任。

## 二级实现任务

### 差分与模糊测试

1. [19.1] 对同一源码执行未优化/优化字节码、`.xar` 和 LLVM 原生结果差分。
2. [19.2] 对 IR、字节码、Protobuf 索引和归档解析器进行结构化模糊测试。
3. [19.3] 注入固定随机源，比较抽取顺序、放回语义和错误边界。
4. [19.4] 对溢出、动态值、容器路径、`drop`、模块初始化和数据竞争诊断建立回归集。

### 跨平台与发布

1. [19.5] 在 Windows、Linux、macOS 验证生成、校验、运行和双击入口。
2. [19.6] 验证不同换行、路径、权限、大小写文件系统和进程信号。
3. [19.7] 测试从旧版本升级、降级、缺少 Runtime、离线缓存和损坏缓存的行为。
4. [19.8] 生成包含优化指纹、依赖摘要、对象哈希和归档成员的发布报告。

### 维护策略

1. [19.9] 定义格式废弃周期、迁移工具和安全修复回溯范围。
2. [19.10] 定义缓存清理、对象保留、索引重建和归档撤销流程。
3. [19.11] 记录已知不支持的目标平台/架构，不让 CLI 默默产生不可运行文件。
4. [19.12] 将性能、体积和安全回归接入持续集成，并保留可复现构建样本。

## 验收标准

- 所有已冻结优化级别在语义、性能、体积和调试基线下有可比较报告。
- `.xiaoc`、索引和 `.xar` 的版本/平台/依赖不兼容都能稳定拒绝或按规则迁移。
- 三平台运行、双击、离线缓存、损坏恢复和安全边界测试通过。
- 发布包可以追溯到源码、依赖锁、优化指纹和内容摘要；任何摘要不一致都不会执行。

## 待定决策

1. 旧格式的拒绝、自动重编译和迁移窗口。
2. 性能回归阈值、基准硬件和 CI 取样规则。
3. 签名/信任、撤销、SBOM 和供应链审计是否属于首版发布门槛。
4. 各平台文件关联和自包含 Runtime 的长期维护策略。
