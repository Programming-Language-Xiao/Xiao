# 17A. 归档格式与编解码

> **17 阶段的第一批**，由 18 个子任务拆成四批中的**格式层**（`17.1`–`17.4`）。
> 后续三批：**17B** 资源与索引接入（`17.5`–`17.8`）、**17C** 入口与运行器（`17.9`–`17.13`）、
> **17D** 平台关联与调试窗口（`17.14`–`17.18`）。
>
> **一句话概括本批**：**把 `.xar` 的物理格式与索引钉死**——容器怎么摆、索引怎么写、
> 什么必须被拒绝。**本批不接运行器**，产出的是一个可验证的归档格式，
> 以及**一批能证明它拒绝了坏输入**的负例测试。

## 二、必须先冻结的 8 条

### 2.1 **ZIP 容器自写，DEFLATE 交给 `flate2`**（已决策）

**已决策**（2026-10-04）：**自己实现 ZIP/ZIP64 容器**（本地文件头、中央目录、
EOCD/ZIP64 EOCD、成员排序、时间戳、extra field），**DEFLATE 压缩与解压交给 `flate2`**。

**冻结**：

- **不得**改用 `zip` crate——容器细节会被它支配，而本阶段的核心验收恰恰是
  **容器的每一个字节都可复现**（时间戳、排序、extra field 都必须在我们的控制下）；
- **不得**自己写 DEFLATE 编码器——可复现性本已是本阶段最难的部分，
  再叠一个自制压缩器会把风险集中到最难验证的地方；
- `flate2` 使用**纯 Rust 后端**（`miniz_oxide`），**不得**启用会走系统 zlib 的特性——
  后者会让不同机器上的产物字节不同，直接破坏本阶段的可复现验收。

### 2.2 **压缩器版本必须进工具链指纹**

规范 `:55` 明写：「**压缩器及版本必须进入工具链指纹**」。

**冻结**：容器版本与 `flate2` 版本一并进入构建指纹。**理由与 15A 的
`b3a1999`（指纹遗漏配置）同源**——该进指纹的没进，缓存就会错误复用。

### 2.3 **扩展 `ArchiveIndex`，不重开它**

16A 已定义 `ArchiveIndex`（`xiao-artifacts/src/lib.rs:1115`）与 `ArchiveEntry`（`:1098`），
且 16A-FIX 已冻结 `validate_archive_index` 的路径。**但 16A 的字段覆盖不全**：
对照规范 `:31` 的要求，**缺五项**——

| 规范要求 | 16A 现状 |
| --- | --- |
| 归档格式 / Schema 版本 | ✓ `schema_major`/`schema_minor` |
| 入口模块与顶层入口 | ✓ `entry` |
| 每个模块/资源/调试对象的逻辑身份与 SHA-256 | ✓ `entries` |
| **依赖锁摘要** | ✗ |
| **最低/最高 Runtime ABI** | ✗ |
| **平台约束** | ✗ |
| **归档是否携带强制调试激活位** | ✗ |
| **构建时有效的系统文案语言默认值** | ✗ |

**冻结**：

- **新增字段，不改已有字段号**（`1`–`6` 保持原义，新字段从 `7` 起）——
  16A 的 `decode` 已实现「未知字段可跳过」，因此新增是**向后兼容**的；
- **不得**改动 `ArchiveEntry` 的既有六个字段的语义与字段号；
- **保持** `.xar` **恰好一个** `META-INF/xiao/index.pb`（规范 `:29`：不并列维护第二份
  manifest 或入口文件）；
- **16A 与 16A-FIX 的既有测试一条都不许改**——它们是「没重开 16A」的守门人。
  若某条必须改，说明改动了既有语义，**停下来说明**。

### 2.4 **可复现的四个固定点**

规范 `:55` 已定，本批**照此实现**：

1. **成员按物理路径的字节序排列**（不是插入序）；
2. **时间戳固定为 ZIP 可表示的纪元 `1980-01-01 00:00:00`**；
3. **归档注释为空**，**权限与额外字段规范化**，除 ZIP64 必需外**不写实现私有 extra field**；
4. 索引 `META-INF/xiao/index.pb` 用 **`STORE`**（不压缩）以便有界读取；
   其余成员**试压缩 `DEFLATE-6`，只在更小时采用，否则 `STORE`**。

### 2.5 **`STORE`/`DEFLATE` 的选择必须确定性**

**冻结**：选择不能依赖「压缩后是否更小」这种**近似判断**的边缘情形而不落定——
对于**压缩结果与原始长度相等**的情况，规则必须**写死**（规范说「只有更小时才用 DEFLATE」，
所以相等时用 `STORE`），且**有测试覆盖这个边界**。

### 2.6 **安全拒绝面是硬验收，不是加分项**

规范 `:59` 列的每一条都要有**负例测试**（`17.4`）：

- 路径穿越、绝对路径、平台相关反斜杠穿越；
- 重复或缺失的 `META-INF/xiao/index.pb`、重复物理成员；
- 越界长度、未知必需版本、**危险压缩比（ZIP bomb）**、加密、多卷、截断；
- 索引内逻辑资源路径的**空段 / `.` / `..` / 绝对路径**。

**冻结**：**读取路径必须先验证再暴露内容**——与 16A 的「先验证再建 VM」同一条判据。
**不得**先解压到临时目录再检查（那正是 ZIP bomb 生效的路径）。

### 2.7 **不接运行器，但格式层要为它留好接口**

**冻结**：本批**不实现** `17.9`–`17.13`（入口解析、执行、错误码、语言上下文）。
但归档模型**必须**能让 17C 直接消费：入口字段、平台约束、Runtime ABI 范围、
调试激活位都要**在索引里可读**，而不是等到 17C 再回头加字段。

### 2.8 **不改 09/14/16 的既有冻结面**

**冻结**：不改 `.xiaoc` 格式（14A）、不改内容寻址命名与分片（16A）、
不改 09 的调用约定与验证器。归档是**外层容器**，不重开里层的格式。

### 2.9 **承接：把 ABI 包装的移除验证提升到运行期可证伪**

**背景**：20AB-FIX 的 §7.2 做了三项移除验证。前两项（契约表项、VM 绑定）的失败证据是
**用例断言失败**，第三项（ABI 包装）是**编译失败**。编译失败**确实**证明了符号被消费——
不删不影响编译、删了就红——但它比运行期断言**弱**：编译失败可能由别的原因引起，
无法区分「移除了这个环节」与「碰巧引入了别的编译错误」。

**冻结**：

- 补一条**运行期可证伪**的验证：**保留符号、破坏行为**——例如让 `xiao_runtime_print_values`
  不再写 stdout 而直接返回成功，断言专门用例**失败**；
- 这**不替代**现有的编译期验证，**两者并存**：编译期证明「符号被引用」，运行期证明「行为被消费」；
- **不改** `xiao_runtime_print_values` 的公开签名与 ABI 语义——验证用**临时改动**做，
  **验证后必须恢复**，并把「改了会红、恢复会绿」的证据记入本批实施记录。

**为什么并入 17A**：它是一次不到十行的验证补强，单独开批的成本高于收益；
而本批本来就要处理「**先验证再暴露**」（§2.6）这一类的可证伪性问题，口径一致。

```text
core/rust/crates/xiao-xar/          从空壳落地
  容器层                            本地文件头 / 中央目录 / EOCD / ZIP64 EOCD
  成员布局                          物理路径字节序、固定时间戳、规范化 extra field

工具链指纹                            容器版本 + flate2 版本进入（§2.2）
```

## 五、硬约束

1. **`flate2` 只用纯 Rust 后端**（§2.1）——不得走系统 zlib；
2. **索引字段号 `1`–`6` 不得改**（§2.3）；
3. **先验证再暴露**（§2.6）——不得先解压到临时目录再检查；
4. **所有长度字段必须 `checked_add`** 并设上界，防整数溢出与越界（16A 的 `ProtoReader` 是同款做法）；
5. **危险压缩比要有明确阈值**，且阈值是**具名常量**而非散落的字面量；
6. **不写实现私有 extra field**（除 ZIP64 必需）；
7. **`.xar` 恰好一个索引**——缺失与重复都拒绝。

3. **读取路径**：列目录、有界读取索引、验证、提取、读取流（`17.2` 后半）；

5. **负例测试**：按 §2.6 逐条覆盖（`17.4`）——**这是本批的验收主体**；
6. **可复现验证**：同一输入两次打包逐字节相同；**并验证压缩器版本变更会改变指纹**；

   证据记入实施记录；
8. **文档与登记**：crate README、主表、UseDocs（若本批有用户可见面）。

## 七、最可能翻车的地方

1. **图省事改用 `zip` crate**（§2.1）——容器细节失控，可复现验收直接崩。
2. **`flate2` 走了系统 zlib**（§2.1）——不同机器产物不同，且**本机测试发现不了**，只在 CI 暴露。
3. **压缩器版本没进指纹**（§2.2）——15A 的 `b3a1999` 刚栽过同款。
4. **改动了索引既有字段号**（§2.3）——破坏 16A 的既有测试与产物兼容。
5. **先解压再检查**（§2.6）——ZIP bomb 正是打这个顺序。
6. **`STORE`/`DEFLATE` 的相等边界没定**（§2.5）——两平台可能给出不同选择。
7. **成员排序用了插入序或 `HashMap` 迭代序**——可复现立即失效。
8. **时间戳没固定**——最容易被忽略的一处，产物每次不同。
9. **长度字段没设上界**——越界与整数溢出。
10. **把 17C 的入口解析提前做了**（§2.7）——批次边界模糊，且本批没有运行器可验。
11. **忘了 `Cargo.lock` 同步**——`check:lock` 会红（16A 栽过一次）。

## 八、验收

1. **标准工具可读**：产物能被通用 ZIP 工具列出与解压（规范 `:27` 的自解释边界）；
2. **恰好一个索引**：`META-INF/xiao/index.pb` 唯一，缺失或重复均被拒绝；
3. **可复现**：同一输入两次打包**逐字节相同**；成员按字节序、时间戳固定 `1980-01-01`；
4. **指纹敏感**：压缩器版本变化会改变工具链指纹（§2.2）；
5. **压缩选择确定**：索引恒 `STORE`；其余按「更小才用」且**相等边界有测试**；
6. **负例全覆盖**（§2.6 逐条）：路径穿越、绝对路径、反斜杠穿越、重复/缺失索引、
   重复成员、越界长度、未知必需版本、ZIP bomb、加密、多卷、截断；
7. **先验证再暴露**：损坏或不规范的归档**不产出任何可用于执行的内容**；
8. **不重开 16A**：16A/16A-FIX 的既有测试**一条未改**且全绿；
9. **载荷校验**：归档内 `.xiaoc` 经 `validate_xiaoc` 校验，与 14A 一致；
10. **不回归**：`cargo test --workspace` 全绿、`cargo clippy --workspace --all-targets -- -D warnings` 绿；
11. **门禁全绿**：`bun run check` 退出码 0（含 `check:lock`，两个 lock 文件都已提交）；
12. **承接项可证伪**（§2.9）：`xiao_runtime_print_values` **保留符号、破坏行为**后专门用例**失败**，
    恢复后通过——证据记入实施记录。这是 20AB-FIX §7.3 的遗留补强，**不替代**其编译期验证。

## 九、不负责与不要重复做的事

- **不做**资源收集与诊断对象（`17.5`–`17.8`，归 17B）；
- **不做**入口解析、执行、错误码与语言上下文（`17.9`–`17.13`，归 17C）；
- **不做**平台文件关联、双击与调试窗口（`17.14`–`17.18`，归 17D）；
- **不做**数字签名/信任链（规范 `:61` 明写属待定安全决策）；
- **不重开** `.xiaoc` 格式（14A）、内容寻址（16A/16A-FIX）、09 的调用约定；
- **不实现** CLI 的 `-xar` 入口——那归 17C/18；
- **不擅自冻结** 17C/17D 才需要的决策（入口解析细节、文件关联的安装方式）。
