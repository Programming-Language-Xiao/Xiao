### 1.1 要做

1. 建立威胁模型和信任边界；探测成熟hash/HMAC/CSPRNG/AEAD/TLS候选实现、版本/特性/许可证/维护/漏洞/审计状态；
2. 冻结hash算法集合、输出编码/长度、流式/整块边界、错误；
3. 冻结HMAC算法/密钥/输出/比较方式、常量时间要求；
4. 冻结CSPRNG系统熵源/失败行为/字节长度上限/并发/能力；区分它与B5确定性PRNG，不公开用户种子或可预测回退；
5. 冻结AEAD算法/Nonce所有权与生成方式/每密钥使用上限/AD/密钥/标签/失败关闭；明确内部生成与调用方提供两类API各自的防复用保证，不能笼统承诺“自动防复用”；
6. 冻结TLS基础的信任根/证书链/主机名与SNI校验、协议版本/密码套件策略、客户端证书和服务端范围、超时/限额/取消、错误；明确B7是否只提供TLS引擎/策略接口，实际socket与HTTP仍归B8；
7. 实现五模块、教程/示例/错误/资源/测试向量；
8. 接通类型/IR/TAC/VM/LLVM/归档、std/stdlib双路径、能力/隔离；
9. 独立安全审阅、三平台/CI；registry只在全部必测和审阅通过范围升级。

### 1.2 明确不做

- 不自研密码算法/协议/随机数生成器；
- 不实现HTTP/数据库/应用协议（B8/B9）；
- 不提供“跳过证书校验”“弱随机回退”“静默降级”开关；
- 不改变B2-B6数值/值模型/工具语义；
- 不临时或未冻结地新增能力位/错误码/intrinsic/ABI；B7所需增量必须先经B7-0冻结及所需上游契约修订；
- 不提前升级registry/教程，不跑旧721；
- 不把功能测试通过写成安全审阅通过。

## 三、分批执行

### B7-0：探测、冻结与安全审阅计划

1. 冻结威胁模型：远端主动攻击者、恶意/超大输入、本地非特权观察者、进程内普通调用方各自的保护目标；说明不覆盖的物理/微架构攻击、宿主已失陷和调用方主动泄密风险；
2. 探测hash/HMAC/CSPRNG/AEAD/TLS候选实现、版本/特性/许可证原文/维护/安全公告/审计范围/三平台；绑定来源提交与摘要，记录未审计代码和残余风险；
3. 冻结hash算法白名单（明确是否排除MD5/SHA-1及非密码学hash）、摘要原始字节/文本编码、二进制输入表示/长度/整块或流式和错误身份；教程不得把裸hash描述成口令存储方案，也不宣称未经认证的FIPS合规；
4. 冻结HMAC与hash的算法映射、密钥/摘要长度、截断规则和输入表示；比较先验证双方为预期固定长度，再用经审阅的常量时间原语逐字节比较；不得使用普通相等操作替代，时序探针不能单独证明常量时间；
5. 冻结CSPRNG系统熵源与目标支持表、读取接口/最大长度、并发、能力和熵源失败错误；生产API不得接受用户seed、导出内部状态或回退到B5确定性PRNG/时钟/进程ID；可注入确定性源仅限不可发布的测试构建；
6. 冻结AEAD算法/nonce与tag长度/AD/密钥表示/密文布局及每密钥调用和数据上限；决定nonce由库安全生成还是调用者提供，并据此写清可达的防复用保证、失败回滚、进程重启/复制状态/VM克隆语义；禁止含糊承诺库自动保证唯一；认证失败统一失败关闭、不暴露或返回部分明文；
7. 冻结秘密生命周期：是否采用不透明Secret/Key句柄或其他明确表示；秘密禁止进入`str`格式化、普通日志、错误参数、`Debug`、常量/归档/集合/字典键和跨线程传输，除非逐项冻结并安全审阅；限制克隆/导出，记录清理保证及其平台/优化器限制，不宣称无法证明的全副本清零；
8. 冻结TLS基础的角色和层次：B7是否只提供TLS策略/引擎及抽象传输接口；B7不得自行打开socket或实现HTTP，B8负责网络连接与network能力接线；确定服务端/客户端、TLS 1.2/1.3支持、密码套件白名单、信任根来源及更新、证书链/主机名/IDNA/SNI、ALPN、客户端证书、撤销检查和超时取消行为；禁止任何验证绕过和不安全降级开关；
9. 复核现有20D能力契约：位0–6已固定、未知位必须拒绝，当前没有`crypto`位；逐项确定外部熵源、TLS传输及其他宿主调用所需能力。只有既有能力语义完全吻合时才可复用；若需新增`crypto`等能力，必须先修订20D契约/掩码验证/序列化与兼容矩阵并冻结ABI增量，不得占用未知位或借用`network`/`native_extension`的名称掩盖；
10. 冻结全部函数签名/参数/返回/效果/所有权/能力/稳定错误码和优先级/资源与性能预算；错误及诊断不得包含密钥、nonce、明文、随机输出、私钥或可直接重放的握手材料；TLS/协议错误应保留内部原因但对公开文本脱敏；
11. 按20P D-15静态内置依赖，固定直接/传递版本、特性、锁、许可证原文、审计来源和`--locked`三平台构建；禁止运行时任意动态加载，不自研算法；任何新增intrinsic/值类型须同步ABI/生成器/`.xiaoc`/`.xar`指纹，保留既有编号及ID 100墓碑；不得声称未经独立认证的FIPS或其他合规身份；
12. 规定测试向量来源/版本/摘要（NIST/RFC/公开互操作向量）、畸形/失败注入/并发/资源/模糊测试矩阵；安全审阅需绑定精确源码、依赖锁和候选产物身份；
13. 安全审阅由实现者以外、具备相关密码工程能力的审阅者执行；B7-0先冻结风险分级和接受权限；报告记录范围、源码/依赖/平台身份、方法、发现严重度、未修复项和签收；严重/高危未关闭或审阅后源码/依赖改变时不得发布或转verified，修复后须按差异复审；中低风险须有明确责任人及书面接受，不能由实现者自行关闭；测试绿不等于审阅签字；
14. 五份完整教程草案/固定示例/registry候选（planned），明确安全使用限制；教程不能展示真实密钥或弱化默认；
15. 记录延期能力（HTTP、服务端/客户端TLS未选部分、证书固定、密钥导入/导出、协议扩展等）。

退出：威胁模型、五模块算法/API/错误/能力/资源、秘密生命周期、依赖/兼容身份、向量/安全测试和独立审阅流程均已冻结；未写产品，也不由B7-0本身授权产品并行实施。

### B7-3：CSPRNG

1. 只用冻结并审阅的操作系统熵源；失败立即报稳定错误，不回退到其他源；
2. 执行能力位检查、长度上限和并发请求边界；不提供生产seed/状态导入或导出；
3. 单测通过仅证明接口与失败路径，不宣称统计测试能证明密码学安全；
4. 用仅测试构建可注入的故障源验证短读/失败/分配失败，确认不返回部分随机数据；
5. 教程说明该API适用范围，不与B5可复现PRNG混用。

退出：CSPRNG内部可用；熵源和能力失败关闭、无可预测回退。

### B7-4：AEAD

1. 仅使用冻结白名单算法，核对nonce/AD/密钥/tag和密文布局；
2. 按冻结API验证nonce来源、每密钥调用/字节上限及调用方责任；覆盖重启/复制执行状态的边界，不声称能检测跨进程的外部nonce重复；
3. 认证失败统一失败关闭，不回传/打印部分明文，错误不泄漏可用于区分tag/密文的细节；
4. RFC/NIST向量、nonce边界/长度负例、篡改/重放场景、密钥清理与资源错误；
5. 教程使用测试密钥并说明nonce规则和数据上限。

退出：AEAD内部可用；认证失败不泄明文，nonce保证准确符合冻结契约。

### B7-5：TLS基础

1. 只实现B7-0冻结的TLS引擎/策略/传输边界，不接入HTTP或自行打开网络连接；
2. 用失败证书、错误主机名、过期/不受信任证书验证默认拒绝，核对信任根来源/SNI/协议与套件；

4. 所有公开/测试/构建路径均无跳过校验或降级开关；
5. 三平台互操作、失败/资源测试与教程。

退出：TLS基础内部可用；验证/协商默认安全，无跳过校验或静默降级。
