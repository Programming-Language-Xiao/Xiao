# 11B. 终端交互式解释器

> 本阶段实现 Xiao 的终端交互式解释器与多行编辑器。它依赖第 09 阶段已经可用的字节码执行闭环和第 11 阶段的 TypeScript CLI；环境包接入必须等第 11A 阶段提供稳定的包视图后再完成，不能进入 Token 解析或最小 AST 里程碑。

## 一级工程目标：冻结入口与执行边界

### 命令入口

交互式解释器具有三个已经冻结的入口：

```text
xiao
xiao --inLF
xiao --inLF "<file.xiao>"
```

- 无参数 `xiao` 以默认单行模式启动交互式解释器。
- `xiao --inLF` 直接以多行模式启动空白编辑缓冲区。
- `xiao --inLF "<file.xiao>"` 在多行模式中打开指定 `.xiao` 文件，用于继续编辑和运行。

`xiao <file.xiao>` 仍是 `xiao run <file.xiao>` 的脚本运行快捷方式，不进入多行编辑器。文件路径含空格时由调用者按当前 Shell 规则加引号，CLI 收到路径后统一交给跨平台路径层处理。

### 执行路径

REPL 是第 09 阶段字节码运行模式的交互前端，不拥有第二套语言解释器。每次确认执行的源码都必须经过与 `xiao run` 相同的词法、语法、类型和生命周期检查，再交给字节码虚拟机；TypeScript 前端只负责终端输入、缓冲区、命令状态和显示。

第 09 阶段字节码闭环与第 11 阶段 CLI 调用接口没有达到验收标准前，本阶段只能制作无语言执行能力的终端输入原型，不能用临时求值器固化错误语义。

## 一级工程目标：定义提示符与环境信息

### 基本提示符

交互式解释器启动时先显示版权和当前 CLI 版本。版本号随实际发布版本变化，格式固定为大写 `V` 加语义化版本号：

```text
Xiao (c) XiaoCZX
V0.1.0
```

激活虚拟环境后的提示符形态为：

```text
# Windows
$venv$ D:\Project\xiao [X>

# Linux
$venv$ /home/project/xiao [X>
```

环境段 `$<虚拟环境名>$` 连同前后两个 `$` 使用 `#87E68C`；输入标记 `[X>` 使用 `#F6E2B7`。环境段与工作目录之间保留一个空格。没有激活虚拟环境时不显示环境段，工作目录和 `[X>` 仍正常显示。

交互式解释器的包视图在启动时按环境状态选定：

- 已激活虚拟环境时，该环境中的所有包命名空间均可引用。
- 未激活虚拟环境时，全局环境中的所有包命名空间均可引用。

启动过程只把可解析的包根名称预注册为延迟命名空间，不执行包代码，也不把注册过程输出到界面。用户可以在交互会话中直接通过包名引用内容，无需先逐个书写 `import`；只有源码首次真正引用包中内容时，运行时才加载所需模块。名称解析和类型检查可以读取无副作用的接口元数据，但这不等同于加载并初始化模块代码；同一具体模块在一个 REPL 运行实例中至多初始化一次。该能力依赖第 11A 阶段的环境包视图，不阻塞无第三方包的 REPL 核心闭环。

### Git 摘要

当前目录是 Git 仓库且摘要配置已启用时，提示符在工作目录之后、`[X>` 之前显示分支与领先/落后计数：

```text
$venv$ D:\Project\xiao main-0↑-0↓ [X>
```

项目级配置命令为：

```text
xiao config CLI.git.summary true
```

该命令把设置写入当前项目的 `config.xiao`。全局配置命令为：

```text
xiao config --global CLI.git.summary true
```

分支和计数使用以下颜色：

| 内容 | 颜色 |
| :--- | :--- |
| `main` | `#D0AAFC` |
| `master` | `#FBA77A` |
| `dev` | `#FA7D74` |
| 其他分支名 | `#7EC0FC` |
| 领先/落后计数 | `#B7CDAA` |

未启用配置或当前目录不是 Git 仓库时不显示 Git 摘要，基本提示符仍必须可用。

## 一级工程目标：实现单行与多行输入

### 默认单行模式

默认模式中，用户每次按 Enter 都立即提交当前输入并运行。REPL 内输入独占一行的 `!inLF!` 可以切换到多行模式；从命令行直接进入多行模式则使用 `xiao --inLF`，不把带 `!` 的内部指令暴露给 Shell 解析。

### 多行缓冲区

多行模式把 Enter 解释为新建逻辑行，不立即运行。每个逻辑行显示为“五字符宽、右对齐的十进制行号 + `|`”，因此第一行形如：

```text
    1|
```

行号上限为 `99999`。这一数值是界面协议的理论上限，实际可编辑规模还受终端绘制缓存和可用内存约束。

终端宽度不足引发的软换行不产生新的逻辑行号。续行使用五个空格加 `|`，原逻辑行的内容关系保持不变：

```text
    1|abcdefghijklmn
     |opqrstuvwxyz
    2|1234567890
```

粘贴大段源码时，编辑器必须保留输入中的真实换行和缩进，并按真实换行依次分配逻辑行号。终端软换行不能被写回为源码换行，也不能改变错误位置。

### 执行准备与确认

多行模式提供两种进入执行准备阶段的方式：

1. 按 Shift+Enter。
2. 在新起的逻辑行中独占输入 `!outLF!` 并按 Enter。

`!outLF!` 是 REPL 控制指令，即使它按示例显示在带行号的编辑区中，也不得作为 Xiao 源码送入词法器或运行时。它是否继续保留在可编辑缓冲区或保存文件中，仍需另行确认。

进入准备阶段后，编辑器停止接收源码，把确认提示嵌入上方分隔线，并在下一行显示独立输入提示符：

```text
─ Press Enter to confirm and run ↩︎ ──────────────────────────────────────────
>
──────────────────────────────────────────────────────────────────────────────
```

分隔线长度必须随当前终端宽度调整，不能依赖示例中的固定字符数。用户看到提示后按 Enter 才确认运行。执行输出与编辑区由分隔线隔开；输出结束后再次显示分隔线和耗时、内存摘要：

```text
──────────────────────────────────────────────────────────────────────────────
time:x.xxxx memory:xxMB
```

运行错误也必须结束本次输出区并回到可继续交互的状态，不能破坏尚需保留的编辑内容。

## 一级工程目标：提供源码保存与重新打开

### 保存入口

多行模式提供两种进入保存模式的方式：

1. 在逻辑行中独占输入 `!save!` 并按 Enter。
2. 按 Ctrl+Shift+S。

`!save!` 同样是 REPL 控制指令，不得作为 Xiao 源码送入词法器或运行时；它是否继续保留在可编辑缓冲区或保存文件中，仍需另行确认。

保存模式必须把保存路径提示嵌入上方分隔线，而不是显示执行确认提示：

```text
─ Enter the save location ────────────────────────────────────────────────────
> |
──────────────────────────────────────────────────────────────────────────────
```

其中 `|` 仅表示光标位置，不是实际输入字符。用户输入包含文件名和扩展名的目标路径并按 Enter 后，编辑器保存当前源码；用户只输入 `q` 并按 Enter 时，退出保存模式并返回编辑。保存失败必须报告目标路径和可操作的原因，不能静默丢弃缓冲区。

保存界面与执行界面属于不同状态。视觉示例只用于说明布局，不能把保存操作解释成 `Press Enter to confirm and run`。

### 打开现有文件

`xiao --inLF "<file.xiao>"` 把现有 `.xiao` 文件载入多行缓冲区，按真实换行编号，随后允许编辑、保存和运行。打开文件不能绕过正常源码编码、路径和读取错误诊断。

## 二级实现任务

### R0：依赖门槛与终端骨架

1. 等待第 09 阶段提供可复用的字节码执行入口及源码诊断接口。
2. 在第 11 阶段的 TypeScript CLI 中实现无参数、`--inLF` 和 `--inLF <file>` 的互斥路由。
3. 建立终端宽度、颜色、光标、组合键和软换行所需的跨平台抽象。
4. 让打包后的独立 CLI 可执行程序在未安装 Node.js 的 Windows、Linux 和 macOS 环境中启动终端骨架。
5. 检测终端是否能够区分 Shift+Enter 或 Ctrl+Shift+S；无法上报组合键时保留 `!outLF!` 和 `!save!` 作为完整功能入口，不能把普通 Enter 错认成组合键。

### R1：单行执行闭环

1. 渲染工作目录、可选环境段和 `[X>` 输入标记。
2. 实现 Enter 提交，并把源码交给第 09 阶段的统一前端和字节码虚拟机。
3. 接回标准输出、标准错误、诊断、耗时和内存统计。
4. 实现 REPL 内部 `!inLF!` 状态切换。
5. 通过第 11 阶段的配置接口读取生效的 `CLI.git.summary` 布尔值，默认关闭摘要。
6. 配置启用时探测当前仓库、分支和上游领先/落后数量，并按已定颜色插入提示符；仓库状态在每次绘制新提示符前刷新。
7. Git 不可用、当前目录不是仓库或状态读取失败时保持基本提示符可用；无上游和分离头指针的具体显示要等下方待定规则冻结后实现。

### R2：多行编辑核心

1. 建立逻辑行缓冲区、五字符行号栏和 `99999` 行边界诊断。
2. 区分真实换行与终端软换行，验证终端缩放不会修改源码缓冲区。
3. 实现保留换行与缩进的多行粘贴。
4. 实现 Shift+Enter 和 `!outLF!` 到执行准备状态的转换，并保证控制指令不会进入交给 Xiao 前端的可执行源码视图。

### R3：确认、运行与结果区

1. 实现执行确认状态、嵌入上方分隔线的提示文字及自适应宽度分隔线。
2. 确认后按已经冻结的控制指令规则生成可执行源码视图，再送入统一字节码执行路径。
3. 隔离编辑区与输出区，并在成功或失败后显示耗时、内存摘要。
4. 覆盖窄终端、窗口缩放、长输出和运行时交互输入等场景。

### R4：保存与文件编辑

1. 实现 `!save!`、Ctrl+Shift+S、嵌入上方分隔线的保存标题和独立的保存路径输入状态。
2. 实现目标路径保存、`q` 返回和写入失败诊断。
3. 实现 `xiao --inLF <file.xiao>` 的文件读取、逻辑行映射和错误报告。
4. 在完成下方相关待定决策后，补齐覆盖、取消和内部指令写回测试。

### R5：环境包延迟加载

3. 在首次真正引用包内容时调用独立的运行时加载接口。
4. 验证启动、命名空间注册和接口查询都不会执行包初始化代码，虚拟环境与全局环境不会交叉泄漏。
5. 复用第 05 阶段的模块状态，保证同一具体模块在一个 REPL 运行实例中至多初始化一次；首次加载失败后的重试行为等待待定规则冻结。

### R6：后置交互增强

## 验收标准

### 入口与发布验收

- `xiao`、`xiao --inLF`、`xiao --inLF <file.xiao>` 分别进入约定模式，`xiao <file.xiao>` 仍直接运行脚本。
- TypeScript CLI 打包为各平台独立可执行程序，未安装 Node.js 时交互式解释器仍可启动。
- REPL 执行使用第 09 阶段的统一检查和字节码虚拟机，不存在只在交互模式生效的临时语言语义。

### 输入与显示验收

- 单行模式按 Enter 立即运行，多行模式按 Enter 只新增逻辑行。
- 行号栏、粘贴缩进和真实换行准确；终端软换行始终显示空白行号栏，且不改变源码位置。
- Shift+Enter 与 `!outLF!` 都进入执行确认；界面显示分隔线内的 `Press Enter to confirm and run ↩︎` 及下一行独立的 `>`，只有确认后才运行，`!outLF!` 本身绝不作为 Xiao 源码执行。
- 提示符颜色、可选 Git 摘要、自适应分隔线和末尾耗时/内存摘要符合本规范。
- 保存模式在上方分隔线显示 `Enter the save location`，能按完整地址保存，并能通过 `q` 返回编辑。

### 环境与延迟加载验收

- 激活环境时只能看到该环境包视图，未激活时只能看到全局包视图。
- 仅启动 REPL、注册包命名空间、查询接口元数据或进入多行模式不会运行任何依赖包代码。
- 首次引用包内容才触发加载，加载错误指向实际包和引用位置。
- 重复引用已经成功加载的具体模块不会再次执行其初始化代码。

## 待定决策：实现前必须冻结

> 下列行为尚未得到确认。实现不得自行选择默认值，测试也不能把某个临时行为写成规范。

1. 保存目标已存在时，是否必须进行二次覆盖确认。
2. 作为编辑器内部指令的 `!save!` 和 `!outLF!` 是否从可编辑缓冲区及最终保存内容中排除；二者不进入待执行 Xiao 源码这一点已经确定。
3. 执行确认状态中是否允许输入 `q` 取消并返回编辑。
4. `xiao --inLF <file.xiao>` 指向不存在的文件时，是创建同路径的新缓冲区还是直接报错。
5. 自动登记的多个包具有相同根名称时如何消歧，以及是否要求用户显式导入冲突包。
6. 当前分支没有跟踪上游时，Git 摘要中的领先/落后区域是省略、显示占位值还是报告提示。
7. 保存目标是否必须使用 `.xiao` 扩展名，还是只要求具有任意扩展名。
8. 执行完成与保存完成后是否保留缓冲区、是否继续处于多行模式、保存路径是否绑定为当前文件，以及光标回到哪个位置。

10. 分离头指针状态时摘要如何表示；Git 命令不可用或仓库读取失败时必须降级为基本提示符，但是否额外显示一次诊断仍待确认。
