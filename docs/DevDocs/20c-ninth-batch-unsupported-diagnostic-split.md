# 20C-第九批. `unsupported` 的两分：已知未实现 vs 降低器缺陷

> **背景**：[20C-第八批](20c-eighth-batch-conversion-and-dynamic-boundaries.md) §4.2 把
> **进程内验证失败**从 `fatal.corrupt_artifact` 改报 `fatal.internal`——
> 但它**没碰另一条也会报 `fatal.internal` 的路径**：09B0 的 `unsupported` 守卫
> （`X09-BYTECODE-001`）。
>
> **第八批的审核探出**：`lint` 取负 → `X09-BYTECODE-001` → `fatal.internal`，
> 而那是一个**普通源码就能写出来的、已知未实现的操作**（§三，实测）。
>
> **一句话概括**：`unsupported` 这个桶里装着**两类完全不同的东西**——
> 「我们还没做」与「我们自家的降低器不一致」——**现在共用一个身份**。

状态：**规划中（2026-10-16）**，两道裁定待下（§四）。**未改任何代码。**

## 一、为什么是这一批

1. **第八批刚把「验证失败」的身份修对，同一批就暴露了另一半**：
   两条路径都通向 `fatal.internal`，但只有一条被处理过；
2. **它是用户可见的**：普通源码（`lint` 取负）触发，报出来的是「**编译器内部故障**」——
   那是在说编译器坏了，而实际是**功能没做**。这与第八批刚立的原则（「不能把用户的东西说成坏了」）
   是同一条原则的**镜像**；
3. **它需要一份实测清单**：`unsupported` 的写入点有 **14 处**（§三 已列），
   要判定每一处属于哪一类，**不能靠读代码归类**；
4. **顺带把 `lint`/`lfloat` 算术债写实**：现在的登记只有一句「算术仍是债项」，
   而实际是「哪些操作、各自当前报什么」——那正是本批补探的产物。

## 二、并入的返工项（**先做**）

### 2.1 H-4（中）：`lint` 一元取负不可用——**既有算术债的更精确表述**

**实测（审核侧临时探针，用完即删）**：

| 形态 | 结果 |
| --- | --- |
| `lint -42` | **成功**，`-42`（小负字面量被**常量折叠**，绕过了 `Neg`） |
| `lint b = -9223372036854775808` | 失败，`X09-BYTECODE-001` |
| **`lint a = 42` → `lint b = -a`**（变量取负） | 失败，`X09-BYTECODE-001` |
| `int -42`（标量对照） | **成功** |

**根因已钉死**（两处，缺一不可）：

1. `xiao-bytecode/src/lower/expr.rs:363-375`：一元负号是「`0 - x`」，
   **零常量必须与操作数同宽**，而那个 `match scalar` 只认 `Sint`/`Int`/`Sfloat`/`Float`，
   `Lint`/`Lfloat` 落进 `_ => lower_unsupported(lowerer, "unary minus", ...)`；
2. **即便补上零常量也不行**：`0 - x` 还要 Runtime 的 `lint` 减法，
   而 `NumericPair::new` 不处理 `Lint`/`Lfloat`——**那是登记在案的算术债**。

⇒ **它不是「新缺陷」，是既有算术债的一个具体面**；本批把它**写实**（哪些操作、报什么），
**不实现算术**（见 §4.2）。

### 2.2 H-5（低）：`lower_literal` 的静默兜底还在

第八批 H-1 的根因正是 `text.parse().unwrap_or_default()`；
`lower_literal` 里 `Sint` 与 `Int` 两臂**仍然是这个写法**。
当前**不可达**（前端范围检查挡着：`sint 2147483648` 与 `int 9223372036854775808`
实测都报 `X02-TYPE-007`），所以**不是活缺陷**——但它只靠前端检查挡着。
**先登记，处置见 §4.2**。

## 三、实测：`unsupported` 里装着两类东西

### 3.1 全部写入点（14 处，`core/rust/crates/xiao-bytecode/src/lower/`）

| 位置 | 文案 | **读法上的**归类 |
| --- | --- | --- |
| `expr.rs:47` | 表方法值的动态调用 | 已知未实现 |
| `expr.rs:139`、`:159` | container | 已知未实现 |
| `expr.rs:175`、`:178`、`:183`、`:186`、`:212` | selector plan / selector path / random selector plan | 已知未实现 |
| `expr.rs:367`、`:374` | **unary minus** | **已知未实现**（本批的引子） |
| `expr.rs:781` | 未知 intrinsic ID | **内部不一致** |
| `expr.rs:858`（`lower_unsupported` 本身） | `{what} 尚未降低` | 由调用方决定 |
| `mod.rs:335` | 运行时检查未消费 | **内部不一致** |
| `mod.rs:477` | 模块导出未能降低为顶层值 | 待判 |
| `mod.rs:872` | 运行时检查尚未降低 | **内部不一致** |
| `stmt.rs:369`、`:648` | 绑定/循环绑定缺少生命周期条目 | **内部不一致** |
| `stmt.rs:449` | 选择器广播缺少类型计划 | **内部不一致** |
| `stmt.rs:464` | 复合赋值的左值形态尚未降低 | 已知未实现 |
| `stmt.rs:707` | 循环跳转没有活动循环 | **内部不一致** |
| `tables.rs:36`、`:133`、`:188` | 表缺前端签名 / new 目标缺静态表身份 / 表方法展开实参尚未降低 | 待判（前两者偏内部不一致） |

**这张表的「归类」一栏是读代码得出的，不是实测**——它只用来**提出候选**，
**不许**直接当成结论。§五 要逐一实测。

### 3.2 两类的区别是**实质的**

- **已知未实现**：用户能写出合法源码，编译器**有意**没做。报出来应当是
  「**这个能力还没实现**」——一条**编译期**限制。
- **内部不一致**：不该发生；一旦发生说明**降低器与前端/生命周期阶段的契约被破坏**。
  这才是真正的「编译器故障」。

**现在两者共用一个出口**（`X09-BYTECODE-001`，消息 `fatal.internal`）——
第八批刚把诊断身份的原则立起来（「不能把用户的东西说成坏了」），
这一条是它的**镜像**：**不能把没做的功能说成编译器坏了**。

## 四、两道待定裁决

### 4.1 裁决一：分档的形式

| | 做法 | 代价 |
| --- | --- | --- |
| **甲** | **给「已知未实现」自己的档位**，`X09-BYTECODE-001` 只留给意外缺口 | 新增一个稳定码；要动 `verify.rs` 与既有测试的期望 |
| **乙** | **不新增码**，只把 `unsupported` 的**消息**按两类分别措辞（仍是 `fatal.internal`） | 便宜；但档位仍是一个，靠消息区分——**按本仓库的判据，消息不是身份** |
| **丙** | 把「已知未实现」**挪出 Fatal**：它是**编译期**限制，报成编译错误（与 `X02-*` 同族）而不是 Fatal | 最名实相符；但改动面最大，且要处理「降低发生在检查之后」的时序 |

**要一并摆上的**：`unsupported` 是**降低器**发现的，而降低发生在类型检查**之后**——
丙 要求把它接回编译期诊断通道，不是换个码那么简单。

### 4.2 裁决二：`lint`/`lfloat` 算术债的范围

| | 做法 |
| --- | --- |
| **甲** | **只登记与写实**：本批出「哪些算术操作、各自当前报什么」的清单，**不实现** |
| **乙** | **顺带做一元取负所需的最小算术**（`Lint`/`Lfloat` 的 `0 - x`） |

**审核倾向：甲。** 理由：一元取负要的是「大整数减法」，
而算术是**成组**的能力（加、减、乘、除、比较）——只做减法是**半截形状**，
与本仓库反复吃的「半截」是同一类。
**且「为 `lint`/`lfloat` 选统一的高精度表示」在 02 里是一条独立设计任务，本批不顺手定。**

## 七、执行顺序（**顺序本身是约束**）

1. **§五 补探**，成表，**结论先汇报**——**在裁定 4.1 之前**，因为「能不能机械分开」
   是 4.1 的前提；
2. **两道裁决**落定后动代码；
3. 实现 + `02-type-system.md` 同笔；
4. **推一次**取证。

**冻结**：

1. **不许**跳过补探直接按 §3.1 的表改档位——那张表是**读出来的**，不是测出来的；
2. **不许**把「已知未实现」那一类**顺手删掉**（例如让 `lint` 取负干脆前端报错）——
   那会把「登记在案的债」变成「没有登记的限制」；
3. **不许**在本批实现 `lint`/`lfloat` 算术（§4.2 若取甲）。
