## 二、本批的特殊之处：**机制第一次被真正使用**

13A（边界）与 13B（套件）都是在**没有 Pass** 的情况下建起来的，
当时它们的行为都**平凡通过**——13B 的实施记录里也这么写了
（「当前"仍不可避免的目标差异"清单为空」）。

**本批是那两批的第一次实战**：

| 13A/13B 建的 | 本批第一次怎么用 |
| --- | --- |
| Pass 接口的**效果/所有权/控制流假设**（13A `§3.3`） | 每个新 Pass 必须**声明**自己的假设 |
| **快照回滚**（13A `§3.5`） | 每个 Pass **前后快照**（`14.6` 明确要求） |
| **验证阻断**（13A `§3.5`） | Pass 改变 IR 后**必须重新验证**（`14.7`） |
| **边界输入套件**（13B） | 三方差分的**输入来源**（`14.10`） |
| **`SkipReason`**（13A） | 收益不足/证明失败时的跳过路径（`14.8`） |

**⚠️ 因此本批的验收不只是"Pass 做对了吗"，还包括"机制真的能报警吗"**——
若某个 Pass 破坏了语义而套件**静默通过**，那是 13B 的缺陷（§八 第 6 条）。

## 三、必须先冻结的 8 条

### 3.1 **不得删除可观察操作**（规范「安全变换范围」）

规范原文点名不得删除：

> 随机、输入输出、模块加载、**引用计数**、**`drop`**、**错误构造**或**数据竞争检查**等可观察操作

**冻结**：

- 这七类**逐类都要有用例**——不是"看起来没删"；
- **⚠️ 最容易被顺手删掉的是"看起来没用"的 `drop` 和引用计数**：
  某个值"没人再读了"**不等于**可以省掉它的释放——`06` 阶段冻结的是**确定性释放顺序**，
  优化器**没有权力**改变它；
- **错误构造**同理：异常路径**没有被走到**不等于可以删掉它。

### 3.2 **优化后必须重新验证**（`14.7`）

规范：`14.7` 要求优化后重新验证**栈高度、跳转、释放计划、源码映射和错误路径**。

**冻结**：

- **五项逐项都要验**，不是"IR 验证器过了就行"——
  **释放计划与源码映射是字节码特有的**，13A 的 IR 验证器**不一定覆盖它们**；
- **验证失败必须阻断**（13A `§3.5` 已冻结）——**不能提交未验证的优化结果**；
- **与 14A 的闸门衔接**：14A 让 VM"检查全通过前不建立 VM"；
  本批要保证**优化后的 `.xiaoc` 同样过得了那道闸门**。

### 3.3 **每个 Pass 前后快照**（`14.6`，13B 报告中提出）

规范 `14.6` 原文：「逐个实现窥孔、跳转、常量池和槽布局 Pass，
并**为每个 Pass 建立前后快照**」。

**冻结**：

- **每个 Pass 都要有**——13B 当时因为"Pass 全是占位"而**沿用 13A 的覆盖**，
  **那个复用到本批失效**：现在每个 Pass 都是真的，
  **每个都需要自己的前后快照用例**；
- **快照要能证明回滚**：失败时保留的是**哪一份**快照，用例断言到**具体那一个**；
- **跳过的 Pass 也要有快照**（13A 的 `bf4e446` 修过这条，**别回退**）。

### 3.4 **失败保留未优化参考结果**（`14.8`）

规范 `14.8`：「对优化失败保留未优化参考结果，具体回退/报错策略按已冻结 CLI 契约执行」。

**冻结**：

- **失败时保留未优化参考**是明确的；
- **但"回退还是报错"仍属待定决策 4**（13A `§3.6` 与 14 规范都没冻结）——
  **本批不做那个决定**，夹具要能**观察两种行为**（断言"保留了未优化参考"这件事本身，
  而不是断言选了哪条路）。

### 3.5 **quickening/JIT 不得写回不可变 `.xiaoc`**（`14.12`）

规范：

> 不得把运行时自适应 quickening 直接写回不可变 `.xiaoc`。
> 若未来加入 JIT，JIT 产物必须使用另一个**可丢弃的运行缓存命名空间**。

**冻结**：

- **本批不做 JIT**（属待定决策 2 的 LTO/PGO 那一类）；
- **`14.12` 要的是"分离"这个事实**——即**确认没有路径**把运行时自适应结果写回 `.xiaoc`；
- **与 14A 的"不压缩"是同一类纪律**：公开产物是**不可变**的，可变的东西进独立缓存。

### 3.6 **三方差分，不是两方**（`14.10`）

规范 `14.10`：「验证**源码、未优化字节码和优化字节码**的输出、错误、
**随机序列**和 `drop` 记录一致」。

**冻结**：

- **三个观察对象**：源码直跑 / 未优化字节码 / 优化字节码——**缺一不可**；
- **四样对照**：输出、错误、**随机序列**、`drop` 记录——
  **注意这里是"随机序列"而不是 10G 的"退出码"**：本阶段明确要验**随机抽取的序列一致**，
  这正是 13B 建固定随机源输入的用途；
- **沿用 13B 的输入**：四类边界夹具（溢出上下界、固定随机源、动态检查失败、容器顺序）
  **就是本批三方差分的输入来源**，**不另建一套**。

### 3.7 **接入 13 的配置与效果摘要，不新造**（`14.5`）

规范 `14.5`：「接入第 13 阶段的**共享优化配置和效果摘要**」。

**冻结**：

- **配置与指纹用 13A 的**；
- **Pass 假设用 13A 的 `PassAssumptions`**（效果/控制流/所有权/源码映射）——
  **不许为字节码 Pass 另立一套假设体系**；
- **跳过原因用 13A 的 `SkipReason`**（含 `InsufficientBenefit`、`TargetIncapable` 等）。

### 3.8 **仍不擅自冻结 4 条待定决策**

14 规范的 4 条**继续有效**。特别提醒两条与本批相邻的：

- **待定决策 2**（分区编号、指令编码、版本初始值、迁移周期）——
  **本批会新增指令编码相关实现**（如"指令编码压缩"），
  **但要改的是编码器行为，不是格式契约**；改动必须落在 14A 已冻结的目录/分区框架内；
- **待定决策 4**（REPL 会话缓存回收时机与失配诊断）——**本批不碰 REPL**。

## 八、最可能翻车的地方

1. **删掉"看起来没用"的 `drop` / 引用计数**（§3.1）——某个值"没人再读了"
   **不等于**可以省掉它的释放。本批头号陷阱。
2. **删掉错误构造**（§3.1）——异常路径"没被走到"不等于可以删。
3. **优化后没重新验证**（§3.2）——尤其**释放计划与源码映射**：
   IR 验证器可能过，但字节码特有的这两项没验。
4. **沿用 13B 的"逐 Pass 快照已由 13A 覆盖"**（§3.3）——**那个复用本批失效**：
   当时 Pass 全是占位，现在每个都是真的。
5. **三方差分只跑两方**（§3.6）——少了"源码直跑"这一方，就丢了基准。
6. **⚠️ 套件静默通过**（§二）——若某个 Pass 破坏了语义而**13B 的套件没报警**，
   问题在套件不在 Pass。**这需要单独判断，不能当成"Pass 正确"的证据。**
7. **把 quickening 写回 `.xiaoc`**（§3.5）——公开产物不可变。
8. **顺手冻结待定决策**（§3.8）——尤其"Pass 失败后回退还是报错"。
9. **为了通过差分而改夹具**（§3.6）——夹具是**上一批为这一刻建的**，
   它报警时**先怀疑 Pass**，而不是先怀疑夹具。
10. **忘了两个 lock 文件**（§六 第 9 条）。

9. **未安装 LLVM 仍可用**：`.xiaoc` 的生成与运行**不依赖 LLVM**（验收）；

## 本批实现记录

当前实现落在 `core/rust/crates/xiao-bytecode/src/optimize.rs` 和
`core/rust/crates/xiao-optimizer/src/differential.rs`。字节码管线复用 13A 的
`OptimizationConfig`、`PassAssumptions`、`SkipReason`、`PassReport` 和验证状态，
不新增第二套配置或 Pass 假设体系。

已实现的保守 Pass 为：

- `bytecode.constant-pool`：按位比较浮点常量，规范化重复常量索引；
- `bytecode.redundant-move`：删除目标寄存器等于源寄存器的无副作用自移动；
- `bytecode.jump-simplify`：把两个目标相同的条件分支改成无条件跳转；
- `bytecode.unreachable-block` 与 `bytecode.slot-layout`：当前证明条件不足，明确报告
  `proof-unavailable` 并保留前后相同快照，不伪装成完成优化。

每个 Pass 都记录 `before:*`/`after:*` 快照；候选 TAC 会重新编码、解码并比较规范字节序列，
`run_checked` 还会调用 09 验证器对账 IR 的释放计划和错误路径。验证或 Pass 失败时错误对象
保留未优化参考程序和最后有效快照，未冻结“回退还是报错”的待定决策。

`xiao-optimizer` 新增三方差分模型，分别执行源码、未优化字节码和优化字节码，比较输出、
错误、固定随机序列和 `drop` 顺序；当前报告显式携带优化级别。运行时仍没有任何 quickening
写回 `.xiaoc` 的入口，公开产物保持不可变。
