## 三、已确认规则

### F-6a：旧 `.xiaoc`/`.xar`/原生元数据

F-6a已确认：

1. B1 原始 1.18 `.xiaoc`/`.xar` 在 B2-B 1.19/21 下执行前拒绝，不改写原件；
2. B2 新 1.19 原件在旧 1.18 Runtime 下执行前拒绝，不依赖“执行到未知原语”才失败；
3. 原始 1.18 原生元数据在 B2-B 验证器前拒绝；新 1.19 元数据在旧验证器前拒绝；
4. 不通过手改旧头、放宽 max 版本或忽略指令流版本宣称兼容；
5. 不改变现有容器格式/索引 schema 版本。

原迁移工具与范围兼容备选未采用；不改写旧原件或放宽精确边界。

### F-6b：B2-A 中间快照

F-6b已确认：

- A 保持 1.18/20，仅内部验证；不发布、不承诺旧 Runtime 具备新的高精度语义；
- A 的版本号不变不等于可以混用旧 Runtime；内部取证仍绑定源码、Runtime 内容和输出路径；
- A 产物不进入 B2 最终兼容矩阵。

### F-6c：B2-B 最终产物与 C 符号

F-6c已确认：

- B2-B 集中升 ABI 1.19、生成器 21；标准库接口版本保持 1；
- 保留既有1.18 C符号、布局与调用约定；新增C符号按加法扩展。数值行为按已确认F-A升级，包括lfloat身份与float **内核；不承诺所有旧数值行为不变；
- `.xiaoc`/`.xar`/原生元数据/缓存按 §二 的精确矩阵执行；
- B1 源码在 1.19/21 重新生成后，重跑 B1 20 入口和完整 721 条 F10；旧成绩只作历史；
- 不修改现有容器格式/索引 schema 版本。
