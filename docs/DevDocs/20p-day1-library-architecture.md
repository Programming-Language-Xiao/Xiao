## 一、Day-1 库的判定标准

“Day-1 库”不是“函数数量足够多”，而是新用户第一次使用时不需要读源码或猜边界。一个库
只有同时满足以下条件才算 Day-1：

1. **一次导入可用**：不装包、不写构建脚本、不依赖隐藏的环境变量；
2. **五分钟能跑通**：教程里有可直接运行的 quickstart，而不是只有签名列表；
3. **所有权和生命周期可预测**：谁消费句柄、何时关闭、失败后资源怎么回收写清楚；
4. **错误可机读**：稳定 `code`/类别/因果链，不匹配本地化文本，不 panic；
5. **资源有上限**：输入大小、结果行数、连接/超时、解压/解析深度都有明确上限；
6. **跨平台一致**：Windows/Linux/macOS 的语义相同；平台差异显式报“不支持”；
7. **兼容边界清楚**：接口版本、标准库身份、产物要求、废弃策略都登记；
8. **示例被测试**：教程里的代码由 CI 实际运行，不是只贴文本；
9. **性能不令人意外**：没有隐藏的 O(n²)、全量复制或无界缓冲；
10. **安全默认值**：TLS 校验、凭据遮蔽、参数绑定、拒绝任意注入是默认行为。

## 二、模块与 API 架构

### 2.1 命名空间

- 稳定公开路径统一为 `std.<domain>`；`std` 是面向用户的别名，内部固定身份仍为
  `stdlib.<domain>`；
- 单个库内部用自由函数，和现有 `text`/`path`/`set`/`dict` 保持同一风格；不引入方法值、
  动态接收者或第二套调用约定；
- 子模块只在“同一领域有多个实现”时使用，例如数据库驱动；
- 不把实现细节（native 库名、Rust 类型、FFI 句柄）暴露进公开路径。

### 2.2 子模块与驱动命名（D-13）

数据库命名方向已由星崽确认（D-13，2026-11-01）：

```text
std.db            公共概念与共同约定（不提供数据库连接本身）
std.db.sqlite     嵌入式 SQLite 驱动
std.db.postgres   PostgreSQL 驱动
std.db.redis      Redis 驱动
std.db.mysql      MySQL 驱动（后置）
```

公共 `std.db` 只放**共享的标量/结果/错误/参数类型约定**，不尝试在没有 trait/接口的
语言里造通用多态驱动。每个驱动暴露自己的连接/语句/事务类型，API 形状保持一致。

### 2.3 API 形状

- 连接、事务、语句、结果集是显式句柄；创建和关闭成对出现，关闭幂等；
- 消费型操作（提交事务、执行一次性命令）明确“消费调用方这一份”；
- 不提供隐式全局连接、隐式重试、隐式字符串插值或隐式网络回退；
- 查询参数必须走参数绑定；字符串拼接 SQL 不是公开示例；
- 结果集默认有行数/字节上限；流式迭代是显式能力，不是默认隐式行为；
- 错误返回使用统一结构化错误，不把驱动原始错误文本当稳定身份。

### 2.4 错误模型（D-14）

- 每个库有稳定的错误码族；错误对象保留类别、cause、suppressed、源码位置；
- 库不得 panic；内部断言只能变成 Fatal 级结构化错误；
- 原始驱动错误作为 cause/诊断字段保留，但不参与用户 `catch` 的稳定匹配；
- 凭据、连接串中的密码、查询参数中的敏感值不得进入错误文本、日志或 `Debug`；
- 连接失败、认证失败、超时、取消、协议错误、资源上限分别有不同身份。

B1-FIX-A 已确认全局 error_code(Error value, /) -> str、intrinsic 32 与独立 ABI 1.18 读取前置，
不开放错误成员访问。精确借用后复制、C 失败状态和源级错误表见
[B1 §二](20o-b1-freeze-draft.md#二error_code-的名称位置与签名)。真实入口已由独立 FIX-B 实现，
当前 ABI 为 1.18；三平台验收见 [FIX-B 收口](20o-b1-fix-b-closeout.md)，七库产品按
[B1-IMP](20o-b1-imp-seven-libraries.md) 逐模块实施，尚未完整交付。

### 2.5 生命周期与并发

- 普通连接/语句/结果集是单线程句柄；跨线程使用必须走显式共享或每线程一份连接；
- 阻塞 API 必须带超时；取消语义与 22 的取消令牌/安全点一致；
- 不引入 async/await、第二套调度器或隐藏后台线程；
- 连接池是显式资源，有上限、获取超时、关闭 drain；不默认无限池；
- 事务必须绑定到创建它的连接，提交/回滚/关闭顺序在文档中固定。

### 2.6 能力与安全

- 文件/网络能力沿用 20D 的 `filesystem`/`network` 位；D-16 已确认独立数据库能力位，
  并与实际所需的 `filesystem`/`network`/`native_extension` 等能力叠加检查；编号/ABI
  留 B9 冻结，B0 不分配；不能用“能打开 socket”隐式等价为“可以访问任意数据库”；
- TLS 默认校验证书和主机名；关闭校验必须是显式、危险的选项，并在文档和诊断中提示；
- 连接串、密码、token、查询参数默认脱敏；
- 所有网络/文件操作必须有超时和失败关闭；
- 不提供 shell 调用、动态 SQL 拼接或未验证的扩展加载作为默认路径。

### 2.7 版本、发布与产物

- 新接口默认是标准库接口版本 1 的兼容扩展；删除/改签名/改错误身份才提升版本；
- 新 intrinsic 或值类型必须升级 Runtime ABI 次版本并更新 `.xiaoc`/`.xar` 指纹；
- 官方库仍不作为普通包进入依赖求解；`.xar` 记录实际所需的 `stdlib.*` 模块；
- 可选驱动/原生库必须显式出现在构建、启动和归档要求中；缺失时 fail-closed；
- D-15 已确认首版静态内置、显式功能开关、锁定依赖与摘要；动态插件契约另立。

## 三、教程与文档架构

### 3.1 每个库必须有教程

每个 `std.<domain>` 模块至少有一页 UseDocs，且包含：

1. 适用范围、状态、版本、ABI、标准库接口版本；
2. 安装/导入方式（官方库无需安装，示例必须真实可运行）；
3. 五分钟 quickstart；
4. 核心概念与所有权/生命周期；
5. 每个公开 API 的签名、参数、返回值、消费关系、错误和上限；
6. 错误表（稳定 code、何时出现、如何恢复）；
7. 资源/性能上限与安全默认值；
8. 至少一个完整可运行示例，且由 CI 执行；
9. 兼容性和废弃策略；
10. 相关故障排查和下一篇文章链接。

### 3.2 示例即测试（D-20；状态门槛为 D-21）

- D-20 已确认：教程中的完整示例放到固定目录 `tests/fixtures/docs/<module>/`，由专门测试
  在 VM 和受控原生上逐字比对 stdout/退出码；
- 片段示例可以不全部执行，但完整示例必须执行；文档标注哪些是完整示例；
- 示例不能依赖本机私有路径或未声明的服务；数据库示例优先用临时 SQLite 文件；
  PostgreSQL/Redis 示例使用 CI 服务并在文档注明；
- 示例输出变化必须同步更新黄金值；不能用“文本包含”代替逐字比较；
- D-21 已确认：只有代码、测试、完整示例执行证据和链接全部通过，UseDocs 才能从
  `planned` 改为 `verified`；B0 的探测通过后仍为 planned。

D-26 已将 B1 默认/原生探测要求收紧为独立 `--exact`、恰好 `1 passed`；维护回归已接入
两个逻辑执行点，并监视教程目录变动。缺少对应提交的三平台证据时继续 planned，
接线和验证层次见 [B1 §八](20o-b1-freeze-draft.md#八本轮-ci-接线与验证)。

### 3.3 文档状态与登记

- 模块、UseDocs、DevDocs、registry、兼容身份五处同步；
- 未交付的库只能有 `planned` 页，不能先写“已验证”；
- 教程和 API 参考引用同一错误表，避免两套口径；
- 教程必须面向学习者，不是把 Rust 文档翻译成英文式列表。

## 四、数据库驱动架构

### 4.1 Day-1 驱动范围与顺序

D-19 已确认上线顺序：**SQLite → PostgreSQL → Redis → MySQL**。

- **SQLite**：嵌入式、无网络/TLS，最容易做到跨平台和可复现，作为驱动架构的样板；
- **PostgreSQL**：SQL、参数绑定、事务、TLS/SCRAM，验证网络能力与安全边界；
- **Redis**：RESP 协议、键值命令、TLS，验证非 SQL 驱动的共同约定；
- **MySQL**：复用 PostgreSQL 的 SQL/网络骨架，后置。

### 4.2 公共概念（不造 ORM）

`std.db` 只冻结以下共同约定，不冻结一个万能驱动接口：

- 连接配置（地址、库名、用户、超时、TLS 开关）；
- 参数绑定值的边界类型；
- 结果行/列的访问方式和上限；
- 事务的开始/提交/回滚顺序；
- 连接/语句/事务句柄的消费和关闭规则；
- 错误分类（连接、认证、超时、取消、协议、约束、资源上限）；
- 凭据脱敏和日志规则。

SQL 与 Redis 命令文本保持驱动自有；不做跨驱动 SQL 方言抽象、查询构建器或 ORM。

### 4.3 SQLite 驱动

- 打开临时文件或显式路径；内存数据库作为测试选项；
- `execute`/`query`/参数绑定/事务/预编译语句；
- 文件能力、路径策略与 20N-H 的 filesystem 冻结一致；
- 不依赖网络/TLS/crypto；
- 作为教程和 Day-1 示例的首选数据库。

### 4.4 PostgreSQL 驱动

- 连接参数：host/port/database/user/password/TLS 选项；
- TCP + TLS（依赖 20N-L 的加密/TLS 基础）；认证失败、证书失败、超时分别有身份；
- 参数绑定、预编译语句、事务、行/字节上限；
- D-18 已确认**首批内置有界连接池**，池为显式资源；容量、获取超时、关闭 drain、
  事务与连接绑定及池内并发所有权在 B9 冻结，不放宽普通连接句柄的单线程边界；
- 取消：客户端超时/关闭连接优先；服务端取消需要单独冻结；
- 不在日志/错误中输出密码或完整连接串。

### 4.5 Redis 驱动

- RESP 协议、连接、命令、简单响应类型（字符串/整数/数组/空）；
- 键值命令先覆盖常用命令，不做 Cluster/Sentinel/PubSub/事务脚本的首版承诺；
- TLS 与网络能力同 PostgreSQL；
- 错误分类：连接、认证、协议、超时、取消、服务端错误；
- 命令参数必须是结构化值，不把用户输入拼成命令字符串。

### 4.6 原生扩展与交付（D-15）

D-15 已确认首版**静态内置**经审计的 Rust 驱动库，按目标平台编译进 Runtime/官方库构建：

- 依赖版本和摘要锁定；构建可复现；
- 驱动可选时通过显式 feature/module 列表控制，产物记录实际所需模块；
- 不默认动态加载任意 `.so`/`.dll`；动态插件契约另立；
- 驱动 ABI 不暴露 Rust 结构布局，仍走稳定 C ABI/不透明句柄；
- 平台不支持时必须报稳定“不支持”，不能静默退化。

### 4.7 测试与服务

- SQLite：本地临时库，VM/native 双路径，三平台；
- PostgreSQL/Redis：CI 在 Linux 起服务容器；Windows/macOS 先做协议/单元/连接失败测试，
  真实服务证据按平台登记“不可验证”或补托管服务；
- 覆盖：连接失败、认证失败、TLS 失败、超时、取消、事务回滚、参数绑定、行数上限、
  关闭幂等、凭据脱敏；
- 示例使用固定 schema/键空间，不依赖共享外部数据库。

## 五、数值与数据模型架构（与 20O 对齐）

- `lint`/`lfloat` 的任意精度底层已确认使用成熟 Rust 数值库（20O D-1）；必须先冻结
  值表示、转换、舍入、错误和 ABI，再写 decimal/fractions；
- `cmath` 的浮点原语是宿主 intrinsic；D-4 已确认首批包含超越函数，具体集合、NaN/Inf/
  域错误/舍入策略必须先冻结；
- JSON/TOML 已确认专用 `json_value` 类型（20O D-7），不公开 `dynamic`；
- 数据类型的构造/访问/序列化/生命周期和两个后端表示必须同批评审；
- 教程中的数字示例要覆盖精度、舍入和错误，不只展示成功路径。

## 六、架构决策

来源：星崽在 B0 会话中逐条直接裁定（2026-11-01）。方向确认不等于接口、能力编号或 ABI
已冻结；本轮仍只做 B0，精确契约在对应批次再次提交。

| 决策 | 已确认方向 | 后续冻结或验收 |
| --- | --- | --- |
| D-13 驱动命名 | std.db.<driver>，共同约定位于 std.db | B9 的实际模块与归档身份 |
| D-14 公共约定 | 统一配置/参数/结果/事务/结构化错误与脱敏，各驱动保留句柄和协议；不造通用多态接口或 ORM | 类型、稳定错误族与生命周期 |

| D-17 结果/事务 | 首批全量物化，行数和字节数双上限；显式 begin/commit/rollback，关闭未完成事务时回滚；流式后置 | 精确限额、错误和回滚/关闭顺序 |
| D-18 连接池 | **首批内置有界连接池** | 容量、获取超时、关闭 drain、事务/连接绑定与并发所有权；普通连接仍不可隐式跨线程 |

| D-20 教程执行 | 固定 tests/fixtures/docs/<module>/；VM/native 逐字 stdout/退出码，为所有库硬门槛；B0 可先放明确标识的完整探测 | B0 复用现有 CI 执行点；后续产品示例须真实导入产品接口 |
| D-21 状态 | 实现、测试、完整示例执行证据和链接全过才能 verified；B0 始终 planned | 每库十项教程与对应提交的证据 |
| D-22 平台证据 | PostgreSQL/Redis 首批用 Linux CI 服务容器；Windows/macOS 按实登记协议/单元/连接失败测试，服务缺证据明确不可验证 | 不用 Linux 成功外推其他平台 |
