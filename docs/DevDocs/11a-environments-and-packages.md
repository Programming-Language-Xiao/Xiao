# 11A. 虚拟环境与包管理

> 本阶段在文件模块、双模运行闭环与 CLI 骨架之上建立项目隔离、依赖物化和包管理能力。它是长期工程，不是模块解析器的附带功能，也不进入 Token 或最小 AST 里程碑。

## 一级工程目标：确定环境模型

### 项目环境

每个 Xiao 项目拥有独立的逻辑环境。环境记录当前项目实际启用的依赖图、工具链约束、目标平台和配置指纹，但不为每个项目重复复制全部依赖源码。

项目环境必须可删除、可重建。只要 `config.xiao`、依赖锁文件、工具链版本和目标条件相同，重新同步应得到等价环境。

### 默认无需激活

正常使用不要求执行 Python 风格的 `activate`：

- `xiao run`、`xiao build` 和 `xiao test` 自动定位项目及对应环境。
- 环境激活脚本只作为交互式终端的可选便利功能。
- 没有激活环境不能改变构建或运行语义。

项目根发现顺序、是否向父目录查找以及找不到 `config.xiao` 时的脚本模式行为仍待定。

### 环境与发布产物

虚拟环境只服务开发、测试和构建。`xiao build` 生成的原生程序不依赖项目虚拟环境存在；需要的 Xiao Runtime 和第三方原生组件按构建规则进入发布产物。

## 一级工程目标：复用全局内容缓存

### 不可变包存储

依赖源码进入全局内容寻址缓存，以规范化包内容的加密摘要作为缓存身份。来源、包名和版本属于解析与锁定元数据，不参与内容缓存键；来自不同位置但内容完全相同的包只保存一份。

项目环境只保存指向缓存条目的逻辑映射，工具链根据映射直接读取全局缓存，不把缓存内容以符号链接、硬链接或副本暴露到项目环境。缓存条目创建完成后必须设为只读，并在使用前验证内容摘要；校验失败时隔离损坏条目，不能继续构建。

本地路径依赖导入缓存时必须形成经过校验的不可变快照；源目录后续发生变化会产生新的内容摘要，不能原地改写旧缓存条目。

### 构建缓存隔离

源码包缓存与构建产物缓存必须分开。构建缓存键至少考虑：

- Xiao 编译器/运行时版本。
- 目标平台与目标架构。
- 调试或发布模式。
- 功能开关和影响代码生成的配置。
- 源码及完整依赖图指纹。

一个平台或配置生成的目标文件不能被另一平台误用。

### 引用与清理

环境删除只删除项目映射，不立即删除其他项目仍可能使用的全局缓存。缓存清理、占用统计、最近使用时间和并发下载锁属于后续管理能力，不能通过扫描并修改项目源码实现。

## 一级工程目标：定义配置与锁定关系

### 声明式 `config.xiao`

`config.xiao` 复用 Xiao 的词法器和语法基础，但只接受不可执行的声明式子集。配置读取阶段禁止：

- 函数定义与函数调用。
- 条件、循环和其他控制流。
- 模块导入。
- 依赖运行时变量的表达式。
- 任何需要先执行项目代码才能得到结果的构造。

允许的最小数据方向包括表头、字符串、数值、布尔值、数组和字典表。精确允许集合、元组、常量引用或环境变量中的哪些能力，需要在配置语法阶段逐项冻结。

### 依赖分组

所有用户直接选择的依赖都写入 `config.xiao`。下面是候选分组，并非已冻结表名：

```xiao
[Dependencies]
http = "^1.4"
utils = { path = "../utils" }

[DevDependencies]
testkit = "^0.3"

[Toolchain]
xiao = "0.1"
```

普通依赖、开发依赖和工具链约束是否足够，是否增加可选依赖、功能组或构建依赖，仍待定。早期阶段不引入可执行安装钩子。

### 依赖锁文件

依赖锁文件是依赖图的唯一精确输入，记录完整依赖图而不是只有直接依赖。完整环境还同时受项目配置、工具链和目标条件约束；项目环境必须能证明自己对应这些输入，不能悄悄使用其他项目或旧版本的依赖。

锁文件名称、格式和更新算法仍待定；用户确认的是“工具生成完整依赖树”，不是某个具体文件名。

## 一级工程目标：形成统一管理入口

### 集成到 `xiao`

虚拟环境创建器、同步器和包管理器直接集成到 `xiao` 命令，不额外要求用户安装第二个管理器程序。

候选命令面如下，具体名称和参数尚未冻结：

```text
xiao env create
xiao sync
xiao add <package>
xiao remove <package>
xiao lock
xiao update
xiao run <entry>
xiao build
xiao test
```

### 命令职责

- `env create`：创建项目环境元数据，不擅自升级依赖。
- `lock`：根据 `config.xiao` 求解并写入依赖锁文件，不要求构建项目。
- `sync`：严格按锁文件物化项目环境。
- `add`/`remove`：结构化修改直接依赖，再更新锁定结果。
- `update`：在用户明确要求时重新求解允许升级的版本。
- `run`/`build`/`test`：使用当前锁定环境，不依赖 Shell 是否激活。

执行命令时是自动同步、只检查后报错，还是提供两种模式，仍待定。常规运行不能在没有明确规则时悄悄升级版本。

## 二级实现任务

### E0：配置与环境指纹

1. 消费第 D0 阶段产出的规范化 `config.xiao` 声明树，不重新执行或解释项目代码。
2. 为项目配置、工具链和目标条件生成稳定指纹，并为后续锁文件摘要预留字段。
3. 建立可删除重建的项目环境元数据，不接入网络。
4. 验证相同规范化配置产生相同指纹，不同目标条件不会误用同一环境状态。

### E1：本地依赖与共享缓存

1. 只支持本地路径包，验证每个包的 `config.xiao`。
2. 把依赖内容导入不可变的全局内容寻址缓存。
3. 让项目环境通过只读逻辑映射引用缓存，并实现 Windows、Linux、macOS 的统一解析接口。
4. 验证多个项目复用同一内容且互不污染。

### E2：锁定与同步

1. 生成包含完整本地依赖图的锁文件。
2. 让同步操作只消费锁文件，不自行选择新版本。
3. 原子地创建或替换环境状态，失败时保留原有可用环境。
4. 为配置与锁文件不一致、缓存损坏和离线缺包提供独立诊断。

### E3：包操作与远程来源

1. 结构化修改 `config.xiao`，保留未修改字段和用户注释。
2. 加入版本求解、注册表或版本库来源及完整性校验。
3. 实现显式升级、离线、冻结和重新锁定模式。
4. 最后评估工具链安装、全局命令和可选激活脚本。

## 验收标准

### 隔离验收

- 两个项目可以锁定同一包的不同版本，运行和构建互不污染。
- 两个项目锁定相同内容时可以复用全局缓存，不重复下载或保存源码。
- 删除项目环境后，可以只凭配置、锁文件和缓存重建等价状态。

### 确定性验收

- 未激活 Shell 环境时，`run`、`build`、`test` 与激活后的解析结果一致。
- 常规命令不会隐式升级锁定版本。
- 相同锁文件、工具链和目标条件产生相同依赖图。

### 配置安全验收

- 读取 `config.xiao` 不执行项目函数、导入或控制流。
- 不可执行构造在依赖下载前即被拒绝。
- 包管理器修改依赖时使用结构化语法树或等价结构，不进行脆弱的文本拼接。
