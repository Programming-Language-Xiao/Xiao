## 三、必须先冻结的 6 条

### 3.1 Shift+Enter 的探测与降级（**本批最容易翻车处**）

`11b:216`（R0 第 5 条）已冻结原则：**「不能把普通 Enter 错认成组合键」**。
这一条在 I1a 必须落到具体实现，否则多行模式会**彻底不可用**——
一旦把 Enter 误判成 Shift+Enter，用户**每按一次回车都会跳进运行确认**。

**冻结**：

- **默认假设「不可区分」**。传统终端下 Enter 与 Shift+Enter 发送**相同字节**，
  所以**必须主动探测**才能启用；
- **探测方式：Kitty 键盘协议**（向终端请求 `CSI u` 上报；成功则组合键带修饰位）；
  探测**只在启动时做一次**，结果缓存在终端状态里；
- **探测失败或超时 → `Shift+Enter` 标记为不可用**，此时
  **`!outLF!` 是进入运行确认的完整入口**（`11b:216` 已定）；
- **⚠️ 不可用时不得猜测**。宁可少一个快捷键，也不能让普通 Enter 走错分支。

**⚠️ 同一原则适用于 `Ctrl+Shift+S` 与 `Ctrl+Shift+P`**：
传统终端下 `Ctrl+S` 与 `Ctrl+Shift+S` 都发 `\x13`，**无法区分**。
所以**二者都按「Kitty 协议可用才启用」处理**，否则 `!save!`（I2）与 `!panel!`（I3）
是唯一入口。**本批只建立这套判定，不实现保存与面板。**

**⚠️ 必须有反例测试**：在不支持 Kitty 协议的终端状态下，
**普通 Enter 必须只新建逻辑行**，断言它**没有**进入任何确认状态。

### 3.2 完整编辑按键协议（**已定：一次冻结**）

`11b:322` 第 7 条目前只冻结了「能够编辑」。本批**一次冻结完整协议**，
并**同时冻结每个键不可上报时的行为**——否则会冻结出一批在某些终端永远触发不了的动作。

**冻结的按键表**：

| 按键 | 动作 | 不可上报时 |
| --- | --- | --- |
| 可打印字符 | 在光标处插入 | — |
| Enter | 新建逻辑行 | — |
| Backspace | 删除光标前一字符 | — |
| Delete / **Ctrl+D** | 删除光标处字符 | Ctrl+D 兜底 |
| ← / → | 光标左/右移一列 | — |
| ↑ / ↓ | 光标上/下移一个逻辑行（**尽量保持列**） | — |
| Home / **Ctrl+A** | 移到逻辑行首 | Ctrl+A 兜底 |
| End / **Ctrl+E** | 移到逻辑行尾 | Ctrl+E 兜底 |
| Alt+← / Alt+→ | 按词左右移动 | **不降级**，静默忽略（见下） |
| Ctrl+W / Alt+Backspace | 删前一词并写入 kill 缓冲 | **不降级**，静默忽略 |
| Ctrl+K | 删到行尾并写入 kill 缓冲 | — |
| Ctrl+U | 删到行首并写入 kill 缓冲 | — |
| Ctrl+Y | 在光标处粘回 kill 缓冲 | — |
| Ctrl+L | 重绘当前界面 | — |
| Ctrl+C | 中断当前输入，回到新的提示符 | — |
| Esc | 编辑态**无操作**（确认态的取消属 I1b） | — |

**⚠️ 三条必须一并冻结的细则**：

1. **kill 缓冲只有一份**——最近一次 `Ctrl+K`/`Ctrl+U`/`Ctrl+W` 的内容。
   **不做多槽 kill ring**：那是 R7「后置交互增强」的范围，现在引入会让测试面失控；
2. **Alt 组合键不降级**：`Alt+←/→` 与 `Alt+Backspace` 在部分终端（如 Windows conhost）
   根本发不出一致的序列，而它们**没有对应的控制指令可退**。
   **冻结为「不可上报时静默忽略」**，不报错、不误判成别的键；
3. **`Ctrl+D` 在空缓冲区**视为 **EOF**（结束会话），**非空时**才是「删除光标处字符」。
   这与 readline 惯例一致，**必须显式冻结**，否则空会话无法用键盘退出。

**⚠️ 写回位置**：冻结后把这张表写进 **`00-decisions:463-475` 的「终端交互式解释器」段**
（那里是已冻结段的所在地），并**删除 `11b:322` 的待定项**。
**不要新开章节**——同一规则写两处是本仓头号病史。

### 3.3 终端抽象与测试策略（沿用既有口径）

`11ae0`/`11ae4` 的冻结口径是**「可注入 Shell 状态模型，不引伪终端」**。本批沿用：

**拆成三个纯函数**，全部可用向量测试：

```text
parseKeys(bytes)                字节流 -> 按键事件（含组合键修饰位）
applyKey(buffer, cursor, key)   按键 -> 新缓冲区与光标（纯函数）
renderMultiline(buffer, terminal, color)  状态 -> 屏幕文本（纯函数）
```

**可注入的终端状态**（不是真 TTY）：

```text

isTTY                 是否交互终端
color                 ColorOptions（复用 I0 的 ui/color.ts）
kittyKeys             是否支持 Kitty 键盘协议（决定 Shift+Enter 等是否启用）
```

**⚠️ 不要引入伪终端库**（`node-pty` 等）——E0/E4 已冻结这条，本批不重开。
**真实终端测试按既有条件门控**（`#[ignore]` 或 `test.skipIf`），不进 CI 默认路径。

### 3.4 readline 与 raw mode 的边界

I0 的单行会话用 `node:readline`（已验收）。I1a 的编辑核心需要 **raw mode**
（逐字节、自定义行号栏、光标控制），readline 做不到。

**冻结**：

- **单行模式保留 readline，本批不动**——I0 已验收，且单行模式不需要行号栏与光标回写。
  **⚠️ 动它就要重跑 I0 的验收，本批不承担这个风险**；
- **多行模式用新的 raw mode 循环**：`stdin.setRawMode(true)` + 逐字节喂给 `parseKeys`；
- **交接点**：单行模式读到**独占一行的 `!inLF!`** 时，退出 readline
  （**先 `setRawMode(false)`、收尾光标与换行**），再进入多行循环；
- **⚠️ 退出多行回到单行时**必须**完整恢复**终端状态，否则后续 readline 输入会错乱
  （典型症状：按键不回显、Enter 不提交、光标停在行中间）。

**⚠️ `setRawMode` 在非 TTY 下不可用**——测试路径必须走注入，
**不得为了让测试能跑而给生产代码加 `if (isTTY)` 的旁路分支**。

### 3.5 软换行与**显示宽度**（含双宽字符）

`11b:112-130` 已冻结行号栏形态（五字符右对齐 + `|`）与续行规则（五个空格 + `|`）。
本批要把它**算出来**：

- **行号栏占 6 列**（5 字符 + `|`），内容区宽度 = `terminal.width - 6`；
- **软换行判定按显示宽度算**，不是按字符数；
- **⚠️ 双宽字符**：中文、日文、韩文、多数 emoji **占 2 列**；
  组合字符与零宽字符占 **0 列**。
  **按 `.length` 计算会在中文源码上直接算错**——这是本批最隐蔽的坑；
- 续行的行号区画**五个空格 + `|`**，内容关系不变（`11b:120-128` 的例子）。

**⚠️ 一行的显示宽度恰好等于内容区宽度时，不应产生空的续行**——
边界要显式测试（这正是 `11b:117` 那个 `abcdefghijklmn` 例子在窄终端下的情形）。

### 3.6 分离头指针追认为「不显示」

I0 的实现把 detached HEAD 走成 `git.ts` 的 `null` → `no-branch` 降级，
**等于用实现冻结了一条待定决策**（`11b:323` 第 8 条仍写着「仍待冻结」）。

**冻结为「不显示摘要」**，理由与「无上游只显示分支名」同源：
detached 状态下**没有分支名可显示**，而短 SHA 对「一眼看懂我在哪」帮助有限。

**要做的**：
- 写进 `00-decisions` 的 Git 摘要相关条目，并**删除 `11b:323` 的待定项**；
- **补一条反例测试**：detached HEAD 的仓库**不显示任何摘要段**，
  且**基本提示符仍完整可用**（`git.test.ts` 已有 `(detached)` 的**单元**断言，
  但缺**真实仓库**的端到端反例）。

## 八、最可能翻车的地方

1. **把普通 Enter 当成 Shift+Enter**（§3.1）——多行模式会彻底不可用，且症状是
   「每按回车就跳确认」，很容易被误诊为状态机 bug。
2. **按 `.length` 算软换行**（§3.5）——ASCII 测试全绿，中文源码一用就错。
3. **退出多行没恢复终端状态**（§3.4）——回到单行后按键错乱。
4. **三个控制指令各写一套识别**（§五）——本仓头号病史，R2 第 4 条要的就是共享分派。
5. **为了测试给生产代码加 `isTTY` 旁路**（§3.3）——注入点要在设计里，不是补丁。
6. **提前接 I4 的包加载**（§2.2）——本批交付后包引用仍不工作，这是预期的。
7. **动了单行模式的 readline**（§3.4）——会连带作废 I0 的验收。
8. **`Ctrl+D` 语义没冻结**（§3.2）——空会话无法用键盘退出。

## 九、验收

1. **入口**：`xiao --inLF` 与 `!inLF!` 都进入多行模式（`12-tests:808`，`Shift+Enter` 部分归 I1b）。
2. **行号栏**：每个逻辑行五字符右对齐行号 + `|`；**多行粘贴保留换行与缩进**（`:809`）。
3. **软换行**：只绘制空白的五行号区 + `|`，**不修改缓冲区、源码位置或下一逻辑行号**；
   **含中文的双宽字符行**有夹具（`:810`、§3.5）。
4. **控制指令**：`!outLF!` 触发瞬间可显示为带行号输入，随后**从编辑缓冲区与源码行号映射中剔除**，
   不进入词法器或保存内容（`:815`）；`!save!`/`!panel!` 的分派已就位但**未实现**。
5. **按键协议**：§3.2 表中每个键有向量；**不支持 Kitty 协议的终端下，
   普通 Enter 只新建逻辑行**（反例）；`Alt` 组合键静默忽略。
6. **边界**：空缓冲区、`99999` 行上限各有明确行为（`:813`）。
