# 20O-B2-B. `lfloat_divide`、`cmath` 与 ABI 1.19/21 实施规划

> **这是 B2-B 的实施规划；B2-B 尚未开工，B2-C 仍未开始。**
> 入口为 A7 内部收口快照 `5749d6e0` 与产品基线 `e7bf7a49`；当前仍为 ABI 1.18、生成器 20、活动 intrinsic 最大 32。
> B2-B 只实现已确认且适用于本批的 F-1～F-12 精表（包括 F-3 资源/性能、F-8 转换、F-10 显示尺度与 F-11 文本边界）；不新增数学裁定，不把 `cmath`/`lfloat_divide` 提前写成已验证。
> A0 的 `result.json` 失败身份、22C/22D、19/11/22 与 B1 历史债务继续独立保留。

## 一、入口与不变量

| 项 | 当前状态 |
| --- | --- |
| A7 | B2-A 已在内部 1.18/20 范围收口；代码快照 `5749d6e0`，产品 `e7bf7a49` |
| 版本 | ABI 1.18、`CODEGEN_VERSION` 20、活动 intrinsic 最大 32、标准库接口 1 |
| 目标版本 | ABI 1.19、生成器 21、标准库接口 1；只在新快照生成，不回改旧原件 |
| 新入口 | 全局 `lfloat_divide`、15 项 `std.cmath`，规划 intrinsic 33～48 |
| 依赖 | F-7 六包精确版本已锁定；`cmath` 需要 `libm =0.2.16` 直接依赖 |
| 状态 | `stdlib.cmath` 仍 planned；最终数值教程/registry 与 721 条 F10 留 B2-C |
| 历史债务 | 22C/22D、19/11/22、B1 旧 721 只作历史，不由 B2-B 核销 |

B2-B 是**功能与内部 1.19/21 验证批**，不是 B2 最终发布。B2-C 才在最终快照重跑完整 B1 721 条 F10、收齐三平台公共产物并升级教程/registry。

### 1.1 要做

1. 按 F-7 固定依赖、锁文件和受控构建环境，补 `libm` 直接依赖，不解析超出六包闭包；
2. 实现四参 `lfloat_divide`：precision 1～32,768、七种 rounding、单次最终舍入、短结果不补零；
3. 实现 15 项 `cmath`：15 个公开包装、15 个底层原语、C ABI 符号与 intrinsic 34～48；
4. 让 `cmath.pow` 与 float `**` 共用同一数学内核，不保留两套域/末位规则；
5. 接通类型、IR、TAC/字节码、VM、LLVM、序列化和普通包隔离；
6. 把 ABI 升到 1.19、生成器升到 21，落实旧/新产物、原生元数据与缓存拒绝矩阵；
7. 建立 B2-B 资源、错误、原子性和三平台性能证据；
8. 在新快照执行 B1 七库 20 入口回归，但不运行旧 721 条 F10。

### 1.2 明确不做

- 不实现 `sfloat` 版 `cmath`、默认参数、重载、方法别名或新数值自动转换；
- 不新增 F-5 之外的 C 符号、intrinsic 或宿主能力；ID 100 墓碑与 1～32 保持；
- 不开放直接 `str → float/sfloat`，不把十进制解析扩成源码新语法；
- 不为兼容而放宽 `.xiaoc`/`.xar`/原生元数据的 max 版本，不手改旧产物头；
- 不运行旧 721 条 F10，不把 B1 历史成绩、A6 性能或 A7 内部证据拼成 B2-B 成绩；
- 不把 `stdlib.cmath` 提前升 verified，不关闭 22C/22D、19/11/22；
- 不在 B2-B 内完成 B2-C 的最终三平台公共发布与教程/registry 收口。

## 二、开工闸门

B2-B 执行前必须确认：

1. A7 有效收口、代码快照、证据目录与自审一致；B2-B 未开始；
2. 当前 ABI 1.18/生成器 20/intrinsic 最大 32/cmath planned 未漂移；
3. F-1～F-12 中适用于 B2-B 的正文已签且无未登记变更；特别核对 F-3 资源/性能、F-8 转换、F-10 显示尺度、F-11 文本边界，以及 F-12 错误顺序；
4. B1 七库 20 入口、资源 17 项、双精确入口和原 28 守卫可复现；
5. `libm` 0.2.16 来源、许可、锁文件和受控构建策略符合 F-7；
6. 唯一任务根、证据目录和全新 target/Runtime/缓存已建立，不覆盖 A0～A7；
7. 若需改数学规则、C 布局、XCON、状态表或版本矩阵，停止并回 B2-FREEZE。

## 三、分批执行

### B0：入口、快照与基线

1. 固定 A7 收口快照、产品基线、锁文件、工具链和三平台目标；
2. 复核当前 16 个规划符号均未活动、intrinsic 1～32 与 ID 100 状态未变；
3. 保存 B1 七库 20 入口、资源 17 项、双精确入口和 28/28 守卫基线；
4. 建独立任务根、输出根和证据目录；不复用 A7 的 Runtime、缓存或可执行文件；
5. 记录 B2-C 与历史债务边界。

退出：B2-B 入口身份可复现；当前仍是 1.18/20，未写产品。

### B1：依赖、共享内核与数值底座

1. 按 F-7 补 `libm = "=0.2.16"` 直接依赖；核对许可、校验值和 `--locked`；其余数值行为按 F-1～F-4、F-8、F-10、F-11 的已确认边界接入；
2. 清理继承的 `RUST_BIGDECIMAL_*`，Cmath 不使用上游默认上下文或 Display；
3. 建立 15 项 `cmath` 的纯 Rust 内核边界；不把宿主 `f64` 结果直接当语言契约；
4. 建立 float `**` 与 `cmath.pow` 的单一共享入口，先定域/符号/错误，再定末位；
5. 建立 ULP/位模式比较工具，参考向量只用离线 MPFR 4.2.2/GMP 6.3.0 生成；
6. 保存依赖解析、锁、工具链、目标和内核单元测试身份。

退出：依赖闭包无未批准漂移；共享内核边界确定；尚无公开 intrinsic。

### B2：`lfloat_divide` 与 intrinsic 33

1. 类型/IR 接受四参 `lfloat_divide(lfloat, lfloat, int, str) -> lfloat`，四参必填；
2. Runtime 先求精确商余，再只在最终结果按七种模式舍入一次；不先舍入倒数再乘；
3. precision 只接受 1～32,768；`precision=0` 或超界为 012，顺序按 F-12；
4. 分母为零为 013；短结果不补零；`1/2` 按 32,768 位仍是 0.5；
5. 结果 scale/系数按 F-10 规范化，工作值受 W、最终值受 D、scale 受 H；
6. 新增 intrinsic 33、C 符号 `xiao_runtime_lfloat_divide` 与 VM/LLVM 绑定；
7. 失败保留 out、输入不变、无部分结果；错误映射统一状态 6。

退出：33 号入口内核、错误、资源和两后端路径可复现；具体数字只在 B2-B 内部登记。

### B3：`cmath` 15 项与 intrinsic 34～48

1. 逐项实现 sqrt/floor/ceil/round/trunc/abs/min/max/pow/sin/cos/tan/exp/ln/log10；
2. 全部入口先拒绝 NaN/Inf；域错误为 009；`sqrt(-0)=-0`、`round(-0.5)=-0` 等按 F-2；
3. 取整/abs/min/max 逐位精确；普通非零超越与 pow 结果不超过 4 ULP；
4. 正常下溢允许子正规数与有符号零；非有限结果报 009，不用数值容差改错误身份；
5. 补充 15 个 C 符号与 intrinsic 34～48；ID 100 墓碑保持；
6. 新增 `stdlib/cmath.xiao` 公开包装，只调用已确认原语，不假装已有私有可见性；
7. C ABI 输入借读、out 已初始化且不重叠；成功释放替换旧 out，失败保持 out。

退出：16 个规划入口全部有内核、C 绑定和错误证据；cmath 仍为 planned。

### B4：语言全链路与承载

1. 类型检查与 IR 共用数值提升/参数规则；`cmath` 参数与返回均为 float；
2. TAC/字节码使用既有标签和承载，不提前改容器版本；新 intrinsic 按 33～48 绑定；
3. VM 与 LLVM 动态 Runtime 共用语义内核；不另写近似实现；
4. 原生降低、符号解析、序列化、并发值和普通包隔离逐项接通；
5. `std.cmath` 与 `stdlib.cmath` 双路径、导出、逐函数移除和真实归档纳入契约测试；
6. 保留源码位置、错误传播、清理和 out 所有权；不把可 catch 的 009/012/013 折叠成编译错误；
7. 若必须改 C 布局、状态表或 XCON 才能安全接线，停止回冻结。

退出：VM/原生/归档/序列化全链路一致；尚无最终版本切换。

### B5：ABI 1.19、生成器 21 与拒绝矩阵

1. ABI 次版本升到 1.19（编码 `0x0001_0013`），生成器升到 21，标准库接口保持 1；
2. `.xiaoc` 头、`.xar` 索引与指令流记录精确 1.19；原生元数据记录 1.19/21；
3. B1 原始 1.18 `.xiaoc`/`.xar` 在执行前按头/索引/指令流拒绝，原件不改写；
4. 新 1.19 产物被旧 1.18 验证器拒绝；生成器 20 缓存因身份不匹配重新生成；
5. 旧原生元数据按精确 ABI 范围与标准库身份拒绝，不做迁移工具；
6. 保留既有 1.18 C 符号、布局和调用约定；新增入口只做加法扩展；
7. 重新生成所有新产物，不复用旧可执行文件或旧 Runtime。

退出：1.19/21 身份、旧/新拒绝和缓存重生成均有实际证据；未通过手改旧头伪装兼容。

### B6：资源、错误、原子性与性能

1. 按 F-3 复核 D/W/H、precision、指数、工作值和结果预算；
2. 002/009/011/012/013/033/034 按 F-12 顺序；033 资源与 011 分配失败分开；
3. 覆盖最大合法 precision、七种舍入、强消去、非终止、下溢/溢出和上限 +1；
4. 测量 33～48 的 VM release、原生 O0/O3、五批独立进程、中位数、OS 峰值和翻倍比；
5. `cmath.pow` 与 float `**` 同路径、同优化比较，不把两套内核拼成一组成绩；
6. 测量 B1 20 入口和 A1 完整示例在新快照的额外开销，不重跑 721；
7. 不可验证项明确记录，不放宽预算、不删场景、不换负载补绿。

退出：16 个新入口的资源/错误/性能有证据或明确不可验证记录；无预算掩盖。

### B7：B1 回归、B2-B 内部收口与 B2-C 交接

1. 在新 1.19/21 快照执行 B1 七库 20 入口、资源 17 项、双精确入口和 28/28 守卫；
2. 复核 A1 完整示例、A2～A5 数值路径和 B2-A 现有边界未被改写；
3. 保存源码、锁、Runtime、工具链、目标、PID、产物和 CI run/job/attempt；
4. 语言参考只提升到“B2-B 内部验证”，`cmath`/`lfloat_divide` 仍未最终 verified；
5. `stdlib.cmath` 仍 planned，registry 不提前升级；B2-C 再按最终证据升级；
6. 旧 721 条 F10 不运行；22C/22D、19/11/22 和 B1 历史债务不关闭；
7. 形成 B2-C 入口：最终三平台、完整 721、教程/registry 与公共发布。

退出：B2-B 内部 1.19/21 收口证据完整；B2-C 未开始；未把内部验证写成最终发布。

## 五、退出条件

1. intrinsic 33～48 全部活动并与 C 符号、VM/LLVM 绑定一一对应；
2. `lfloat_divide` 七种舍入、precision、scale、错误和资源全部有证据；
3. 15 项 `cmath` 与 float `**` 共用内核，域/符号/ULP 符合 F-2/F-9；
4. 类型到序列化的全链路在 VM/原生一致，普通包隔离和移除通过；
5. ABI 1.19/生成器 21/标准库接口 1 精确生效，旧/新拒绝矩阵实际执行；
6. 新增路径按 F-3 完成资源/错误/性能取证，或明确记录不可验证；
7. B1 20 入口/17 资源/双精确/28 守卫在新快照通过；旧 721 未运行；
8. `stdlib.cmath` 仍 planned，B2-C 未开始；历史债务未核销；
9. B2-C 入口明确，不能把 B2-B 内部 1.19/21 写成最终公共发布。

## 六、风险与禁止

- 用宿主 libm 的直接结果冒充已确认的位模式/ULP 契约；
- 为 `cmath.pow` 另写一套实现，导致与 float `**` 域或末位分叉；
- 用十进制 f64 计算中间商，造成双重舍入或错误 scale；
- 先升 ABI/生成器再补绑定，留下新旧 Runtime/缓存混用；
- 通过放宽 max 版本、手改旧头或忽略指令流版本来“兼容”旧产物；
- 用 B2-A 内部 1.18/20 证据、A6 性能或 B1 旧 721 冒充 B2-B；
- 提前把 `cmath`/registry 升 verified，或关闭历史债务；
- 为通过 ULP/性能阈值删场景、换负载、加 ignore 或改用例。
