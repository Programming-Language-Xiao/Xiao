## 三、必须先冻结的 7 条

### 3.1 覆盖模式（Ins 切换，仿 VSCode）

`\x1b[2~` 切换插入/覆盖。**冻结语义**：

- **覆盖模式下输入可打印字符 → 替换光标处的字素**，光标右移一个字素；
- **光标在逻辑行行尾 → 追加**，**不替换换行**（换行只能被 Delete/Backspace 显式删除）；
- **覆盖模式不跨越逻辑行**——替换到行尾就变成追加，绝不吞掉下一行；
- **Enter / Backspace / Delete / 方向键在覆盖模式下行为不变**（与 VSCode 一致）；
- **⚠️ 有选区时输入 → 替换整个选区**，且**替换后保持覆盖模式**（不是退回插入模式）；
- **覆盖模式是编辑器状态的一部分**，不是终端状态——`EditorState` 要带这个字段。

**⚠️ 覆盖模式与软换行**：替换会改变显示宽度，**重绘必须按新宽度重算物理行**。
不得复用上一帧的行数缓存。

### 3.2 选区模型

**冻结为「锚点 + 光标」两点模型**：

```text
anchor   固定端，不随方向键移动
cursor   活动端，所有移动都改它
anchor == cursor 时无选区
```

**存在选区时的按键语义**（这一组必须一次冻结，否则每批各写一套）：

| 按键 | 有选区时 |
| --- | --- |
| 可打印字符 / 粘贴 | **替换整个选区** |
| Backspace / Delete | **删除整个选区** |
| Ctrl+Shift+X | 剪切选区（删并入剪贴板） |
| Ctrl+Shift+C | 复制选区（**不改变缓冲区**） |
| Ctrl+K / Ctrl+U | 删除到行尾 / 行首（**与选区无关**，沿用 I1a） |
| ← / → / ↑ / ↓（无 Shift） | **取消选区**，光标移到选区一端：左/上移到**起点**，右/下移到**终点** |
| Shift + 方向键 / Home / End | **扩展选区**（Home/End 扩到行首/行尾） |
| Ctrl+Shift+A | 全选 |
| 鼠标点击（无 Shift） | 取消选区并把光标放到点击处 |
| 鼠标拖动 | 以按下处为锚点扩展选区 |

**⚠️ `Esc` 保持 I1a 的「编辑态无操作」，本批不改。**
虽然 VSCode 里 Esc 取消选区，但终端里 Esc 还承担转义序列前缀的角色
（`keys.ts` 已有 40ms 的 `escapeTimer` 消歧），**再给它一个语义会放大歧义**。
取消选区有方向键和鼠标点击两条路，够用。**要改冻结的话另开批次。**

### 3.3 鼠标：协议、坐标与「Shift 保留本地选中」

**冻结**：

- **开启**：`\x1b[?1000h`（按键）+ `\x1b[?1002h`（按住拖动）+ `\x1b[?1006h`（SGR 坐标编码）；
- **退出时按相反顺序关闭**，与 I1a 的 raw/Kitty/括号粘贴/光标恢复**一起放进同一个 `finally`**；
- **必须用 SGR（`?1006h`）**：旧坐标编码在列号 >223 时**溢出**，宽终端上会算错位置；
- **⚠️「按住 Shift 才上报」是终端的内建行为，不要自己实现**。
  开启上报后，终端会把**按住 Shift 的鼠标事件仍当作本地选中**处理（xterm 惯例）。
  写代码时**不要**去检测修饰位再决定要不要处理——那会在不同终端上表现不一。
- **⚠️ 滚轮会被吃掉**：开启上报后滚轮事件也发给我们。
  **本批不做滚动**（长缓冲区滚动是独立的大功能），**滚轮事件忽略**。
  用户想滚动查看时**按住 Shift 滚滚轮**（同样是终端内建）。
  **这条代价必须写进 UseDocs**，否则用户会以为滚轮坏了。

**⚠️ 反向映射是本批的核心工程**（现状里缺的正是它）：

点击给的是 **(物理行, 物理列)**，要换算回 **(逻辑行, 字素列)**：

1. `renderMultiline` 现在只返回文本，**要额外返回每个物理行的来源**
   （逻辑行号 + 该段起始字素索引，以及本帧的滚动偏移）；
2. 在一段内按**显示宽度**累加找字素边界——**不能用字符索引**；
3. **⚠️ 点在双宽字符的后半格**：冻结为**归到该字素之前**（与「光标只在字素边界」一致）；
4. **点在行号栏区域**（物理列 ≤ 6）：**忽略点击**，不移动光标。

### 3.4 剪贴板：只增不改，且必须能降级

**⚠️ `Ctrl+A` 与 `Ctrl+C` 的含义保持 `00-decisions` 的冻结**
（分别是「移到逻辑行首」与「清空当前输入并回到新提示符」）。**本批不推翻任何一条**。

**新增的键全部走 `Ctrl+Shift` 系列**：

| 按键 | 动作 | 不可上报时 |
| --- | --- | --- |
| `Ctrl+Shift+C` | 复制选区到**程序内剪贴板** | **降级为终端自身的复制**（见下） |
| `Ctrl+Shift+X` | 剪切选区到程序内剪贴板 | 同上 |
| `Ctrl+Shift+A` | 全选 | 同上 |

**⚠️ 降级是安全的，这是选 `Ctrl+Shift` 系列的关键理由**：
传统终端下 `Ctrl+Shift+C` 由**终端模拟器自己**处理为「复制选中文本到系统剪贴板」——
即使我们收不到，**用户仍然能用那条路复制**。所以降级不会让人失去能力，
只是失去「程序内选区」这一层。

**⚠️ 程序内剪贴板与系统剪贴板是两回事**，要分清：

- **复制（`Ctrl+Shift+C`）**：写入**程序内剪贴板**（编辑器状态），供 `Ctrl+Shift+X`/yank 使用；
- **系统剪贴板**：**本批不碰**。终端里读写系统剪贴板需要 OSC 52（`\x1b]52;c;<base64>\x07`），
  而**多数终端默认禁用或限制它**（安全考虑：远端的程序可以借此偷读剪贴板）。
  **要引入 OSC 52 必须单开批次并显式冻结**，不在本批偷偷加。
- **粘贴**：**继续走括号粘贴**（I1a 已实现）。终端自带的 `Ctrl+Shift+V` 走的就是它，
  保真度最高（能带换行和缩进）。**本批不实现 `Ctrl+V`**——它在多数终端被终端自己吃掉，程序根本收不到。

### 3.5 新增按键的降级原则（沿用 `11b:216`）

本批新增的**所有**组合键都必须回答一个问题：**终端发不出这个序列时怎么办？**

- `Ins`（`\x1b[2~`）：**传统终端就能发** ✓ 无需降级。
  **⚠️ 但不少笔记本键盘没有 Ins 键**——所以覆盖模式必须**另有一条进入路径**，
  见 §3.6；
- `Ctrl+←/→`（`\x1b[1;5D`）：传统序列 ✓ 无需降级；
- `Ctrl+Shift+C/X/A`：**只在 Kitty 协议确认后可用**，否则按 §3.4 降级；
- 鼠标：`?1006h` 已开但终端不支持的场景极少；**不支持时静默无反应**，不得报错。

### 3.6 覆盖模式的第二条进入路径（键盘没有 Ins 时）

**⚠️ Ins 键在笔记本上经常不存在**（很多 60% 键盘、MacBook 全系都没有）。
只靠 Ins 会让覆盖模式在一部分设备上**完全无法进入**。

**冻结**：保留 `!ovr!` 作为与 `!outLF!`/`!save!`/`!panel!` **同级的控制指令**，
独占一行时由 `commands.ts` 的**同一张分派表**识别并切换覆盖模式。

**⚠️ 必须在 `commands.ts` 的既有分派表里加一行，不是另写一套识别**——
R2 第 4 条要的就是共享分派，I1a 已经把它建好了。

### 3.7 `Ctrl` 加方向键：行首/行尾与首行/尾行

**新增四个导航键**（全部是传统序列 `\x1b[1;5X`，**不需要 Kitty 协议**，全终端可用）：

| 按键 | 传统序列 | 动作 |
| --- | --- | --- |
| `Ctrl+←` | `\x1b[1;5D` | 移到**逻辑行首** |
| `Ctrl+→` | `\x1b[1;5C` | 移到**逻辑行尾** |
| `Ctrl+↑` | `\x1b[1;5A` | 移到**缓冲区首行**行首 |
| `Ctrl+↓` | `\x1b[1;5B` | 移到**缓冲区尾行**行尾 |

**⚠️ 三条必须一并冻结**：

1. **`Ctrl+←/→` 与 `Home`/`Ctrl+A`、`End`/`Ctrl+E` 语义完全相同**——
   是**多入口**，不是新语义。**四个入口必须落在同一个实现分支上**，
   不得各写一份（本仓头号病史）。加它的价值在于笔记本键盘的 `Home`/`End`
   常需要 Fn 组合；
2. **`Ctrl+↑/↓` 是新能力**（跨逻辑行的首尾跳转），此前没有对应键。
   **⚠️ 跳到尾行后光标可能在视口外**——`renderMultiline` 已有的
   `start = max(0, cursorRow - height + 1)` 会让**视口跟着光标走**，
   所以**不需要滚轮**也能看到（本批不做滚动的代价因此被抵消一部分）；
3. **`Ctrl+←/→` 明确不做「按词移动」**——按词移动留给 `Alt+←/→` 与 `Alt+B/F`（§2.2）。
   这一条与终端世界的常见约定（`Ctrl+←/→` 多为按词）**不同**，
   **必须在 UserDocs 里写明**，否则按惯常直觉操作的人会按错。

**⚠️ 要往 `00-decisions` 的按键表里新增这四行**，并把「Alt+← / Alt+→」那行的
「不可上报时」从「静默忽略」改回「—」（§2.2 修掉了误标的 `kittyOnly`）。

## 六、硬约束

1. **不推翻 `00-decisions` 已冻结的按键**（§3.4）——`Ctrl+A`/`Ctrl+C` 含义不动。

8. **不做滚动、不做语法高亮**（§十）。

3. 有选区时输入、Backspace、Delete、粘贴都作用于**整个选区**；`Ctrl+Shift+C` 复制**不改变缓冲区**。
4. `Ctrl+Shift+A` 全选；`Ctrl+Shift+X` 剪切；三者在**不支持 Kitty 协议的终端上降级**为终端自身的复制，且**不得报错**。
5. 鼠标点击把光标定位到点击处的字素边界；**点在双宽字符后半格归到该字素之前**；点在行号栏忽略；退出 REPL 后鼠标上报已关闭。
6. `Ctrl+←/→` 移到逻辑行首/行尾、`Ctrl+↑/↓` 移到缓冲区首行/尾行；
   **行首/行尾与 `Home`/`End`/`Ctrl+A`/`Ctrl+E` 落在同一实现分支**（多入口、单一语义）；
   `Ctrl+↑/↓` 之后**视口跟随光标**，光标不被留在屏幕外。
7. 覆盖模式与选区的状态**不进入源码**：`editorSource` 只反映真实文本与真实换行。

## 九、最可能翻车的地方

1. **反向映射按字符索引算**（§3.3）——中文行上点击位置会整体偏移，且**只在含双宽字符时错**。
2. **自己实现「Shift 保留本地选中」**（§3.3）——终端已经做了，自己再做会双重判断。
3. **忘了关鼠标上报**（§3.3）——退出 REPL 后终端里鼠标失灵，用户以为终端坏了。
4. **开了鼠标却不说滚轮被吃**（§3.3）——用户会以为滚轮坏了；**必须写进 UseDocs**。
5. **剪贴板与 kill 缓冲做成两份**（§五）——本仓头号病史。
6. **偷偷用 OSC 52 读写系统剪贴板**（§3.4）——绕过冻结，且部分终端会拒绝或告警。
7. **推翻 `Ctrl+A`/`Ctrl+C`**（§六 第 1 条）——那是已冻结的规则，改了要重跑 I1a 验收。
8. **覆盖模式吞掉换行**（§3.1）——行尾覆盖会把下一行接上来，静默损坏源码。
9. **`Ctrl+Shift` 三键在无 Kitty 时报错**（§3.4）——必须静默降级，终端自身的复制仍然可用。
10. **四个行首/行尾入口各写一份实现**（§3.7）——`Ctrl+←`、`Home`、`Ctrl+A` 必须走同一个分支。
11. **把 `Ctrl+←/→` 做成按词移动**（§3.7）——那是终端世界的常见约定，但**本仓已冻结为行首/行尾**，
    改了要回头改 `00-decisions` 与 UserDocs。
