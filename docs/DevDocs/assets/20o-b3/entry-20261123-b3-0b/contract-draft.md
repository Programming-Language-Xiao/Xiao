# B3-0B 冻结契约与版本候选

time、args、cli 的公开面、能力、错误、预算和性能协议已取得答复。版本一节记录 B3-0B 已确认的联合候选及 B3-0D 的待定项。[实际答复](decisions.json)

所有公开名字以 `std.<module>` 和 `stdlib.<module>` 两条路径选择导入，规范身份为 `stdlib.<module>`。表中的参数均必填，沿用现有位置与命名调用规则。

## 接口

| 模块 | 公开签名 | 所有权和能力 |
| --- | --- | --- |
| time | `utc_now(str unit) -> int`、`monotonic(str unit) -> int`、`format_utc(int unix_time, str unit) -> str`、`sleep(int duration, str unit) -> none` | 两个取钟入口和 sleep 使用既有 `clock` 位 1。格式化只消费输入值，返回拥有的字符串 |
| args | `program_name() -> str`、`argv() -> [str]` | 读取已注入的运行快照，检查既有 `process` 位 2。各次调用交付拥有的结果，返回数组的改变不影响快照 |
| cli | `split_terminator([str] values) -> [[str]]` | 纯 Xiao。输入借读，返回长度为 2 的新外层数组和两个新的字符串数组 |

### time

单位参数必填，只接受严格小写的 `"ms"`、`"ns"`。取钟时使用实际宿主精度，换算为选定单位的整数后检查 64 位范围。UTC 墙钟从 Unix 纪元起按数学向下取整，墙钟回拨如实反映。单调钟从当前运行进入应用前起算，子任务共享一份基准。宿主读数回退时，最近一次发布的时长作为下界。到期判定使用单调钟。

格式化采用前推格里高利历、固定 ASCII 与 `Z`。毫秒输出 24 字节，纳秒输出 30 字节，分别保留三位和九位小数。毫秒格式输入域为 `-62135596800000..253402300799999`，对应 0001～9999。纳秒格式支持整个有符号 64 位域。例如 `format_utc(-1, "ns")` 产生 `1969-12-31T23:59:59.999999999Z`。

sleep 上限为 60 秒，`ms` 最大 60,000，`ns` 最大 60,000,000,000，两个上限都包含。零值执行取消与超时检查后完成，负值属于非法参数。等待期间继续响应控制信号，允许 OS 调度引入延迟。最终安全点先检查取消，再检查运行截止时间，再决定是否正常完成。根请求沿用 `X09-DRIVER-001/002`，独立子任务取消沿用 `X06-RUNTIME-027` 并按既有 `join`/`wait` 规则交付。既有取消清理要求覆盖 `finally` 与释放。[B3-0A 实测](../entry-20261122-b3-0/README.md) · [执行取消](../../../09b0e-vm-cancellation-checkpoint.md)

### args

每次应用入口接收一份独立程序名和有序 UTF-8 参数，供 VM、原生和其子任务只读使用。嵌入方无显式输入时采用 `""` 与 `[]`，CLI 使用当前运行目标的调用拼写，直接启动的原生产物使用宿主拆分后的 `argv[0]`。程序参数属于执行期输入。其传递及协议失配规则待版本轮确认。

Windows 补测用 Bun 1.4.0 观察到孤立 UTF-16 单元 `D800` 和合法 `FFFD` 都变成 `U+FFFD`，空串则原样保留。严格校验须在读取原生参数时完成。原生启动器如何传递已校验的快照、协议失配如何拒绝，在版本与兼容轮裁定。Linux/macOS 保留 B3-0A 的 Rust 原始参数观察。[Windows 观察回执](preflight.json) · [B3-0A 观察](../entry-20261122-b3-0/README.md)

### cli

首个 `--` 之前为第一组，之后为第二组，首个分隔符移除。后续的 `--`、空项和重复项保持顺序。无分隔符时返回输入元素组成的第一组及空的第二组。边界包括空输入、开头与末尾分隔符。完整选项解析、默认值和帮助生成后置。启动器分界属于运行入口，`split_terminator` 仅接收调用者给出的数组。

签名表中的 `[[str]]` 描述已确认的返回形状。固定解析器对显式嵌套数组返回注解报告 `X04-PARSE-005`。源码声明由当前前端推导返回类型。等价样例经临时标准库根中的 `std.text` 和 `stdlib.text` 导入，Windows VM、原生 O0/O3 和删源后的 `.xiaoc`、`.xar` 回放均匹配独立黄金。该写法作为实现选择记录，实际答复仍为原台账的十二项。[注解探测](cli-shape.zip) · [两条模块导入探测](cli-import.zip)

### args 与 cli 接纳预算

| 层 | 条目上限 | 单项上限 | 总上限 |
| --- | --- | --- | --- |
| args 快照 | argv 1,024 项，程序名单独计数 | 程序名与每个参数各 4,096 UTF-8 字节 | 程序名与参数合计 65,536 UTF-8 字节 |
| cli 输入 | 1,024 项 | 每项 4,096 UTF-8 字节 | 所有项合计 65,536 UTF-8 字节 |
| cli 输出 | 两个数组的元素总数等于输入数减去移除项数 | 保留项的字节数不变 | 两组输出合计至多输入字节数 |

允许空串及合法 `U+FFFD`。程序快照中的 NUL 不符合宿主 argv 的边界，嵌入输入也拒绝。纯 Xiao 分隔辅助接收正常语言字符串，其中的 NUL 原样保留。计数和 UTF-8 字节预算采用有界线性检查。先验证输入规模再构造返回值，输出预算包含分组容器和保留字符串的归属。

## 错误、性能与版本

### 错误与优先级

| 场景 | 错误身份 |
| --- | --- |
| 实参动态类型不符、能力缺失 | 分别沿用 `X06-RUNTIME-002` 和 `X06-RUNTIME-026` |
| 非法时间单位、负时长、格式域越界或宿主时钟失败 | 沿用 `X06-RUNTIME-012`，保留现有错误类及 `runtime.invalid_value` |
| 取钟结果或时间期限无法表示 | `ArithmeticError/X06-RUNTIME-009` |
| sleep 超过 60 秒、cli 输入超出预算 | 分别为 `ResourceError/TIME_SLEEP_LIMIT_EXCEEDED` 和 `ResourceError/CLI_LIMIT_EXCEEDED` |
| 有效运行请求的程序快照含非法原生编码或 NUL、接纳预算超限 | 分别为 `X09-DRIVER-004` 与 `X09-DRIVER-005`，执行前拒绝，退出码 2。帧编码/请求结构错误沿现有协议检查 |
| 输出受控分配失败、Runtime 不可恢复故障 | 分别沿用 `ResourceError/X06-RUNTIME-011` 和既有 Fatal 边界 |

进入函数后先核对调用类型，再核对能力，再校验输入和工作量。阻塞操作通过接纳后进入中断安全点。运行入口若已经拒绝，保持驱动器原有前置顺序。sleep 安全点按取消、截止、自然完成排序。墙钟使用实际值，Epoch 前的毫秒向下取整。单调钟按运行内最后发布值钳制回退，之后才换算单位。UTC 日历使用无闰秒的前推格里高利历。格式化域和单位失败可被程序捕获，取消沿既有驱动器/子任务通道。

args 入口先核对条目数，再按程序名和参数顺序逐项核对编码、NUL、单项字节和累计字节，首次失败使整份快照失效。cli 先验证输入是数组并检查条目数，其后逐项核对字符串类型及单项/累计预算，最终构造结果。运行期错误关联调用 span，现有错误传播、`catch`、`finally` 和释放机制按所属通道执行。原始 argv 文本不进入诊断。

### 性能与三平台

| 工作负载 | 验收规则 |
| --- | --- |
| 取钟、格式化与快照读取 | Rust 1.96.0 锁定 release Runtime/VM，原生 O0/O3 分记。取钟/格式化各 4,096/8,192/16,384 次。程序名和 argv 以注入快照测 256/512/1,024 个参数，各项 32 个 UTF-8 字节，另测单项和总字节边界。共享输入只锁定一次，使用实际返回值 |
| 纯 Xiao 分隔 | 同规模测首项、中部、尾项和无分隔符，另测输出元素数和最大总字节。源样例与验收黄金按 D-20 单独固定 |
| 非等待负载 | 每项五个独立进程，各预热一次。校准目标 100 毫秒，测量批至少 50 毫秒，重复增量至多 16 倍，最多 `2^24` 次。基于真实单次样本重算归一化中位数，VM ≤10 秒，原生 ≤2 秒，驻留内存增量最大 ≤64 MiB，适用翻倍比 ≤3 |
| sleep | 受控时钟核对 0、1 ns、1 ms、60 秒和越界、同时发生取消与到期、清理只执行一次。真实宿主各测 1 ms、10 ms 和 100 ms，五个独立样本记录实际时间及唤醒延迟。自然返回不得早于期限。取消响应中位数 ≤100 ms，最大 ≤1 秒，按已收到取消标记起算 |

平台为 Windows x86_64 MSVC、Linux x86_64 GNU、macOS arm64。实测保存源、Runtime、工具、目标、独占任务根和平台、后端及优化级别。缺可靠数据时登记不可验证。Windows 公共候选每份由产品验证器给出 COFF `Complete`，并核对声明组件和观察组件。B3-0B 证据用于冻结，产品三平台执行与验收分别属于 B3-1/2/6/7。

### 版本与 ABI

| 模块 | Runtime 原语与 C 符号候选 | 效果 |
| --- | --- | --- |
| time | `os_time_utc_now` → `xiao_runtime_time_utc_now`，`os_time_monotonic` → `xiao_runtime_time_monotonic`，`os_time_format_utc` → `xiao_runtime_time_format_utc`，`os_time_sleep` → `xiao_runtime_time_sleep` | 两种取钟观察时钟，sleep 等待且可中断，格式化分配字符串 |
| args | `os_args_program_name` → `xiao_runtime_args_program_name`，`os_args_argv` → `xiao_runtime_args_argv` | 读取当前运行快照、交付拥有的结果。各次调用维持能力和失败检查 |
| cli | 使用现有语言数组能力，无新增 intrinsic 或 C 符号 | 纯计算及有界输出分配 |

候选以 ABI 1.20、生成器 23、标准库接口 1 为联合目标。维持现有值标签和 C ABI 对象布局，六个入口只作加法扩展。规划编号及原生入口的上下文传递符号与 B3-0C 合并到 B3-0D 定案，旧 1～48 与 ID 100 归旧契约。

VM/TAC 和原生上下文统一传递当前运行的程序名、参数快照、基准及中断控制。候选把可选 `arguments` 字段放入运行协议的 `RunOptions`，形状为 `{program_name: str, argv: [str]}`。省略采用已确认的空快照。握手须明确指示核心支持此字段，防止旧核心静默丢弃。协议/Core 版本的最终选择以及原生入口如何注入由 B3-0D 与其他模块合并裁定。

C ABI 候选采用 `const XiaoValue*` 借读输入及已初始化的 `XiaoValue* out`。成功替换、失败保留。状态 0 成功，1/2/3 为结构输入失败，6 保留既有错误和并发取消交付约定，8 走 Fatal。入口传递值保持不重叠和有效强引用。暂停等待的中断由已有控制通道恢复和清理。

可移植产物维持容器与索引格式。受 ABI 约束的 B2 与 B3 原件交叉执行前拒绝，回归从源码重生成，原生缓存以 ABI、生成器和 Runtime 内容身份失配重建。运行的参数快照只参与执行，产物、构建缓存身份和归档索引使用静态输入。
