# B3-0C 三模块冻结契约

三模块的公开接口、能力、宿主行为、错误及性能协议已冻结。联合版本表记录本批确认的候选，具体编号和接线身份由 B3-0D 定案。[九项实际答复](decisions.json) · [B3-0B 冻结正文](../entry-20261123-b3-0b/contract-draft.md)

| 模块 | 公开签名 | 能力与所有权 |
| --- | --- | --- |
| fs | `write_text(str path, str text, bool overwrite) -> none`、`list_dir(str path) -> [str]`、`remove(str path) -> none`、`rename(str source, str destination, bool overwrite) -> none`、`metadata(str path) -> dict<str, int>` | 复用 `filesystem`。输入借读，枚举和元数据返回调用者拥有的新容器 |
| env | `get(str name) -> [str]`、`set(str name, str value) -> none`、`unset(str name) -> bool` | 使用专用 `environment` 授权。查找返回拥有的零项或一项数组，以一次读取区分缺失和空值 |
| log | `write(str level, str message, str target) -> none` | 检查 `clock` 与 `stdout`，借读三个字符串并以一条记录交付 |

公开路径采用 `std.<module>` 与 `stdlib.<module>`，规范身份为 `stdlib.<module>`。参数均必填，沿用位置和命名调用。

## fs 路径与提交

- 相对路径从调用所在进程的 cwd 解释。绝对路径、`..` 和中间符号链接交由宿主处理。空路径或 NUL 在宿主调用前拒绝。宿主权限与受限模式遵循已确认方向。
- `write_text` 先在目标同目录准备完整 UTF-8 文本，再用宿主原子操作提交最终目录项。禁止覆盖时按提交结果判定是否已经存在，包含悬空链接。允许覆盖时处理目录项本身，避免写入链接目标。现有目录或平台无法保证相应原子语义时返回错误。提交前失败时保留旧目标并清理临时文件，清理失败保留独立原因。
- `list_dir` 枚举直接子项的名称，按原始 UTF-8 字节升序。目录路径本身按宿主规则解析链接。名称严格解码，错误、取消或限额失败时整份结果作废。
- `remove` 只删除指定文件、空目录或链接目录项，调用语义为非递归。符号链接的末段只处理链接本身。`rename` 移动目录项，覆盖显式，符号链接末段只移动链接本身。跨卷及无法实现所选覆盖语义时返回错误。
- `metadata` 观察末段本身，返回 `kind`、`size`、`modified_ms` 三个整数字段。`kind` 的 1/2/3/4 分别对应文件、目录、链接和其他对象。`size` 为普通文件字节数，其余为 -1。`modified_ms` 为 Unix 毫秒。

三平台宿主观察支持上表的路径差异和错误边界分析。原子提交、取消及清理按产品阶段的并发和故障注入验收。[三平台原始观察](../entry-20261122-b3-0/entry.json) · [既有 os 契约](../../../../../stdlib/os.md)

## env 快照与继承

- 每次运行的授权入口装入一份私有快照。嵌入请求省略输入时使用空快照。授权的 CLI 与直接原生进程在进入应用前从原生环境取一次，未授权的请求跳过该读取。新增位号和旧请求默认掩码由 B3-0D 核对。
- 每次查找、设置和删除在本次运行内一次生效。Xiao 并发任务共享该视图。`get` 缺失返回 `[]`，存在空值返回 `[""]`。`unset` 删除存在项时返回 true，缺失返回 false。现有 `std.os.spawn` 按既有契约继承宿主环境。
- Windows 名称按宿主的序号不区分大小写规则比较。Linux 与 macOS 按原始名称精确比较。名称必须非空并排除等号和 NUL，值允许空串并排除 NUL。原生输入严格解码。若有效名称重复或输入非法，整份快照的接纳失败。Windows 宿主管理的驱动器 cwd 伪变量由启动适配层过滤。

专用授权控制当前运行的环境访问。局部写删随运行结束释放，宿主环境保持独立。[20D 能力边界](../../../20d-capability-context.md) · [既有进程契约](../../../../../stdlib/os.md)

## log 记录与失败归属

- 接受小写级别 `debug`、`info`、`warn`、`error`，目标为 `stdout`。交付格式为 UTC 毫秒时间戳、空格、大写级别、空格、消息和一个 LF。消息中的 CR、LF 和 NUL 在读取时钟前拒绝。
- 单次调用构造一条完整记录，在运行输出端串行交付并刷新。输出端写入或刷新失败时交付可机读错误，已写出的字节保留。并发日志保持记录边界，每次运行按实际交付次序观察。
- VM 使用可报告接纳失败的运行输出端，原生使用受控 stdout。封装工具在运行结果之后转发输出时，转发失败由该工具报告。stdout 的实际捕获、关闭流、部分写入及刷新失败是产品验收项。

当前 VM 的 `print` 通过输出事件交付，原生 `print` 持 stdout 锁完成写入和刷新。日志发布需要独立验证这些边界。[现有 VM 输出入口](../../../../../core/rust/crates/xiao-vm/src/semantics/exec.rs) · [现有原生输出入口](../../../../../core/rust/crates/xiao-runtime/src/abi_io.rs)

## 资源与性能

| 入口 | 上限 |
| --- | --- |
| fs | 每条路径 4,096 UTF-8 字节。写入文本 8 MiB。目录枚举至多 1,024 项，单项 4,096 字节，全部名称合计 65,536 字节 |
| env | 每次运行至多 1,024 对。名称至多 256 UTF-8 字节，值至多 65,536 字节，名称与值合计 1 MiB。授权快照和局部写入使用同一限额 |
| log | 消息至多 4,096 UTF-8 字节。每次运行至多尝试交付 1,024 条，编码记录合计至多 1 MiB。秒级日期部分与三位毫秒、级别、分隔符及 LF 均计入 |

上限均包含。fs 枚举在遇到第 1,025 项时终止，完成校验后才排序并交付。env 更新按提交后的逻辑大小检查，替换先扣除旧项，同名更新不增加条目数。log 在开始向输出端交付时计入配额，写入或刷新失败也计入本次尝试。单条编码最大 4,128 字节。

产品阶段使用 Windows x86_64 MSVC、Linux x86_64 GNU、macOS arm64 的固定工具身份，Rust 1.96.0 release Runtime 和 VM，原生 O0/O3 单列。每个负载用五批独立进程，预热一次，从 50 毫秒起计并校准至 100 毫秒，增长不超过 16 倍、总重复不超过 `2^24`。用实测中位数核对单次负载，VM 不超过 10 秒、原生不超过 2 秒，峰值驻留增量不超过 64 MiB，适用翻倍比不超过 3。

- fs 在每批独立任务目录测 1/2/4/8 MiB 原子写、256/512/1,024 项枚举，并测删除、重命名和元数据。编译与构造目录语料不计入运行时间。
- env 测 256/512/1,024 对的快照构造及固定次数的读、替换和删除，另测满额替换与超限失败。输出和诊断使用合成值。
- log 在独立输出端测每次运行的 256/512/1,024 条记录，消息统一使用 64 字节合成文本。计时包含运行输出端交付与刷新。每个校准重复使用新运行视图，刷新结果以受控宿主观察。最大单条和累计编码字节边界另测。

真实等待、故障注入和正常吞吐分别登记。观察记录保留源码、锁、Runtime、工具、目标、命令、独占目录和原始作业身份。

## 错误与取消

函数入口顺序为 `002` 类型、`026` 权限、`012` 非法参数、输入及工作量预算、运行控制安全点、宿主操作。log 依次检查 `clock` 与 `stdout`，输入合法且预算允许后才读钟。应用入口接纳环境快照失败时，在执行用户代码之前拒绝。

| 场景 | 错误身份 |
| --- | --- |
| 值类型、权限、参数、定宽溢出、受控分配 | 沿用 `X06-RUNTIME-002/026/012/009/011`。非法路径或原生名称编码使用 012，时钟/文件时间/尺寸转换溢出使用 009 |
| fs 超限、禁止覆盖时存在、原子语义不可用、宿主 IO 失败 | `ResourceError`，分别为 `FS_LIMIT_EXCEEDED`、`FS_EXISTS`、`FS_UNSUPPORTED`、`FS_IO_FAILED`。宿主权限失败带结构化原因，清理失败保留附带原因 |
| env 快照非法、快照超限、运行内写入超限 | 执行前分别为 `X09-DRIVER-006/007`，退出码 2。运行内用 `ResourceError/ENV_LIMIT_EXCEEDED` |
| log 超限、运行输出端写入或刷新失败 | `ResourceError/LOG_LIMIT_EXCEEDED`、`ResourceError/LOG_OUTPUT_FAILED`。诊断避免附带完整消息和环境数据 |
| fs、log 自身操作期限到达 | `ResourceError/FS_TIMEOUT`、`ResourceError/LOG_TIMEOUT`。运行取消和运行截止沿 `X09-DRIVER-001/002`，独立并发任务取消沿 `X06-RUNTIME-027` |

fs 与 log 的操作期限从进入各自的首次运行控制安全点计起，为单调时钟 10 秒。运行截止更早时使用该截止。安全点依次检查取消、运行截止、操作期限。检查覆盖 IO 前、分块或枚举批次间、提交与交付前以及返回结果前。运行控制和模块期限保持各自错误身份。需要等待的宿主适配必须提供受控等待或明确报告不支持，产品验收单列不可中断宿主调用的限制。

fs 的原子提交进入后交付实际提交结果，成功提交的目录项保留。提交前的中断清理本次暂存文件；失败结果保留原错误，并附带清理失败。枚举和元数据在交付前被中断时不交付容器。log 若观察到中断或输出失败，已写字节保留，不自动重试。env 在线性化修改前检查运行控制，失败保持旧视图。

## 联合版本候选

| 模块 | 新原语候选 | C 符号候选 |
| --- | --- | --- |
| fs | `os_fs_write_text`、`os_fs_list_dir`、`os_fs_remove`、`os_fs_rename`、`os_fs_metadata` | 对应 `xiao_runtime_fs_*`，复用 `filesystem` |
| env | `os_env_get`、`os_env_set`、`os_env_unset` | 对应 `xiao_runtime_env_*`，使用专用 `environment` |
| log | `os_log_write` | `xiao_runtime_log_write`，声明并检查 `clock` 与 `stdout` |

三模块九个原语与 B3-0B 的六个原语合并，沿用 ABI 1.20、生成器 23、标准库接口 1 的一次联合增量候选。C ABI 沿用借读的 `const XiaoValue*` 与独立初始化的输出槽。成功替换结果，失败保留输出槽。结构错误沿 1/2/3，运行错误沿 6，Fatal 沿 8，取消沿已有控制通道。保持既有符号、值布局和能力位含义。新增模块记录实际联合能力要求，日志归档纳入 `clock` 与 `stdout`。

运行快照属于每次执行的上下文，产物及缓存使用静态身份。旧新产物沿版本约束执行前校验，身份失配的缓存重建。ID、位号、旧默认掩码、精确协议载体、原生注入和 COFF 验证器落点由 B3-0D 定案。Windows 政策为 `complete_required`，当前实际状态为 `pending`。[B3-0B 联合候选](../entry-20261123-b3-0b/contract-draft.md) · [20D 能力边界](../../../20d-capability-context.md)
