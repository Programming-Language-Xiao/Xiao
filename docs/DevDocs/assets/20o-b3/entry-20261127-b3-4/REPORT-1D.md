## 方法与判定

- 每端 42 个组合。release VM 与原生 O0/O3 分别测快照构建、`get`、`set` 同名替换、`unset` 各 256/512/1,024 对，以及两项满额用例。每个组合五个全新子进程和独占任务目录。两个平台先后测量。
- 普通输入每个值 32 个 ASCII 字节。每次读、替换或删除负载调用 64 次，使用固定的 64 个键。满额输入同时为 1,024 对和 1,048,576 逻辑字节。满额替换对同一键交替写入等长值 64 次。超限负载尝试 32 次新增第 1,025 个键，以及 32 次让现有值增加一字节。每次失败须命中 `ResourceError/ENV_LIMIT_EXCEEDED`。随后读回旧值和哨兵，验证新键缺席，再等长替换、释放哨兵的配额并插入新键，复核新值与配额回收。
- VM 快照测 `EnvironmentSnapshot::from_pairs`。原生快照测 `xiao_runtime_env_run_injected` 从调用到进入回调，含显式 JSON 解码和安装上下文。随后经同一读取负载验证快照。操作项计时用 Xiao 的 `std.time.monotonic("ns")`，只取同一次运行内两读数的差。循环及读值、删除、失败用例所需的返回校验计入相应窗口。每个重复重新接纳快照。操作项的快照接纳、编译、进程启动、输入文件读写和最终校验位于各自窗口外。原生示例只在示例 LLVM 产物中接入嵌入入口和输出采集，原生操作仍经产品生成器、Runtime 与 `std.env`。
- 每个子进程先记录同 PID 的当前和峰值驻留，再准备输入并预热一次。校准从重复 1 次开始，单次至少 50 ms 时直接取该轮，其余按实际时长向 100 ms 增长。单轮增长至多 16 倍，重复上限为 `2^24`。保留预热与每轮原始总时长、次数、RSS 和末轮正式样本。归一化以末轮总时间除以实际重复次数，取五批中位数。末轮须至少 50 ms。
- 驻留增量取同 PID 的 OS 高水位减去子进程的当前驻留基线，再取五批最大值。Windows 记录当前和峰值工作集，Ubuntu WSL 记录 `/proc/self/status` 的 `VmRSS` 与 `VmHWM`。基线后产生的 VM 模块准备、快照输入、预热与校验内存也计入保守峰值。
- 阈值为 VM 中位数 ≤10 s，原生各档中位数 ≤2 s，峰值驻留增量 ≤64 MiB，同一平台、同一后端的适用相邻规模中位数比 ≤3。翻倍仅用于快照构建和固定次数读、替换、删除。完整负载的两项满额用例只有 1,024 对。校准、子进程退出、黄金或证据失败均进入判定。
