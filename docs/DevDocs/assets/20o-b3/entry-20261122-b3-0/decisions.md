## B3-0B 方向候选

| 项 | 建议 | 待冻结 |
| --- | --- | --- |
| time | UTC 墙钟用有符号 Unix 毫秒，单调钟用运行请求内的已过毫秒，UTC 格式含固定三位小数和 `Z`。sleep 用整数毫秒，挂接既有取消、超时和清理通道。墙钟、单调钟和 sleep 复用 `clock`，纯格式化只消费输入值 | 精确函数名、位置/命名、UTC 年份域、数值与时长限额、零值语义、主请求与子任务错误、竞态和等待上界 |
| args | 启动端在运行请求入口提交一份程序名和参数数组。统一快照传给源码、字节码、归档和原生。参数按原序保留，Unicode 校验失败按整份拒绝 | CLI/直接原生/API 的来源、缺省值、包容性、序列化边界、字节及条目上限、具体错误码 |
| cli | 纯函数在第一个 `--` 处分为两组，原样保留组内次序、空项和重复项。启动器的 `--` 截断规则单列，保护传给程序的参数 | 精确入口、返回类型、位置参数、无分隔符行为、输出预算和帮助/选项解析的延期范围 |

固定 Rust RunOptions 尚无程序名或 argv 字段。CLI 当前由全局解析消费帮助选项，分隔符后的实际结果由本批原始观察保存。分隔符属于启动边界，标准库辅助只处理调用者给出的数组。[固定协议源码](../../../../../core/rust/crates/xiao-driver/src/protocol/request.rs) · [CLI 参数解析](../../../../../cli/ts/src/commands/parser.ts)

### 首轮问题单

| 编号 | 推荐候选 | 需要定夺的差异 |
| --- | --- | --- |
| B3-0B-TIME | 墙钟和单调钟统一返回 `int` 毫秒。墙钟以 Unix 纪元计数，单调钟从当前运行入口起算，运行内的并发子任务使用同一起点。UTC 固定 `YYYY-MM-DDTHH:mm:ss.SSSZ`。sleep 用整数毫秒并复用既有取消通道 | 毫秒适合调度、CLI 和日志。若选纳秒，须同批确定定宽范围、格式精度、转换和日志口径 |
| B3-0B-ARGS | 运行请求接收独立程序名和有序参数向量，VM/原生第一次进入应用时锁定。启动入口只消费自己的选项，`--` 后按宿主拆分结果逐项透传。程序名独立，空项和重复项原样保留，非法 Unicode 整批拒绝 | 支持嵌入与归档复用同一输入契约。另一候选是先限 CLI 启动，嵌入与归档的显式输入后续单独接通 |
| B3-0B-CLI | 首批只做纯函数的分隔辅助。在首个 `--` 处分组并移除该分隔符，后续各项原样保留。无分隔符时第一组为全部输入，第二组为空。完整选项、默认值、重复规则和帮助生成后置 | 一项小辅助不需要宿主权限。另一候选是先保留启动器透传，把 `std.cli` 首批公开面交回规划裁定 |

首轮答复只决定上表范围。精确签名、程序名来源与缺省、运行中断优先级、错误编号和资源/性能表随后单独确认。

## 后续裁定

- B3-0C 先确定 os/fs 的公开归属与原子写承诺，再确定 env 的可见范围、快照/写入/删除/继承，以及 log 的目标流、时钟授权、记录边界和写入失败。
- B3-0B/C 逐项给出签名、权限优先级、回收、资源和性能表。既有 026、012、025、011、002 等按现有适用语义核对。新增错误身份须有单独裁定。
- B3-0D 以通过裁定的函数和宿主能力为输入，再定 intrinsic/ABI/生成器、C ABI、归档/缓存和 COFF 验收方式。
- B3-0E 以最终签名和错误身份编写六份完整教程候选，确认后固定源码、黄金和执行入口。
- B3-0F 登记实际裁定来源、复核冻结状态并生成 B3-1 入口。
