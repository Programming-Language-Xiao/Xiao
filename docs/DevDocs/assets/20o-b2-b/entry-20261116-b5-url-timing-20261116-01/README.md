# B5 URL 看门狗直接计时结果

本目录已完成八次受控直接计时，B5 受阻状态保持不变。旧归因目录保持只读。稳定版 Rust 1.96.0 拒绝了测试程序的 report-time 选项，因此本轮使用独立源码副本中的最小测试计时补丁。测量针对原资源目标的默认并发执行，不替代完整默认 workspace 门禁。

固定 A 为 cfa79381bbae027cec11136ca380e82f66720c34，固定 B 为 5864cbde627f727483ab676c6f4bc1bf0a7819bb。两份原始资源测试的 Git SHA-256 都为 facb94018bcbf434d7588da58147407bf80c531b20e5dcdfd7b3ee05e97753e9，均包含原来的 17 项测试和同一处 60 秒控制窗口。

instrument.py 只在 URL Unicode 测试调用驱动器前后输出开始与结束标记，不改变输入、输出黄金、断言、测试集合、默认并发或看门狗。计时范围包括请求构造与驱动调用，后者包含前端、降低、VM 等阶段；不把它描述为单独 URL 函数的 F10 时间。两份诊断测试都必须由固定原始 Git 字节重建。

已执行协议为：两个独立任务根分别预编译，构建不进入时间样本；直接运行资源目标的原 17 项默认并发，顺序按 ABBA、ABBA 执行，两份快照各 4 次。每次启动独立进程，隔离临时目录与 Xiao 缓存。两份预编译均先于八次测量结束；没有使用测试串行参数，也没有将本轮诊断写成完整默认 workspace 重新通过。

winmetrics.py 使用 Windows kernel32、psapi 和 PDH 采集原始进程 CPU、工作集、私有提交、系统内存、系统 CPU、处理器队列和系统上下文切换率。进程指标覆盖整个 17 项测试进程；系统指标属于整机，不冒充 URL 线程指标。采样周期和有效性须在正式回执登记，首个 PDH 速率样本可能无效，缺失值不能写成零负载。

正式采集须保存完整原始日志、全部连续采样、编译输出、固定源码与诊断补丁身份、实际测试二进制和环境摘要。失败和异常不得剔除。触发原 60 秒控制窗口的样本属于右删失：记录实际观察时长和超时，不把它当作完整运行耗时，亦不借此推断 ABI 或环境已经归因。预算或看门狗修改仍需星崽明确裁定。

采集器 collect.py 固定半秒采样周期，同时保存实际单调时钟和 Unix 时间。Rust 计时记录独立的单调耗时、起止 Unix 时间和 PID，用于对齐采样；读取标记的轮询时间单独保存。构建使用独立 target、原 dev 配置和四个构建作业，完成两份预编译后才进入八次运行；测量不通过参数改变默认测试线程数。每次运行使用新建的 Xiao 缓存与临时目录。

内容寻址对象超过 8 KiB 时以固定 mtime 的 gzip 保存，同时登记压缩字节和原始字节的摘要与大小。采集工具固定在 b6eca0b0；源码、测试二进制和调试 Runtime 对象保持各自身份，回执逐次追加。timing.json 保存完整汇总，runs/ 保存八份逐次回执，builds/ 和 sources/ 保存预编译及源码身份，objects/ 保存实际日志、诊断测试字节及全部原始连续采样。没有 collection-failure.json。

A 的四个完成样本中位数为 59.4263539 秒；B 的三个完成样本中位数为 59.2912152 秒。B 的第 2 次观察返回 X09-DRIVER-002，60.0253925 秒记录的是控制窗口结束后的观察时长，不是该次任务正常完成所需的时长。完成样本统计排除了这一右删失样本，存在选择偏差，不能据此宣称 B 比 A 更快或两者没有差异。

八次观察均保留完整的 17 项资源测试；没有忽略、过滤或剔除失败。计时标记、PID、源码前后身份、原始日志和连续采样经核心审计核对一致。进一步的反例、最终文档门禁与文件清单以实际封存回执为准。

## 负载记录及解释边界

每次 URL 时间窗口内的整机平均 CPU 使用率约为 45.8%～50.6%，整个资源测试进程平均消耗约 10.47～10.74 个逻辑核心等效。这里不是 URL 单线程 CPU 归因。处理器队列通常处于 0～2，A 的第 4 次窗口中观测到一次最高 21；系统上下文切换率和原始 API 状态均保留在连续序列中。

URL 窗口内可用物理内存的整体观察范围为 4,239,106,048～5,807,271,936 字节，约 3.95～5.41 GiB；各次整个资源测试进程的工作集观察峰值约为 124.0～158.0 MiB。它包含同时执行的其它资源用例，不能当作 URL 单次函数的 F10 内存成绩。目标采样周期为 0.5 秒，实际最大相邻采样间隔约为 0.549 秒；首个 PDH 速率读数无效时保留缺失及状态，没有补成零。

本轮数据支持“该用例在两份快照中都贴近 60 秒窗口”的判断。它仍不能证明 ABI 导致回退，也不能把某一负载指标认定为超时原因。诊断标记及隔离缓存本身改变了观测条件，实际系统调度和后台负载仍未完全受控，因此不把这些资源目标样本扩大为完整 workspace 的验收。

causal_attribution_proven=false、b5_closed=false、b6_started=false 保持不变。下一步可依据本轮记录独立优化用例或其热点，也可提交明确的看门狗/预算裁定；本轮没有修改任何冻结预算或看门狗。
