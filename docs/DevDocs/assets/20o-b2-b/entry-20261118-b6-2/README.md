## 负载和测量

每个平台和后端执行同样的 183 项，其中数值 82 项、cmath 75 项、兼容回归 26 项。数值组复用已冻结的 A6 负载并新增显式精度除法五项。cmath 从正式 F-9 向量选取语言可构造的参考输入，涵盖两个官方导入别名和浮点幂运算符。兼容组测 B1 的 20 个产品入口及 A1 三条完整教程示例。A1 示例在计时窗口内构造与教程输出同格式的字符串，窗口外核对黄金。兼容组记录本次快照的绝对成本，跨版本增量缺少同协议基线。

每项在五个独立进程中运行。每个进程先读取初始化后驻留基线、构造输入、预热并核对黄金，再执行 F-3 校准与采样。原生以同一降低入口分别编译 O0、O3，测量程序以 C 计时桩截取标记。VM 使用真实标准库加载器。编译、链接与黄金比较位于计时窗口外。

URL 全转义最大负载为 `%F0%9F%9A%80` 重复 16,384 次，输入 196,608 字节，独立黄金 65,536 字节。4,096、8,192、16,384 三档按 F10 的输入字节数取样，适用翻倍比上限 3。

## 实测结果

Windows、Linux 和 macOS 的 VM、O0、O3 各通过 183 项，共 1,647 项和 8,235 个独立测量进程。黄金输出、耗时、驻留增量及适用的翻倍比均达标。汇总记录为 `matrix_complete=true`、`perf_pass=true`。[机器可读回执](summary.json)

| 平台 | URL 最大档 VM（秒） | O0（秒） | O3（秒） | 最大驻留增量（MiB） | 最大翻倍比 |
| --- | ---: | ---: | ---: | ---: | ---: |
| Windows | 8.367207 | 0.968194 | 0.955429 | 7.7930 | 2.0418 |
| Linux | 2.731410 | 0.650984 | 0.622507 | 3.5117 | 2.0518 |
| macOS | 1.571550 | 0.419651 | 0.379194 | 3.6562 | 2.9598 |

表中耗时是 URL 最大档的五批归一化中位数，驻留增量取该档三个后端的保守最大值，翻倍比取三种后端在 4,096→8,192 和 8,192→16,384 两对规模中的最大值。

每个平台、后端均在相同的三个 F-9 输入上比较 `std.cmath.pow`、`stdlib.cmath.pow` 与浮点 `**`。输入覆盖有限非零结果、零结果与 009 域错误，九组均通过。逐路中位数和驻留增量见回执的 `pow` 字段。[机器可读回执](summary.json)

Windows COFF 导出完整性仍未验证，Linux Clippy 未执行。B6-3 边界负载、B6-4 工程门禁和 B6-5 收口待各批验收。

## 复跑与审计

本地和 macOS 作业共用 `tools/gates/b2_b6_performance.py`。在仓库根指定新任务目录和本机 LLVM 工具目录。

```text
python -B -X utf8 tools/gates/b2_b6_performance.py run --task <新目录> --llvm-bin <LLVM目录>
python -B -X utf8 docs/DevDocs/assets/20o-b2-b/entry-20261118-b6-2/audit.py
```

Windows 在宿主机、Linux 在同一机器的 WSL Ubuntu 26.04 执行，任务独立，部分时段重叠。macOS 采用独立 `macos-15` ARM64 Runner，VM、O0、O3 分别为作业 `134616425164`、`134616425573`、`134616425472`。三个作业均为 [运行 44249501458](https://github.com/Programming-Language-Xiao/Xiao/actions/runs/44249501458) 的 attempt 1，Runner 提交为 `6eddee2d1b2677fac5d2665a15cb56166a638fd0`。
