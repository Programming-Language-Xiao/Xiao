# 01. 词法与语法

> 本阶段把已确认的表面规则变成可解析的语法。输出应是稳定的语法树，而不是直接执行源码。

## 一级工程目标：建立词法规则

### 字符集与换行

- 源文件统一按 UTF-8 读取。
- 换行、缩进和文件结束都必须进入词法器的结构化结果。
- 编译器不能把不同平台的换行形式解释成不同语义。

### 标识符

普通标识符遵循 ASCII 规则。反引号标识符允许任意 UTF-8 字符：

```xiao
`用户名称` = "星崽"
print(`用户名称`)
```

反引号只改变名称字符范围，不改变变量的静态类型规则。关键字不能通过普通写法改义；反引号关键字是否允许作为变量名，需要名称解析阶段明确。

### 注释

- `#` 到行尾是单行注释。
- `###` 开始的文档注释可跨多行，并预留类似 Javadoc 的 `@param`、`@return` 标签。
- 注释不产生运行时值，但文档注释应保留到 AST 或文档生成器可读取的位置。

## 一级工程目标：定义缩进和顶层结构

### 缩进块

- `def`、`if`、`elif`、`else`、`for`、`while` 等代码块必须使用缩进。
- 不允许用 `{}` 替代代码块，也不允许同一代码块混用花括号和缩进。
- `{}` 保留给字典表，`<>` 保留给字典列。
- 缩进宽度、Tab 是否允许以及混合缩进的诊断策略仍待定，但同一文件必须可被唯一解析。

### 表头和字段

表头、表字段和键值对顶格书写；缩进只表示代码块层级。例如：

```xiao
[App]
name = "Xiao"
version = 1

def start()
    print(name)
```

`[Table]`、`[[Table]]` 的语义在第 05 阶段确定，本阶段只负责识别其结构并阻止缩进歧义。

## 一级工程目标：形成表达式语法草案

### 基础表达式

第一版至少需要支持：

- 整数、浮点、字符串、布尔值和空值字面量（空值名称待定）。
- 变量引用、数组/元组/字典表/字典列字面量。
- 算术、比较、逻辑、成员访问和索引表达式。
- `as` 显式类型转换。
- 函数调用和 `new` 构造调用。

### 语句

第一版语句集合为：

- 绑定与赋值：`a = value`。
- 复合赋值：`+=`、`-=`、`*=`、`/=`、`//=`、`%=`、`**=`。
- `if`、`elif`、`else`、`for ... in ...`、`while`。
- `def` 函数定义。
- `return`、`break`、`continue`。
- `const` 编译期常量声明。

不支持 `i++` 和 `i--`，避免自增表达式在语句和表达式位置产生歧义。

## 二级实现任务

### 词法器

1. 生成带行列号的 Token。
2. 生成 `INDENT`、`DEDENT` 和换行 Token。
3. 识别反引号标识符，并验证 UTF-8。
4. 为错误 Token 提供源码片段和修复提示。

### 语法分析器

1. 先实现表达式、赋值和控制流。
2. 再实现表头、表字段和函数定义。
3. 让所有 AST 节点携带源位置。
4. 为歧义语法建立拒绝规则，而不是依赖解析器回溯猜测。

## 验收标准

### 语法验收

- 同一份 UTF-8 源码在 Windows、Linux、macOS 上生成相同 AST。
- 缩进错误、混用块符号、未闭合反引号都有明确行列号。
- 字典表花括号不会被当作代码块。

### 文档验收

- 每个新增语法都能在本阶段给出最小正例和最小负例。
- 语法尚未定稿的写法必须标记为“待定”，不能被测试用例默认为正式语法。
