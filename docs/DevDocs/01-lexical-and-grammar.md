# 01. 词法 Token 与语法入口

> 本阶段很大，必须分门槛推进。第一个门槛只输出稳定的最小 Token 流；完整词法器通过验收后，才允许开始语法树解析。

## 一级工程目标：先完成 Token 最小闭环

### 最小交付范围

最早可验收实现只识别以下 Token：

- ASCII 普通标识符。
- 十进制整数字面量。
- 赋值符号 `=`。
- 换行与文件结束。
- 无法识别字符对应的错误 Token 或词法诊断。

例如源码 `a = 1` 应稳定输出“标识符、赋值、整数、换行、文件结束”，并为每个 Token 携带字节区间和行列号。这个里程碑不生成 AST，不执行代码，也不检查变量类型。

### 后续词法增量

最小闭环通过后，再分别加入字符串、浮点数、布尔值、关键字、反引号标识符、运算符、注释、括号、缩进和表头。每一项都应作为可独立回归的小改动，不要求一次完成整个词法器。

### 解析器准入条件

只有 Token 类型、源码位置、错误模型、换行和缩进输出稳定后，才开始 AST 解析。解析器不能与 Token 最小闭环绑成同一次交付。

## 一级工程目标：建立词法规则

### 字符集与换行

- 源文件统一按 UTF-8 读取。
- 换行、缩进和文件结束都必须进入词法器的结构化结果。
- 编译器不能把不同平台的换行形式解释成不同语义。

### 标识符

普通标识符遵循 ASCII 规则。反引号标识符允许任意 UTF-8 字符：

```xiao
`用户名称` = "星崽"
print(`用户名称`)
```

反引号只改变名称字符范围，不改变变量的静态类型规则。关键字不能通过普通写法改义；反引号关键字是否允许作为变量名，需要名称解析阶段明确。

### 注释

- `#` 到行尾是单行注释。
- `###` 开始的文档注释可跨多行，并预留类似 Javadoc 的 `@param`、`@return` 标签。
- 注释不产生运行时值，但文档注释应保留到 AST 或文档生成器可读取的位置。

## 一级工程目标：定义缩进和顶层结构

### 缩进块

- `def`、`if`、`elif`、`else`、`for`、`while` 等代码块必须使用缩进。
- 不允许用 `{}` 替代代码块，也不允许同一代码块混用花括号和缩进。
- 花括号同时承载集合和字典表字面量：`{值, 值}` 是集合，`{键 = 值}` 是字典表，空的 `{}` 固定表示空字典表。
- 空集合写作 `set()`；`<>` 保留给字典列。
- 缩进宽度、Tab 是否允许以及混合缩进的诊断策略仍待定，但同一文件必须可被唯一解析。

### 表头和字段

表头、表字段和键值对顶格书写；缩进只表示代码块层级。例如：

```xiao
[App]
name = "Xiao"
version = 1

def start()
    print(name)
```

`[Table]`、`[[Table]]` 的语义在第 05 阶段确定，本阶段只负责识别其结构并阻止缩进歧义。

## 一级工程目标：形成表达式语法草案

### 基础表达式

完整表达式解析阶段计划支持：

- 整数、浮点、字符串、布尔值和空值字面量（空值名称待定）。
- 变量引用、数组/元组/集合/字典表/字典列字面量。
- 算术、比较、逻辑、成员访问和索引表达式。
- `as` 显式类型转换。
- 函数调用和 `new` 构造调用。

### 语句

完整语句解析阶段计划支持：

- 绑定与赋值：`a = value`。
- 复合赋值：`+=`、`-=`、`*=`、`/=`、`//=`、`%=`、`**=`。
- `if`、`elif`、`else`、`for ... in ...`、`while`。
- `def` 函数定义。
- `return`、`break`、`continue`。
- `const` 编译期常量声明。

不支持 `i++` 和 `i--`，避免自增表达式在语句和表达式位置产生歧义。

## 二级实现任务

### L0：源码游标与位置

1. 按 UTF-8 字节读取源码，但不把一个多字节字符拆成多个字符。
2. 维护字节偏移、行号和列号。
3. 统一处理 `LF` 与 `CRLF`。
4. 定义不可变的源码区间结构，后续 Token、AST 和诊断共同复用。

### L1：最小 Token 流

1. 定义最小 Token 枚举和携带源码区间的 Token 结构。
2. 识别 ASCII 标识符、整数、`=`、换行和文件结束。
3. 对非法字符生成稳定诊断，并确保游标能够继续前进。
4. 建立 Token 快照测试，不引入 AST 或执行器。

### L2：完整基础词法

1. 分批加入字符串、浮点、布尔值、关键字和全部已确认运算符。
2. 识别反引号标识符并验证 UTF-8。
3. 区分括号、集合/字典表花括号、字典列尖括号和数组路径分隔符。
4. `+` 只生成统一的加号 Token；它表示数值加法还是集合并集由类型检查阶段决定。

### L3：换行、注释与缩进

1. 生成 `INDENT`、`DEDENT` 和换行 Token。
2. 处理空行、单行注释和文档注释对缩进的影响。
3. 拒绝无法唯一解释的混合缩进。
4. 为未闭合字符串、反引号名称和括号提供源码片段。

### P0：语法分析器入口

1. 在完整词法验收后，只解析字面量、名称和简单赋值。
2. 再逐步加入表达式优先级、代码块、表头和函数。
3. 让所有 AST 节点携带复用的源码区间。
4. 为歧义语法建立拒绝规则，不依赖解析器回溯猜测。

## 验收标准

### Token 最小验收

- `a = 1` 能输出顺序、种类、文本区间都稳定的最小 Token 流。
- 空文件只产生文件结束 Token，尾部有无换行的行为均有测试。
- 非法字符不会导致死循环或崩溃，并带有准确位置。
- 该门槛不以生成 AST、运行代码或支持集合为验收条件。

### 完整词法验收

- 同一份 UTF-8 源码在 Windows、Linux、macOS 上生成相同 Token 序列和等价源码区间。
- 缩进错误、未闭合字符串、未闭合反引号都有明确行列号。
- 注释和空行不会制造错误的 `INDENT`/`DEDENT`。

### 语法入口验收

- 最小表达式和赋值能从已经冻结的 Token 流生成稳定 AST。
- 集合和字典表的花括号不会被当作代码块，解析器能依据条目形式区分二者。
- `{}` 始终产生空字典表，`set()` 始终产生空集合。

### 文档验收

- 每个新增语法都能在本阶段给出最小正例和最小负例。
- 语法尚未定稿的写法必须标记为“待定”，不能被测试用例默认为正式语法。
