## 一级工程目标：先完成 Token 最小闭环

### 最小交付范围

最早可验收实现只识别以下 Token：

- ASCII 普通标识符。
- 十进制整数字面量。
- 赋值符号 `=`。
- 换行与文件结束。
- 无法识别字符对应的错误 Token 或词法诊断。

例如源码 `a = 1` 应稳定输出“标识符、赋值、整数、换行、文件结束”，并为每个 Token 携带字节区间和行列号。这个里程碑不生成 AST，不执行代码，也不检查变量类型。

### 后续词法增量

最小闭环通过后，再分别加入字符串、浮点数、布尔值、关键字、反引号标识符、运算符、注释、括号、缩进和表头。每一项都应作为可独立回归的小改动，不要求一次完成整个词法器。

### 解析器准入条件

只有 Token 类型、源码位置、错误模型、换行和缩进输出稳定后，才开始 AST 解析。解析器不能与 Token 最小闭环绑成同一次交付。

## 一级工程目标：建立词法规则

### 字符集与换行

- 源文件统一按 UTF-8 读取；非法 UTF-8 在进入词法器前以稳定诊断拒绝。
- 换行、缩进和文件结束都必须进入词法器的结构化结果。
- 编译器不能把不同平台的换行形式解释成不同语义。
- F0/L0 保留原始字节偏移；列号按 Unicode 标量值计数，行列均从 1 开始。

### 标识符

普通标识符遵循 `[A-Za-z_][A-Za-z0-9_]*` ASCII 规则。反引号标识符允许任意 UTF-8 字符：

```xiao
`用户名称` = "星崽"
print(`用户名称`)
```

反引号只改变名称字符范围，不改变变量的静态类型规则。普通关键字不能被改义；反引号包裹
关键字时按名称处理，例如 `` `def` `` 可以作为变量名。反引号形式必须在定义和引用处保持一致。
L2 允许反斜杠转义反引号和反斜杠；其他转义或跨行名称报告稳定词法错误。

### 注释

- `#` 到行尾是单行注释，不产生 Token，但保留物理换行。
- `###` 开始、下一个 `###` 结束的文档注释可跨多行；同一行的 `### 文档 ###` 也有效，整体产生一个 `DocComment` Token。
- 注释不产生运行时值，但文档注释应保留到 AST 或文档生成器可读取的位置。

## 一级工程目标：定义缩进和顶层结构

### 缩进块

- `def`、`if`、`elif`、`else`、`for`、`while` 等代码块必须使用缩进。
- 不允许用 `{}` 替代代码块，也不允许同一代码块混用花括号和缩进。
- 花括号同时承载集合和字典表字面量：`{值, 值}` 是集合，`{键 = 值}` 是字典表，空的 `{}` 固定表示空字典表。
- 空集合写作 `set()`；`<>` 保留给字典列。
- 每个 Tab 在编译和解释时统一展开为四个空格；空格与 Tab 混用按展开后的逻辑宽度判断。
- 语句只由换行结束，首版不支持显式分号；L2 产生 `INDENT`/`DEDENT`。
- 空行与普通注释行不改变缩进栈；括号、方括号和花括号内部保留物理换行但不改变缩进栈。

### 表头和字段

表头、表字段和键值对顶格书写；缩进只表示代码块层级。例如：

```xiao
[App]
name = "Xiao"
version = 1

def start()
    print(name)
```

`[Table]`、`[[Table]]` 的语义在第 05 阶段确定，本阶段只负责识别其结构并阻止缩进歧义。

## 一级工程目标：形成表达式语法草案

### 基础表达式

完整表达式解析阶段计划支持：

- 整数、浮点、字符串、布尔值和 `none` 空值字面量。
- 变量引用、数组/元组/集合/字典表/字典列字面量。
- 算术、比较、逻辑、成员访问和索引表达式。
- `as` 显式类型转换。
- 函数调用和 `new` 构造调用。

### 精确索引与高级选择器

所有数字索引从 `0` 开始。斜杠 `/` 在方括号内连接嵌套路径段，例如 `value[2/1]` 表示先进入索引 `2` 的元素，再读取其中索引 `1` 的元素。单项精确索引直接返回命中的元素。

高级选择器的全部选择项必须写在同一对方括号中：

```xiao
value[0, 1]          # 多项精确选择
value[0~2, 5~6]      # 一个或多个闭区间，~ 两端都包含
value[<2]            # 选择路径 2 之前的元素，不包含边界
value[<=2]           # 选择路径 2 以前的元素，包含边界
value[>0]            # 选择路径 0 之后的元素，不包含边界
value[>=0]           # 选择路径 0 以后的元素，包含边界
value[=]             # 选择全部元素
value{step}[=]       # 以整数 step 对范围选择结果取步长
value[?count]        # 无放回随机选择
value[!?count]       # 放回随机选择
```

`value[0],[1]` 不是多项选择语法。多项和多范围之间的逗号只能出现在同一对方括号内。范围端点可以是嵌套路径，例如 `value[1~2/1]`；路径、结果形状和支持这些操作的容器类别由第 03 阶段定义。

步长修饰符 `{step}` 位于来源表达式与范围选择器之间，可用于 `~`、边界选择、`[=]` 以及包含范围项的多范围选择。`step` 必须是整数字面量或整形变量；`0` 报错，负数表示按相反方向遍历。随机数量同样只能使用整数字面量或整形变量：`0` 返回同来源容器类型的空结果，负数报错。

词法器采用最长匹配识别 `!?`，使它成为“放回随机”标记；`?`、`!?` 和 `~` 都必须保留独立且稳定的 Token。`<`、`<=`、`>`、`>=` 和 `=` 继续复用比较或赋值所用 Token，由解析器依据方括号选择器上下文确定语法角色。

### 语句

完整语句解析阶段计划支持：

- 绑定与赋值：`a = value`。
- 复合赋值：`+=`、`-=`、`*=`、`/=`、`//=`、`%=`、`**=`。
- `if`、`elif`、`else`、`for ... in ...`、`while`。
- `def` 函数定义。
- `import module`、`import module as alias` 和 `from module import symbol`。
- `return`、`break`、`continue`。
- `const` 编译期常量声明。

不支持 `i++` 和 `i--`，避免自增表达式在语句和表达式位置产生歧义。

## 二级实现任务

### F0：源码游标与位置

1. 按 UTF-8 字节读取源码，但不把一个多字节字符拆成多个字符。
2. 维护字节偏移、行号和列号。
3. 统一处理 `LF` 与 `CRLF`。
4. 定义不可变的源码区间结构，后续 Token、AST 和诊断共同复用。

### L0：最小 Token 流

1. 定义最小 Token 枚举和携带源码区间的 Token 结构。
2. 识别 ASCII 标识符、整数、`=`、换行和文件结束。
3. 对非法字符生成稳定诊断，并确保游标能够继续前进。
4. 建立 Token 快照测试，不引入 AST 或执行器。

### L1：完整基础词法

当前状态：已完成首批实现；交接细节见 [01B. L1 基础词法扩展交接记录](01b-l1-implementation.md)。

1. 分批加入字符串、浮点、布尔值、`import`/`from`/`as` 等关键字和全部已确认运算符。
2. 识别反引号标识符并验证 UTF-8。
3. 区分括号、集合/字典表花括号、字典列尖括号和数组路径分隔符。
4. `+` 只生成统一的加号 Token；它表示数值加法还是集合并集由类型检查阶段决定。
5. 加入 `~`、`?` 和最长匹配的 `!?` Token，并保证选择器中的 `<`、`<=`、`>`、`>=`、`=` 不被词法器改写为专用含义。

### L2：换行、注释与缩进

当前状态：已完成首批实现；交接细节见 [01C. L2 实现交接记录](01c-l2-implementation.md)。

1. 生成 `INDENT`、`DEDENT` 和换行 Token。
2. 处理空行、单行注释和文档注释对缩进的影响。
3. Tab 先展开为四个空格；缩进宽度固定为四空格倍数，错误归入最近已知层级。
4. 为未闭合字符串、反引号名称、文档注释和括号提供源码片段。

### P0：语法分析器入口

1. 在完整词法验收后，只解析字面量、名称和简单赋值。
2. 再逐步加入表达式优先级、代码块、表头、函数和模块导入语句。
3. 让所有 AST 节点携带复用的源码区间。
4. 为歧义语法建立拒绝规则，不依赖解析器回溯猜测。

### P1：索引与选择器解析

1. 分开建立单项精确索引、多项选择、闭区间、单边范围、全选、步长和随机选择 AST 节点。
2. 把 `/` 分隔的数字或键路径保留为有序路径段，不在解析阶段把它当作除法。
3. 让一个多选节点携带多个精确路径，或让一个多范围节点携带多个闭区间，并把所有项限制在同一对 `[]` 内；精确项与范围项是否允许混写仍待定。
4. 将 `?count` 与 `!?count` 分别记录为无放回和放回模式；数量及步长的字面量或变量节点保留源码区间。
5. 在语法层拒绝缺失端点、空选择项、方括号外续写选择项，以及把步长修饰符用于不支持步长的选择器。

## 验收标准

### Token 最小验收

- `a = 1` 能输出顺序、种类、文本区间都稳定的最小 Token 流。
- 空文件只产生文件结束 Token，尾部有无换行的行为均有测试。
- 非法字符不会导致死循环或崩溃，并带有准确位置。
- 该门槛不以生成 AST、运行代码或支持集合为验收条件。

### 完整词法验收

- 同一份 UTF-8 源码在 Windows、Linux、macOS 上生成相同 Token 序列和等价源码区间。
- 缩进错误、未闭合字符串、未闭合反引号都有明确行列号。
- 注释和空行不会制造错误的 `INDENT`/`DEDENT`。

### 语法入口验收

- 最小表达式和赋值能从已经冻结的 Token 流生成稳定 AST。
- 集合和字典表的花括号不会被当作代码块，解析器能依据条目形式区分二者。
- `{}` 始终产生空字典表，`set()` 始终产生空集合。
- `a[0, 1]` 只生成一个多选节点，`a[0~2, 5~6]` 生成包含两个双端闭区间的选择节点。
- `a[<2]`、`a[<=2]`、`a[>0]`、`a[>=0]`、`a[=]`、`a{x}[=]`、`a[?x]` 和 `a[!?x]` 均能生成互不混淆的 AST。
- `a[1~2/1]` 的两个端点保持为路径 AST；解析器不会把 `/` 当作除法，也不会丢失 `~` 的双端包含语义。
- `a[0],[1]` 不会被接受为一条多项选择表达式；`!?` 按最长匹配产生一个稳定 Token。

### 文档验收

- 每个新增语法都能在本阶段给出最小正例和最小负例。
- 语法尚未定稿的写法必须标记为“待定”，不能被测试用例默认为正式语法。
