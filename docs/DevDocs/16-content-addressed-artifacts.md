# 16. SHA-256 内容寻址与二进制索引

> 本阶段为 `.xiaoc` 及后续归档建立不可变产物存储。它复用环境与包管理阶段的内容寻址思想，但构建产物、源码包和依赖锁文件必须保持不同的命名空间与生命周期。

## 一级工程目标：建立内容寻址对象库

### 哈希命名

用户要求字节码文件按内容 `SHA-256` 摘要重命名；本阶段将原文中的“SAH256”暂按 `SHA-256` 记录，算法拼写和是否为最终规范仍需确认。摘要来自规范化的字节码内容，而不是源文件路径、缓存位置或下载地址；“规范化内容”的确切边界（完整 `.xiaoc` 文件、头部加载荷或仅字节码载荷）尚待冻结。

对象文件名应由摘要稳定生成，不能使用时间戳、随机数或递增序号代替。完整哈希还是截断哈希、十六进制大小写、是否带算法前缀和扩展名规则均需在格式阶段确定。理论哈希碰撞不能静默覆盖：写入时必须比较完整内容并报告冲突。

### 对象隔离

至少区分以下对象类型：

- 源码/依赖内容缓存。
- 优化后的 `.xiaoc` 字节码对象。
- 可选的原生构建片段或最终二进制。
- `.xar` 归档及其资源。

不同对象类型不能只凭同一个文件名空间相互解释。对象写入后视为不可变；项目环境、构建缓存和归档索引保存引用关系，而不是原地修改对象。缓存根目录、权限、跨平台位置和淘汰策略沿用第 11A 阶段的待定决策，不能在本阶段偷偷依赖某个操作系统路径。

## 一级工程目标：集中维护二进制索引

### 索引职责

二进制索引集中记录摘要到对象元数据的映射，至少应能回答：对象类型、逻辑模块/路径、语言/IR/虚拟机或 Runtime 版本、目标平台/架构、优化配置、模块图与依赖锁摘要、入口信息、大小、校验状态和创建工具版本。索引不是依赖锁文件的替代品；锁文件仍记录依赖求解结果，索引只记录可寻址产物。

用户提出使用 CBOR、MessagePack 或 Protobuf 一类的二进制格式。最终选型、是否需要自描述 Schema、随机读取/流式写入能力和向前兼容策略尚待确认。无论选哪一种，索引版本和记录类型都必须显式编码，未知字段应按版本策略跳过或拒绝。

### 原子一致性

写入顺序建议固定为“规范化产物 -> 临时对象 -> 完整哈希校验 -> 原子改名为摘要名 -> 原子更新索引”。索引更新中断时，旧索引仍可读取；孤立对象可以通过扫描回收。读取索引不能只相信文件名，必须重新计算摘要并检查对象类型、长度、版本和格式校验。

并发构建需要进程间锁或等价的无竞争提交协议。两个进程写入相同摘要时应共享已验证对象，写入不同摘要时不能互相覆盖。索引损坏、对象缺失、摘要不匹配、权限不足和磁盘空间不足都要有独立诊断及可恢复路径。

## 二级实现任务

### 摘要与对象存储

1. 冻结规范化字节边界、摘要算法表示和对象目录布局。
2. 实现流式 SHA-256、完整内容比较、碰撞保护和摘要校验工具。
3. 实现只读对象写入、临时文件、原子改名、权限设置和并发锁。
4. 将 `.xiaoc`、源码包和可选原生产物分配到独立对象类型。

### 索引编解码

1. 从 CBOR、MessagePack、Protobuf 候选中选定首版编码，并冻结 Schema/版本。
2. 实现摘要查找、按元数据筛选、记录追加/替换和原子提交。
3. 提供无索引扫描重建能力，重建前重新验证每个对象。
4. 验证未知版本、未知字段、截断索引和对象缺失的错误边界。

### 缓存维护

1. 记录项目、锁文件和 `.xar` 对对象的引用，避免清理仍在使用的对象。
2. 实现显式清理、可选 LRU/引用追踪和损坏对象隔离；最终淘汰算法待确认。
3. 支持离线读取和跨项目复用，但不能绕过摘要与格式验证。
4. 测试多进程同时构建、终止恢复、只读权限和跨平台路径。

## 验收标准

- 同一规范内容在不同机器和进程中得到相同摘要和对象名。
- 对象写入或索引提交中断不会留下可被误认为有效的半成品。
- 读取前始终验证摘要、长度、格式和版本；损坏对象不会进入运行或打包。
- 索引可在损坏或丢失时由已验证对象重建，且不修改依赖锁文件语义。
- 相同 `.xiaoc` 内容可被多个项目复用，不同优化配置/目标/ABI 不会错误命中同一对象。

## 待定决策

1. `SHA-256` 拼写确认、摘要输入边界、完整/截断形式、大小写和扩展名布局。
2. 索引选 CBOR、MessagePack 还是 Protobuf，以及 Schema、版本和兼容策略。
3. 缓存根目录、权限、并发锁、远程缓存信任和淘汰/回收规则。
4. 是否对原生二进制、资源和 `.xar` 本身也采用内容寻址命名。
5. 哈希完整性之外是否需要数字签名、发布者身份和信任链。
