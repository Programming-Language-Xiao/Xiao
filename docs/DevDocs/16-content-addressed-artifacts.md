# 16. SHA-256 内容寻址与二进制索引

> 本阶段为 `.xiaoc` 及后续归档建立不可变产物存储。它复用环境与包管理阶段的内容寻址思想，但构建产物、源码包和依赖锁文件必须保持不同的命名空间与生命周期。

## Agent 交接上下文

### 接手前提

- 先阅读 [14. 字节码优化与 `.xiaoc` 产物](14-bytecode-optimization.md)、[11A. 虚拟环境与包管理](11a-environments-and-packages.md) 和 [12. 测试与开发里程碑](12-tests-and-milestones.md) 的 O3 条目。
- `.xiaoc` 已确定为单模块、不可变的优化字节码对象；项目和归档通过索引引用多个对象。
- 摘要算法已确定为 SHA-256；二进制索引首版已选 Protobuf。摘要输入边界、目录布局和索引作用域仍由本阶段细化。

### 本阶段交付与不负责事项

- 交付：对象类型命名空间、SHA-256 流式校验、不可变写入、Protobuf Schema/编解码、索引事务和扫描重建工具。
- 不负责：字节码指令优化、LLVM Pass、归档入口和 CLI 命令；分别依赖第 14、15、17、18 阶段的稳定接口。
- 索引不能替代依赖锁文件，也不能把未经验证的路径或文件名当作信任依据。

### 交接检查

接手代理必须能在无网络、不同进程和三种目标平台上，用同一规范 `.xiaoc` 产生相同摘要，完成对象写入/读取/损坏隔离，并用 Xiao 内置 Protobuf Schema 查找记录。所有临时文件和锁必须在测试结束后可清理。

## 一级工程目标：建立内容寻址对象库

### 哈希命名

用户要求字节码文件按内容 `SHA-256` 摘要重命名，算法名称已经确认。摘要来自规范化的字节码内容，而不是源文件路径、缓存位置或下载地址；“规范化内容”的确切边界（完整 `.xiaoc` 文件、头部加载荷或仅字节码载荷）尚待冻结。

对象文件名应由摘要稳定生成，不能使用时间戳、随机数或递增序号代替。完整哈希还是截断哈希、十六进制大小写、是否带算法前缀和扩展名规则均需在格式阶段确定。理论哈希碰撞不能静默覆盖：写入时必须比较完整内容并报告冲突。

### 对象隔离

至少区分以下对象类型：

- 源码/依赖内容缓存。
- 优化后的 `.xiaoc` 字节码对象。
- 可选的原生构建片段或最终二进制。
- `.xar` 归档及其资源。

不同对象类型不能只凭同一个文件名空间相互解释。对象写入后视为不可变；项目环境、构建缓存和归档索引保存引用关系，而不是原地修改对象。缓存根目录、权限、跨平台位置和淘汰策略沿用第 11A 阶段的待定决策，不能在本阶段偷偷依赖某个操作系统路径。

## 一级工程目标：集中维护二进制索引

### 索引职责

二进制索引集中记录摘要到对象元数据的映射，至少应能回答：对象类型、逻辑模块/路径、语言/IR/虚拟机或 Runtime 版本、目标平台/架构、优化配置、模块图与依赖锁摘要、入口信息、大小、校验状态和创建工具版本。索引不是依赖锁文件的替代品；锁文件仍记录依赖求解结果，索引只记录可寻址产物。

索引首版采用 Protobuf（Protocol Buffers）。Protobuf Schema 和解码器由 Xiao 工具链提供，因此索引本身不要求完全自解释；索引仍必须携带 Schema 标识、版本和记录类型，供 `xiao inspect` 等工具选择正确解码器。是否随发布包附带 descriptor、随机读取/流式写入能力和向前兼容策略尚待确认。采用确定性序列化，避免字段顺序或未排序映射造成无意义差异。

选择 Protobuf 的理由是：索引字段由 Xiao 工具链控制、读取频率高且需要紧凑编码和稳定的字段编号；不自解释的缺点由随 `xiao` 提供的 Schema/解码器弥补。外部工具若没有 Xiao，不得自行猜测字段含义，应使用显式 descriptor 或 `xiao inspect` 导出的文本/机器可读视图。

### 原子一致性

写入顺序建议固定为“规范化产物 -> 临时对象 -> 完整哈希校验 -> 原子改名为摘要名 -> 原子更新索引”。索引更新中断时，旧索引仍可读取；孤立对象可以通过扫描回收。读取索引不能只相信文件名，必须重新计算摘要并检查对象类型、长度、版本和格式校验。

并发构建需要进程间锁或等价的无竞争提交协议。两个进程写入相同摘要时应共享已验证对象，写入不同摘要时不能互相覆盖。索引损坏、对象缺失、摘要不匹配、权限不足和磁盘空间不足都要有独立诊断及可恢复路径。

## 二级实现任务

### 摘要与对象存储

1. [16.1] 冻结规范化字节边界、SHA-256 表示和对象目录布局。
2. [16.2] 实现流式 SHA-256、完整内容比较、碰撞保护和摘要校验工具。
3. [16.3] 实现只读对象写入、临时文件、原子改名、权限设置和并发锁。
4. [16.4] 将 `.xiaoc`、源码包和可选原生产物分配到独立对象类型。

### 索引编解码

1. [16.5] 冻结 Protobuf Schema、字段编号、索引版本和确定性序列化规则。
2. [16.6] 实现摘要查找、按元数据筛选、记录追加/替换和原子提交。
3. [16.7] 提供无索引扫描重建能力，重建前重新验证每个对象。
4. [16.8] 验证未知版本、未知字段、截断索引和对象缺失的错误边界。

### 缓存维护

1. [16.9] 记录项目、锁文件和 `.xar` 对对象的引用，避免清理仍在使用的对象。
2. [16.10] 实现显式清理、可选 LRU/引用追踪和损坏对象隔离；最终淘汰算法待确认。
3. [16.11] 支持离线读取和跨项目复用，但不能绕过摘要与格式验证。
4. [16.12] 测试多进程同时构建、终止恢复、只读权限和跨平台路径。

## 验收标准

- 同一规范内容在不同机器和进程中得到相同摘要和对象名。
- 对象写入或索引提交中断不会留下可被误认为有效的半成品。
- 读取前始终验证摘要、长度、格式和版本；损坏对象不会进入运行或打包。
- 索引可在损坏或丢失时由已验证对象重建，且不修改依赖锁文件语义。
- 相同 `.xiaoc` 内容可被多个项目复用，不同优化配置/目标/ABI 不会错误命中同一对象。

## 待定决策

1. 摘要输入边界、完整/截断形式、大小写、扩展名和对象目录布局。
2. Protobuf Schema 是否随归档/发布包附带 descriptor，以及版本兼容和未知字段策略。
3. 缓存根目录、权限、并发锁、远程缓存信任和淘汰/回收规则。
4. 是否对原生二进制、资源和 `.xar` 本身也采用内容寻址命名。
5. 哈希完整性之外是否需要数字签名、发布者身份和信任链。
