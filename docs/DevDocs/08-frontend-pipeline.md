# 08. 前端与统一中间表示

> 本阶段把前面的语言规则串成一条编译前端，确保解释模式与原生模式不会各自实现一套语义。

## 一级工程目标：建立前端流水线

### 处理顺序

```text
UTF-8 源码
  + config.xiao 直接依赖与包外导出
  + 可选的已解析外部包图
  -> 词法 Token
  -> 缩进/语法 AST
  -> 文件模块与目录命名空间解析
  -> 导入图和名称解析
  -> 表解析
  -> 类型推断和检查
  -> 逃逸/生命周期分析
  -> 类型化 Xiao IR
```

每一步都应产生可独立测试的中间结果和诊断，不允许后端通过重新解析源码弥补前端缺失。

源码中的 `import` 决定文件间实际使用关系，`config.xiao` 声明直接外部依赖与包外公共接口。第 11A 阶段完成后，依赖锁文件再为前端提供精确的外部包图；在此之前，前端必须能只处理当前项目与本地模块，不能把锁文件作为核心编译闭环的前置条件。这几类信息需要分别保留，不能合并成无法追溯来源的一张清单。

`config.xiao` 与普通源码复用 Token、源码区间和声明式语法节点，但配置验证器必须拒绝函数、控制流、导入及其他可执行构造。依赖解析不能通过运行项目代码获取配置值。

### 语义单一来源

数组路径、字典列顺序、布尔奇偶加减、数值溢出、`drop` 计划、动态值检查和错误编号必须在前端或共享运行库中定义一次。字节码后端与 LLVM 后端只负责映射，不得重新解释语言规则。

## 一级工程目标：设计 IR 层级

### 语法树层

AST 保留用户写法、缩进位置、表头、路径段和注释关联信息，主要服务于诊断、格式化和文档工具。

### 类型化 IR 层

类型化 IR 显式表示：

- 静态标量和动态值。
- 数组形状、路径约束、元组位置类型。
- 集合元素约束、可哈希检查、成员判断、集合运算和无序语义。
- 字典表按键访问和字典列顺序访问。
- 函数调用、控制流和入口初始化。
- 文件模块身份、目录命名空间、包身份和导入来源。
- 堆提升、引用计数、`Weak` 和 `drop`。
- 编译期常量与运行时错误。

### 后端接口层

后端只接收类型化 IR 和目标平台信息：

- 字节码后端生成指令和运行时元数据。
- LLVM 后端生成 LLVM IR、链接信息和最小运行时依赖。

## 一级工程目标：建设诊断系统

### 诊断结构

每个诊断至少包含：错误等级、稳定编号、主源位置、相关源位置、简短原因和修复建议。中文是面向用户的默认消息语言，内部编号不随翻译变化。

### 错误恢复

解析器可以在编辑器场景恢复并继续解析，但命令行构建遇到语义错误不得生成可执行文件。恢复节点不能改变后续正式编译的 AST。

## 二级实现任务

### 前端模块

1. 建立 `lexer`、`parser`、`resolver`、`typechecker`、`escape` 和 `lowering` 模块。
2. 为每个模块定义输入/输出数据结构和错误边界。
3. 为表、数组路径、集合字面量和反引号名称补充独立测试。
4. 输出可序列化的 AST/IR 快照供回归测试使用。

### 模块解析

1. 根据源码根和 `.xiao` 文件路径建立模块身份。
2. 解析源码导入边，并区分本包模块与外部依赖。
3. 对照 `config.xiao` 验证依赖是否已声明、符号是否允许包外访问。
4. 接受可选的已解析外部包图，并把当前可用模块的确定初始化顺序交给后端；读取和生成锁文件不属于前端职责。

### 后端契约

1. 固定 IR 的值类别、控制流和所有权指令。
2. 定义运行时库调用的 ABI。
3. 定义字节码和 LLVM 后端都必须通过的语义测试集。
4. 在后端之外验证静态类型和释放计划。

## 验收标准

### 一致性验收

- 同一源文件只经过一次名称解析、类型检查和逃逸分析。
- 两个后端消费同一个类型化 IR。
- AST 和 IR 快照在跨平台构建中稳定。

### 诊断验收

- 每类核心错误都有稳定编号和源位置。
- 解析恢复不会把错误源码编译成不同的合法程序。
