# 08. 前端与统一中间表示

> 本阶段把前面的语言规则串成一条编译前端，确保解释模式与原生模式不会各自实现一套语义。

当前首个实现子阶段 **08A/U0** 已完成，具体交接、接口和未负责事项见 [08A U0 实现交接记录](08a-u0-frontend-implementation.md)。

## 一级工程目标：建立前端流水线

### 处理顺序

```text
UTF-8 源码
  + config.xiao 直接依赖与包外导出
  + 可选的已解析外部包图
  -> 词法 Token
  -> 缩进/语法 AST
  -> 文件模块与目录命名空间解析
  -> 导入图和名称解析
  -> 表解析
  -> 类型推断和检查
  -> 逃逸/生命周期分析
  -> 类型化 Xiao IR
  -> 可选的共享优化管线
      ├─ 字节码后端
      └─ LLVM 后端
```

每一步都应产生可独立测试的中间结果和诊断，不允许后端通过重新解析源码弥补前端缺失。

源码中的 `import` 决定文件间实际使用关系，`config.xiao` 声明直接外部依赖与包外公共接口。第 11A 阶段完成后，依赖锁文件再为前端提供精确的外部包图；在此之前，前端必须能只处理当前项目与本地模块，不能把锁文件作为核心编译闭环的前置条件。这几类信息需要分别保留，不能合并成无法追溯来源的一张清单。

`config.xiao` 与普通源码复用 Token、源码区间和声明式语法节点，但配置验证器必须拒绝函数、控制流、导入及其他可执行构造。依赖解析不能通过运行项目代码获取配置值。

### 语义单一来源

数组路径、高级选择器、字典列顺序、布尔奇偶加减、数值溢出、`drop` 计划、动态值检查和错误编号必须在前端或共享运行库中定义一次。共享优化器、字节码后端与 LLVM 后端只负责保持语义的变换或映射，不得重新解释语言规则。

## 一级工程目标：设计 IR 层级

### 语法树层

AST 保留用户写法、缩进位置、表头、路径段和注释关联信息，主要服务于诊断、格式化和文档工具。

读取表达式必须区分以下节点，不能把它们都压成普通二元运算：

- 单项精确路径索引。
- 同一对方括号内的多项选择。
- `~` 双端包含区间和 `<`、`<=`、`>`、`>=` 单边范围。
- `[=]` 全选及可选的 `{step}` 步长修饰。
- `[?count]` 无放回随机选择和 `[!?count]` 放回随机选择。

类型路径声明（例如 `int list[3/2]`）与读取索引（例如 `list[3/2]`）必须使用不同 AST 节点，即使两者复用路径段结构。这样类型检查器不会把一次读取误当成声明，也不会让后端根据上下文猜测。

### 类型化 IR 层

类型化 IR 显式表示：

- 静态标量和动态值。
- 数组形状、路径约束、元组位置类型。
- 有序容器的精确索引和规范化选择描述，包括结果根类型、嵌套路径、闭区间边界、步长方向、随机模式及数量操作数。
- 集合元素约束、可哈希检查、成员判断、集合运算和无序语义。
- 字典表按键访问和字典列顺序访问。
- 函数调用、控制流和入口初始化。
- 文件模块身份、目录命名空间、包身份和导入来源。
- 堆提升、引用计数、`Weak` 和 `drop`。
- 编译期常量与运行时错误。

### 后端接口层

后端只接收已经验证的类型化 IR、规范化优化配置和目标平台信息：

- 字节码后端生成指令和运行时元数据。
- LLVM 后端生成 LLVM IR、链接信息和最小运行时依赖。

### 优化器接口层

类型化 IR 需要为第 13 阶段的共享优化器提供控制流、类型、效果、别名、所有权、释放计划和源码位置映射。优化器可以输出另一份已验证 IR，但不能改写原始语义信息或把证明失败当作“允许优化”。

字节码与 LLVM 可以在各自降低后执行目标相关优化，但都必须从同一优化配置和效果契约派生。第 08 阶段只预留稳定接口，不以实现优化 Pass 为退出条件；完整 SOP 见 [13. 优化契约与统一管线](13-optimization-contract.md)。

## 一级工程目标：建设诊断系统

### 诊断结构

每个诊断至少包含：错误等级、稳定编号、`message_id` 与结构化参数、主源位置、相关源位置、简短原因和修复建议。有效文案语言由项目/全局 `config.xiao` 的 `[language].locale` 决定，未配置时使用内置中文；内部编号、参数和位置不随翻译变化。运行时的 `XiaoError` 复用稳定编号、消息身份、源位置和原因链；前端产生的编译期诊断不得被包装成可捕获的运行时错误。消息目录和语言包边界见 [11c-localization.md](11c-localization.md)。

### 错误恢复

解析器可以在编辑器场景恢复并继续解析，但命令行构建遇到语义错误不得生成可执行文件。恢复节点不能改变后续正式编译的 AST。

## 二级实现任务

### 前端模块

1. 接入前序阶段已经分别完成的 `lexer`、`parser`、`resolver`、`typechecker` 和 `escape`，再建立统一的 `lowering` 集成层；本阶段不重新实现这些组件。
2. 冻结各模块之间的输入/输出数据结构和错误边界。
3. 为表、数组路径、集合字面量和反引号名称补充独立测试。
4. 输出可序列化的 AST/IR 快照供回归测试使用。

### 选择器检查与降低

1. 解析器为精确路径、多选、范围、步长和两种随机模式生成互不混淆的 AST，并保留每个路径段的源码位置。
2. 名称与类型检查阶段只允许数组、元组、`str` 和字典列使用高级选择；字典表只允许精确键路径，集合拒绝索引。
3. 验证步长和数量只能是整数字面量或整形变量；字面量中的零步长、负数量及无放回超量直接报错，变量值降低为运行时检查。
4. 把选择器降低为共享 IR：静态可确定路径的单项精确索引使用对应元素类型，多选、范围和随机选择的结果根类型与来源根容器一致；异构容器的运行时索引结果类型和字典列重复条目例外必须等各自待定规则冻结后再编码。
5. 为跨嵌套路径附加结果形状计划，使 `a[1, 2/1]` 与 `a[1~2/1]` 无需后端推导即可分别重建局部嵌套结构。
6. 将随机选择标记为有运行时可观察顺序的操作，优化器不得删除、合并或越过其他可观察操作重排抽取。

### 模块解析

1. 根据源码根和 `.xiao` 文件路径建立模块身份。
2. 解析源码导入边，并区分本包模块与外部依赖。
3. 对照 `config.xiao` 验证依赖是否已声明、符号是否允许包外访问。
4. 接受可选的已解析外部包图，并把当前可用模块的确定初始化顺序交给后端；读取和生成锁文件不属于前端职责。

### 后端契约

1. 固定 IR 的值类别、控制流和所有权指令。
2. 定义运行时库调用的 ABI。
3. 定义字节码和 LLVM 后端都必须通过的语义测试集。
4. 在后端之外验证静态类型和释放计划。
5. 固定精确索引、范围迭代、结果形状重建、步长和随机源调用的 IR 契约，使两个后端只做直接映射。
6. 为后置优化器提供效果、别名、生命周期和源码映射接口，并保证未优化 IR 仍可直接进入两个后端。

## 验收标准

### 一致性验收

- 同一源文件只经过一次名称解析、类型检查和逃逸分析。
- 共享优化器和两个后端消费同一个类型化 IR 契约，优化关闭时两个后端仍可直接消费未优化 IR。
- AST 和 IR 快照在跨平台构建中稳定。
- `a[0, 1]`、`a[0~2, 5~6]`、四种单边范围、`a[=]`、`a{x}[=]`、`a[?x]` 和 `a[!?x]` 都有独立且稳定的 AST/IR 快照。
- 单项精确索引 IR 返回元素；多选、范围和随机 IR 携带来源根类型及嵌套形状计划。
- 同一份选择 IR 在字节码和 LLVM 后端产生相同顺序、边界、空结果和错误类别；随机用例在注入同一测试随机源时结果一致。

### 诊断验收

- 每类核心错误都有稳定编号和源位置。
- 解析恢复不会把错误源码编译成不同的合法程序。
