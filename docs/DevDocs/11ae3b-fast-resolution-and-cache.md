## 二、⚠️ 本批最重要的一件事：**两类存储语义必须分开**

这是本批的架构决定，也是 `11a:325-331` 那四条能同时成立的前提。

四类东西的**存储语义不同**：

| 类别 | 语义 | 理由 |
| --- | --- | --- |
| **包元数据**、**源码/预编译正文** | **内容寻址**（不可变、可去重、跨源共享） | 任务 3 要求「全局**内容寻址去重**」；E1 已为正文建立此形状 |
| **源快照的"当前指向"**、**联邦源索引** | **按源身份存 + 原子替换** | `:331` 要求「更新失败**保留上一份**已验证索引，不得用空文件覆盖」；这是**覆盖语义**，不是去重语义 |

**若把四类都做成内容寻址**：`current` 指针就要单独存，快照更新变成"写对象 + 改指针"两步，
中途崩溃即不一致（而 `:331` 恰恰要求任何时刻都能读到**已验证的完整索引**）。

**若把四类都按源身份存**：直接放弃跨源去重，与任务 3 冲突，也与 E1 的缓存体系脱节。

### 2.1 布局（已冻结）

```text
XIAO_HOME/cache/
  objects/
    source/sha256/<前两位>/<digest>/     ← 复用 E1，正文
    metadata/sha256/<前两位>/<digest>/   ← E3B 新增，包元数据
  snapshots/
    <source_id 的摘要>/
      current.json                        ← 原子替换；指向下面某个快照
      <snapshot_id>.json                  ← 历次快照都在，不删
  federation/
    index.json                            ← 原子替换
```

**⚠️ 目录名不能用 `source_id` 原文**：E3A 冻结的 `source_id` 含协议、host、路径
（如 `static:https://example.org/one`），**含 `:` 和 `/`，不能直接做目录名**。
用**其 SHA-256**（复用 E1 的 `sha2`），并在 `current.json` 里写回完整 `source_id` 以便审计。

**⚠️ 元数据的新命名空间必须与 16 阶段分开**：`objects/metadata/` 是**包元数据**，
`objects/xiaoc/`（16）是**构建产物**。`16:3` 要求「构建产物、源码包和依赖锁文件
必须保持**不同的命名空间与生命周期**」。

### 2.2 原子替换复用既有设施

`:331` 的「不得空文件覆盖」「不得让并发 `sync` 读取半成品」两条，**不需要新机制**：

- **原子替换** → E2A 的 `atomic_write_file`（同目录暂存 + `rename`）；
- **并发读** → `11A-CONC` §1.6 的 `create_new` 跨进程锁，**按缓存条目加锁**。

**⚠️ 「保留上一份」的实现方式**：不是把旧文件备份，而是**永不删除旧快照**
（`<snapshot_id>.json` 一直在），`current.json` 只是换指向。这样"回滚"就是再写一次
`current.json`。

## 三、必须先冻结的 5 条

### 3.1 快速路径的判据（`11a:326` 已给方向，本批落成规则）

`:326`：「**有效锁文件、对应源快照/元数据和完整内容缓存都命中时，允许完全离线地物化环境**」
——三类条件是**与**关系。本批要把每一项落成可判定的谓词：

| 条件 | 判据 | 复用 |
| --- | --- | --- |
| 有效锁文件 | `validate_lockfile` 通过，**且**其 `config_fingerprint` 与当前配置一致 | E2A |
| 对应源快照命中 | 每个**可能影响优先级判断**的源在 `snapshots/*/current.json` 里有记录 | 本批 |
| 完整内容缓存命中 | 锁文件里每个条目的 `content_digest` 在 `objects/` 下存在**且校验通过** | E1 |

**⚠️「可能影响优先级判断的源」是关键词**——`:327` 要求「缺少**且可能影响选择的**快照时
必须报告结果不确定」。所以判据是**按源在 `config_order` 中的位置**，而不是"所有源"：
若某个更靠前的源可能有该包而你无法确认，**不能跳过它直接用它后面的源**。

### 3.2 旧快照过期规则（**`:328` 明说是本批的实现参数**）

**冻结为：过期由"配置/锁文件状态变化"触发，不由时间触发（无 TTL）。**

理由：`00-decisions:292` 的口径是「**未改变源配置且锁文件/快照缓存仍有效时**可以走离线快速路径」
——判据是配置与锁文件，**没有提时间**。引入 TTL 会让同一份配置在两天后产生不同结果，
而 `12-tests:781` 要求「结果仍**可确定性复现**」。

**⚠️ 所以 `fresh`/`cached` 的区分不是"新/旧"，而是"本次是否真的读到了源"**：

| 状态 | 含义 |
| --- | --- |
| `fresh` | 本次从源读到了快照 |
| `cached` | **沿用**了缓存里的快照（源未读或读失败但旧快照仍可用） |
| `unavailable` | 该源不可达**且没有可用快照** |

`:328` 要求 `cached` 时「在锁定或同步报告中**显示快照摘要和新鲜度**」——
"新鲜度"是**快照的生成/读取时间戳**，用于展示，**不参与判定**。

### 3.3 三态与失败的分流（**与 `11A-CONC` §1.5 的判据合并使用**）

`11A-CONC` §1.5 已冻结：「单源不可达/摘要不匹配/协议版本不支持 → 记为该源状态；
缓存根不可写/锁无法获取/磁盘满 → 中止」。本批在此基础上加一条：

**`unavailable` 的源不得被当作空源**（`:327`、`12-tests:782`）——即：

- **不改源顺序**、**不改配置顺序**、**不自动改源、不删除锁文件**（`:327` 原文）；
- 若 `config_order` 中**更靠前**的源处于 `unavailable` 且无可用快照，
  **必须失败并指出缺少哪个源快照**，不能报"未找到包"。

**⚠️ 这条要有反例测试**：构造"第一个源不可达、第二个源有该包"，断言结果是
**明确的失败/不确定诊断**，而**不是**静默用了第二个源的包。

### 3.4 断点恢复（**本批只能验接口与中断安全，不能验真实 Range**）

任务 3 要求「**断点恢复**」。但 E3B **用本地源驱动，没有"断点"这个概念**。

**冻结**：

- 断点恢复的**能力声明放在适配器 trait 上**（E3A 的 trait 已有形状），本批**只定义语义**：
  「适配器可声明支持部分读取；不支持时必须整体重取」；
- E3B **要验的是"中断安全"**：读取中途失败**不产生**半成品缓存条目、
  不留可被后续误用的残留、重试后结果正确；
- **真实的 HTTP Range 断点恢复归 E3C**，并在验收里**明确标注未验证**。

**⚠️ 不要把"重试一次成功"称作断点恢复**——两者不是一回事，混称会在 E3C 接真实
传输时掩盖缺口。

### 3.5 诊断编号续号

`X05-SOURCE-001`/`002`/`007` 已被 E3A 占用（协议版本、alias 冲突、JCS 相关）。
E3B 新增的（快照归属不匹配、摘要不匹配、源不可用但影响选择、缓存条目损坏）
**续用 `X05-SOURCE-*`**，并在文档里列出完整分配表。

## 九、验收

1. **条件 8**：三类条件全中时**完全离线**物化（把源目录移走后仍成功）；
   任一不中则**重新解析**；并行结果按 `config_order`（**快源排末尾的区分度用例**）。
2. **条件 9**：`fresh`/`cached`/`unavailable` 三态各有正例；
   **反例：更靠前的源不可达且无快照 → 必须失败并指出缺哪个源快照，不得静默用后面的源**。
3. **四类缓存分离**：四类各自落在 §2.1 的路径；元数据与正文可跨源去重；
   快照/联邦索引是覆盖语义。
4. **保留上一份**：联邦索引更新失败后，读到的仍是**上一份已验证索引**（不是空文件）。
5. **中断安全**：读取中途失败**不产生半成品条目**、无残留、重试结果正确。
6. **跨进程**：两个进程并发写同一缓存条目的用例；陈旧锁可回收。
7. **零新增依赖**；门禁全绿。
