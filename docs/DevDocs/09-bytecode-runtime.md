# 09. 字节码运行模式

> 本阶段实现 `xiao run` 背后的字节码执行核心。字节码后端消费统一前端生成的类型化 IR，再生成并执行字节码，不直接解释未经检查的源码；第 11 阶段再把稳定执行接口接入正式 CLI。

## 一级工程目标：定义运行命令

### 命令入口

面向用户的最终 CLI 计划支持以下等价方向：

```text
xiao run test.xiao
xiao test.xiao
```

第二种写法是脚本快捷方式，具体命令行解析规则在第 11 阶段冻结。本阶段通过库接口或内部测试驱动器验证两者共同需要的执行流水线；不能为了提前出现 `xiao run` 命令而在字节码阶段另写临时 CLI。无论最终采用哪种入口，源码都应经过词法、类型和生命周期检查后执行。

### 字节码产物

字节码可以在内存中生成，也可以写入缓存。Xiao 对外公开的可序列化字节码文件扩展名已经确定为 `.xiaoc`，且每个 `.xiaoc` 只表示一个模块；本阶段先完成内存字节码和虚拟机最小闭环，第 14 阶段再实现正式 `.xiaoc` 格式、优化、内容寻址和加载兼容规则，不能让公开扩展名反过来阻塞最小执行器。

任何落盘缓存都必须包含语言版本、目标平台和类型/IR 版本号，版本不匹配时重新生成。临时内部缓存不能仅改扩展名就冒充通过正式格式验证的 `.xiaoc`。

字节码缓存必须绑定前端实际使用的模块图指纹。第 11A 阶段接入锁文件后，该指纹还必须包含锁定依赖图摘要；核心字节码闭环只使用当前项目模块时不要求锁文件存在。`xiao run` 不能因为使用解释模式而绕过已经可用的 `config.xiao` 约束。

正式产物链完成后，`xiao run`、脚本快捷入口和 REPL 默认采用 `-O0` 并生成经过验证的 `.xiaoc`。普通源码模块默认进入第 16 阶段的全局内容寻址缓存，不在源码旁生成杂项文件；依赖当前交互状态的 REPL 片段只进入可回收的会话缓存，不能冒充可跨项目复用的独立模块。缓存命中只能省略重复生成，不能省略格式、摘要、版本和 Runtime ABI 验证。

### 优化与公开加载接口

字节码优化承担类似旧版 `.pyo` 的用途，但不兼容 Python 字节码。解释器运行 `.xiaoc` 前必须验证格式、指令边界、栈高度、释放计划、版本、Runtime ABI 和完整性，包括默认 `-O0` 产物。优化后的指令不得改变源码执行、未优化字节码和原生模式之间的可观察语义。

正式格式、字节码级 Pass、调试映射和运行时自适应缓存隔离见 [14. 字节码优化与 `.xiaoc` 产物](14-bytecode-optimization.md)。本阶段只需为后续加载器、验证器和优化器预留接口。

## 一级工程目标：实现字节码虚拟机

### 指令类别

最小指令集需要覆盖：

- 常量加载、局部变量和表字段访问。
- 算术、比较、逻辑和显式转换。
- 数组路径、集合可哈希检查与集合运算、字典表键和字典列顺序索引。
- 有序容器的多项选择、闭区间、单边范围、全选、正负步长以及放回/无放回随机选择。
- 条件跳转、循环、函数调用和返回。
- 动态值检查、引用计数、`Weak` 和 `drop`。
- 运行时错误构造与传播。

### 执行栈

虚拟机维护调用栈、局部槽和当前作用域释放计划。本阶段定义并消费与配置文件无关的规范化运行参数对象；没有外部参数时使用运行时默认值，调用栈等限制超限必须产生可诊断错误。第 11 阶段负责把 `config.xiao` 和命令行值校验、归一化后映射到该对象，因此本阶段不解析配置文件，也不依赖最终表名或键名。

## 一级工程目标：保证语义与原生模式一致

### 共享规则

字节码不能自行决定类型、溢出、默认填充或释放顺序。所有这些规则来自类型化 IR 和共享运行库。

选择器同样遵守这一边界：字节码只执行 IR 中已经规范化的路径、双端包含边界、结果形状计划、步长方向和随机模式。虚拟机不能把字典表的存储次序当作高级选择顺序，也不能为集合临时增加索引能力。

### 调试能力

字节码最小闭环至少保留源码位置映射、栈回溯、变量/路径检查和运行时错误上下文。错误上下文必须包含稳定的 `code`、`message_id` 和结构化参数，文本由第 11C 阶段的有效语言目录在展示边界渲染。完整断点调试器可以后置，但不能牺牲错误定位。

运行时错误必须通过第 07 阶段的统一边界传播：可恢复错误交给 `try`/`catch`，未捕获错误由入口报告器输出，`panic` 不得被普通处理器伪装为成功。显式 `-debug` 时，虚拟机必须在用户代码前启动独立诊断窗口，并向诊断进程发送结构化节点事件（模块、函数、作用域、`drop`、钩子、预断点/断点、日志和错误）及运行时间、内存、全部结构化运行时错误事件计数等指标；由调试构建保存的激活位启动 `.xiaoc` 或 `.xar` 时也遵守同一规则。诊断事件不能改变字节码的执行顺序或释放语义。

## 二级实现任务

### 编译器

1. 将类型化 IR 降低为带源位置的字节码。
2. 编码函数、表、常量池和运行时调用信息。
3. 验证跳转目标、栈高度和释放计划。
4. 为字节码格式加入版本号和校验。
5. 暴露可供第 11 阶段调用的稳定运行接口，并提供不承担用户 CLI 契约的内部测试驱动器。
6. 为第 14 阶段预留从验证后字节序列加载、检查及执行的接口，不在最小闭环中伪造 `.xiaoc` 完整格式。

### 虚拟机

1. 实现解释循环和调用栈。
2. 接入统一动态值、容器和内存运行库。
3. 实现错误回溯和资源清理。
4. 为脚本模式提供快速启动路径。
5. 接入统一 `XiaoError`、`try`/`catch` 展开和未捕获错误边界；`panic` 使用独立终止路径。
6. 为 `-debug` 提供独立诊断进程的事件发送、堆栈采样、内存/错误/钩子计数和窗口启动接口；窗口启动失败必须形成明确诊断，不能静默改为普通运行。
7. 从 CLI 接收不可变语言上下文，保留错误的 `code`、`message_id` 和参数；字节码后端不自行选择或拼接本地化文案。

### 选择器指令与运行时接入

1. 为精确路径读取和高级选择描述建立不同的字节码操作数格式；具体操作码编号在字节码格式冻结时确定。
2. 执行双端包含区间、单边范围和全选，并把多范围按源码中的项目顺序交给结果构造器。
3. 执行正负步长，对动态零步长抛出统一运行时错误。
4. 调用共享随机源完成 `[?count]` 无放回和 `[!?count]` 放回抽取，保留抽取顺序及可由结果类型表示的重复项；字典列例外不能由字节码自行决定。
5. 按 IR 形状计划建立同根类型结果；任何中途错误都沿当前作用域释放计划清理已构造节点。
6. 在测试虚拟机中允许注入确定性随机源，用同一随机序列对照原生后端结果。

## 验收标准

### 运行验收

- 字节码运行接口能运行脚本模式和 `[main]` 工程模式；正式 `xiao run` 命令在第 11 阶段验收。
- 类型错误、溢出、索引错误和释放钩子行为与 IR 预期一致。
- 字典表无顺序承诺，字典列顺序稳定。
- 集合不暴露索引，并在两种模式下保持相同的唯一性结果。
- 集合并集由 `+`/`+=` 执行，`|`/`|=` 不会被后端偷偷映射为并集。
- 单项精确索引返回元素；多选、范围和随机选择保持数组、元组、`str` 或字典列的来源根类型，字典列重复条目的待定例外除外。
- `~` 两端包含，四种单边范围包含关系正确；跨嵌套选择能按 IR 计划保留中间容器形状。
- 步长 `0` 报错、负数反向；`?` 无放回且拒绝超量，`!?` 放回且允许超过候选量。
- 随机数量为 `0` 返回同类型空结果；负数或空来源上的正数请求报错。
- 字典表的高级选择和集合的任何索引均在执行前或执行时稳定失败，不受底层存储顺序影响。
- 可恢复错误、错误原因链、`finally`/`drop` 清理和未捕获错误报告与统一错误契约一致；`panic` 不会继续执行后续用户代码。
- `-debug` 事件和错误堆栈能回溯到源码位置，关闭诊断窗口或诊断通信不会改变已经启动程序的结果。
- 切换 `[language].locale` 只改变字节码错误和诊断的显示文本，不改变错误身份、堆栈、退出码或用户输出。

### 性能验收

- 字节码启动路径不要求 LLVM 编译器存在。
- 动态值使用集中在需要它们的路径，不把所有标量强制装箱。
- B0 最小闭环不以 `.xiaoc` 优化完成为前置；第 14 阶段再验收公开文件的加载与优化性能。
