# 09. 字节码运行模式

> 本阶段实现开发优先的 `xiao run`。它使用统一前端生成的字节码，不直接解释未经检查的源码。

## 一级工程目标：定义运行命令

### 命令入口

首版支持以下等价方向：

```text
xiao run test.xiao
xiao test.xiao
```

第二种写法是脚本快捷方式，具体命令行解析规则在第 11 阶段冻结。两者都应经过词法、类型和生命周期检查后执行。

### 字节码产物

字节码可以内存生成，也可以缓存到工程目录。缓存必须包含语言版本、目标平台和类型/IR 版本号，版本不匹配时重新生成。

## 一级工程目标：实现字节码虚拟机

### 指令类别

最小指令集需要覆盖：

- 常量加载、局部变量和表字段访问。
- 算术、比较、逻辑和显式转换。
- 数组路径、字典表键和字典列顺序索引。
- 条件跳转、循环、函数调用和返回。
- 动态值检查、引用计数、`Weak` 和 `drop`。
- 运行时错误构造与传播。

### 执行栈

虚拟机维护调用栈、局部槽和当前作用域释放计划。`call_stack_depth` 等运行时限制应在统一运行时配置中读取，超限必须产生可诊断错误。

## 一级工程目标：保证语义与原生模式一致

### 共享规则

字节码不能自行决定类型、溢出、默认填充或释放顺序。所有这些规则来自类型化 IR 和共享运行库。

### 调试能力

首版至少保留源码位置映射、栈回溯、变量/路径检查和运行时错误上下文。完整断点调试器可以后置，但不能牺牲错误定位。

## 二级实现任务

### 编译器

1. 将类型化 IR 降低为带源位置的字节码。
2. 编码函数、表、常量池和运行时调用信息。
3. 验证跳转目标、栈高度和释放计划。
4. 为字节码格式加入版本号和校验。

### 虚拟机

1. 实现解释循环和调用栈。
2. 接入统一动态值、容器和内存运行库。
3. 实现错误回溯和资源清理。
4. 为脚本模式提供快速启动路径。

## 验收标准

### 运行验收

- `xiao run` 能运行脚本模式和 `[main]` 工程模式。
- 类型错误、溢出、索引错误和释放钩子行为与 IR 预期一致。
- 字典表无顺序承诺，字典列顺序稳定。

### 性能验收

- 字节码启动路径不要求 LLVM 编译器存在。
- 动态值使用集中在需要它们的路径，不把所有标量强制装箱。
