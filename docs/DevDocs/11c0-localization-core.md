# 11C-0. 消息目录与接入

> **11C 的第一批**：做 L0（消息模型与内置目录）、L1（配置解析与语言上下文）、
> L2（错误、日志与交互接入）。**不含 L3（语言包插件）**——那是扩展能力，
> 等内置两套目录跑顺了再单开。
>
> **本批的性质**：它的**代码量集中在"搬运"**——把散落全仓的**约 943 处**硬编码文案
> 收进消息目录。**技术难度不高，但面极广**，所以验收的核心不是"新功能能跑"，
> 而是「**搬运没有悄悄改变任何一句默认语言的文本**」（§3.5）。
>
> **11C 的验收标准在 [11C 规范](11c-localization.md) `:131-158`**，
> 不在 `12-tests`（本阶段自带验收段，这是既有安排）。

## 三、必须先冻结的 6 条

### 3.1 边界：**谁的消息归谁**

`11c:66` 的「输出边界」划的是**内容**，本批要把它落成**代码边界**：

| 谁 | 管什么 | 目录在哪 |
| --- | --- | --- |
| **Rust 侧** | 编译器/Runtime/包管理器/诊断窗口的错误、日志、状态 | **`xiao-i18n`**（本批新建） |
| **TS 侧** | REPL 的界面标签（版权、确认、保存、面板、提示符） | **CLI 侧的一小组消息** |

**⚠️ 冻结**：

- **两组的消息身份不得重名**——命名空间要分开（如 `xiao.error.*` 与 `xiao.cli.*`）,
  否则将来合并目录时会撞；
- **⚠️ 但"TS 侧也有一份目录"不等于"两套翻译"**（§3.2）——
  TS 侧那份**只管它自己那 ~8 条界面文案**，**不复制 Rust 的任何一条**；
- **用户程序输出、第三方程序原始输出、未声明目录键的文本保持原样**（`11c:69` 的红线）。

### 3.2 渲染侧：**Rust 渲染，协议带 `locale` 与 `text`**（已定）

- **CLI 解析 `config.xiao` 得到有效语言**，**在 `run` 请求里带 `locale`**；
- **Rust 侧用统一渲染器生成本地化 `text`**，**随结构化诊断一起返回**；
- **`code` / `message_id` / `params` 始终保留**，`text` 是**附加**的
  （`11c:67`：「是否附带本地化 `text` 不得影响机器解析」）；
- **TS 侧直接用 `text` 呈现**，**不自己再查一遍 Rust 的消息**。

**⚠️ 三条推论**：

1. **协议要加字段**——本批**可以加**（I4b 的「协议不改字段」只属于 I4b），
   但**必须照 `peak_live_bytes` 的先例**：**缺字段不崩、旧核心降级**；
2. **`text` 缺失时**（旧核心或回退失败），TS 侧**退回显示 `message_id` + 参数**，
   **不得显示空白**（`11c:75` 的回退链末端就是这个）；
3. **`locale` 是请求侧的**，**`text` 是响应侧的**——两者不对称，**都要能缺省**。

### 3.3 回退链：**照 `11c:74-77` 执行，不自行设计**

```
精确标签 → 基础语言 → 内置英语参考目录 → 原始 message_id 与参数
```

**冻结**：

- **内置 `zh-CN` 与 `en-US` 在首版必须覆盖所有核心消息**（`11c:76`）；
- **插件缺条目时只触发回退**，**不能显示空白或抛新异常**（本批无插件，但回退链要按这个写）；
- **插值参数必须经目录声明的格式检查**；**格式化失败保留错误码 + 安全占位文本**。

**⚠️ 最后一级是"原始 `message_id` 与参数"**——意味着**任何情况下都能显示出一个
可读的、可检索的东西**。**这条要写测试**（§九 第 6 条）。

### 3.4 有效语言上下文：**只创建一次，不可变**

`11c:108`（L1 第 2 条）要求「在 CLI 启动、编译/运行入口、REPL 和 `.xar` 启动入口
**只创建一个不可变有效语言上下文**」。

**冻结**：

- **上下文是值对象，随调用链传递**——**不做全局可变单例**；
- **⚠️ `.xar` 启动入口不能漏**（`11c:126`）：原生调试产物要**保存构建时的有效语言元数据**，
  脱离项目目录启动时仍能呈现可读错误；
- **同一个运行实例的所有组件用同一有效语言**（`11c:70`）——
  不得因字节码/LLVM 后端、线程或诊断窗口不同而混用。

### 3.5 **搬运不得改变默认语言的文本**（**本批最硬的一条**）

约 943 处文案要搬家。**风险不在于搬不动，而在于搬错**——
把某句错误信息顺手"改进"了一下，或漏了参数，用户会发现**未经宣布的行为变化**。

**冻结**：

- **默认语言下，搬运前后的人类可读文本必须逐字一致**——
  每搬一处，**都要有对照**（§七 的分步提交按这个拆）；
- **⚠️ 允许的唯一例外**：`11c` 规范明确要求改变的（如英文示例标题变成本地化结果）；
  **这类要在提交信息里逐条列出**，不能混在"搬运"里；
- **不接受"顺手修文案"**——想改措辞**另开提交**，且要说明理由。

**⚠️ 这条是本批的验收核心**：功能测试全绿但文本悄悄变了，是**最坏的结果**——
因为没人会去看第二遍。

### 3.6 机器输出与固定拼写

- **`code` / `message_id` / 参数 / 位置 / 退出码跨语言完全一致**（`11c:112`、`:143`）；
- **源码标识符不被翻译**；
- **控制指令保持固定拼写**（`11c:114`）：`!save!`、`!panel!`、`!outLF!`、`!inLF!`、`!ovr!`
  **永远不翻译**——它们是语法，不是文案；
- **日志文件可以存本地化文本，但必须同时存稳定身份与规范 `locale`**（`11c:68`）。

## 六、硬约束

1. **搬运不改默认语言文本**（§3.5）——本批最硬。
2. **渲染侧只有一处**（§3.2）——Rust 渲染，TS 消费，**不复制消息**。
3. **协议加字段必须能缺省**（§3.2）——缺字段不崩、旧核心降级。
4. **回退链照规范，末端是可读的 `message_id` + 参数**（§3.3）——不显示空白。
5. **语言上下文只创建一次且不可变**（§3.4）——不做全局可变单例。
6. **控制指令不翻译**（§3.6）。
7. **机器输出跨语言一致**（§3.6）。
8. **不做 L3 插件**（§2.3）。
9. **门禁**：**`cargo test --workspace`（不是部分 crate）**、`bun run check`（含 clippy）、
   TypeScript 类型检查、`cli/ts` 全目录测试。

## 八、最可能翻车的地方

1. **搬运时改了默认语言文本**（§3.5）——**功能全绿但用户看到的信息变了**，最难发现。
2. **TS 侧复制了 Rust 的消息**（§3.1）——本仓头号病史的国际化版。
3. **翻译了控制指令**（§3.6）——`!save!` 变成 `!保存!` 就再也不是控制指令了。
4. **翻译了用户程序输出**（`11c:69`）。
5. **回退链末端显示空白或抛异常**（§3.3）。
6. **语言上下文被创建多次**（§3.4）——同一实例里混用语言。
7. **漏了 `.xar` 启动入口**（§3.4）——脱离项目目录启动时错误变回默认语言。
8. **协议加字段没做降级**（§3.2）——旧核心直接崩。
9. **机器输出因语言而变**（§3.6）——脚本与 CI 会碎。
10. **只跑部分 crate 就说门禁全绿**（§六 第 9 条）——上次的存量债就是这么躲了四天。

## 九、验收

**以 [11C 规范](11c-localization.md) `:131-158` 为准**（跳过 `:145` 插件验收），本批补充：

1. **默认语言对照**：搬运前后，`zh-CN` 下的**人类可读文本逐字一致**；
   **唯一例外在提交信息里逐条列出**（§3.5）。
2. **配置**：项目覆盖全局、缺失用 `zh-CN`；`zh`/`en` 规范化为 `zh-CN`/`en-US`；
   非法值在执行前产生稳定诊断（`:133-138`）。
3. **语言只影响文案**：Token、源码标识符、错误码、退出码、用户程序输出**不变**（`:138`）。
4. **消息与错误**：`code`/`message_id`/参数/位置/退出码**跨语言一致**；
   两套内置目录覆盖所有核心消息；**缺条目走回退且不显示空白**（`:139-144`）。
5. **回退链**：四级都可测；**末端显示原始 `message_id` + 参数**（§3.3）。
6. **控制指令**：五种控制指令在任何语言下**拼写不变**（§3.6）。
7. **协议兼容**：缺 `locale`/`text` 的旧客户端与旧核心**都能工作**（§3.2）。
8. **上下文唯一**：CLI、编译/运行、REPL、`.xar` 四个入口**各只创建一个**（§3.4）。
9. **不回归**：11B 与 I4 系列的全部用例保持绿；**`cargo test --workspace`** 全绿。
10. **门禁全绿**，含 `-debug` 窗口标题的本地化验证。
