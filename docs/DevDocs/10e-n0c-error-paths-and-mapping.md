# 10E. N0-C 错误路径与源码映射

> **10 阶段第三个批次。** N0-A（纯静态标量闭环）与 N0-B（Runtime ABI）已落地，
> 本批做 **N0-C**：把**统一错误路径、源码映射、诊断事件和 `-debug` 构建标志**
> 降低到原生 Runtime ABI，并建立**字节码与原生结果的差分**。
>
> **一句话概括本批**：让原生产物**错得和字节码一样**——
> 同样的错误码、同样的堆栈位置、同样的释放记录，
> 而不是把段错误或平台异常当成"某种失败"糊过去。
>
> **N0-D（三目标固定宽度、Runtime 裁剪验证）不在本批**——先做正确性，再做验证。
> **否则 D 的裁剪验证会建立在未验证的错误路径上。**

## 三、必须先冻结的 6 条

### 3.1 **平台异常不得伪装成可恢复的 Xiao 错误**（本批的红线）

`10:60` 的末句：**「不得让平台异常伪装成可恢复 Xiao 错误」**。

**冻结**：

- **段错误、栈溢出、非法指令、系统调用失败等平台级异常**，
  **不得**被翻译成一个可以被 `catch` 捕获的 Xiao 错误——
  那会让用户以为"这个程序只是抛了个错"，而实际上进程已经处于不可继续的状态；
- **它们应当表现为不可恢复的失败**（进程终止 + 可诊断的报告），
  **与 `07` 阶段冻结的 Fatal 语义一致**；
- **⚠️ 反过来也要守住**：**真正可恢复的 Xiao 错误**（`try`/`catch` 能接的）
  **不得**因为走原生路径就变成进程终止——
  **两个方向的错都是 bug，而后者更容易被忽略**（因为"程序崩了"看起来像别的问题）；
- **要有双向测试**：可恢复的不终止、平台级的不被捕获（§九 第 2 条）。

### 3.2 字节码差分：**三样都要一致**

`12-tests:687`：「**字节码与原生模式的输出、错误和释放记录一致**」。
`10:71`：「资源释放、容器路径和**错误类别**与字节码模式一致」。

**冻结**：

- **对照的三样是：输出、错误、释放记录**——**缺一不可**；
- **"错误一致"指**：`code`、`message_id`、参数、**源码位置**、**退出码**逐项一致；
  **不是**"都报错了就算一致"；
- **"释放记录一致"指**：确定性释放的顺序与时机一致——
  这是 `06` 阶段冻结的语义，**原生路径不得因为 GC 或析构时机不同而错位**；
- **⚠️ 差分测试要能在同一份 IR 上跑两次**（字节码 + 原生），
  对照三样结果。**这是本批的验收主体**（§九 第 1 条）。

### 3.3 语言上下文与诊断：**接上，不复制**

`10:61`：保留 `code`/`message_id`/参数/源码位置/退出码；
**原生后端不复制翻译逻辑**。

**冻结**：

- **原生产物从 CLI 接收不可变语言上下文**（`11C-0` 的模型），
  **消息渲染仍走 11C-1 的那一份渲染器**；
- **⚠️ 原生侧不得再实现一套目录查找或插值**——那是本仓头号病史；
- **机器的部分不受语言影响**：`code`/`message_id`/参数/位置/退出码
  **跨语言、跨后端完全一致**（这正是差分能成立的前提）；
- **⚠️ `-debug` 产物的语言**：调试版要能脱离项目目录启动，
  所以**有效语言要么随产物保存、要么由启动参数给出**——
  **具体形态属 N0-D 的"调试构建标志"，但本批要保证接口留得下**。

### 3.4 `-debug` 产物：**不依赖启动器、不受 GUI 抑制**

`10:71` 的完整要求：

> `build -debug` 产物能输出与字节码模式**可比**的错误码、堆栈位置和诊断事件，
> 并**在直接启动时自动打开独立诊断窗口**；该行为**不依赖 `xiao` 启动器**，
> 也**不受 GUI 子系统设置抑制**。

**冻结**：

- **不依赖 `xiao` 启动器**——产物自带启动诊断窗口的能力；
- **不受 GUI 子系统抑制**——即使业务程序声明了 GUI 子系统、或标准终端不可用，
  **调试窗口仍要打开**，**不得静默取消**（`10:63` 第 8 条的措辞是"仍不能静默取消"）；
- **⚠️ 这条的难点在"失败时怎么办"**：启动器缺失、套接字连不上、窗口起不来时，
  **要有确定的行为**——**但"静默"不是可选项**；
- **"可比"的含义**：与字节码模式**能对照**（同样的 `code`/位置/事件），
  **不要求逐字节相同**（两者承载形式不同）。

### 3.5 `try`/`catch`/`finally` 的展开要与字节码一致

`10a:79` 列 N0-C 时明写「`try`/`catch`/`finally`」。
这套语义在 `07B` 已冻结（`finally → drop → catch/继续传播` 的展开顺序）。

**冻结**：

- **原生路径的展开顺序必须与 `07B` 冻结的一致**——
  **`finally` 先于 `catch`、`drop` 在两者之间的位置**都不能变；
- **⚠️ 与 `3.2` 的"释放记录一致"是同一件事的两面**：
  展开顺序错了，释放记录必然对不上——**差分测试会同时抓到**；
- **不重开 `07B` 的展开规则**——本批是实现它，不是重新讨论它。

### 3.6 与 N0-D 的边界

**冻结**：

- **本批不做**：三目标固定宽度的**验证矩阵**（`10:54-57`）、
  **Runtime 裁剪的验证**（`10:56`、`10:78`）、**调试构建标志的产物级验证**；
- **⚠️ 但本批要保证接口留得下**：§3.3 最后一条与 §3.4 的"启动入口"
  都会**影响 D 的形态**，**实现时不能把它们做成只有本批能用的临时形态**；
- **D 的验证要建立在本批已验证的错误路径上**——**所以顺序是 C 先于 D**。

## 六、硬约束

1. **平台异常不得伪装成可恢复 Xiao 错误**（§3.1）——双向测试。

## 八、最可能翻车的地方

1. **把平台异常翻译成可捕获的 Xiao 错误**（§3.1）——用户以为只是抛了个错。
2. **反过来**：可恢复的错误在原生路径上变成进程终止（§3.1）——**更难发现**。
3. **差分只对输出、漏了错误或释放记录**（§3.2）——三样缺一不可。
4. **"错误一致"做成"都报错了"**（§3.2）——要逐项对 `code`/位置/退出码。
5. **原生侧另实现一套消息渲染**（§3.3）——本仓头号病史。
6. **`-debug` 窗口在失败时静默**（§3.4）——`10:63` 明确禁止。
7. **展开顺序与 `07B` 不一致**（§3.5）——释放记录必然对不上。
8. **把 N0-D 的验证顺手做了**（§3.6）——顺序反了，验证会建在未验证的基础上。
9. **差分留到最后才搭**（§七）——那时前几步的问题已经堆在一起，定位成本翻倍。
10. **只跑部分 crate 就说门禁全绿**（§六 第 8 条）。

## 九、验收

1. **字节码差分**：同一份 IR 经字节码与原生两条路径，**输出、错误、释放记录三样一致**
   （`12-tests:687`、`10:71`）——**逐项对照 `code`/`message_id`/参数/位置/退出码**（§3.2）。
2. **错误边界双向**：可恢复的 Xiao 错误**不终止**；平台级异常**不被 `catch` 捕获**、
   表现为不可恢复失败（§3.1）。
3. **展开顺序**：`try`/`catch`/`finally` 与 `07B` 冻结一致（§3.5）。
4. **语言上下文**：原生产物按有效语言呈现人类可读文本，
   **机器字段跨语言、跨后端一致**；**没有第二份渲染实现**（§3.3）。
5. **`-debug` 产物**：输出与字节码**可比**的错误码/堆栈位置/诊断事件；
   **直接启动自动打开独立诊断窗口**；**不依赖 `xiao` 启动器**；
   **GUI 子系统或终端不可用时也不静默取消**（`10:71`、`10:63`）。
6. **普通产物**：不携带强制诊断激活位、不自动打开诊断窗口（`10:73`）。
7. **不回归**：N0-A/N0-B、09-B0、11C 系列的用例保持绿；**`cargo test --workspace`** 全绿。
8. **门禁全绿**。
