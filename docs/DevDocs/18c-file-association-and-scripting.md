## 二、必须先冻结的 8 条

### 2.1 **三平台都实现执行体，macOS 的真实注册按 10D 门控**（已决策）

**已决策**（2026-10-05）：三个平台的执行体**都写**，**macOS 的真实注册与卸载按环境门控**。

**冻结**：

- **Windows**（注册表）、**Linux**（`.desktop` + `MimeType`）、**macOS**（`Info.plist` 关联）
  三套执行体**都要实现并各有测试**；
- **macOS 的真实注册与卸载**在无 GUI 的 CI 上无法验证——按
  [10D](10d-environment-gated-test-spec.md) 的 `#[ignore]`/skip 门控标记，
  **缺环境时明确失败或如实报告跳过**，**不得**让测试以"未覆盖"的方式变绿；
- 这与 11X0-P1、17D 的既有处置一致；**报告里不得声称 macOS 已验证**；
- **卸载必须真的可移除**——规范 `:14` 的措辞是「可安装/**可移除**」，
  卸载路径与安装路径**同样要测**，不能只测安装。

### 2.2 **安装/检查/移除是三个可独立调用的接口**

`18.9` 的措辞是「**安装、检查和移除**接口」。

**冻结**：

- **检查**必须能在**不修改任何状态**的前提下报告当前关联情况（装了没、指向哪、
  是否指向已安装的 `xiao`）——它与安装/移除的副作用面**必须分开**；
- **指向已安装的 `xiao`**：关联的命令行要能定位到实际安装位置（沿用 11X0-C 的核心发现顺序），
  **不得**写死一个安装路径；
- 查不到已安装的 `xiao` 时，**检查**报告该状态，**安装**给出清晰拒绝或提示，
  **不得**注册一个指向不存在程序的关联。

### 2.3 **非交互模式要有稳定契约，不能只是「没有输出」**

`18.10` 要求「非交互模式、详细日志和机器可读结果，便于 CI 使用」。

**冻结**：

- **非交互模式**：不等待输入、不弹提示、不依赖 TTY；已在 11X0-B 定下的
  「`NO_COLOR` 或非 TTY 自动去色」继续适用；
- **机器可读结果**：复用 18B 的 `--json` 形态与既有 `exit_code`/`diagnostics` 结构，
  **不新造响应形态**；
- **详细日志与机器结果的边界**：日志走 stderr、机器结果走 stdout，
  **不得**让日志污染机器可读输出（17C 已立过这条判据）；
- 非交互模式下**任何需要确认的操作要么有显式参数、要么拒绝**，
  **不得**默默采用默认值。

### 2.4 **四种破坏场景必须各有测试**

`18.11` 明列四类：**中断、重复执行、只读目录、并发命令**。

**冻结**，逐类对应到既有机制：

| 场景 | 要验什么 | 复用 |
| --- | --- | --- |
| **中断** | 缓存/索引不残留可被误认为有效的半成品 | 16A 的原子改名、16B 的两阶段清理 |
| **重复执行** | 幂等：第二次不产生不同结果或损坏 | 内容寻址天然幂等，要有断言 |
| **只读目录** | 读路径**不因无法写入而失败** | 16B 已把 `read_global`/`read_archive` 改为纯读 |
| **并发命令** | 跨进程锁保护，互不破坏 | `xiao-lock` 的 `EntryLock`（16B 已统一） |

**冻结**：这四类**不得**只写一句"已有机制保护"——**每类都要有可证伪的用例**，
且**删掉对应保护时用例必须失败**（沿用 20AB-FIX 立下的移除验证口径）。

### 2.5 **`18.12` 的记录要能回答「这次用的是哪份东西」**

`18.12`：「记录实际使用的**优化指纹、对象摘要和归档版本**」。

**冻结**：

- 三者都**取实际使用值**，不是"配置里写的值"——缓存命中时用的是**被命中的那个对象**的摘要；
- 与 18B 的 `cache.optimization` **同源**，**不新造第二套指纹字段**；
- 归档版本取 `ArchiveIndex` 的 schema 版本（17A 已定义）；
- 这些字段要能在 `--json` 下被 CI 采集，与 `18.10` 衔接。

### 2.6 **承接 18B 的一处缺口**

18B 的 §2.9 ② 要求：在 [18A 文档](18a-optimization-parameters-and-config.md) 的实施记录里
**写明**那处必要的既有测试改动（`["build", "main.xiao", "-O1"]` 从"抛 `X11-CLI-ARG-001`"
变成合法）与理由。

**实测 18B 的三份提交里没有 `18a-*.md`**——这处说明**仍未补**。

**冻结**：补写，**不得**让后人看到"改了既有测试却没说"。

### 2.7 **`18.13` 的 GUI 子系统验证只能在本机做，必须如实标注**

`18.13` 要求验证「调试版原生产物**脱离 `xiao` 启动器、以 GUI 子系统启动时仍须开窗**」。

**冻结**：

- 复用 11X0-D 的机制与 17D 已接的归档路径，**不新造**；
- **GUI 子系统场景**（`windows_subsystem = "windows"` 之类）在无 GUI 的 CI 上无法验证
  ——**与本批 §2.1 的 macOS 同一处境**：按 10D 门控，**如实标注"本机验证"**，
  **不得**写成"CI 已验证"；
- 17D 时这条是**源码字符串断言**（`toolchain.rs:1321` 检查源码含 `CREATE_NEW_CONSOLE`），
  `11x0p1:363-364` 自己也点名过那是文本断言——**本批至少要给出行为证据**，
  而**不能只保留文本断言**。

### 2.8 **不重开 17D/11X0-D/18B 的既有冻结面**

**冻结**：

- **不改** 17D 已冻结的关联模型与双击行为契约（cwd 不可依赖、退出码一致）——只**实现**它；
- **不改** 11X0-D 的三处裁定（诊断进程位置、平台终端启动、管道/套接字）；
- **不改** 18B 的 `verify`/`cache` 接口与 `cache.optimization` 字段形态；
- **不重开** 19 的发布验收范围。
