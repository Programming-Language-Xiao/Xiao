## 二、⚠️ 本批最大的技术点：**fish 不是 POSIX Shell**

bash 与 zsh 可以共用同一套钩子（都用 `PS1`、都用 `export`、都用 `function`），
**fish 三个都不一样**：

| | bash / zsh | fish |
| --- | --- | --- |
| 提示符 | 变量 `PS1` | **函数 `fish_prompt`** |
| 环境变量 | `export X=Y` | **`set -x X Y`** |
| 函数定义 | `f() { … }` / `function f { … }` | **`function f; …; end`** |
| 保存原值 | `[[ -z "${X+x}" ]]` | **`set -q X`** |

**所以 fish 支持不是"加一个分支"，而是要按它的模型重写一遍提示符钩子。**

**⚠️ 关键约束**：fish 的 `fish_prompt` 是**用户可能已经定义过的函数**——
内置的默认提示符就是它。所以：

- **必须先保存用户原有的 `fish_prompt`**（`functions -c fish_prompt __xiao_original_prompt` 之类），
  **不能直接覆盖**；
- 取消激活时要**恢复**原函数；
- **重复激活不得叠加**（与 E0 对 bash 的要求一致）。

**这一条是 fish 最容易做错的地方**——bash 那边"保存 `PS1` 字符串"是平凡的，
fish 这边要保存的是**函数定义**。

## 三、必须先冻结的 5 条

### 3.1 Shell 矩阵（**已定**）

```
bash          已有
zsh           新增（macOS 默认）
fish          新增（机制不同，见 §二）
powershell    已有
cmd           降级——**不声称自动激活**，输出手工激活提示（保持 E0 口径）
```

**⚠️ 不认识的 Shell 必须有稳定诊断**，不能落进 `cmd` 分支冒充（现状即如此，
本批要把它变成明确诊断 + 列出支持的矩阵）。

### 3.2 安装：标记块 + 备份 + 可移除（**已定**）

- **默认行为不变**：`xiao shell-init <shell>` 只输出（保持 `11a:63` 的 E0 口径）；
- **`--install` 显式安装**：写入目标 profile，用**标记块**包围：

```sh
# >>> xiao init >>>
...
# <<< xiao init <<<
```

**要冻结的三件事**：

1. **幂等**：重复 `--install` **不叠加**（先移除已有标记块再写，或检测后跳过）；
2. **备份**：写入前备份原文件（`.bak` 或带时间戳），**并在输出里告知备份路径**；
3. **可精确移除**：提供卸载路径，**只删标记块内的内容**，不动用户的其他配置。

**⚠️ 目标 profile 的判定要显式**：`~/.bashrc` vs `~/.bash_profile` vs `~/.zshrc` vs
fish 的 `~/.config/fish/config.fish`（**注意 fish 的配置不在 `$HOME` 根下**）。
**不要猜**——要么让用户指定，要么按明确规则选并**在输出里说明选了哪个**。

**⚠️ 不要自动创建不存在的 profile 目录**（fish 的 `~/.config/fish/` 不存在时怎么办？
要定，且失败要明确）。

### 3.3 新增 Shell 必须走**同一个激活协议**

E2B 冻结的通道是：钩子 `export XIAO_ACTIVATION_FILE=<临时文件>` → `xiao` 写两行 →
钩子**校验后**提取路径并赋值（**不 `source`**）。

**zsh 与 fish 必须走同一条**：

- **zsh**：几乎可直接复用 bash 的脚本（`PS1`/`export` 都有），**但要注意 zsh 的数组下标从 1 开始**
  ——若脚本里有 `${arr[0]}` 之类的写法会错位；
- **fish**：`set -x XIAO_ACTIVATION_FILE <path>` + 同样的两行校验逻辑，
  但**解析要用 fish 的语法**（`string split` 等）。

**⚠️ 白名单校验规则必须与 E2B 一致**（恰好两行、变量名固定、路径必须绝对、无控制字符）。
**四份实现（bash/zsh/fish/powershell）各写一套校验正是本仓头号病史**——
**校验规则要写成夹具向量，四份实现共同消费**（同 JCS 向量的做法）。

### 3.4 取消激活的"生产级"含义

`11a:66` 说「生产级取消激活命令留给 E4」，本批接过来。要冻结它比 E0 多了什么：

- **移除安装**（若用过 `--install`）与**取消激活当前会话**是**两件事**，要分开；
- **未激活时执行**不应报错（幂等），也不应破坏提示符；
- **fish 要能恢复原 `fish_prompt` 函数**（§二）。

### 3.5 跨平台测试怎么做

`12-tests:790` 要求「通过**跨平台测试**」。**⚠️ 不能真去起 zsh/fish**（CI 环境未必有）。

**冻结**：

- 沿用 E0/E2B 的**可注入 Shell 状态模型**（不引伪终端，`11ae0` 的冻结口径）；
- **每个 Shell 的脚本文本本身要有规格夹具**（断言生成的脚本包含什么、不含什么）；
- **真实父终端测试保持 E0 的显式门控**（`#[ignore]`），不放进 CI 默认路径。

### 3.6 工具链安装：**评估，不实现**

`11a:515` 的措辞是「**评估**工具链安装和其他全局命令」。本批**出一份结论**
（该不该做、边界在哪），**不实现**。**⚠️ 不要在文档里把"评估"写成"实现"**——
这会让退出条件看起来满足了而实际没有。

## 八、最可能翻车的地方

1. **fish 直接覆盖 `fish_prompt`**（§二）——用户的原提示符就没了。
2. **四份实现各写一套校验**（§3.3）——本仓头号病史。
3. **zsh 里照抄 bash 的 `${arr[0]}`**（§3.3）——zsh 下标从 1 开始。
4. **`--install` 重复执行叠加标记块**（§3.2）。
5. **安装后无法移除**，或移除时误删用户配置。
6. **`~/.config/fish/` 不存在时静默失败或乱创建**（§3.2）。
7. **不认识的 Shell 落进 `cmd` 分支冒充**（§3.1）——现在是这个行为，要改成明确诊断。
8. **把"评估工具链安装"做成了实现**（§3.6）——或反过来，把没做的说成做了。

## 九、验收

1. **矩阵**：bash / zsh / fish / powershell 各有夹具；`cmd` 降级不声称激活；
   不认识的 Shell 有稳定诊断（§3.1）。
2. **fish 原提示符**：安装→取消后**用户的 `fish_prompt` 复原**（§二 反例）。
3. **校验向量**：四份实现**消费同一份向量**，且非法内容（第三行、相对路径、带换行）
   在四者上**都被拒绝**。
4. **安装**：重复 `--install` 不叠加；备份路径被输出；移除只删标记块；
   fish 的 `~/.config/fish/` 缺失时行为明确。
5. **取消激活**：未激活时执行不报错、不破坏提示符；与"移除安装"是两条路径。
6. **跨平台测试**：用可注入模型；真实终端按 E0 的显式门控。
7. **工具链安装**：有明确的评估结论，**且没有把它说成已实现**。
8. **门禁全绿**。
