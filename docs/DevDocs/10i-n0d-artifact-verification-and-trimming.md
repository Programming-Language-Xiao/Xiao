## 三、必须先冻结的 6 条

### 3.1 ⚠️ **IR 层没调用 ≠ 链接后没有符号**（本批最容易糊弄过去的地方）

`LlvmModule.uses_runtime == false` 与 `runtime_components.is_empty()` 是**IR 层**的证据；
`10:78` 要的是「**纯静态标量程序不会因为动态运行时能力而完整装载 Runtime**」——
那是**产物层**的陈述。

**冻结**：

- **两层都要有证据**：IR 层（已有）+ **链接后产物**（本批要补）；
- **产物层的验证方式**：检查链接后可执行文件的**符号表/依赖**里**不含未使用的 Runtime 组件**
  （如纯静态程序不应出现 `weak`/`tables` 相关符号或对 Runtime 库的引用）；
- **⚠️ 不接受"IR 里没有"当作"产物里没有"**——链接器会按需拉取静态库成员，
  **IR 干净但产物拖进一整块 Runtime 是完全可能的**；
- **反例也要有**：一个**确实用了**容器的程序，在产物里**应当**能看到对应组件——
  否则"什么都没找到"可能只是**探测方法失效**，而不是真的裁掉了。

### 3.2 三目标验证：**用受控描述与适配器，不依赖主机工具链发现**

`10:57`：**「通过受控目标描述和测试适配器验证三个目标的固定宽度与错误行为；
主机工具链自动发现留到第 11 阶段。」**

**冻结**：

- **"三个目标" = 三个对象格式**：`Coff`（Windows）/ `Elf`（Linux）/ `MachO`（macOS）
  （`target.rs:16-23`）；
- **验证的是目标描述层**：固定宽度字段、错误行为（越界/窄化/类型不匹配）；
- **⚠️ 本批不做交叉编译，也不做主机工具链自动发现**——那是第 11 阶段（X0）的事；
  **不要把"找不到交叉编译器"当成阻塞**，那本来就不在本批范围；
- **三个格式的验证要等价**——不能只把 Windows 那条跑通，另两个靠"结构相同"推断。

### 3.3 Runtime 组成**可解释**（`10:79`）

`10:79`：「构建产物的 Runtime 组成**可以通过诊断选项解释**」。

**冻结**：

- `runtime_components` 目前只进 `LlvmModule`，**要接一个诊断出口**，
  让"这个产物为什么带/不带某个组件"**可被查询**；
- **只报事实，不解释成因**——本批不做"为什么"的推理，那是后续优化接口的事；
- **与 `-debug` 的诊断选项边界划清**（`-debug` 是调试窗口，本条是构建产物的组成查询）。

### 3.4 调试构建标志的**产物级**验证（从 10H §3.6 划来）

10H 做完了 `-debug` 的**启动入口**与三不（不依赖启动器/不受 GUI 抑制/失败不静默），
但**"调试构建标志"的产物级验证矩阵**划到了本批。

**冻结**：

- 验证 `-debug` 与普通产物的**产物差异**是**受控的**：只有诊断相关部分不同，
  业务逻辑产物一致；
- **普通产物不带激活位**已由 10H 的三条反向测试覆盖（IR 层），
  **本批补产物层**（§3.1 同款要求）；
- **不重开 10H 的三不**。

### 3.5 未优化基线（`10:80`）

`10:80`：「**未优化基线可以独立生成**；第 15 阶段加入的任何优化级别都必须与该基线进行语义差分。」

**冻结**：

- **本批只保证基线可独立生成且被记录**（`-O0` 路径）；
- **不做任何优化级别**——15 阶段的事；
- **但要留下差分的接口**：基线产物要能被第 15 阶段拿来做语义对照（沿用 10G 的差分口径）。

### 3.6 与相邻批次的边界

**冻结**：

- **不做 11 阶段（X0）**：主机工具链自动发现、用户可见 `xiao build`、跨平台打包；
- **不做 15 阶段**：规范化优化配置、Pass 报告、目标特化、优化级别；
- **不重开** N0-A 的档位边界、N0-B 的 ABI 选型、N0-C 的错误路径与诊断设计；
- **本批做完，10 阶段的四个批次全部收口**。

## 八、最可能翻车的地方

1. **把 IR 层的干净当成产物的裁剪**（§3.1）——链接器按需拉取静态库成员，
   **IR 干净而产物拖进整块 Runtime 完全可能**。这是本批头号陷阱。
2. **裁剪验证没有反例**（§3.1）——"什么都没找到"可能只是**探测方法失效**。
3. **三目标只跑通一个再推断另两个**（§3.2）——三个对象格式各有各的边角。
4. **试图做交叉编译或主机工具链发现**（§3.2）——那明确是第 11 阶段，**不是本批的阻塞项**。
5. **带着未知的 CI 状态往下做**（§二）——地基没验，上面全是悬的。
6. **组成查询顺手做"成因推理"**（§3.3）——本批只报事实。
7. **顺手做了优化级别**（§3.5）——15 阶段的事，且会污染基线差分的前提。
8. **诊断相关测试忘了 `XIAO_DIAGNOSTICS_PATH`**（§六 第 9 条）——10H 刚踩过的坑，
   表现为"终端环境问题"，极难定位。
9. **忘了两个 lock 文件**（§六 第 8 条）。
10. **只跑部分 crate 就说门禁全绿**（§六 第 8 条）。
