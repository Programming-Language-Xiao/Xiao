# 静态 LLVM 浮点相等比较独立修复规划

> 2026-11-16（立项时）：产品修复未开始。B5 已在固定 B4 产品 `cfa79381` 直接复现；本项不阻断 B5 的版本矩阵，但必须保留独立缺陷及后续修复入口。

> 2026-11-17：Windows基线发现Float/Sfloat静态`==`生成非法LLVM，静态`!=`存在异号零语义差异。星崽已批准按位相等/不等修复和生成器21→22；本机产品实施及验收已完成，ABI保持1.19，跨平台与远端CI未验证。

## 一、问题与固定证据

静态比较降低器在浮点 `==` 分支选择整数谓词 `eq`，随后选择 `fcmp` 指令，产生 LLVM 不接受的 `fcmp eq double`。位置为 `core/rust/crates/xiao-codegen-llvm/src/ir.rs` 的 `emit_binary_values`。该代码也处理 `sfloat`，修复时须一并核对，不能只验证 B5 暴露的 Float pow 表达式。

最小复现：

```xiao
def probe(float a, float b) -> float
    return a ** b
probe(2.0, 3.0) == 8.0
```

[B5 原始问题记录](assets/20o-b2-b/entry-20261116-b5-rebuild/known-issues.json)固定了旧/新失败回执、复现源码摘要及旧快照提交。旧宿主忽略可选源码参数的首次尝试已明确排除；采用的是 `b4/static-float-equality-reproduction.json` 的直接复现。历史证据保持只读。

## 二、独立实施范围

1. 先核对语言和 VM 对有限 Float/Sfloat 的 `==`、`!=`、异号零及混合数值提升的既有语义，列出静态/动态对照矩阵。
2. 静态Float/Sfloat比较在共同数值提升后按位处理`==`与`!=`，保留异号零语义；整数、布尔、排序、非有限值入口和cmath/pow内核不变。
3. 增加真实参数形态，避免常量折叠掩盖降低；覆盖相等、不相等、正负零、Float/Sfloat 及既有混合提升。
4. 对生成文本运行真实 `llvm-as`，并在原生 O0/O3 执行，与 VM 及动态路径比较结果。保留上述最小复现作为永久回归。
5. lowering文本语义变化须将生成器21升至22，并独立验证元数据拒绝与缓存失配；不得修改已冻结B5的1.19/21矩阵。

本页原只建立修复任务；2026-11-17星崽另行明确批准按位`==`/`!=`修复及生成器21→22。ABI、intrinsic、标准库接口、registry、UseDocs、22C/22D与19/11/22债务不在本项范围。

## 三、验收与交接

- 所有相关静态生成文本都能被真实 LLVM 汇编器接受，不再产生 `fcmp eq`。
- VM、静态/动态原生 O0/O3 的值和错误边界一致；整数/布尔比较及共享 Float pow 回归通过。
- 修复提交、源码、Runtime、生成器/缓存、工具、执行命令和日志均有独立身份；B5 用 C 位模式观察数值的旧证据不冒充本项回归。
- 新目录保存独立结果；本机实施已完成，三平台与远端CI未执行时不扩大为最终发布验收。

### 4.1 已核对的语义入口

静态比较在 ir.rs 的 emit_binary_values 中，先使用 common_numeric 得到共同操作数类型，再选择 icmp 或 fcmp。Float 和 Sfloat 都属于 common.is_float()，而当前相等分支无条件选择 eq；因此两种静态浮点宽度都需要覆盖。布尔比较已经单独使用 icmp eq，不能改动这一分支。

[Runtime 语言入口](../../core/rust/crates/xiao-runtime/src/value/language.rs)的 language_binary 对混合数值先执行 binary_operand_scalar 规定的提升，再执行实际算子；[VM 比较入口](../../core/rust/crates/xiao-vm/src/ops.rs)也委托该入口。混合用例的黄金必须来自这一语言语义，不能直接调用不同标签的结构相等方法作为参照。现有 Runtime 单元规格还明确登记了 int 9007199254740993 与 float 9007199254740992.0 在语言提升后相等的边界；本项不改写该规则。

有限数值、异号零及混合提升沿既有语言语义验收；不借此开放 NaN/Inf 源码输入，也不修改非有限值的既有入口和错误边界。

Runtime 的 Float/Sfloat 相等实现比较 `to_bits()`，哈希也采用位模式。探针直接调用语言入口，并以真实函数参数在 VM、默认降低和打印动态路径复核，得到以下事实：

| 基线观察 | 实际结果 |
| --- | --- |
| VM | 16组均成功；Float/Sfloat 异号零 `==` 为false、`!=` 为true，同号负零 `==` 为true |
| 打印动态原生 | 16组×O0/O3共32次汇编、构建、执行，与VM输出一致 |
| 默认降低中的浮点相等 | 12组×O0/O3共24份文本均由真实llvm-as拒绝，实际错误为非法 `fcmp eq double/float`；未执行原生产物 |
| 默认降低中的异号零不等 | Float/Sfloat×O0/O3共4次汇编和执行成功，但布尔观察为false，与VM及动态路径的true不一致 |
| 整数/布尔对照 | 2组×O0/O3共4次汇编和执行，与VM一致 |

默认降低的局部静态比较可能与 Runtime 辅助调用共存；记录中的 `actual_uses_runtime=true` 不能单独证明整段程序走动态比较。应同时检查归档LLVM中的比较指令及动态入口。静态布尔观察使用测试入口退出码：0表示false、1表示true，不能把1误报为执行失败。

`oeq`会把异号零判为相等，因此未采用。最终实现按提升后位模式比较，保留已有Runtime语言语义。

### 4.2 已批准并实施的产品修改

实现保留 `common_numeric` 和两侧 `cast_value` 的提升顺序，然后仅对共同类型为 Float/Sfloat 的 `==`、`!=` 使用位模式比较：

1. Float 两侧分别由double按位转换为i64，Sfloat两侧分别由float按位转换为i32；使用LLVM `bitcast`，不进行数值整数转换。
2. 相等使用对应宽度的 `icmp eq`，不等使用 `icmp ne`。比较对象是提升后的值，不能比较原始不同标签的载荷。
3. 整数与布尔继续原有整数比较；排序分支继续原有有序浮点谓词。不修改 Runtime Eq/Hash、动态语言算子、数值提升、所有权或 cmath/pow 内核。

星崽已明确批准同时修复`==`与`!=`。产品代码在共同数值提升后将Float按位转换为i64、Sfloat按位转换为i32，并发射icmp eq/ne。整数、布尔、排序、动态Runtime、所有权和cmath/pow内核不变。

[后端版本规则](../../core/rust/crates/xiao-codegen-llvm/README.md)要求改变生成文本的lowering语义递增版本。本项已将CODEGEN_VERSION从21升至22，ABI保持1.19、标准库接口保持1，元数据格式、字节码与归档格式不变。

driver现行快照测试current_artifacts_bind_exact_abi19_and_current_codegen及B4 cmath现行断言已同步到22；B1/B4历史夹具20/21身份断言保持不变，固定B5的1.19/21证据未改写。
