# 静态 LLVM 浮点相等比较独立修复规划

> 2026-11-16：已立项，产品修复未开始。B5 已在固定 B4 产品 `cfa79381` 直接复现；本项不阻断 B5 的版本矩阵，但必须保留独立缺陷及后续修复入口。

> 2026-11-17：已完成 Windows 本机生成器21基线复核。Float/Sfloat 的静态 `==` 均产生非法 LLVM；静态 `!=` 还存在异号零与 VM 不一致的问题。原 `oeq` 候选已撤回，修订方案和生成器22均待实际裁定，产品修复仍未开始。

## 一、问题与固定证据

静态比较降低器在浮点 `==` 分支选择整数谓词 `eq`，随后选择 `fcmp` 指令，产生 LLVM 不接受的 `fcmp eq double`。位置为 `core/rust/crates/xiao-codegen-llvm/src/ir.rs` 的 `emit_binary_values`。该代码也处理 `sfloat`，修复时须一并核对，不能只验证 B5 暴露的 Float pow 表达式。

最小复现：

```xiao
def probe(float a, float b) -> float
    return a ** b
probe(2.0, 3.0) == 8.0
```

[B5 原始问题记录](assets/20o-b2-b/entry-20261116-b5-rebuild/known-issues.json)固定了旧/新失败回执、复现源码摘要及旧快照提交。旧宿主忽略可选源码参数的首次尝试已明确排除；采用的是 `b4/static-float-equality-reproduction.json` 的直接复现。历史证据保持只读。

## 二、独立实施范围

1. 先核对语言和 VM 对有限 Float/Sfloat 的 `==`、`!=`、异号零及混合数值提升的既有语义，列出静态/动态对照矩阵。
2. 静态浮点相等须保留既有 VM 语义。原先预期 `oeq`、不修改 `!=` 的方案已被§4的实测推翻；现建议在共同数值提升后，以按位比较同时对齐 `==` 与 `!=`，扩大到 `!=` 的范围须另获明确裁定。整数与布尔比较、排序、非有限输入边界和 cmath/pow 数学内核保持原范围。
3. 增加真实参数形态，避免常量折叠掩盖降低；覆盖相等、不相等、正负零、Float/Sfloat 及既有混合提升。
4. 对生成文本运行真实 `llvm-as`，并在原生 O0/O3 执行，与 VM 及动态路径比较结果。保留上述最小复现作为永久回归。
5. 核对后端指纹版本规则。若修复要求生成器21递增，须作为独立版本变更明确裁定后实施；不得借此修改已冻结 B5 的1.19/21矩阵或伪称旧缓存已失效。

本页只建立修复任务，不授权本轮改产品、改生成器或重写 B5 旧取证。ABI、intrinsic、标准库接口、registry、UseDocs、22C/22D与19/11/22债务不在本项范围。

## 三、验收与交接

- 所有相关静态生成文本都能被真实 LLVM 汇编器接受，不再产生 `fcmp eq`。
- VM、静态/动态原生 O0/O3 的值和错误边界一致；整数/布尔比较及共享 Float pow 回归通过。
- 修复提交、源码、Runtime、生成器/缓存、工具、执行命令和日志均有独立身份；B5 用 C 位模式观察数值的旧证据不冒充本项回归。
- 新目录保存独立结果；修复完成前，本问题保持未关闭。三平台未执行时只报告实际平台，不扩大为最终发布验收。

## 四、2026-11-17 源码复核与待裁定执行单

本节基于固定入口 `816866cda9e66fb0ce6a25c7e45d413cfa6a6627` 的复核。实际探针复用固定 `5864cbde627f727483ab676c6f4bc1bf0a7819bb` 的已登记调试库和 Runtime；这两个提交的本项受保护产品路径无差异，构建来源、依赖指纹和字节摘要另见[基线证据](assets/20o-b2-static-float-equality/entry-20261117-review/README.md)。这不是新冷构建，也不是当前文档提交重新构建后的产品验收。

当前仍为 ABI1.19、生成器21、标准库接口1，产品修复和增版均未执行。此前问题卡基于 `oeq` 候选，且尚未收到答复；该候选现已撤回，不能将工具接收问题卡、用户未答复或之后的笼统答复视作对修订方案的批准。以下分开登记实测事实与待裁定方案。

### 4.1 已核对的语义入口

静态比较在 ir.rs 的 emit_binary_values 中，先使用 common_numeric 得到共同操作数类型，再选择 icmp 或 fcmp。Float 和 Sfloat 都属于 common.is_float()，而当前相等分支无条件选择 eq；因此两种静态浮点宽度都需要覆盖。布尔比较已经单独使用 icmp eq，不能改动这一分支。

[Runtime 语言入口](../../core/rust/crates/xiao-runtime/src/value/language.rs)的 language_binary 对混合数值先执行 binary_operand_scalar 规定的提升，再执行实际算子；[VM 比较入口](../../core/rust/crates/xiao-vm/src/ops.rs)也委托该入口。混合用例的黄金必须来自这一语言语义，不能直接调用不同标签的结构相等方法作为参照。现有 Runtime 单元规格还明确登记了 int 9007199254740993 与 float 9007199254740992.0 在语言提升后相等的边界；本项不改写该规则。

有限数值、异号零及混合提升沿既有语言语义验收；不借此开放 NaN/Inf 源码输入，也不修改非有限值的既有入口和错误边界。

Runtime 的 Float/Sfloat 相等实现比较 `to_bits()`，哈希也采用位模式。探针直接调用语言入口，并以真实函数参数在 VM、默认降低和打印动态路径复核，得到以下事实：

| 基线观察 | 实际结果 |
| --- | --- |
| VM | 16组均成功；Float/Sfloat 异号零 `==` 为false、`!=` 为true，同号负零 `==` 为true |
| 打印动态原生 | 16组×O0/O3共32次汇编、构建、执行，与VM输出一致 |
| 默认降低中的浮点相等 | 12组×O0/O3共24份文本均由真实llvm-as拒绝，实际错误为非法 `fcmp eq double/float`；未执行原生产物 |
| 默认降低中的异号零不等 | Float/Sfloat×O0/O3共4次汇编和执行成功，但布尔观察为false，与VM及动态路径的true不一致 |
| 整数/布尔对照 | 2组×O0/O3共4次汇编和执行，与VM一致 |

默认降低的局部静态比较可能与 Runtime 辅助调用共存；记录中的 `actual_uses_runtime=true` 不能单独证明整段程序走动态比较。应同时检查归档LLVM中的比较指令及动态入口。静态布尔观察使用测试入口退出码：0表示false、1表示true，不能把1误报为执行失败。

`oeq` 会把异号零判为相等，不能保持这组已有语言行为；只把非法谓词替换成合法谓词不足以验收。本机探针完成不代表缺陷修复，当前缺陷继续开放。

### 4.2 修订后的待裁定产品方案

建议保留 `common_numeric` 和两侧 `cast_value` 的提升顺序，然后仅对共同类型为 Float/Sfloat 的 `==`、`!=` 使用位模式比较：

1. Float 两侧分别由double按位转换为i64，Sfloat两侧分别由float按位转换为i32；使用LLVM `bitcast`，不进行数值整数转换。
2. 相等使用对应宽度的 `icmp eq`，不等使用 `icmp ne`。比较对象是提升后的值，不能比较原始不同标签的载荷。
3. 整数与布尔继续原有整数比较；排序分支继续原有有序浮点谓词。不修改 Runtime Eq/Hash、动态语言算子、数值提升、所有权或 cmath/pow 内核。

这是保留现有语义的实施候选，尚未写入产品或验收。原规划明确排除 `!=`，本次实测暴露了相关缺陷，因此须明确批准将它纳入，而不能静默扩大范围。若只批准相等修复，不等缺陷须独立保持开放，不能宣称所有比较路径已一致。

[后端版本规则](../../core/rust/crates/xiao-codegen-llvm/README.md)要求改变生成文本的 lowering 语义递增版本。因此产品实施须与独立的 CODEGEN_VERSION 21→22 同批执行，ABI维持1.19、标准库接口维持1，元数据格式、字节码与归档格式不变。不得在版本裁定前应用产品补丁，也不得通过保留版本21绕过缓存隔离。

当前 driver 测试 `current_artifacts_bind_exact_abi19_and_codegen21` 对现行生成器写死21，`20o_b2_b4_cmath_llvm.rs` 也有现行版本名称、指纹前缀与断言。若本项获批，应同步更新现行快照断言和测试名称，并增加新元数据与生成器常量一致的断言；B1/B4历史夹具的20/21身份断言继续保留。当前测试的调整不改变固定B5快照曾以1.19/21取证的事实。

### 4.3 计划回归矩阵

下表均为修复后的待执行项；§4.1只有未修复基线证据，不能冒充这里的通过结果。

| 层 | 输入或条件 | 预期与核对范围 |
| --- | --- | --- |
| Float 相等 | 真实形参1.5与1.5、1.5与2.0 | 分别为true、false；候选为double按位转换后比较i64 |
| Sfloat 相等 | 真实形参sfloat(1.5)与相同/不同值 | 对应true、false；候选为float按位转换后比较i32 |
| 有符号零 | Float/Sfloat各自的+0与-0、同号零 | 异号零相等为false、不等为true；同号零相等为true，正反方向均核对 |
| 混合提升 | int/float、sint/sfloat、sfloat/float的既有合法组合 | 与同源VM语言提升一致；包含9007199254740993的既有舍入边界 |
| 不等与排序 | 真实参数的普通有限值、同号/异号零及原有排序用例 | 不等若获批则按位比较并与相等互补；排序保持原有行为 |
| 整数与布尔 | 相等和不相等的正反例 | 继续生成icmp；不得被浮点专用匹配误伤 |
| 原始复现 | probe(2.0, 3.0) == 8.0 | 真实llvm-as接受，原生O0/O3与VM结果一致，Float幂仍共用cmath_pow |
| 路由守卫 | numeric_range整数、Float pow、混合程序、sfloat pow | 保留FIX.1的整数动态/weak、Float共享核及sfloat既有路径 |

每组须使用真实函数参数，并分别核对局部比较指令、实际Runtime依赖和动态降低入口。LLVM文本断言之外，还须运行真实llvm-as和原生O0/O3；不能以“没有搜索到fcmp eq”替代汇编及执行证据。复用现有N0-A、driver原生观察面和B4路由回归，测试数据及实际执行范围在实施证据中单列。已撤回的 `rejected-oeq-test.rs` 没有编译执行，不属于产品回归。

### 4.5 裁定前后顺序

裁定前只进行基线复核、复现和本执行单完善，当前产品和生成器保持原状。需针对§4.2的按位相等/不等方案与21→22取得明确的独立实施授权；原 `oeq` 问题卡不再代表修订后的请求。获批后依次执行比较修复与增版、真实回归、元数据及缓存矩阵、适用工作区门禁、最终文档与证据审计。

所有新证据另建目录，绑定实际源码、工具、Runtime、执行文件、命令和原始日志。URL默认workspace看门狗阻塞继续独立保留；本项不得放宽其预算或将其写成已经解决。cmath教程/registry、三平台发布及B2-C完整721不因本修复自动升级，22C/22D与19/11/22债务也不核销。
