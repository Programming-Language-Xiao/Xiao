# 20O-B2-B5. ABI 1.19、生成器 21 与拒绝矩阵实施规划

> **2026-11-13 版本裁定执行：星崽在本会话已批准“B4 升到生成器21，更新规划并调整B5边界”。B4-3改LLVM调用文本，按后端版本规则20→21；ABI仍1.18、接口1。B5只将ABI升1.19并核验既有生成器21的最终拒绝/重生成矩阵，不再次因本批接线递增生成器。下文将21留B5或B4不得升21的旧句均由本裁定替代；签署的冻结正文及历史证据不改写。**

> **B4-0/B4-1 已完成 Windows 本机内部验收；B4-2A 与 FIX1 已完成 Windows 本机退出；B4-2B已完成Windows内部验收；B4-3实施中，B4-4/B4-5尚未完成；B5仍未开始，B6、B7与B2-C后置。**
> B5 开工入口必须是 B4-5 内部收口后的固定源码与证据；B4-3前历史版本为ABI1.18/生成器20；当前B4-3产品接线已提交为`4be30eaf`，`CODEGEN_VERSION=21`，固定冷构建与O0/O3矩阵验收中；B4-3退出后仍固定为ABI1.18/生成器21、接口1。
> B5只将ABI升级到1.19，CODEGEN_VERSION沿用B4-3的21，完成旧/新产物拒绝、缓存重生成和C ABI加法扩展。
> B5 不新增 cmath 数学语义或语言接线；B4 全链路内部验收是开工前置。不升级 registry/教程、不跑旧 721；B2-C 才做最终公共发布。

## 一、入口与范围

| 项 | 当前状态 |

| B4-0/B4-1 | 已完成 Windows 本机内部验收；不代表 B4 全链路完成 |
| B4-2A | 已完成 Windows 本机退出；仅为内部 TAC/字节码批次 |
| B4-3～B4-5 | 尚未完成；B4-2B已完成Windows内部验收；B4-5内部收口是B5开工前置 |
| 历史入口版本 | ABI 1.18、`CODEGEN_VERSION=20`、标准库接口1、活动intrinsic1～48 |
| B4-3退出版本 | ABI 1.18、`CODEGEN_VERSION=21`、标准库接口1；产品接线提交`4be30eaf`，fixed验收仍进行中 |
| B5 目标 | ABI1.19（编码`0x0001_0013`）、生成器仍为21、接口1 |
| 产物 | `.xiaoc`/`.xar` 精确 1.19、原生元数据 1.19/21、标准库身份 1 |
| 兼容 | 旧 1.18 原件拒绝；新 1.19 被旧 1.18 验证器拒绝；B4-3生成器20历史缓存因生成器变更失效；B5再使1.18/21过渡缓存因ABI变化失效 |
| F-6a 历史 ABI 基线 | 以冻结的 B1 原始 1.18 产物/旧 Runtime 为准；这是拒绝矩阵与旧调用方兼容的历史参照 |

| 未做 | B6 资源/性能、B7 收口、B2-C 721/教程/registry/三平台最终发布 |

B5 是 **版本矩阵内部切换批**，不是 B2-C 最终发布。开工前要求 B4-5 已记录内部 `language_available=true`，公开 `stdlib.cmath`/UseDocs/registry 仍 planned。B5 的产物仍只作内部验证；最终三平台公共产物、完整 721 和 registry 升级留 B2-C。

### 1.1 要做

1. ABI 次版本 1.19（编码 `0x0001_0013`）、生成器 21、标准库接口保持 1，intrinsic 1～48 与 ID 100 墓碑不变；
2. `.xiaoc` 头、`.xar` 索引和指令流记录精确 1.19；
3. 原生元数据记录 1.19/21 和标准库身份 1；
4. B1 原始 1.18 `.xiaoc`/`.xar`/原生元数据按 F-6a 在执行前拒绝，原件不改写；
5. 新 1.19 `.xiaoc`/`.xar`/原生元数据被固定身份的旧 1.18 验证器拒绝；
6. 生成器20旧缓存在B4-3已失配；B5验证1.18/21过渡缓存因ABI失配重生成，不复用对象；
7. 保留 B5 入口实际存在的全部 1.18 C 符号/布局/调用约定；本批不得移除、重命名、重编号或改变旧入口语义；如另有新增 C 入口，必须单列符号清单并只做加法；
8. 保存旧/新拒绝、缓存重生成、B1 20 入口回归和版本身份证据。

### 1.2 明确不做

- 不手改旧 `.xiaoc`/`.xar` 头或放宽 max 版本；
- 不增加迁移工具或“兼容重放”旧原件；
- 不改变容器格式/索引 schema 版本；
- 不升级 `stdlib.cmath`/registry/教程；
- 不跑旧 721，不关闭 22C/22D、19/11/22；
- 不把 B5 内部 1.19/21 写成 B2-C 最终发布或三平台产品。

## 二、开工闸门

1. B4-1～B4-5 审计通过，B4-5 已记录内部 `language_available=true`；最终产品/证据身份固定；
2. 15 项 cmath 内部语言链路、30 条导入、双路径/归档/序列化可复现；
3. 当前B4-3工作树ABI1.18、`CODEGEN_VERSION=21`、接口1、cmath planned；开工前须固定B4-3已提交快照；
4. F-6a 登记的 B1 原始 1.18 `.xiaoc`/`.xar`/原生元数据原件可从归档按原始字节读取并计算摘要；缺失时阻断，不用新版本重造旧原件；
5. 固定身份旧1.18验证器/Runtime、生成器20历史缓存与1.18/21过渡缓存的源码、构建参数、产物摘要可复现；
6. F-6a 历史 C ABI 符号/布局/调用约定和 B4当前内部1.18/21过渡符号表分别保存，不能混为同一个版本快照；
7. 唯一任务根、独立 target/Runtime/缓存已建立。

## 三、分批执行

### B5-0：版本/产物基线

1. 固定B4-5最终源码、B1原始1.18产物、旧验证器/Runtime、生成器20历史缓存及B4生成器21过渡缓存；
2. 为 F-6a 每个原始产物记录来源、原始字节数和 SHA-256，并记录 `.xiaoc` 头、`.xar` 索引、指令流 runtime ABI、原生元数据中的 ABI/生成器/标准库身份；
3. 分别生成并保存 F-6a 历史 1.18 C 符号/布局清单与 B4-3退出后的内部1.18/21源码快照清单；后者当前已含 `xiao_runtime_lfloat_divide` 和 `xiao_runtime_cmath_*`，不据此改写历史基线；
4. 固定旧 1.18 验证器/Runtime 的源码提交、构建工具链、二进制/静态库 SHA-256；版本字符串不能单独证明旧验证器身份；
5. 分别记录生成器20历史缓存与21过渡缓存的源码、目标、优化计划、ABI 与 Runtime 静态库身份；
6. 保存只读基线清单与原始文件摘要。

退出：两类 1.18 基线、产物/验证器/缓存/C 符号身份可分别复现；旧原件保持未改写。

### B5-1：ABI 1.19（生成器沿用21）

1. `ABI_MINOR_VERSION=19`，由 `encoded_abi_version(1, 19)` 得到 `0x0001_0013`；主版本仍 1；
2. `CODEGEN_VERSION`沿用21；ABI变化本身不导致生成器再次升级；标准库接口保持1；
3. `.xiaoc` 头 runtime ABI min/max 精确 1.19；
4. `.xar` 索引 runtime ABI min/max 精确 1.19；
5. 指令流运行时 ABI 精确 1.19；
6. 原生元数据记录 ABI 1.19、生成器 21、标准库身份 1；
7. 不改变容器 schema/索引结构版本；
8. 保存常量、头/索引/元数据样本。

退出：新产物精确记录 1.19/21；`.xiaoc` 格式、`.xar` 目录/索引 schema 均未变化。

### B5-2：旧/新拒绝矩阵

1. 使用 B5 验证器加载 F-6a 原始 1.18 `.xiaoc`/`.xar`，必须在入口版本检查、任何用户代码/模块初始化/宿主副作用前拒绝；原件 SHA-256 前后不变；
2. 使用 B5 1.19 验证器读取新 `.xiaoc`/`.xar` 并确认接受；再用固定身份的旧 1.18 验证器读取同一产物，必须在执行前拒绝；
3. F-6a 原始 1.18 原生元数据被 B5 验证器按精确 ABI 范围/标准库身份拒绝；
4. B5 验证器接受新 1.19/21 原生元数据；固定身份的旧 1.18 验证器拒绝同一元数据；
5. 每格记录输入 SHA-256、验证器/Runtime SHA-256、退出码、实际拒绝阶段/错误和无执行副作用检查；不能只凭版本字符串或执行到未知原语失败；
6. `.xiaoc` 格式及 `.xar` 目录/索引 schema 维持基线版本；拒绝由冻结的 ABI min/max 与元数据身份规则触发；
7. 不做迁移工具、不手改旧头、不放宽 max；
8. 保存四类旧/新拒绝的原始日志、机器回执和原件只读摘要。

退出：旧/新 `.xiaoc`、`.xar` 与原生元数据拒绝矩阵全部实际执行；原件未改写，拒绝发生在用户代码运行前。

### B5-3：缓存重生成

1. 固定一份B4-3前由生成器20生成的历史缓存及其源码提交、目标三元组、工具链、优化计划、ABI 和 Runtime 静态库身份；
2. 在隔离任务根中以相同输入源码/目标/优化计划切换到 ABI 1.19/生成器 21，并提供旧缓存副本作为失效探针；
3. 缓存身份核对生成器、ABI、优化计划和 Runtime 静态库内容；任一不匹配都必须 miss 并重生成；
4. 证明旧对象、旧可执行文件和旧 Runtime 未被链接或执行；新产物链接到摘要已记录的 1.19 Runtime；缓存探针在独立 target/cache 根运行，不读写 Cargo 全局缓存；
5. 保存旧 fingerprint、miss 原因、新 fingerprint、新对象及 Runtime SHA-256 和链接/执行日志。

退出：旧缓存不被误用；新产物身份完整。

### B5-4：C ABI 加法扩展

1. 以 F-6a 历史 1.18 C ABI 清单为旧调用方基线，并另存 B4当前1.18/21过渡符号集；
2. B5 保留 F-6a 全部符号、布局和调用约定；当前 B4 内部快照已存在的 33～48 相对 F-6a 基线属于加法扩展，B5 保留其精确符号和签名，不在 B5 重复定义或改变；
3. B5 不新增 intrinsic ID；如需增加冻结集之外的新 C 符号，必须另有明确接口授权并以追加方式登记；
4. 实测旧 1.18 调用方仅使用 F-6a 既有符号时可链接/运行于 1.19 Runtime；使用 33～48 的 1.19 产物仍必须被旧 Runtime 在执行前拒绝；
5. C ABI 向后兼容不放宽 `.xiaoc`/`.xar`/原生元数据的精确版本拒绝；
6. 保存历史/内部/新版本符号表差异、布局断言、旧调用方实测和拒绝矩阵关联证据。

退出：相对 F-6a 的 C ABI 扩展清单可解释；历史符号布局未破坏，B5 内部 1.18/21 的 33～48 未重复定义。

### B5-5：测试与证据

1. ABI 1.19/21 `.xiaoc`/`.xar` 编码、解码及代表性执行；格式/目录 schema 与基线一致；
2. 执行 B5-2 全部旧/新产物拒绝矩阵；
3. 原生元数据旧/新拒绝；
4. 1.18/21过渡缓存因ABI身份变化miss/重生成，新对象和 1.19 Runtime 实际链接身份可核对；
5. 从 B1 七库源码在 1.19/21 下重新生成回归产物，运行 20 入口、资源 17、双精确及 B4 cmath 内部语言链路；不得把旧 1.18 的执行成绩当新版本回归；完整 721 留 B2-C；
6. 在 B5 最终源码上重跑 28/28 守卫并保存工作流/脚本/源码身份；守卫只验证计数逻辑，不代替产品测试；
7. 使用 Rust `1.96.0` 运行完整 workspace gates：`cargo +1.96.0 test --manifest-path core/rust/Cargo.toml --workspace --locked`、`cargo +1.96.0 clippy --manifest-path core/rust/Cargo.toml --workspace --all-targets --locked -- -D warnings`、`cargo +1.96.0 fmt --manifest-path core/rust/Cargo.toml --all -- --check`、`bun run check:lock` 和 `bun tools/repo-check/src/cli.ts all`；
8. 保存源码、锁、旧/新 Runtime、工具链、目标、PID、日志及前后摘要；
9. 记录 Windows 本机与未执行平台；三平台/721 未跑。

退出：版本矩阵证据完整；B6 未开始；B2-C 未开始。

### B5-6：收口与 B6 交接

1. 复核 1.19/21/接口 1、拒绝矩阵、缓存；
2. 复核无 registry/教程/721 改动；
3. 形成 B6 资源/性能入口；
4. 记录 B2-C 最终三平台/721/教程/registry 后置。

退出：B5 内部收口；B6 未开始。

## 四、证据矩阵

| --- | --- |
| 版本 | ABI 1.19 编码、生成器 21、接口 1、intrinsic 1～48 与 ID 100 |
| 容器 | `.xiaoc` 头、`.xar` 索引、指令流、原生元数据；格式/schema 版本不变 |
| 拒绝 | F-6a 原始 1.18 原件由新验证器拒绝；新 1.19/21 原件由固定旧验证器拒绝；记录入口与副作用 |

| 回归 | B1 20/17/双精确/资源 17、最终源码 28 守卫、B4 cmath、完整 workspace gates |

## 五、退出条件

1. ABI1.19生效、生成器21沿用、接口1不变；
2. `.xiaoc`/`.xar`/指令流/原生元数据记录正确；
3. 旧/新拒绝矩阵实际执行，旧原件未改写；
4. 1.18/21过渡缓存不复用，新缓存/Runtime 身份完整；
5. C ABI 旧布局保留、新增加法；

## 六、风险与禁止

- 手改旧头/放宽max版本伪装兼容；
- 只改头不改索引/指令流/原生元数据；
- 旧缓存被复用或旧Runtime混入新产物；
- 新增入口破坏旧C布局/调用约定；
- 提前跑721/升级registry/教程；
- 把B5内部1.19/21写成B2-C最终发布。
