# 20O-B2-B5. ABI 1.19、生成器 21 与拒绝矩阵实施规划

> **B4-2～B4-5 尚未完成；B5 仍未开始，B6、B7 与 B2-C 后置。**
> 入口为 B4 内部语言收口后的最终源码；当前 ABI 1.18、生成器 20、接口 1。
> B5 只做 ABI 1.19/生成器 21、旧/新产物拒绝、缓存重生成和 C ABI 加法扩展。
> 不实现 cmath（B4 已完成）、不升级 registry/教程、不跑旧 721；B2-C 才做最终公共发布。

## 一、入口与范围

| 项 | 当前状态 |
| --- | --- |
| B4 | 内部 1.18/20 语言可用性收口（待完成） |
| 当前版本 | ABI 1.18、`CODEGEN_VERSION=20`、标准库接口 1、活动 intrinsic 1～48 |
| B5 目标 | ABI 1.19（编码 `0x0001_0013`）、生成器 21、接口 1 |
| 产物 | `.xiaoc`/`.xar` 精确 1.19、原生元数据 1.19/21、标准库身份 1 |
| 兼容 | 旧 1.18 原件拒绝；新 1.19 被旧 1.18 验证器拒绝；生成器 20 缓存失效 |
| 未做 | B6 资源/性能、B7 收口、B2-C 721/教程/registry/三平台最终发布 |

B5 是 **版本矩阵内部切换批**，不是 B2-C 最终发布。B5 的产物仍只作内部验证；最终三平台公共产物、721 和 registry 升级留 B6/B2-C。

### 1.1 要做

1. ABI 次版本 1.19（编码 `0x0001_0013`）、生成器 21、标准库接口保持 1；
2. `.xiaoc` 头、`.xar` 索引和指令流记录精确 1.19；
3. 原生元数据记录 1.19/21 和标准库身份 1；
4. B1 原始 1.18 产物在执行前按头/索引/指令流拒绝，原件不改写；
5. 新 1.19 产物被旧 1.18 验证器拒绝；
6. 生成器 20 缓存因身份不匹配重新生成，不复用旧对象；
7. 保留既有 1.18 C 符号/布局/调用约定，新增入口只做加法；
8. 保存旧/新拒绝、缓存重生成、B1 20 入口回归和版本身份证据。

### 1.2 明确不做

- 不手改旧 `.xiaoc`/`.xar` 头或放宽 max 版本；
- 不增加迁移工具或“兼容重放”旧原件；
- 不改变容器格式/索引 schema 版本；
- 不升级 `stdlib.cmath`/registry/教程；
- 不跑旧 721，不关闭 22C/22D、19/11/22；
- 不把 B5 内部 1.19/21 写成 B2-C 最终发布或三平台产品。

## 二、开工闸门

1. B4-1～B4-5 审计通过，最终产品/证据身份固定；
2. 15 项 cmath 内部语言链路、30 条导入、双路径/归档/序列化可复现；
3. 当前 ABI 1.18/生成器 20/接口 1/cmath planned 未变；
4. B1 原始 1.18 `.xiaoc`/`.xar`/原生元数据归档可读；
5. 旧 1.18 验证器和生成器 20 缓存基线可复现；
6. C 符号表/布局/调用约定基线已保存；
7. 唯一任务根、独立 target/Runtime/缓存已建立。

## 三、分批执行

### B5-0：版本/产物基线

1. 固定 B4 最终源码、B1 原始 1.18 产物、旧验证器和生成器 20 缓存；
2. 记录 `.xiaoc` 头、`.xar` 索引、指令流 runtime ABI、原生元数据当前值；
3. 记录 1.18 C 符号/布局/调用约定和 33～48 新增符号；
4. 记录旧 1.18 验证器/运行器对当前产物的行为；
5. 保存基线。

退出：版本/产物/缓存/C 符号基线可复现。

### B5-1：ABI 1.19 与生成器 21

1. `ABI_MINOR_VERSION=19`，编码 `0x0001_0013`；主版本仍 1；
2. `CODEGEN_VERSION=21`；标准库接口保持 1；
3. `.xiaoc` 头 min/max 精确 1.19；
4. `.xar` 索引记录精确 1.19；
5. 指令流运行时 ABI 精确 1.19；
6. 原生元数据记录 ABI 1.19、生成器 21、标准库身份 1；
7. 不改变容器 schema/索引结构版本；
8. 保存常量、头/索引/元数据样本。

退出：新产物精确记录 1.19/21；无 schema 变化。

### B5-2：旧/新拒绝矩阵

1. B1 原始 1.18 `.xiaoc`/`.xar` 在执行前拒绝，原件不改写；
2. 新 1.19 `.xiaoc`/`.xar` 被旧 1.18 验证器拒绝；
3. 原始 1.18 原生元数据被 1.19 验证器按精确 ABI 范围/标准库身份拒绝；
4. 新 1.19 原生元数据被旧 1.18 验证器拒绝；
5. 不能只靠执行到未知原语才失败；必须在入口版本检查拒绝；
6. 不做迁移工具、不手改旧头、不放宽 max；
7. 保存四类拒绝的实际错误/入口和日志。

退出：四种旧/新拒绝路径实际执行；原件未改写。

### B5-3：缓存重生成

1. 生成器 20 缓存身份与新 1.19/21 不匹配，必须重新生成；
2. 缓存指纹包含生成器/ABI/优化计划/Runtime 静态库内容；
3. 不复用旧可执行文件、旧 Runtime 或旧对象；
4. 重新链接 1.19/21 产物，记录新 Runtime/缓存摘要；
5. 保存旧缓存拒绝/新缓存生成证据。

退出：旧缓存不被误用；新产物身份完整。

### B5-4：C ABI 加法扩展

1. 保留既有 1.18 C 符号/布局/调用约定；
2. 新增 33～48 入口按加法扩展，不改变旧结构；
3. ABI 1.19 不要求旧调用方升级主版本；
4. 不把二进制兼容写成容器接受超出 max 版本；
5. 保存符号表/布局/旧调用方兼容证据。

退出：C ABI 加法扩展；旧布局未破坏。

### B5-5：测试与证据

1. 1.19/21 `.xiaoc`/`.xar` 编码/运行；
2. 旧 1.18 原件/新 1.19 对旧验证器拒绝；
3. 原生元数据旧/新拒绝；
4. 生成器 20 缓存失效/新缓存生成；
5. B1 七库 20 入口、资源 17、双精确、28 守卫；
6. B4 cmath 内部语言链路回归；
7. 保存源码、锁、Runtime、工具链、目标、PID、日志；
8. 记录 Windows 本机与未执行平台；三平台/721 未跑。

退出：版本矩阵证据完整；B6 未开始；B2-C 未开始。

### B5-6：收口与 B6 交接

1. 复核 1.19/21/接口 1、拒绝矩阵、缓存；
2. 复核无 registry/教程/721 改动；
3. 形成 B6 资源/性能入口；
4. 记录 B2-C 最终三平台/721/教程/registry 后置。

退出：B5 内部收口；B6 未开始。

## 五、退出条件

1. ABI 1.19/生成器21/接口1精确生效；
2. `.xiaoc`/`.xar`/指令流/原生元数据记录正确；
3. 旧/新拒绝矩阵实际执行，旧原件未改写；
4. 生成器20缓存不复用，新缓存/Runtime身份完整；
5. C ABI 旧布局保留、新增加法；
6. B1/B4回归通过；旧721未跑；历史债务未核销；
7. B6未开始；B2-C未开始；三平台/性能仍未声称。

## 六、风险与禁止

- 手改旧头/放宽max版本伪装兼容；
- 只改头不改索引/指令流/原生元数据；
- 旧缓存被复用或旧Runtime混入新产物；
- 新增入口破坏旧C布局/调用约定；
- 提前跑721/升级registry/教程；
- 把B5内部1.19/21写成B2-C最终发布。
