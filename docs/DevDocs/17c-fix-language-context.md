## 二、问题清单

### 2.1 **`language_locale` 的消费不完整**（验收 8 的实质缺口）

> **⚠️ 本节在审核后更正过。** 初版写的是「被序列化但运行时**未消费**」，
> 并称 `xiao-xar` 的 runner 与 `xiao-driver` 的协议里**零命中**——**这个判断不准确**。
> 更正记录与原因见 §八。**以下是更正后的描述。**

**17C 的实际做法**（`xiao-driver/src/protocol/run.rs`，重构前）：

```rust
let effective_locale = if locale.is_none() {
    fs::read(&path).ok()
        .and_then(|bytes| decode_xar(&bytes).ok())
        .map(|archive| archive.index().language_locale.clone())
        .filter(|value| matches!(value.to_ascii_lowercase().as_str(), "zh" | "zh-cn" | "en" | "en-us"))
} else {
    locale.clone()
};
```

**所以协议层是读了的**，只是有三处不足：

1. **白名单过滤**——只有 `zh` / `zh-cn` / `en` / `en-us` 四个值被接受，
   其他语言（如 `ja-JP`）被**静默丢弃**，且**没有任何诊断**说明发生了什么；
2. **没有降级状态**——无法区分「用上了归档声明的语言」与「回落到了别处」，
   这正是 `17.13` 第 2 句要的「**语言资源缺失时仍能输出可读的内置诊断**」所缺的；
3. **`XarRunOptions` 没有语言入口**（`xiao-xar/src/runner.rs:14` 只有
   `runtime_abi` / `platform` / `vm_options`）——协议层的本地化**包不到运行器内部**：
   `run_archive` 自己产生的错误消息（四类 `XarRunError`）走的是**无语言上下文**的路径。

**`17.13` 的原文**：「接入第 11C 阶段的语言上下文和内置消息目录；**归档记录构建时语言默认值**，
**语言资源缺失时仍能输出可读的内置诊断**」。**第 1 句部分满足（协议层），第 2 句不满足**。

### 2.2 **成功路径没有回归测试**（验收 2 的强度缺口）

`run_archive` 在仓库里的用例**全是错误路径**——
`archive_runner_checks_runtime_before_entry_execution`（`xiao-xar/src/lib.rs:2292`）
的**两次调用都在 `.unwrap_err()`**：一次测 ABI 版本不兼容、一次测载荷校验失败。

**成功路径（`print` 真的输出、退出码 0）只有审核时的临时探针验过**，
仓库里没有留下回归。而这条恰是 17C 的**核心目标**（「让 `.xar` 真的能跑起来」）。

### 2.3 **「不得部分执行」缺断言**（验收 3 的强度缺口）

`run_archive`（`xiao-xar/src/runner.rs:91`）的**结构是对的**——
`decode_xar` → ABI 检查 → 平台检查 → 遍历 `entries` → 找入口 → **最后才调 VM**。
但现有测试只断言了**错误码**，**没有断言"没有指令被执行"**。

规范 `:67` 末句是「校验或诊断窗口启动失败时**不得部分执行**已加载模块」——
这是一条**行为要求**，不是错误码要求。

## 三、必须先冻结的 4 条

### 3.1 **语言默认值来自归档，可被调用方覆盖**

规范 `:31` 说归档记录的是「构建时有效的系统文案语言**默认值**」，
且「语言默认值**只影响系统文案，不改变归档语义**」。

**冻结**：

- 归档的 `language_locale` 是**默认值**——运行时的有效语言 = **调用方显式指定**（若有）
  **否则**取 `index.language_locale`，**再否则**回落到 11C 既有的缺省（`zh-CN`）；
- 优先级**不得**与 11C 已有的「项目配置覆盖全局」冲突——归档是**新的一层输入**，
  它的位置（在显式参数之下、缺省之上）要写进本文档的实施记录；
- **语言不影响机器字段**——`exit_code`、错误 `code`、`message_id`、结构化参数**都不随语言变**，
  这与 11C 既有契约一致（UseDocs 与 11C 都反复强调过这条）。

### 3.2 **消息渲染必须走 11C 的既有目录，不新造**

**冻结**：

- 复用 `xiao-i18n` 的消息目录与渲染器，**不得**为归档路径另写一套文案；
- 新引入的诊断/提示文本要**同时补进两套目录**（11C 的登记要求），
  并遵守「文案搬运」批次的台账口径；
- **不翻译**源码标识符、包名、路径（既有决策）。

### 3.3 **语言资源缺失时降级，不得失败**

`17.13` 明写：「语言资源**缺失时仍能输出可读的内置诊断**」。

**冻结**：

- 归档声明的语言在宿主上没有对应资源时，**回落到内置目录并继续执行**，
  **不得**因此拒绝运行；
- **但**要在诊断里**如实说明发生了降级**（哪个语言被请求、回落到了哪个），
  **不得静默**——静默降级会让"看到英文"这件事无从解释。

### 3.4 **补的两条回归必须是可证伪的行为断言**

**冻结**：

- §2.2 的端到端回归：断言 **`IntrinsicOutput` 事件真的带着 `hello world!`** 与
  `result.is_success()`——**不是**只断言 `run_archive` 返回 `Ok`；
- §2.3 的"不得部分执行"：断言**没有任何执行事件产生**
  （`ModuleLoaded`/`FunctionEntered`/`IntrinsicOutput` 等），而**不只是**断言错误码；
- 两条都要能在**删掉对应实现**时失败——与 20AB/`20AB-FIX` 立下的
  「**移除验证**」口径一致，**不得**写成同义反复。

## 四、修复要求

### 4.1 接语言上下文（对应 §2.1）

- `XarRunOptions` 增加语言输入（显式指定为 `Option`，**默认取归档记录的 `language_locale`**），
  按 §3.1 的优先级解析出有效语言；
- 归档执行路径的消息渲染接 `xiao-i18n`；
- 补 §3.3 的降级与如实说明。

### 4.2 补端到端回归（对应 §2.2）

按 §3.4 写一条**成功路径**用例，覆盖「源码 → IR → TAC → `.xiaoc` → `.xar` → `run_archive`」
的完整链路（审核时的探针就是这个形状，可直接据此落地）。

### 4.3 补「不得部分执行」断言（对应 §2.3）

构造一个**索引/对象校验会失败**的归档，断言**没有任何执行事件**产生。

## 五、验收

1. **归档语言生效**：归档记录 `zh-CN` 时，**不传**显式语言，诊断/系统文案为中文；
2. **可覆盖**：显式指定其他语言时**覆盖**归档默认值；
3. **机器字段不随语言变**：`exit_code`、`code`、`message_id`、结构化参数在两种语言下**一致**；
4. **降级可读**：归档声明的语言在宿主上无资源时，**回落到内置目录并继续执行**，
   且诊断**如实说明降级**（哪个语言、回落到哪个）；
5. **端到端回归**：成功路径用例断言 `IntrinsicOutput` 携带 `hello world!` 且 `is_success()`；
6. **不得部分执行**：校验失败的归档**不产生任何执行事件**；
7. **两条回归可证伪**：删掉对应实现时会失败（按 §3.4）；
8. **不回归**：两种 CLI 形式仍等价、`xiao run hello.xiao` 仍零诊断；
9. **不重开**：17A/17B/17C/11C 的既有测试未改且全绿；
10. **门禁全绿**：`cargo test --workspace`、`cargo clippy --workspace --all-targets -- -D warnings`、
    `bun run check`（含 `check:lock`）全绿。

## 八、审核更正记录

### 8.1 「运行时未消费」的判断是错的

本文件初版 §2.1 写「`language_locale` 被序列化但运行时**未消费**」，
并称 `xiao-xar` 的 runner 与 `xiao-driver` 的协议里**零命中**。

**这个判断不成立**：17C 的 `protocol/run.rs` 里**确实读了**
`archive.index().language_locale`（更正后的代码引用见 §2.1）。

**出错的原因**：审核时跑的 grep 是

```bash
grep -rn "language_locale" ... | grep -v "17a\|index_for" | head -8
```

`xiao-artifacts` 里该字段命中很多（字段定义、编解码、多个测试夹具），
**`head -8` 把它们全部占满**，`run.rs` 的命中根本没机会显示；
`grep -v` 的过滤条件也过宽。**这是一次「截断式 grep 导致的假阴性」。**

**为什么保留这条更正**：它不改变 17C-FIX 的**结论**（§2.1 的三处不足成立、
修复仍有价值），但**改变问题的性质**——从「整条路径没接」变成「接了但接得粗糙」。
二者的修复面不同：前者要**新建**语言入口，后者是在既有读取上**补**白名单之外的降级、
降级状态与运行器内部入口。

**教训（写给后来者）**：用 `grep` 下「**零命中**」这类**全称否定**的结论时，
**不得**同时用 `head` 截断、或用过宽的 `-v` 过滤——两者都会把「没看到」伪装成「不存在」。
先确认命中总数（`grep -c`），再决定怎么取样。
