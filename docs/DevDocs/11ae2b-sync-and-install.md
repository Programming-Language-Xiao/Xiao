## 三、必须先冻结的 6 条（**否则实现会先于设计**）

### 3.1 激活通道：临时文件（**本批的核心机制**）

**问题**：`11a:59` 已冻结「钩子调用 `xiao` 可执行程序，**接收经过校验的环境变更**，
再应用到当前终端」——但**这条通道 E0 没有建**。E0 的 `venv` 靠 shell 函数
**从命令行参数推导**环境名，而 `xiao sync` 没有环境名参数（目标是"激活优先 → `.venv` → 创建"
**算出来的**），钩子无从推导。

**冻结机制**：

```bash
# 钩子侧（Bash）
xiao() {
  export XIAO_ACTIVATION_FILE="$_xiao_tmpdir/xiao-act-$$"
  command xiao "$@"; local _xiao_status=$?
  if [[ $_xiao_status -eq 0 && -f "$XIAO_ACTIVATION_FILE" ]]; then
    # 校验后应用（见下）
    source "$XIAO_ACTIVATION_FILE"
    rm -f "$XIAO_ACTIVATION_FILE"
  fi
}
```

`xiao` 需要激活时写该文件，内容只有两行：

```sh
XIAO_ACTIVE_ENV='/abs/path/to/.venv'
export XIAO_ACTIVE_ENV
```

**⚠️⚠️ 安全要害：`source` 一个文件等于执行任意代码。**

钩子**必须**在 `source` 前做白名单校验，**不得**直接把文件内容喂给 `source`：

- 只接受**恰好两行**；
- 第一行必须匹配 `XIAO_ACTIVE_ENV='<绝对路径>'`（单引号包裹、路径必须绝对、不含换行）；
- 第二行必须是 `export XIAO_ACTIVE_ENV`；
- **任何其他内容一律拒绝并删除文件**，不报错地忽略（或输出一行警告）。

**不校验的后果**：任何能写该路径的进程都能让用户的下一个 `xiao` 调用后执行任意命令。
这不是理论风险——临时目录是可预测的，`$$` 也可预测。

**同时冻结的配套项**：

- 临时文件路径必须**不可预测**（含随机分量，`mktemp` 级），且在用户私有目录下；
- 钩子无论成功失败都要删除该文件（避免残留被下次误读）；
- **PowerShell 用同一机制**（文件路径 + 环境变量），不依赖 fd 重定向（PowerShell 无此概念）。

**⚠️ 这是对 E0 的行为变更，要写明**：`XIAO_ACTIVE_ENV` 从
「不导出的**名称**变量」变为「导出的**绝对路径**变量」。

- E0 冻结的是**命令与行为**（`shell-init`/`deactivate`、前缀结构、颜色规则、`cmd` 降级），
  **不是变量名**，所以扩展不破约；
- 但**这是真实的行为变化**，必须在 `11a` 的 E0 章节（`:59-66`）**补充激活通道的具体说明**：
  那段现在只写了「钩子接收经过校验的环境变更」这个**原则**，
  **没有写通道形态、也没有写变量名**。本批把通道落地后，`11a` 要同步写明
  `XIAO_ACTIVATION_FILE` 与 `XIAO_ACTIVE_ENV` 的语义与校验规则。

**⚠️ `cmd.exe` 降级路径**：`cmd` 没有 shell 函数机制，`XIAO_ACTIVATION_FILE` 对它无意义。
**保持 E0 的降级口径**：命令成功、**不宣称已自动激活**、输出手工激活提示。
不要为了"统一"给 `cmd` 编一个假的激活。

**E0 的 `venv` 分支要不要统一到这条通道？** 建议**统一**——
消掉「从参数推导」这个脆弱做法（它现在还硬编码了"跳过 `--` 开头参数"的启发式，
`xiao venv --help` 之类会误判）。若统一，`venv` 也改为写激活文件。

### 3.2 `sync` 的目标环境选择（E2A 已冻结，本批落地）

E2A 已冻结：**激活环境优先 → `.venv` → 都没有则创建 `.venv`**。

**本批的前置条件由 §3.1 提供**：在 E2B 之前，`XIAO_ACTIVE_ENV` 读不到，
所以"激活优先"**无从判断**。**必须先做 §3.1，再接线 §3.2。**

环境目录基准沿用 `00-decisions:278`：向上发现 `config.xiao` 所在项目根，找不到回退当前目录。

### 3.3 `--keep-extra`（反向开关名）

`11a:380` 只说「反向开关保留它们」，名字未冻结。**本批冻结为 `--keep-extra`**。

`sync` 的完整开关集：

```text
xiao sync                  默认：同步到锁文件描述的目标状态，含移除多余包
xiao sync --keep-extra     保留环境中不属于依赖集的多余包
xiao sync --locked         锁文件必须已是最新；需要变动则以非零退出码失败并说明原因
xiao sync --frozen         只用现有锁文件；缺失或不一致直接失败
```

⚠️ `--locked` 与 `--frozen` 的**冲突组合**（同时给）要定：建议**直接报错**，不静默取其一。

### 3.4 `sync` 流水线里**哪些步骤本批是空实现**

`11a:401` 冻结了完整顺序：

```
读取已配置源 → 校验并合并联邦源索引 → 应用显式源/配置顺序规则
→ 生成或验证锁文件 → 下载并校验正文 → 原子更新环境映射
```

但**本批只有本地路径依赖**（E1 已限定），远程源属 E3。**要冻结的是**：

| 步骤 | E2B 的行为 |
| --- | --- |
| 读取已配置源 | **无源可读**——本地路径依赖不经过源协议 |
| 合并联邦源索引 | **跳过**（E3A/E3B） |
| 应用源顺序规则 | **跳过**（单源即本地） |
| 生成/验证锁文件 | **E2A 已实现**，本批接线 |
| 下载并校验正文 | **无下载**——本地内容直接进 E1 缓存 |
| 原子更新环境映射 | **E2A 已实现**，本批接线 |

**⚠️ 必须在文档里写明这些跳过**，否则接手者会以为 E2B 漏了阶段。
**不要**为跳过的步骤写空壳函数占位——那会让"未实现"和"已实现但为空"无法区分。

### 3.5 全局环境由 `install` 隐式创建（**一条真歧义**）

`11a:372` 说 `install`「**不创建环境**，也不自动激活环境」；
而 `11a:375` 说它「没有激活环境时**写入全局环境的依赖映射**」。

**两条合起来的推论**：全局环境不存在时，`install` **必须能创建它**，
否则"写入全局环境的映射"无处可写。

**冻结口径**：

- `install`/`i` **不创建项目环境**（`.venv`/具名环境）——这是 `11a:372` 的本意；
- `install`/`i` **按需创建全局环境目录 `envs/<name>/`**——它不是一个"项目环境"，
  而是被动的映射容器；
- **不得**因为创建了全局环境就激活它（`12-tests:768` 明写"均不创建或激活环境"）。

**⚠️ 这里的措辞要小心**：`12-tests:768` 的"不创建"与"按需创建全局环境"表面冲突。
**文档必须显式解释**：该条约束的是**项目环境**，全局环境是映射容器、不是被同步的目标环境。

### 3.6 11B 接口的验收方式（**没有消费者，怎么验**）

E2B 二级任务第 4 条要求「向第 11B 阶段提供只读的环境包视图、接口元数据查询和延迟运行时加载接口，
验证**枚举、注册或类型查询不会执行包代码**」。

**11B 尚未开始，没有消费者。** 冻结验收方式：

- **只读环境包视图**：直接读 E2A 的 `package_mappings`，成本极低；
- **接口元数据查询 / 延迟运行时加载**：用**副作用探针**验收——
  在测试包里放一个「一旦被求值就会写标记文件 / panic」的模块，
  调用接口元数据查询后**断言标记不存在**。
  这样即使没有 11B 消费者，**"不执行包代码"这条也是可断言的事实**，而不是承诺。

⚠️ 若某条接口在 E2B 之后仍无消费者、也无副作用探针能覆盖，
**要显式登记为债项交给 11B**，不得记为"已验证"。

**不要**把"创建环境 → 装依赖 → 激活"的判定逻辑写在 TS 里——那会与 Rust 侧的
目标选择规则形成**第二份实现**（本仓头号病史）。

## 六、硬约束

### 6.1 单一来源

- **目标选择规则只有一份**（§5.2）——不得在 TS 侧重推；
- **不重新扫描 `config.xiao`**（`05d:103`）；
- **不重建锁文件与环境映射**——E2A 是唯一实现；
- **激活文件的校验规则只有一份**——Bash 与 PowerShell 两侧必须是同一条白名单，
  **两侧各写一套正则正是本仓头号病史**；建议把"合法内容"的生成放在 Rust/TS 单一函数里，
  校验规则写在文档里并由两侧测试共同锁定。

### 6.2 `install` 不重新求解

`11a:401`：「`install` / `i` **不重新求解**：它按已有锁文件物化，不更新锁文件。」
所以 `install` 遇到锁文件缺失/失配时**报错**，不自动生成。

### 6.3 严格区分 `sync` 与 `install`

`11a:373`：「`i` 是 `install` 的短命令，行为必须完全一致；**两者都不是 `sync` 的别名**。」
`install` 不创建环境、不激活、不更新锁文件、不移除多余包。

### 6.4 门禁

`A0-LAYOUT-002`（§5.1）、`A0-SIZE-001`、`A0-DOCS-001/002`、
以及**本批起 `check` 已包含 clippy**（E2A 修复，见 §十一.1）。

1. **条件 1**：`sync` 在无环境时创建 + 安装 + **激活**；
   有环境时补齐缺失依赖；**默认移除多余包**，`--keep-extra` 保留；
   `--locked` 需要变动时**非零退出码 + 说明原因**；`--frozen` 缺失/不一致直接失败。
2. **条件 2**：`install` 与 `i` **行为完全一致**（逐项对照测试）；
   有激活环境写该环境映射，否则写全局环境映射；
   **两者都不创建项目环境、不激活、不更新锁文件、不移除多余包**。
3. **激活通道**：
   - 合法内容能激活、提示符正确；
   - **非法内容（注入第三行、相对路径、非 `XIAO_ACTIVE_ENV` 变量、带换行的路径）
     一律被拒绝**——**每条都要有独立用例**；
   - 激活文件在成功与失败后都被清理；
   - `cmd.exe` 降级路径**不宣称激活**。
4. **目标选择**：激活环境、`.venv`、都没有→创建，三种路径各有正反例（§3.2）。
5. **11B 接口**：副作用探针——调用接口元数据查询后**标记文件不存在**（§3.6）。
6. **幂等**：连续两次 `sync` 第二次不重写锁文件、不重复安装（E2A 的 `LockFileWriteStatus::Reused`）。
7. **门禁全绿**：`bun test`、`bun run check`（**已含 clippy**）、`check:lock`、`bunx tsc`、
   `cargo test --workspace`。

## 十二、E2B 实施收口（2026-09-25）

- **命令与核心**：Rust `xiao-package/src/sync.rs` 独立完成激活优先、`.venv` 回退、
  锁文件模式、缓存和原子映射更新；`xiao-driver` 的 `package` 请求返回选中的绝对路径。
  TypeScript 仅负责开关、协议调用和显示；`install` 与 `i` 解析为同一命令。
- **激活通道**：Bash/PowerShell 从随机私有临时目录读**两行数据**，按同一白名单
  校验后赋值而**不执行文件**，成功/失败都清理；`venv` 共用，`cmd.exe` 保留无激活降级。
  PowerShell 5.1 的实际执行及注入拒绝已在 Windows 原生 PowerShell 上验证；
  Windows 的 MSYS Bash 通过 `XIAO_TEST_MSYS_BASH` 可选回归验证激活与注入拒绝；
  Linux/macOS 的普通 Bash 用例由当地测试执行，不把 WSL 当作裸机性能证据。
- **包视图和债项**：只读视图验证映射并读取元数据，静态源码不被求值；尚无 11B
  的接口声明元数据查询和延迟运行时加载消费者，因此**这两条接口及相应副作用探针
  明确交由 11B**，不得标成 E2B 已验证。离线缺包针对远程源尚不适用。
- **跳过的流水线**：本批仅本地路径依赖，不调用联邦索引、远端源优先级或网络下载；
  源码直接导入 E1 缓存，锁与映射使用 E2A 接口。没有为这些跳过阶段新增空壳实现。
- **证据**：`tests/spec/11a-sync` 的有效/错误夹具覆盖缺锁、高版本、嵌套同名文件、
  循环、变更锁失败；`e2b_sync.rs` 验证三档目标、幂等和只读映射；
  `activation.test.ts` 按恶意输入逐条运行 PowerShell 钩子；
  `index.test.ts` 比较 `install` 与 `i` 的协议结果。Windows 实测真实 `xiao-core`
  协议完成同步、锁定与全局安装；该机器只有 GNU clang（目标为 windows-gnu），
  CLI 工具链发现拒绝 MSVC 目标，故未将**真实 CLI 全链路**冒充为已验证。
