## 二、F-12 的三个裁定对象

### F-12a：033/034 是否保留

建议保留规划编号，不占用活动诊断表：

- 033：`NUMERIC_LIMIT_CODE` / `runtime.numeric_limit`，ResourceError；
- 034：`NON_TERMINATING_DIVISION_CODE` / `runtime.non_terminating_division`，ArithmeticError。

033 表示数值接纳/工作/结果预算超限，不等于实际分配失败 011；
034 表示有限的精确语言除法遇到非终止十进制，不等于除零 013。
两者在本批只登记为规划身份，不改 `xiao-diagnostics` 活动表。

如果星崽选择复用旧代码，则必须给出 033→011/009、034→009/013 的完整映射；不得保留两个含义不清的“泛化错误”。

### F-12b：错误优先级

建议冻结以下从外到内的顺序：

1. 调用/类型错误（X06-RUNTIME-002）；
2. `precision`/`rounding` 参数域（X06-RUNTIME-012）；
3. 输入文本/数值预算与合法性（原文超限 033；输入语法 012）；
4. 除零（013）与数学域/非有限结果（009）；
5. 工作/结果预算（033）；
6. 受控输出分配失败（011）；
7. 真实 OOM/Fatal 沿用既有边界，不伪装成可恢复数值错误。

约定示例：

- `precision=0` 且分母为 0：先报 012，不先报 013；
- 原文超过 65,536 字节：先报 033，不因后续坏字符改成 012；
- 合法输入的 `1/3`：034，不是 013；
- `1/0`：013，不是 034；
- `cmath.ln(0)`：009，不是 033；
- 输出分配失败：011，不是 033。

### F-12c：与 F-5 C ABI 状态的映射

建议：

- 1/2/3 仍为指针/标签/句柄结构错误，不设置挂起错误；
- 6 为有效标签的可恢复类型/参数/域/预算/受控分配错误，设置对应正常挂起错误；
- 033、034、011、009、012、002 都经状态 6 传播；out 保留；
- 8/Fatal 只用于既有不可恢复边界，不把 034/033 伪装成 Fatal；
- 成功时释放并替换 out，失败时保留 out；输入借用/强引用规则沿用 F-5。
