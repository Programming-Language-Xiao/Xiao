# 集合与成员判断

本页说明 C2-A/C2-B/C2-C 的集合静态边界，以及 09R2F1 研究 VM 的执行闭环。集合是
无序容器：元素的书写顺序不构成语言层迭代或索引契约。研究 VM 已能创建真实集合并
执行四种代数、六种关系比较和成员判断；正式生产 `xiao run`、成员增删和 `for` 迭代
仍属于后续阶段。

## 创建集合

非空花括号中只写值时表示集合：

```xiao
ids = {1, 2, 3}
names = {"xiao", "rust"}
flags = {true, false}
empty = set()
mixed = {1, "xiao", true}
```

`set()` 是空集合构造式，当前阶段要求它没有参数。空花括号 `{}` 仍然表示空字典表，
不能把它写成空集合：

```xiao
empty_set = set()
empty_table = {}
```

花括号中出现 `键 = 值` 条目时表示字典表；同一个花括号不能混用集合值条目和
字典键值条目。字典表的说明见[字典表与字典列](dictionaries.md)。

## 显式元素类型

显式类型约束的是“每个成员允许的类型”，不是位置，也不会给无序集合增加顺序：

```xiao
int ids = {1, 2, 3}
str names = {"xiao", "rust"}
bool flags = {true, false}
set<int> typed_ids = {1, 2}
set<int | str> typed_values = {1, "xiao"}
```

`set<T>` 和 `set<T | U>` 约束的是“每个成员允许的类型”，不是位置，也不会给无序
集合增加顺序。当前类型项只允许标量和 `none`；重复类型项会在类型层去重。显式声明
保留完整的成员并集，即使初始化器只出现一个成员类型：

```xiao
set<int | str> values = {1}
```

上例的绑定类型仍是 `set<int | str>`。未显式声明的非空集合会自动推导静态成员并集，
例如 `{1, "xiao", true}` 的类型摘要为 `set<bool | int | str>`。旧式 `int values =
{1, 2}` 仍然是同构容器约束，不能因为默认异构规则而接受字符串或布尔值。

`set<T>` 只能写在变量根声明上；集合不支持 `set<int> values[0]` 这种路径声明，
也暂不支持 `const set<...>`。

## 唯一性与可哈希性

集合中的相等元素只能出现一次。能够在编译期确定的重复标量会直接报告诊断；相等和
哈希身份按静态类型隔离，所以 `true` 与 `1`、`1` 与 `1.0`、不同整数宽度不会被视为
同一元素。集合元素必须可哈希，哈希值在元素位于集合期间必须稳定。当前类型层可直接
验证标量和 `none`；数组、字典表、字典列、普通集合等可变容器不能作为集合元素。
当前实现将元组统一视为不可哈希，递归证明留给后续阶段。

动态表达式作为集合成员时，类型层保留已知成员并集并登记运行时可哈希检查；09R2F1
研究 VM 会执行可哈希检查（失败时复用 `X06-RUNTIME-016`）。显式 `set<T>` 的动态
成员类型兼容检查仍是后续债项，不能把动态值当作静态证明。

集合不提供数字索引、键名索引、范围、步长或随机选择。对集合使用 `values[0]`
或其他选择器会产生容器选择诊断，而不是返回某个“看起来像第一项”的值。

## 成员判断

`in` 和 `not in` 的结果类型固定为 `bool`：

```xiao
ids = {1, 2, 3}
has_two = 2 in ids
missing = 4 not in ids
```

右侧必须是集合，左侧值必须可哈希并满足集合的元素类型约束。静态无法确定的边界会
登记运行时检查；09R2F1 研究 VM 已执行 `in`/`not in`，右侧不是集合或左侧不可哈希
时报告 `X06-RUNTIME-023`。显式成员类型的动态兼容半仍待后续阶段。

## 集合运算（C2-C）

两侧都是集合时，`+` 表示并集，`&` 表示交集，`-` 表示差集，`^` 表示对称差：

```xiao
left = {1, "x"}
right = {1, true}
all_values = left + right       # set<bool | int | str>
common = left & right            # set<int>
removed = left - right           # set<int | str>
different = left ^ right         # set<bool | int | str>
```

类型阶段的结果描述可证明的成员类型；09R2F1 研究 VM 已执行集合值运算。并集与对称差取两侧已知
成员类型并集，差集保留左侧已知成员，交集取静态成员类型交集。静态上没有共同成员
的交集显示为 `set<never>`；这代表已证明为空，与 `set()` 的未知元素类型不同。

集合比较 `==`、`!=`、`<`、`<=`、`>`、`>=` 都返回 `bool`。其中 `<`/`<=` 是真子集/子集，
`>`/`>=` 是真超集/超集；异构集合也可以比较。集合带有动态成员或来自未知 `set()` 时，
类型阶段会登记运行时检查，不会把未知情况当成静态证明。研究 VM 对动态集合操作数
失败报告 `X06-RUNTIME-021`，动态集合比较失败报告 `X06-RUNTIME-022`。

研究 VM 的结果使用操作数的稳定序列：并集为左侧原序再接右侧独有元素，交集和差集
按左侧过滤，对称差为左侧独有后接右侧独有。该序列用于跨载体验证，不改变集合在
语言层的无序语义，也不依赖哈希索引或排序。

原地形式 `+=`、`-=`、`&=`、`^=` 都按左值当前锁定类型检查：左值必须可变，结果不能
自动扩大其类型。已知成员冲突会在类型阶段报错；动态尾标会额外登记成员检查。
研究 VM 已接通这些运算的 TAC 降低；动态操作数检查会在执行前失败。`|` 和 `|=` 不
表示集合并集。

## 常见边界

- `{}` 是空字典表；空集合必须写 `set()`。
- 集合无序，不能通过索引读取，也不能依赖某次运行的显示顺序。
- `bool` 不会被当作整数，`{true, 1}` 会保留两个不同的静态成员类型。
- 显式 `set<int>` 集合不能加入字符串、布尔值或其他不兼容成员；旧式 `int` 前缀也
  保持同构约束。
- `set<int | str>` 的并集声明保留完整类型，不表示集合有顺序。
- 动态成员只得到运行时检查标记，不会被静态检查器默认为任意类型合法。
- `frozenset` 不属于当前阶段。
- 集合增删、`for`/迭代、正式生产 `xiao run` 和 `.xiaoc` 产物不属于 09R2F1。
