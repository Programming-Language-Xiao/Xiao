# `xiao-bytecode`

## 目录职责

定义生产字节码指令、常量池、函数/模块元数据、验证输入、内存编码接口和正式 `.xiaoc` 容器。
这里不实现解释循环。

## 工程期

09 建立内存指令流；14A 冻结分段 `.xiaoc` 格式、源码映射、完整性验证和格式检查命令；
14B 接入复用 13A 契约的字节码优化快照与验证管线。

## 模块放置

指令定义、常量池、函数/模块元数据、编码器、解码器和生产验证器放在 `src/`；解释循环放在
`xiao-vm`。09R3 冻结的布局版本为 `FORMAT_VERSION = 3`、opcode `0..40`，B0 不重新编号。

## 09R 沿革与兼容边界

09R2 的实质实现已经迁入 `src/`：`tac.rs` 定义统一三地址指令、常量池、寄存器类别映射与调用
签名表，`sig.rs` 补 `IrProgram` 缺失的调用 ABI 描述，`lower/` 按关注点拆分降低规则，
`verify.rs` 做自校验与释放序列对账，`encode.rs` 作为门面、`encode/` 按职责拆分实现，
提供 41 个稳定 opcode、布局版本 3 的内存编码/解码。09R2H 新增程序级表定义段，
携带静态成员签名、字段初始化函数和方法索引；构造与成员访问接入既有 Runtime 状态机。
选择器执行使用 `SelectorApply`、`BroadcastAssign`、`RandomSeed` 携带类型阶段计划；精确
`IndexGet` 与高级选择分开编码，LEB128 和定宽 `u16` 均有往返及拒绝测试。

`src/research/` 现在是兼容重导出层，保留旧的 `research::...` 路径供 09R 共享向量和基准
使用；新生产代码应依赖 crate 根路径。别名层的移除条件是 B0-C 交付且生产驱动器成为唯一
消费方，在此之前不得删除。研究编码仍只在内存中流转，不使用 `.xiaoc` 扩展名落盘。

`xiaoc.rs` 定义正式文件头、可扩展分区目录、稳定元数据/函数/常量/源码映射表和严格
边界检查。`encode_xiaoc` 只写入不压缩的确定性分区，`decode_xiaoc` 在返回 `TacProgram`
前验证完整性、Runtime ABI、未知必需能力、目录重叠和 09R 指令流；`xiaoc-check` 是只读
格式检查命令。头部和目录项由长度字段界定，未来可选分区可以按长度跳过，不能把研究编码
误当作公开格式。

`optimize.rs` 提供 14B 字节码管线：常量池规范化、无副作用自移动删除和等目标分支简化
是当前已实现的保守 Pass；不可安全证明的不可达块与槽布局明确记录为跳过。每个 Pass 都
保存前后快照，重新编码/解码并可用来源 IR 对账释放计划和错误路径，失败时保留未优化
参考程序。

冻结结论与施工顺序见 [09R. 字节码寄存器机型特别研究](../../../../docs/DevDocs/09r-bytecode-machine-research.md)。

## 禁止事项

不在字节码层重新定义类型或释放语义；交给 `xiao-vm` 前必须通过生产验证器，
`TacProgram.unsupported` 非空属于内部一致性错误。
