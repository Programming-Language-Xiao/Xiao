# 边界

该文件是既有 C ABI 符号实现的单一入口，内部 helper、错误槽、句柄覆盖和表/资源 ABI 之间共享大量私有函数与布局校验。22D 只把并发适配放到旁置 `abi_concurrency.rs`，保留旧入口的统一替换与释放顺序。

# 理由

直接拆分现有 ABI helper 会改变 `unsafe` 句柄检查、错误槽和输出槽释放的可见边界，容易产生重复符号或改变链接裁剪结果。当前超限来自历史 ABI 实现和少量并发分派分支的合并，文件仍由同一个 Runtime C ABI 所有者维护。

# 替代方案

已采用独立 `abi_concurrency.rs` 承载新增并发盒子和 trampoline；继续按每个 ABI 子域拆分旧表、资源、动态值模块会要求同步移动大量私有 helper、测试路径和符号可达性，风险高于当前小幅超限。后续若继续增加 ABI 能力，将优先新建旁置模块。

# 移除计划

当 22E 冻结并发产物元数据后，下一次 ABI 维护批统一盘点 `abi.rs` 的错误、值和兼容入口，把剩余历史子域拆到已有 `abi_*` 模块；完成拆分并通过符号/释放回归后删除本说明。
