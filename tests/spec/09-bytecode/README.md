# 09-bytecode 语义向量

本目录记录 09R2 的**执行结果**向量，对应工程期 09R2。与 `01`–`06` 的静态快照
不同，这里的 `status` 是 `verified-runtime`：期望值来自真实执行，而不是静态分析。

## 与机型无关

向量里**不得出现任何机型专属字段**。当前由栈式、分类型寄存器式和混合式三种
载体直接复用同一组期望值；**禁止为某一型修改期望**。`r2_vectors.rs` 只保留一份
解析与观察逻辑，依次运行三种载体。

## 每条用例锁定什么

- `outcome`：`success`、`error` 或 `fatal`。三者分开是因为致命故障不可被普通
  捕获恢复，也不能与可恢复错误共用一个分支。
- `error_code`：稳定错误码或故障码。
- `value`：入口返回值的结构化 JSON 观察形式；集合、数组和元组保留容器种类与元素序列。
- `releases`：`(作用域, 退出边, 值, 类别)` 的**完整有序释放序列**。它来自冻结
  释放计划，是后端「没有重排、去重或漏放」的可观察证据。
- `max_call_depth`：达到过的最大调用深度。

## 文件

- `scalar.json`：标量算术、比较、字符串字面量与拼接、布尔奇偶加减。
- `control.json`：条件分支、循环、递归与嵌套调用。
- `errors.json`：整数溢出（可恢复）与调用栈耗尽（致命）。
- `containers.json`：数组/元组/集合构造、数组与字符串的精确索引（含负索引）、
  以及传参字面量临时值的释放。
- `selectors.json`：多选、嵌套范围、固定种子随机选择和事务性广播（4 条）；同一文件由
  栈式、分类型寄存器式和混合式三种研究载体复用。
- `sets.json`：集合四种代数、六种关系比较、成员判断、空集/异构边界、动态检查错误和
  运行时去重；同样由三种研究载体复用。
- `iteration.json`：数组、元组、字符串码点、集合、字典表/字典列迭代，空容器、嵌套
  循环、`break`/`continue`、动态可迭代检查和循环绑定重赋值；同样由三种研究载体复用。
- `tables.json`：单例、实例隔离、方法参数、别名/容器析构、初始化失败回滚、异常展开和
  致命故障（6 条）；同时锁定完整释放序列。

运行时的容器越界与键缺失**没有进向量**：静态检查器会提前拒绝常量越界与缺失键，
因此它们在字面量程序里不可达。那两类语义由 `xiao-vm` 的 `ops.rs` 单元测试直接
覆盖。

## 读期望值时注意

标量形参和局部值即使跨作用域读取或递归传递，仍按值保留在栈/寄存器中，不产生堆释放
事件；字符串和容器等堆值才会进入释放序列。生命周期回归测试会守住这条边界。

运行时可恢复错误**不能用字面量构造**：`value = 7 % 0` 会在类型阶段被常量折叠
拒绝（`X02-TYPE-007`），那是正确行为。运行时向量一律用编译期不可知的形参参与
运算来构造。

表向量的释放序列已对照 `IrOwnership` 和冻结计划审阅：实例用例先释放调用接收者，
再按逆声明顺序释放 `second`、`first`；别名用例依次释放 `items`、`alias`、`first`，
最后释放全局单例。未物化的构造定义和方法名不虚报释放；析构只读视图也不增加对象强计数。
未捕获的初始化/析构错误消费 `unmatched_error` 计划，Fatal 不执行计划。错误原因链与
析构调用次数另由 `r2_table_values.rs` 精确断言。

当前目录共 79 条向量（`scalar` 6、`control` 4、`errors` 9、`containers` 8、`selectors` 4、
`sets` 29、`iteration` 13、`tables` 6）；09R2H 未修改既有 73 条向量的期望。
对应实现测试为 `core/rust/crates/xiao-vm/tests/r2_vectors.rs`；研究 VM 仍不是生产 `xiao run`。
