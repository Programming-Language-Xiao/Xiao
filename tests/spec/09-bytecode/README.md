# 09-bytecode 语义向量

本目录记录 09R2 的**执行结果**向量，对应工程期 09R2。与 `01`–`06` 的静态快照
不同，这里的 `status` 是 `verified-runtime`：期望值来自真实执行，而不是静态分析。

## 与机型无关

向量里**不得出现任何机型专属字段**。本批次只有栈式载体在跑，但后续的分类型
寄存器机型和混合式机型必须直接复用同一组期望值；**禁止为某一型修改期望**。

## 每条用例锁定什么

- `outcome`：`success`、`error` 或 `fatal`。三者分开是因为致命故障不可被普通
  捕获恢复，也不能与可恢复错误共用一个分支。
- `error_code`：稳定错误码或故障码。
- `releases`：`(作用域, 退出边, 值, 类别)` 的**完整有序释放序列**。它来自冻结
  释放计划，是后端「没有重排、去重或漏放」的可观察证据。
- `max_call_depth`：达到过的最大调用深度。

## 文件

- `scalar.json`：标量算术、比较、字符串字面量与拼接、布尔奇偶加减。
- `control.json`：条件分支、循环、递归与嵌套调用。
- `errors.json`：整数溢出（可恢复）与调用栈耗尽（致命）。

## 读期望值时注意

`recursion` 用例里同一个值被释放四次，这不是噪声：递归调用会把形参标记为逃逸，
`int` 形参因此升级为堆值，每帧各持有并释放一次。

运行时可恢复错误**不能用字面量构造**：`value = 7 % 0` 会在类型阶段被常量折叠
拒绝（`X02-TYPE-007`），那是正确行为。运行时向量一律用编译期不可知的形参参与
运算来构造。

对应实现测试为 `core/rust/crates/xiao-vm/tests/r2_vectors.rs`。
